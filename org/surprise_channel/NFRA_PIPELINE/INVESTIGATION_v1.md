## S1 -- the channel's class axis carries a PRECEDENCE RULE, and the estate's own memory names that as the tell for two axes fused

**How it surfaced:** the pre-commit risk-reflex fired on `NFRA_ONTOLOGY_C2C3_CANONICAL.yaml` and
named its citation — `memory/feedback_token_census_pinned_surface_set_and_precedence_rule_tell.md`.
I read it because the reflex said to. Its clause (2), CTO-authored 2026-08-20: *"A single-intent
MECE axis never needs precedence — its values are disjoint by construction. A precedence clause is
a repair for a MECE failure the author decided to live with; it reads as rigour, which is why it
survives review."* **My class axis, landed ninety minutes earlier, contains exactly that repair:**
`BLOCKING > LATENT_HAZARD > OBSERVATION`.

**The measured specimen, and it is mine:** I filed the portal `tsc --noEmit` false green as the
**OBSERVATION** exemplar. But it satisfies my own LATENT_HAZARD test verbatim — its danger
actuates through the FUTURE NORMAL operation of the process (a seat types the obvious command and
gets a confident green on a promote). **And the fabric treated it as armed while I called it an
observation: COO routed it into the DT spawn brief and CTO landed a portal law line (@82d3f28f) —
that is a DISARM, same-turn, off-cadence.** The remedy actually applied contradicts the class I
assigned. **Rule 24(iv) applied to my own enum: one remedy does not move all members, so the axis
is not one axis.**

**What is fused:** (i) INTERRUPTION RIGHT — does it interrupt the current work? (ii) HAZARD
STANDING — is it armed against future normal operation if nobody acts? An item can be both
(blocking now AND armed for later); the precedence rule was the repair that let one field pretend
otherwise.

**Why ARMED standing (prose: a latent hazard) rather than merely an observation:** nothing stops, but it detonates on
the channel's normal operation — the next seat classifying an item mis-files it, and a mis-filed
hazard silently loses its disarm obligation. Dormant, armed, actuated by ordinary use.

**DISARM (same-turn, this seat, off-cadence):** the precedence rule is REMOVED and the fused
property is made expressible — `hazard_standing: ARMED | INERT` lands as its own orthogonal field
with its own four-postulate record, so an item that both blocks and is armed carries a disarm
owner instead of being forced to a single value. The tsc specimen is re-filed in the protocol as
OBSERVATION-class + ARMED-standing, which is what actually happened to it.

**REMEDIATION (rides the round, NOT mine alone):** whether the ratified three-value `class` enum
should itself collapse to the interruption axis, with standing carried only by the new field, is a
question about vocabulary named in the ratified pipeline doc — CTO/COO's ruling, not a CVO
schema edit. Graduated to `REMEDIATION_v1.md` with them as owners. **DISARMED ≠ REMEDIATED: the
trap is defused; the vocabulary question is open.**
