## Position

dell1 on Andrew's word, 2026-10-15) keep their write sets. The act adds only a read principal on objects they already
publish.

## Why it gave pause

### Ambiguity
"Shared bucket" counts as a CROSS-BOX hit, but this act is read-only. A read grant on a shared bucket's served prefix moves
no other box's output; the question is whether reading alone is cross-box.

### Out of pattern
The harvest table's producer is now dell1's. A site Z tool on it couples the gateway to dell1's write cadence: if dell1
changes the table's key shape, the tool breaks with no signal on site Z.

### Other solutions
(1) Rule all eight out of the 22:00Z line and carry them as a named next increment. That costs nothing today, but leaves
eight live research surfaces with no agent read. (2) Add only the seven `served/*` tools and route the harvest table to
dell1's AMGT_HARVST as that project's own tool. That keeps the coupling on the producer's box. **This seat would accept
(2) as an amendment.**
