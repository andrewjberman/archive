## Why it gave pause

### Ambiguity

"Box agent identity" is not defined anywhere in the IRPT tree. The dell2 seats cannot see which principal each box's agents run as, or which root declares it. Those are cluster infrastructure (the agentbus and box identities), not IRPT's.

### Out of pattern

The normal pattern is that the project that owns a resource also grants its readers in its own root. That pattern does not fit here:
- the readers are the four boxes' identities, which no IRPT root declares;
- the consumer is the commit-time client-data hook, which ruling 3ffa142af0 places in the laptop CTO's lane once the first list lands.

### Other solutions

- **(b) dell2 grants by a bucket and secret resource policy naming the four principals.** This is worse. dell2 would have to guess principal ARNs it cannot see, and it would put cross-box identities into an IRPT root, as a second writer of the readers' access.
- **(c) Each box's MSTR grants its own identity.** This is worse. It gives four writers for one access rule, and no single place to revoke.
- **(d) Wait until the hook is built, then decide.** This is acceptable, but it only delays the same answer as (a).
