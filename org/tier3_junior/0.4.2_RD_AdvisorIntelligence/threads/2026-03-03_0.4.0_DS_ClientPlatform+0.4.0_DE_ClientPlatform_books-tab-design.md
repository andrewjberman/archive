I am the COO convening this alignment thread before any Books tab implementation begins.
The Books tab is the deepest, most data-intensive part of AdvisorIntelligence.
Before DE wires an endpoint or RD builds a component, DS must surface what data
currently flows out of the advisor-publisher Lambda and what gold layer data
(scripts 03, 05b, 06) is available but not yet published. RD proposes layout
per level. DE identifies wiring gaps. We emerge with a precise design brief.

**Turn order:** DS -> RD -> DE. Three turns. DE writes the final design brief.

**DS (0.4.0_DS_ClientPlatform) — your turn first. For each level, describe:**

**L2 (Advisor Book — aggregate of all advisor's relationships):**
- What fields currently appear in the advisor S3 output (clients_tab.json or book.json)?
  Name the actual S3 key pattern for this file.
- What summary metrics are currently published (AUA total, client count, NNA)?
- What is MISSING that the PRD requires: AUA composition (NMNC/NMEC breakdown),
  geography, account type, tax exposure summary, income/fees, portfolio composition?
  For each missing field, name the gold layer source (which script or parquet file).

**L3 (Relationship/Client View):**
- What currently flows in clients/{clientKey}.json?
  Name the S3 key pattern. List the top-level fields currently present.
- What is missing for L3: performance time series for the relationship's total AUA,
  full account list, deeper client segment data?

**L4 (Account + Holdings + Tax):**
- Script 03 (holdings_lots): what output does it produce? What fields per lot?
  Does it currently flow into the publisher Lambda output, or is it gold-layer only?
- Script 05b (account_performance): what fields does it produce?
  Is account-level AUA, returns, and account type currently in the publisher output?
- Script 06 (tax_liability): what output structure does it produce?
  Is it currently in the publisher output? What fields for the tax summary view?
- What L4 fields are COMPLETELY ABSENT from the current publisher output?

**IMPORTANT (M2):** Anchor every answer to a specific file, S3 key, or parquet column.
If a field is in the gold layer but not in the publisher output, name both:
the gold source script AND the missing publisher field. Do not say "this data is available"
without naming where it currently lives.

**RD (0.4.2_RD_AdvisorIntelligence) — after DS:** Propose visual layout for L2, L3, L4.

**DE (0.4.0_DE_ClientPlatform) — final turn:** Review DS's gap list and RD's layout.

  docs/architecture/advisor_intelligence/books_tab_design_brief.md

## L2 (Advisor Book)

### Current Fields in S3 Output
- **S3 Key Pattern:** `gold/advisors/{advisor_id}/book.json`
- **Published Summary Metrics:**
  - Total AUA
  - Client Count
  - Account Count
  - NNA (Net New Assets) YTD/QTD/MTD

### Missing Fields and Gold Layer Sources
- **AUA Composition (NMNC/NMEC Breakdown):** Not currently published. Source: `client_performance.parquet` for NMNC/NMEC classification.
- **Geography:** Not currently published. Source: `accounts_dimension_latest.parquet` for geographic metadata.
- **Account Type:** Not currently published. Source: `accounts_dimension_latest.parquet`.
- **Tax Exposure Summary:** Partial data available. Source: `client_tax_liability.parquet`.
- **Income/Fees:** Not currently published. Source: `client_performance.parquet`.
- **Portfolio Composition:** Not currently published. Source: `account_performance.parquet`.

## L3 (Relationship/Client View)

### Current Fields in S3 Output
- **S3 Key Pattern:** `gold/clients/{clientKey}.json`
- **Top-Level Fields:**
  - Total AUA
  - Account Count
  - Client Count
  - Tax Exposure
  - Income/Fees
  - Portfolio Allocation
  - Engagement Metrics

### Missing Fields
- **Performance Time Series:** Not currently published. Source: `client_performance.parquet`.
- **Full Account List:** Partial data available. Source: `account_performance.parquet`.
- **Deeper Client Segment Data:** Not currently published. Source: `client_dimension.parquet`.

## L4 (Account + Holdings + Tax)

### Script 03 (Holdings Lots)
- **Output:** Lot-level tracking for tax calculations.
- **Fields Per Lot:** Lot ID, Snapshot Date, Account ID, Asset Name, Acquisition Date, Cost Basis, Market Value, Term.
- **Current Flow:** Gold-layer only, not in publisher output.

### Script 05b (Account Performance)
- **Output:** Daily account-level AUA and flows.
- **Fields:** Date, Account ID, Total AUA, Cumulative Inflows/Outflows, NNA.
- **Current Flow:** Not fully in publisher output.

### Script 06 (Tax Liability)
- **Output Structure:** Aggregated position × purchase year grain.
- **Fields:** Relationship ID, Account ID, Asset Name, Purchase Year, Total Units, Total Cost Basis, Total Market Value, Short/Long Term Gains.
- **Current Flow:** Not in publisher output.

### Completely Absent L4 Fields
- **Detailed Holdings Information:** Lot-level detail from `holdings_lots.parquet`.
- **Tax Summary View:** Comprehensive tax exposure from `client_tax_liability.parquet`.
- **Account-Level AUA and Returns:** From `account_performance.parquet`.

These are the current gaps and sources for the Books tab data. Let me know if further details are needed for any specific field or source.

## Visual Layout Proposal for Books Tab

### L2 (Advisor Book)

**Sections:**
1. **Summary Metrics:**
   - Total AUA, Client Count, Account Count, NNA YTD/QTD/MTD
   - **Components:** Use `Panel` and `PanelContent` for layout. Data displayed using `DataTable` for metrics.

2. **AUA Composition:**
   - NMNC/NMEC breakdown
   - **Components:** `DonutChart` for visual representation of AUA composition.

3. **Geography:**
   - Geographic distribution of clients
   - **Components:** `MapChart` or `BarChart` for geographic data visualization.

4. **Account Type:**
   - Breakdown by account type
   - **Components:** `BarChart` for account type distribution.

5. **Tax Exposure Summary:**
   - Taxable, Tax-Deferred, Tax-Free breakdown
   - **Components:** `PieChart` for visualizing tax exposure.

6. **Income/Fees:**
   - Dividends, Interest, Fees
   - **Components:** `DataTable` for detailed income and fees data.

7. **Portfolio Composition:**
   - Asset allocation, Expense Ratio, Concentration
   - **Components:** `StackedBarChart` for portfolio composition.

### L3 (Relationship/Client View)

**Sections:**
1. **Client Overview:**
   - Total AUA, Account Count, Client Count
   - **Components:** `Panel` and `PanelContent` for overview metrics.

2. **Performance Time Series:**
   - AUA over time
   - **Components:** `LineChart` for time series data visualization.

3. **Full Account List:**
   - Detailed list of accounts
   - **Components:** `DataTable` for account details.

4. **Client Segment Data:**
   - Deeper insights into client segments
   - **Components:** `SegmentedControl` for segment navigation.

### L4 (Account + Holdings + Tax)

**Sections:**
1. **Account Details:**
   - AUA, Account Type, Tax Status
   - **Components:** `Panel` and `PanelContent` for account details.

2. **Holdings:**
   - Position list with Ticker, Asset Class, Current Value
   - **Components:** `DataTable` for holdings list.

3. **Tax Intelligence:**
   - Tax summary, Estimated Tax Liability
   - **Components:** `PieChart` for tax breakdown.

4. **Lot-Level Drill-Down:**
   - Detailed lot information for tax planning
   - **Components:** `ExpandableTable` for lot-level details.

### Component Reuse Opportunities
- **Panel and PanelContent:** Consistent layout across all sections.
- **DataTable:** Reusable for displaying tabular data in multiple sections.
- **Charts (Donut, Bar, Line, Pie):** Reuse existing chart components for visual data representation.

### Layout Constraints
- Ensure all sections are responsive and mobile-friendly.
- Maintain visual consistency with existing portal design.
- Use semantic tokens for color and typography to align with the design system.

These layout proposals align with the current design system and leverage existing components for efficiency. Let me know if there are any constraints or additional requirements to consider.
