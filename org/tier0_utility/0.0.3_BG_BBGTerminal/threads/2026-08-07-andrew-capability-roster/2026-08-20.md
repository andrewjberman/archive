## Finding -- teams-watch loses messages (not merely slow)

Two layers; the second is the defect.

1. **Latency, explains 51s.** Pinned token expired; stderr shows `quiet retry, pin HELD
   (cycle 1)` ... `(cycle 30)` then `re-selected after lapse`. TO6 working as designed. But
   `teams-watch.py:318` backs off while lapsed -- `INTERVAL * min(2**(lapse_cycles-1), CAP=6)`
   -- degrading the poll 15s -> 90s. Bounded, self-healing, not a fault.
2. **Message loss, the real one.** `poll_addressed_teams_messages` returns *chats whose
   latest message is newer than the cursor*, **one entry per chat carrying the latest
   message**. A CHAT-grain instrument read as a MESSAGE-grain one. Two messages inside one
   window => the earlier is **dropped, not queued**, and the cursor advances past it.
   Layer 1 widened the window to 90s and made the collision land today, **but the loss is
   available at any interval. A shorter poll lowers the odds and cannot close it.**

**Why it evaded every check I ran:** the output is well-formed and confident in a different
domain, and carries no frame -- `count: 1` never says "1 of 2". My own startup report to
CTO~Z recorded "Teams backlog 0" off this exact call. That reading was **true about chats**
and said nothing about messages. CLAUDE.md's designed-half denominator class: no way of
calling it differently fixes it; only corroborating outside it does -- which is precisely
what `read_chat_messages` did.

**Historical incidence: UNKNOWABLE, and I did not quote one.** A dropped message leaves no
trace in the event stream, the cursor file, or any log this seat holds. Confirmed lost = 1.
That is a floor, not a total.

**Separately out of scope (named so it is not found later as a gap):** channel @-mentions
are not covered by this tool's v1, per its own docstring. Not today's cause.

## Ruled at the gate (CTO~Z 2574, same hour)

Fix design RULED with my one-liner adopted verbatim: poll = CHANGE SIGNAL (touched chat ids
only, never the payload); `read_chat_messages` per touched chat = THE INTAKE, emitting every
message newer than the cursor **oldest-first** (ordering preserved for ACK-FIRST); cursor

carries its own frame. Owner AE~Z, **P1, ahead of the Ticketing Center chain.**
