# atom_layer0 workflow

Use the run template and validate after every stage. These checkpoints are method
assertions, not estate gates.

## S0 - Pin the concept

1. Pin concept name, definition, claimed layer, grain, scope, authorities, and consumers.
2. Characterize composition, state, position, behavior, and semantic role using
   molecule discipline. Mark inapplicable dimensions explicitly.
3. Hold the record suspect. A declared authority is a candidate until its pointer and
   content are directly read at the pinned vintage.
4. Enumerate code consumers separately because they inherit the no-redeclaration rule.

Halt as `STAGE_UNREACHABLE` if the authority or required consumer population cannot be
enumerated. Do not compensate with prose confidence.

## S1 - Decomposition sweep

1. Declare the generator set and each generator's derivation dependencies.
2. Run definition, usage, cross-derivation, and incident generators where applicable.
3. Emit raw candidates with citations.
4. Normalize all candidates to S0's grain before union or count.
5. Apply the admissible-decomposition predicate from `decomposition-grammar.md`.
6. Print raw, normalized, duplicate, excluded, unreachable, and not-assessed residue.

If a generator cannot run, the frontier remains open. A generator with no evidence is
correctly empty only when its population was enumerated and its instrument discriminated
on a positive control.

## S2 - Nothing-beneath challenge

1. Freeze `decomposition_grammar@version`, its pre-subject commit, scope partitions,
   and the frontier matrix. Confirm the layer declares this binding grammar.
2. Appoint a differently-derived splitter. Record shared dependencies.
3. Charge it to produce a concrete admissible decomposition, not to approve the author.
4. Exercise every declared frontier cell until a witness is found or the frontier closes.
5. Render exactly one typed terminal result using the Rule 24 precedence record.

Consequences:

- `DECOMPOSITION_FOUND`: atomicity fails; recurse on normalized children or stop with an
  owned branch plan.
- `DECLARED_FRONTIER_EXHAUSTED`: S3 may proceed and a bounded certificate may be minted.
- `BUDGET_EXHAUSTED_WITH_FRONTIER_OPEN`: UNKNOWN; preserve the frontier.
- `INSTRUMENT_UNKNOWN`: UNKNOWN; instrument status dominates partial search results.
- `NOT_EXERCISABLE`: UNKNOWN; an unavailable independent splitter is not a run.

## S3 - Legislate the layer

Proceed only after `DECLARED_FRONTIER_EXHAUSTED`.

1. Mint `ATOMIC_WITHIN(grammar@version x scope)` with grain and vintage.
2. Attach Rule 24 records for the concept's axis, member set, predicates, and any adopted
   schema surfaces.
3. Name the population predicate, generation process, denominator, and residue.
4. Run the token-hygiene census with a positive control.
5. State the intended authority home under the registry entry bar.

All outputs remain PROPOSED until the authorized naming act ratifies them.

## S4 - Resolution contract

1. Enumerate every adjacent or higher binding layer and its consumer population.
2. Create one contract row per binding.
3. Evaluate cardinality, HEAD pointer, content, grain, and code citation operands.
4. Run mechanical, declarative, and semantic seam checks.
5. Derive `resolved`; never hand-author it.
6. Print unresolved, unreachable, and not-assessed residue with candidate owners.

The resulting table is the schema for a later resolution census pass.

## S5 - Proving run

1. Use a cheap real subject selected outside the method-authoring seat.
2. Run S0-S4 without editing the subject's owner surfaces.
3. Record at least one method defect, the observed failure, the repair, and a regression
   check that would fail on the pre-repair method.
4. Validate the final run with `--require-proving-defect`.

If no defect is found, the proving acceptance bar remains open.

## Re-entry

Any new candidate, changed grammar, changed authority, changed consumer population, or
changed scope reopens the earliest affected stage. A new grammar version never silently
invalidates historical certificates; it invalidates their current eligibility for uses
that require the newer grammar. Rival-grammar disagreement routes to the layer owner.
