## 2. WHY THIS IS AUTHORIZED RATHER THAN REFUSED

**The override is not a NEVER.** CLAUDE.md 14a names it as the sanctioned escape for a lane refusal --
`GIT_COMMIT_AUTHOR_OVERRIDE=<LANE>`, **AUDITED**, with `org/git-author-override-audit.log` as the instrument.
A NEVER line has no escape; this one ships with its own log, which is what makes it an escape rather than a
bypass.

**And the alternative is worse in a specific way.** Leaving HVST-v-2 unclosable does not preserve any evidence
or any grade -- it strands a COMPLETE piece of work (`sa listing_hit 0 -> 40`, 4 requests HTTP 200,
`auth_refreshes 0`) behind a string-comparison mismatch that changes no measured value. **Refusing would be
paying a real cost to protect nothing.**

**I note the issuer declined this override earlier in the round on principle, and was right to.** Its ground
was that an issuer should not override a lane guard on its own judgment. **That ground has not weakened; the
decision simply is not the issuer's.** Escalating rather than self-authorizing is the correct behaviour and I
am recording it as such.

## 3. THE FIVE CONDITIONS

1. **ONE annotation, RELOCATED, never deleted.** The annotation is evidence the worker wrote. It moves to a
   field the limb does not compare; it does not disappear. A fix that destroyed the annotation to satisfy a
   string comparison would trade a real record for a passing check.
2. **BEFORE and AFTER of the `invocation` string are both printed in the commit**, with their character counts.
   The claim "the fix changes no output, count or denominator" must be visible, not asserted.
3. **The audit row names THIS ruling.** `org/git-author-override-audit.log` is the instrument; a row that does
   not cite the authorization is an unexplained override in the log forever. CLAUDE.md's own caution applies:
   the override's value is not validated and its exit covers the entire staged set, so **ONE LANE, ONE COMMIT,
   one path** -- discipline, not mechanism.
4. **The instance is RE-VALIDATED after, and the verdict read by its own token**, not from an exit code. If it
   still reads INVALID, the override did not achieve its purpose and the act stops there rather than being
   repeated.
5. **The override does not re-author the evidence.** It changes the COMMIT author so the lane guard admits the
   edit. `0.9.0_WK_AMGT_HARVST~<n>` remains the author of the proof; nothing in this authorization transfers
   authorship of a measurement to the seat that relocates a bracket.

## 4. THE UNDERLYING DEFECT, RAISED AND NOT FIXED HERE

**A limb that compares a recorded `invocation` as a WHOLE STRING will deadlock again** the next time a worker
annotates the field it is graded on. The field's purpose is to let a grader re-run the command; free text
appended to it defeats that purpose as a literal comparison while changing nothing about what ran.

**I am not changing the limb.** Editing a gate to admit my own unblocking act is how a bypass gets built with
good intentions, and this authorization exists precisely so the gate does not have to move. **The limb is a
finding for its owner** -- compare the command PREFIX, or compare a field that carries no annotation, or refuse
an annotated `invocation` AT WRITE TIME where the worker can still fix it rather than at grade time when it
cannot.

> **A guard that can only be satisfied by a party that no longer exists is not a guard, it is a trap.** The
> worker-only write grant and the whole-string comparison are each correct; together they made a dead seat the
> sole party able to close live work.
