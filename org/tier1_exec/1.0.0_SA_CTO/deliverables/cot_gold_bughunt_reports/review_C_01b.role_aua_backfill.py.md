## Finding 1 -- [high/empty-null-handling/both]
- **Location:** `data/cot/scripts/gold/C_01b.role_aua_backfill.py:104 and :117 (_build_one_date)`
- **Mechanism:** The null-role filter only treats NaN and '' as 'no advisor' (line 104: merged[c].where(merged[c].notna() & (merged[c] != ''), pd.NA); line 117: keeps advisor where notna() & != ''). It does NOT recognize the 'Unassigned' sentinel that A_00 stamps into the architect column (A_00 line 495 fillna('Unassigned'), line 496 replace('No Architect Value Assigned','Unassigned')) and that A_01 canonicalizes as the no-advisor marker (A_01 lines 460-464 map '' -> 'Unassigned'; normalize_role/_ADVISOR_NULLS). So 'Unassigned' is passed through as if it were a real advisor name and AUA is attributed to it.
- **Failure scenario:** Currently DORMANT on cot: cot silver emits no role columns, so accounts_dimension.architect is all-NaN (A_00 line 495 empty-series assign yields NaN, verified) -> C_01b's fallback (line 213) reads that all-NaN column -> _n_roles=0 for every account -> every partition is empty (correct). It goes LIVE the moment cot's architect column becomes populated with the sentinel: the active ADVI_COTPPLADVFIX single-advisor patch adds an architect column; any account left blank is turned into the literal 'Unassigned' by A_00 line 495 fillna. Then C_01b --upload writes, for EVERY historical date, a phantom row (advisor='Unassigned', role='architect', aua = SUM of all accounts' total_aua = entire firm AUA) into gold/canonical/role_aua/{date}.parquet, instead of empty. If D_02 is cut over to consume canonical role_aua (the stated RA-P2b purpose of this backfill), the advisor timeseries surfaces a fake advisor 'Unassigned' holding 100% of firm AUA across all history. Two gates (architect populated AND D_02 cutover) keep it from being critical today, but the compute path is already wrong.
- **Proposed fix:** Treat role values through the same no-advisor sentinel set the rest of the pipeline uses (A_01.normalize_role / _ADVISOR_NULLS plus the literal 'Unassigned'). E.g., define _ADVISOR_NULLS = {'', 'unassigned', 'no architect value assigned', 'no advisor value assigned', ...} and change line 104 to also NA-out values whose .strip().lower() is in that set, and mirror it in the line-117 melt filter. This makes an all-'Unassigned' firm produce empty partitions (matching the intended empty advisor layer) instead of a phantom mega-row.

## Finding 2 -- [medium/unguarded-read/both]
- **Location:** `data/cot/scripts/gold/C_01b.role_aua_backfill.py:213 (account_team fallback inside the except block)`
- **Mechanism:** The fallback reads a hardcoded LEGACY key _load_parquet('gold/accounts_dimension_latest.parquet') instead of the canonical constant ACCOUNTS_DIMENSION = 'gold/dimensions/accounts_dimension_latest.parquet'. The try/except at lines 204-206 wraps ONLY the primary gold/views/account_team.parquet read; the fallback body (lines 212-216) runs inside the except and is itself unguarded, so any error in _load_parquet there propagates uncaught. _load_parquet is a raw s3.get_object (lines 64-67) that raises NoSuchKey on a missing key.
- **Failure scenario:** For cot the primary account_team.parquet is absent, so the fallback always executes. It resolves TODAY only because A_00 still dual-writes the legacy key (A_00 lines 638-642: legacy_key = LEGACY.get(output_key); s3.upload_file(...)). When that migration dual-write is retired (or on any bucket/first-run where only the canonical gold/dimensions/ path exists), the fallback get_object raises NoSuchKey -> uncaught ClientError -> the backfill aborts non-zero. The docstring's 'stops C_01b dying' intent is defeated because the fallback can itself die. (The cited 'D_01 pattern' is also inexact: D_01 reuses an acct_dim already loaded from the canonical ACCOUNTS_DIMENSION, not a re-read of the legacy path.)
- **Proposed fix:** Read the canonical constant ACCOUNTS_DIMENSION (imported from lib.s3_layout) rather than the hardcoded legacy string, and wrap the fallback load in its own try/except that degrades to an empty account_team (account_id-only -> all partitions empty) rather than aborting the run.

## Finding 3 -- [low/other/both]
- **Location:** `data/cot/scripts/gold/C_01b.role_aua_backfill.py:224 and :296 (list_objects_v2 without pagination)`
- **Mechanism:** Both s3.list_objects_v2 calls read only the first response page (no paginator / ContinuationToken); list_objects_v2 caps at 1000 keys. The 'existing' skip-existing set (lines 225-229) and 'final_count' (lines 297-298) are therefore silently truncated at 1000 partitions.
- **Failure scenario:** DORMANT on cot (partitions empty, well under 1000). On a bucket with >1000 role_aua partitions (bd-style daily dates exceed 1000 after ~4 years), 'existing' only contains the first 1000 keys, so target_dates (line 235) includes dates whose partitions exist beyond page 1 -> with --skip-existing still True, those dates are recomputed and OVERWRITTEN (same content, so no data corruption, just wasted compute/S3 writes), and the 'Final S3 count' log line is capped at 1000 and misleading. No served-number corruption; correctness/idempotency + log-accuracy only.
- **Proposed fix:** Enumerate with a paginator: for page in s3.get_paginator('list_objects_v2').paginate(Bucket=S3_BUCKET, Prefix=CANONICAL_ROLE_AUA_PREFIX): ... to build the full existing set and the final count.
