## Finding 1 -- [medium/empty-null-handling/full]
- **Location:** `_load_perf (data/cot/scripts/gold/D_00b.portal_timeseries.py:1257-1300) feeding _build_static_aua_periods:_periods_monthly (line 583, latest_perf_date.to_period('M')) / _periods_annually (line 608, range(...,latest_perf_date.year+1)); root helper lib/gold_utils.py:39-44`
- **Mechanism:** _load_perf's except-branch is meant to FAIL LOUD ('cot snapshot-first: account_performance required ... raise, don't mask'), but _load_parquet swallows s3 NoSuchKey and returns an empty typed frame instead of raising. So an absent OR 0-row ACCOUNT_PERFORMANCE never triggers the RuntimeError; _load_perf returns an empty perf. Later latest_perf_date = pd.DatetimeIndex([]).max() = NaT, and NaT.to_period('M') raises AttributeError (verified) inside _periods_monthly (range(2020, NaT.year+1) also raises TypeError in _periods_annually). No timeout wraps gold compute steps, so the uncaught exception hard-fails the whole downstream chain.
- **Failure scenario:** C_03 emits an empty account_performance.parquet (0 rows), or the gold/timeseries/account_performance.parquet key is absent/renamed. Instead of the intended clear 'account_performance required' RuntimeError, D_00b aborts with a cryptic 'NaTType object has no attribute to_period' deep in _build_static_aua_periods, taking down the rest of the parallel gold chain and masking the real cause.
- **Proposed fix:** Restore the intended fail-loud after loading: e.g. `if perf.empty: raise RuntimeError('account_performance empty/absent -- cot snapshot-first requires it')` in _load_perf (or immediately in load_for_timeseries), and/or guard _build_static_aua_periods to return empty period lists when perf_ts is empty (if len(perf_ts)==0: return {gran:{'categories':['NMNC','NMEC'],'data':[]} ...}).

## Finding 2 -- [low/other/full]

## Finding 3 -- [low/schema-column/full]
- **Location:** `_build_aua_mix -> _load_monthly_mix, data/cot/scripts/gold/D_00b.portal_timeseries.py:680-689`
- **Mechanism:** _load_parquet(snap_key, columns=['asset_name','market_value','is_open']) tolerantly ADDS any requested-but-missing column as all-None (lib/gold_utils.py:50-52). Line 681 then does `df = df[df['is_open'] == True]`. `None == True` is False for every row (verified), so a holdings_lots snapshot that is missing the is_open column (or whose key is absent -> NoSuchKey -> empty frame) yields 0 rows, class_agg is empty, and the month returns {class: 0.0 for all classes}. This is silent: no exception is raised (the try/except in _load_monthly_mix only catches raises), so the aua_mix chart shows an all-zero asset-class breakdown for that month with no error.
- **Failure scenario:** A holdings_lots partition is written by a B_01 variant/schema-migration that omits or renames is_open (e.g. 'position_open'), or a month's snapshot key is briefly absent. The served timeseries_chart.json aua_mix segments for that month become all-zero (Equities/Fixed Income/... = 0) rather than the true mix, silently understating/blanking the asset-allocation chart.
- **Proposed fix:** After load, assert the column is real and typed, e.g. `if 'is_open' not in df.columns or df['is_open'].isna().all(): raise ValueError(f'{snap_key} missing is_open')`, or coerce explicitly (`df['is_open'] = df['is_open'].astype('boolean')`) and skip/flag months where the column is absent instead of silently emitting zeros.
