## Finding 1 -- [medium/unguarded-read/full]
- **Location:** `main() steps 1-17 (line 3725) with no per-step try/except; concrete raise points: _load_canonical_nna_flows fut.result() at line 1662 and build_account_summaries _read_parquet(holdings_key) at line 1249`
- **Mechanism:** D_04 runs as the terminal PHASE_D4 (single process, no timeout, hard-fail on non-zero exit). main() invokes 17 build_* publisher steps sequentially with NO try/except around them. _read_json is guarded (returns None), but _read_parquet and s3.get_object in several steps are NOT. In _load_canonical_nna_flows, the inner _load_one only wraps the columns-fallback, so a get_object NoSuchKey (partition deleted between list and read) or a fully-corrupt parquet propagates through the unguarded fut.result() at line 1662; likewise build_account_summaries reads holdings_lots at line 1249 unguarded. Any such raise aborts main() before the remaining steps run. This breakout path IS live for cot: the guard at line 1861 (nna_geo_cats AND nna_adv_cats) is satisfied because D_00 emits geo state categories and an nna_adv category set (architect all-'Unassigned' still yields ['Unassigned','Other']).
- **Failure scenario:** One canonical_nna/*.parquet partition is unreadable/corrupt on a nightly full run -> _load_canonical_nna_flows raises inside build_timeseries_overview (Step 7). Steps 1-6 already wrote platinum/ (firm dashboard, mix_summary, client summaries, client timeseries, account summaries = today's data), but Steps 8-17 never execute: cumulative_chart.json, leaderboard.json, header_metrics.json/timeseries_chart.json pass-throughs, clients-tab-slim.json, client_directory.json, cohort/cash/out-of-scope stay at yesterday's vintage. The served portal then renders a mix of fresh and stale platinum artifacts (cross-panel AUA/date inconsistency), and the chain exits 1 at wait_phase PHASE_D4.
- **Proposed fix:** Wrap each build_* call in main() in try/except that logs the failure and continues (the publisher steps are independent side-writes); and guard fut.result() in _load_canonical_nna_flows so one bad partition is skipped (append to a warn list) rather than aborting the entire firm publish.

## Finding 2 -- [medium/numeric-sign-units/full]
- **Location:** `_absorb_residual_into_other net-sum assertion, lines 1778-1783 (tol _NNA_PARTITION_HARD_TOL=0.05, line 1607); reached via _attach_nna_breakouts inside build_timeseries_overview (Step 7)`
- **Mechanism:** After absorbing residual into 'Other', the code hard-asserts sum-invariance on inflow, outflow, AND net. The inflow/outflow assertions close exactly (Other.inflow/outflow are set to make the 2-decimal sum equal entry.inflow/outflow to the cent). But net is a DERIVED, independently-rounded quantity: sum_net2 = sum over cells of round(inflow_i - outflow_i, 2), compared against entry['net'] = round(period_inflow - period_outflow, 2) which is double-rounded from a DIFFERENT source (ts_chart.nna cumulative-diff, whereas the breakout sums come from canonical_nna daily flows). Per-cell net rounding drift accumulates at up to ~0.005*N; for by_geo with ~10 state categories that is ~0.05, plus up to 0.01 from entry.net's own double-rounding -> the combined error can exceed the FIXED 0.05 tolerance even though inflow/outflow invariants hold. The tolerance does not scale with category count.
- **Failure scenario:** On some historical by_geo period (quarterly/monthly/annually), the ~10 per-state net roundings align so that |sum_net2 - entry['net']| > 0.05 -> raise AssertionError. This is uncaught, crashes build_timeseries_overview (Step 7), and strands Steps 8-17 exactly as in Finding 1 (partial platinum publish + chain exit 1). Across the full history x 2 cohorts x 3 granularities there are many periods, so the low per-period probability compounds.
- **Proposed fix:** Do not hard-assert on a re-derived net. Either compute expected net = round(sum_in2 - sum_out2, 2) (both already closed to top-level) and compare cell nets to THAT, or make each cell's net consistent with its own rounded inflow/outflow, or scale the tolerance with the cell count (e.g. 0.01 * n_cells). At minimum, downgrade the net check from raise to a WARN so a sub-cent rounding artifact cannot abort the firm publish.

## Finding 4 -- [low/numeric-sign-units/full]
- **Location:** `build_partner_analytics, lines 1955-1958`
- **Mechanism:** The donut-total override loops over ALL periods in views.adv and sets period_data['donut']['total'] = round(float(firm_headline_aua)) — i.e. every historical period's donut total is overwritten with the CURRENT firm headline AUA, not that period's AUA. The per-advisor slices are left at their original (period-specific) values, so donut.total no longer equals the sum of that period's slices.
- **Failure scenario:** If D_01 partner_analytics_{gran}.json is present, a historical period (e.g. 2024-Q1) renders today's firm AUA as its donut total, so its distribution percentages are computed against the wrong denominator. Currently dead-for-cot (the advisor/partner-analytics layer is empty), so it is a latent silent-distortion that would surface if that layer is ever populated for cot.
- **Proposed fix:** Override only the latest/current period's donut.total, or override each period with that period's own firm AUA — never apply a single current value to all historical periods.
