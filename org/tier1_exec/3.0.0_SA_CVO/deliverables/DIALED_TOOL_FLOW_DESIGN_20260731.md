## 1. What this is

A repeatable per-tool workflow that takes ONE comp-tool from "works" to **DIALED** -- the state
comp-estate reached on 2026-07-30 -- proactively, before defects force it. "Dialed" is not a
feeling; it is nine exercised gates and a committed scorecard.

The source arc being generalized (comp-estate, one night, all of it Andrew-present):
purpose ruling verbatim-installed -> naming consolidated + retired aliases declared -> registration
invariant gate-held -> ladder vocabulary in the output -> drill/--structure exposure -> D-rail
canon-surface alignment -> gate-b behavior suite held 29/29 through every change -> 5-class module
census with ruled deletions -> independent CTO descent test with same-hour fixes -> --head
pagination as the tool-wide UX reference.

**The one property that made it work, and the workflow's spine: EVERY GATE IS AN EXERCISE, NOT AN
INSPECTION.** All 8 estate-report defects and all 3 descent-test defects were found by running the
thing, zero by reading it. A phase "passes" only on a probe that could have failed.

## 2. The phases (per tool)

**P0 SCOPE + BASELINE.** Census the tool's units: engine files, every registry row naming it,
aliases/forwarders, consumers (who routes TO it: comp-which, HUD nudges, other tools' fallbacks,
skills). Print the denominator. Cut behavior baselines (golden outputs on fixed inputs) BEFORE
touching anything -- the baseline is the change-detector for every later phase.

**P1 PURPOSE.** One line, consumer-anchored: what question does this tool exist to answer, for
whom. If the purpose is ambiguous or contested -> Andrew ratifies (a purpose is a naming act);
verbatim into the engine docstring AND the registry. Frame before rigour -- NO RIGOUR INSIDE A
FRAME VALIDATES THE FRAME; a tool tightened around the wrong purpose is comp-estate's ruling-6
lesson at tool scale.

**P2 NAME + ALIASES.** Canonical name settled. Retired names DECLARED (`retired_aliases`), never
vanished: old invocations die LOUD (rc=2 stub naming the successor) or forward deliberately --
never dangle. Re-point every router: comp-which mappings, HUD nudge strings, skill docs, XXX.md/
CLAUDE.md mentions. Gate: invoke each retired name; each must produce its loud verdict. (The
pipescript->comp-estate consolidation is the reference; the HUD coherence-injection defect is the
scar.)

**P3 REGISTRATION + CONTRACTS.** Present in every registry the estate maintains (graph-call-
manifest, comp-tools.yaml, tools_index, output-contracts, coverage-map) with the gate-maintained
invariant passing (comp-manifest-check completeness -- the count stays the gate's, never prose).
Output contract declared. Provenance header present: vintage + freshness basis on every emission
-- a tool that cannot say how fresh its answer is fails P3.

**P4 VOCABULARY + STRUCTURE.** Output speaks the canonical ontology vocabulary (the C(N)/D(N)
ladder precedent) -- no private synonyms for estate concepts. Structure exposure: the tool can
show its own descent/dependency shape (--structure / drill analog). UX reference patterns adopted
(--head pagination et al.) so every dialed tool feels like one instrument family.

**P5 DEPENDENCY ALIGNMENT.** Ground the tool's graph position: what feeds it, what consumes it,
what breaks if its output shifts (comp-blast). Then the D-rail analog: sweep every canon surface
that NAMES the tool (CLAUDE.md, XXX.md, manifests, skill docs, rule banks) -- all must say the
same, current thing; superseded language is a defect to fix in the pass, and the rule bank
versions if rules changed. A dialed tool with a stale law about it is the
stale-record-with-authority hazard.

**P6 EXERCISE GATES.** A behavior suite that HOLDS THROUGH EVERY CHANGE (gate-b analog): positive
controls, negative controls, and at least one DELIBERATELY-CORRUPTED input that must FAIL not
warn (a validator nobody has tried to fool is untested). Baselines from P0 re-cut only
deliberately, with a one-line reason committed -- a silent re-cut converts a regression into a
new baseline.

**P7 RESIDUE AUDIT.** 5-class census of everything in the tool's orbit: NECESSARY / HISTORICAL /
TRASH / GENERATED / AT-RISK. Deletions are RULED (Andrew where sovereign), executed
delete-together (the thing and every reference to it in one motion); live-but-wrong surfaces are
RE-GROUNDED, not deleted (critical-surfaces v0.4 precedent).

**P8 INDEPENDENT DESCENT.** A second agent -- not the dialer -- cold-exercises the tool from its
docs alone (CTO descent-test analog). Every stumble is a defect in the tool or its docs, fixed
same-session. The descent script is banked as a regression so the next dial replays it.

**CLOSE -- THE DIAL RECORD.** Per-tool scorecard committed: phase verdicts, evidence pointers
(the probes run, their outputs), baselines, and DECLARED RE-DIAL TRIGGERS -- the events that
reopen the tool (rename touching it, registry schema change, canon-surface edit naming it,
engine change beyond N lines, routing/HUD change). A dial without re-dial triggers is a frozen
map the moment the estate moves.

## 3. Frontrunning: the queue is ranked by routing centrality

"Frontrun" means the order is chosen by blast radius, not by convenience: **dial first the tools
other things route TO** -- comp-which targets, HUD nudge destinations, other tools' fallbacks,
skill-invoked tools. A misaligned tool's cost multiplies by its in-degree (the comp-grep dead-
fallback incident: the rail itself routed to a name that did not resolve). The queue is derived
from the routing tables at queue-build time -- measured, not remembered -- and re-derived per
dial, never maintained as a hand-list.

## 4. Roles + cost shape

- **Executor:** any agent (per-pod owners natural). **Andrew:** P1 purpose ratification + P7
  deletion rulings only -- the two naming acts. **CVO:** P0/P6 baseline discipline + the CLOSE
  verdict (verifier-not-fixer; the dialer never grades their own dial). **Registries:** counts
  stay gate-maintained.
- **Scale-down is explicit:** comp-estate took a full Andrew-present night; a routine tool should
  take a fraction. Any phase may be SKIPPED-WITH-REASON (one committed line); a silent skip is a
  defect. The workflow bends, it does not silently thin.
