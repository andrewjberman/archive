# GRANT-SCOPE DETERMINATION: the 49F–BD **SCANNING** grant does NOT cover a template WRITE

## The question
CRO~A holds a standing Andrew-direct grant for 49F Black Diamond. **Does it cover amending a
persisted vendor template (adding dim 436), or only pulls?**

- `ADVI_BDPARITY.T1-ORACLE_PROOF_OF_SPEC.json` + the tie-out deliverable, both:
  > *"Standing lifts cover cot-BD (Cottonwood Black Diamond) explicitly **NOT bd/49f**; the 49f BD

- `MEMORY.md` vendor-egress index, independently: standing lifts = ORION · SMARTX · **cot-BD
  (Cottonwood ONLY, not bd/49f)** · arxiv · ECLIPSE.

## DETERMINATION: **NO — it does not cover the write.**

**SCANNING IS A READ VERB.** The grant covers pulling from BD's 49F surface.

**Amending a persisted vendor template is a WRITE to the vendor's own configuration.** It changes
what **every subsequent export carries, for everyone, indefinitely**. That is **not a bigger read; it
is a different act** — and the standing law is explicit that *a lift on the WIRE is not a lift on the
WORK*, and that availability is not authorization.

## Consequence — the remedy SPLITS
| Act | Covered? | Disposition |
|---|---|---|
| qt6 group-grain re-run (T1-ORACLE needs it) | **YES** — it is a pull | proceeds at CRO~A on respawn, no new word |
| Add dim 436 to persisted template 390224 | **NO** — vendor-config write | **needs Andrew's one-line per-use word FIRST** |

**Still one seat and one pass** — act 1 does not wait on act 2. My earlier "one grant, one seat, one
pass" routing to MSTR was **half right, and is corrected by this determination.**

## Why this is inherited law, not a manufactured gate
CTO **declined** to add a CTO review of the template change's mechanics — correctly: that would be a
new approval step on simple work. **The asymmetry that makes both calls right:** a review gate would
be *invented*; the sovereign word on a vendor-config write is *existing law*. One is created here,
the other is only being applied here.

## What the ask is NOT
Not vendor onboarding. Not a new vendor relationship. Not a new egress surface. It is a **write to a
template on a vendor we already pull from daily**, to add **one dimension Andrew's own book ruling
partitions on**. Framing it larger would be as wrong as skipping it.

## Standing generalisation worth carrying
**A GRANT'S VERB IS ITS SCOPE.** *Scan / pull / read* grants authorize retrieval. They do not
authorize **mutating the vendor-side configuration that determines what future retrievals contain** —
because that act outlives the grant's occasion and binds everyone downstream. Check the verb before
assuming the noun.
