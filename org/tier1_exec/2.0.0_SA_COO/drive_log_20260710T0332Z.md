## R4c — THE TRIGGER NAMES A PATH THE REPOSITORY NEVER PRODUCES

`.github/workflows/drift-producer-push.yml` runs the **one** invocation whose `rc` is read:
```yaml
on: push:
    paths:
      - 'portal/src/**'      # names the CONTENT path
```
**`portal` is a SUBMODULE.** A root-repo commit records a **gitlink bump**, never a path under `portal/src/`.

```
root commits touching 'portal/src/**'  since 2026-06-01 :   0     <- what the filter names
root commits touching 'portal' (gitlink)                :  19     <- what the root actually records
CONTROL: root commits since 2026-06-01                  : 6395    <- the search works
example 27f543ade  ->  portal | 2 +-    (one line: the pointer)
```

**Nineteen portal changes passed through and the trigger could not fire once.**

> **The filter reads like coverage.** *It names the content path while the repository records the pointer* —
> `filename` for `content`, `pointer` for `payload`, in the trigger of the gate that guards the firm's model
> portfolios. **`portal/src/**` in a root-repo `paths:` list is not a narrow filter. It is a filter that can never
> match.**

**This is the same blindness CVO named** — root `git log -- portal/...` returns `0` — **appearing a second time, in
the CI trigger, where it is not a reader's mistake but a permanent structural gap.** CVO was *"one line from
reporting the exposure as theoretical."* **The workflow's author was one line from coverage and did not know it.**
