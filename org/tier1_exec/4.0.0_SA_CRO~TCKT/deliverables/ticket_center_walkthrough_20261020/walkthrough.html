Step 4 · The upload check ("Did you mean")

PROD today: a holdings row with an unknown ticker (SPYY) gets "Did you mean SPY?" with Yes / Replace / No. Nothing is filed until it is answered.
Front end
Pressing File Analysis Request first sends the holdings file. If a ticker does not exist, the form shows the door's suggestion: Yes accepts it, Replace lets you type a ticker (checked again), No files it as-is with "Opal Staff will manage the replacement". A ticker that exists but cannot be priced is filed without a prompt and replaced in the back end.
Back end
The "upload door", Lambda irpt-ycharts-generate (intake/uploads.py). It checks every ticker against Yahoo first, then YCharts only for symbols Yahoo lacks. It stores the original file and its normalized form under irpt/<firm>/state/. Staff are never refused for a missing advisor: the owner falls back to the signed-in staff user (served.py, release r37, live since 3:10 AM).
State
PROVEN through the API in run 6 (4:02 AM): an unseeded staff user with no advisor uploaded and was accepted. The Yes/Replace/No prompt is proven only offline. The "kept unknown ticker → back-end replacement" path has never been run past this step.
Questions for your memo
  • Is Yes / Replace / No the behavior you want, or should unknown tickers always go straight to Opal staff?
