## §0 — Convergence reading

The main result is real and the discard is mechanically correct. The candidate
scorecard at `comp/targets/click/scorecards/3edd0e6_d869779f.json:36` shows
primary_metric = 0.09166989116548743, structural.f1 = 0.6506024096385542, precision
= 0.5094, recall = 0.9, best_lift = 0.090909..., best_selector = random,
token_reduction_pct = 0.61083984375, and mutation_stability.aggregate =
0.8522012578616353. That matches the primary-metric formula in `comp/bench/primary.py:30`:
0.090909 * (1 + 0.3 * 0.61084) * 0.85220 * (1 - 0.0) = 0.09167. So the discard
is not a judgment call; it follows the system as implemented.

The important mechanism read is slightly sharper than the CTO summary. This is not
just "structure improved but token cost got worse." In this system, structural F1
is not part of the primary objective except as a tiebreaker; the real objective is
AB lift times token efficiency times mutation stability, per `comp/program.md:166`.
So the real failure is: the new structure did not convert into selector-usable
lift. The scorecard shows exactly that: centrality and keyword stayed at zero lift
while only random got 1/11, `comp/targets/click/scorecards/3edd0e6_d869779f.json:39`.
That means the compiler is producing graph truth the scorer can reward
structurally, but not graph surfaces the selectors can exploit behaviorally. Framed
that way, SC's diagnosis about vocabulary mismatch and routing is the right one.
