## §0 — Convergence reading

The important result is not merely that sphinx failed Path A. It is that the Stage 3 pre-screen surfaced a measurement-surface defect before primary scoring began, which is exactly what the new design was supposed to do. Mechanically, sphinx fails Path A because INCLUDE = 2 < 5, with 10 INVESTIGATE and 0 raw SENTINEL (`comp/results/sphinx/prescreen/prescreen_summary.yaml:4-20`; `org/tier1_exec/1.1.0_SA_CTO/deliverables/COMP_LEARNS.076_pre_screen_review_ruling.md:13-22`). But the more important evidence is SC's sentinel review note and your .076 ruling: the raw zero-SENTINEL outcome is itself a grader-surface artifact, and under a format-aware semantic reading the pool is mostly prior-dominated rather than measurement-room rich (`comp/results/sphinx/prescreen/prescreen_summary.yaml:9-18`; `org/tier1_exec/1.1.0_SA_CTO/deliverables/COMP_LEARNS.076_pre_screen_review_ruling.md:53-59`). That makes the next design move a grader-governance problem, not just a target-selection problem.

## §1 — Recommendations by driver

### For CTO (`1.1.0_SA_CTO`)

**[P0] R-CTO-1 — Take Option C, but refine it: exact-match and semantic-aware grading must govern different decisions**

Treating A/B/C as a single-choice grader replacement question is slightly malformed. The project already decided in the PRD that pre-screen triage must consume R-SC-2 semantic labels rather than raw binary pass/fail (`docs/architecture/COMP_LEARNS_STAGE3.md:55-65`). That means exact-match alone is already insufficient for target triage. My ruling is therefore a refined Option C:
- **Semantic-aware grading governs pre-screen partitioning and artifact characterization**
- **Exact-match grading remains the primary ratchet/champion score unless and until you explicitly redesign the benchmark claim**
- **Disagreement rate becomes a first-class runtime metric**

Why: if exact-match remains the only surface for pre-screen decisions, sphinx-class targets will keep masquerading as INVESTIGATE-heavy when they are actually SENTINEL-heavy (`comp/results/sphinx/prescreen/prescreen_summary.yaml:9-18`). But if you fully replace exact-match with a semantic grader, you introduce a second judgment surface into the primary metric without enough validation evidence yet. The disciplined move is asymmetric governance, not wholesale replacement.

**[P0] R-CTO-2 — Hold Path B target re-selection until this grader-governance rule is codified**

Your .076 escalation is correct on this point. Path B target selection under the current unresolved rule would spend curation effort on a selection surface that still confuses `semantic-correct-but-unparseable` with genuine semantic misses (`org/tier1_exec/1.1.0_SA_CTO/deliverables/COMP_LEARNS.076_pre_screen_review_ruling.md:53-59`). Because PRD §2.3 already says semantic labels must drive triage, the blocking issue is no longer "should we maybe improve the grader later?" but "what exact decision does each grader output control?" Until that is written, Path B re-selection is premature.

**[P1] R-CTO-3 — Amend the PRD reactively, not speculatively**

Wait for the ruling, then issue V1.2. That is the cleaner path. The current PRD already contains the essential hooks: semantic-label-driven triage, empty-SENTINEL review note, paired C1/C4 pilot, and delivered-context references (`docs/architecture/COMP_LEARNS_STAGE3.md:55-65`; `docs/architecture/COMP_LEARNS_STAGE3.md:109-109`; `docs/architecture/COMP_LEARNS_STAGE3.md:179-184`; `docs/architecture/COMP_LEARNS_STAGE3.md:230-230`). What is missing is the governance sentence that says semantic-aware grading controls pre-screen classification while exact-match remains the primary scored metric with disagreement surfaced. That is a precise amendment, not a speculative rewrite.

**[P2] R-CTO-4 — Do not spend time re-auditing click q03**

The click reclassification stands. The honesty note explicitly says the q02/q11 numeric ambiguity does not apply to q03, which is a set-membership case with a different failure mode (`comp/results/dev-click-001/scoring_regime_honesty_note.md:68-72`). Re-opening click q03 here would be confirmatory at best and would not change the design decision now in front of you.

### For SC (`2.1.0_SC_CompLearns`)

**[P0] R-SC-1 — Emit semantic/exact-match disagreement as a runtime characterization artifact on every future pre-screen**

The current evidence already shows why. The sphinx summary note says approximately 8-10 questions would be SENTINEL under a format-aware read, despite raw counts of SENTINEL = 0 and INVESTIGATE = 10 (`comp/results/sphinx/prescreen/prescreen_summary.yaml:9-18`). That disagreement rate is not side information anymore; it is part of the target characterization. SC should therefore emit, per question and per target summary:
- exact-match label
- semantic label
- triage decision
- disagreement flag

Without that, the project will keep discovering grader-artifact dominance only through ad hoc closeout memos.

**[P1] R-SC-2 — Split `grader_artifact` into at least two operational subclasses**

Right now q01/q07 are "format elicitation only" and the 8 INVESTIGATE questions are "already semantically correct in both regimes, but unparseable." Those are not the same mechanism even though both are grader-surface issues (`org/tier1_exec/1.1.0_SA_CTO/deliverables/COMP_LEARNS.076_pre_screen_review_ruling.md:28-45`; `org/tier1_exec/1.1.0_SA_CTO/deliverables/COMP_LEARNS.076_pre_screen_review_ruling.md:53-59`). SC should separate:
- **format-elicitation gain**: context changes answer shape, not knowledge
- **semantic-prior / unparseable**: knowledge already present in both regimes

That split matters because only the second one is a clean SENTINEL; the first is a real behavioral effect that just does not belong in the program's primary retrieval claim.

### For DS (`1.1.0-1.4.0_DS_CompLearns`)

**[P1] R-DS-1 — Implement Option C as dual outputs, not as hidden grader replacement**

DS should wire the runtime so each response yields both exact-match and semantic-aware outputs, with scorecard/report consumers choosing according to the governance rule above. The important implementation constraint is transparency: do not overwrite the exact-match result with the semantic result or vice versa. Emit both and let the packet/report logic consume them explicitly.

**[P2] R-DS-2 — Keep the sphinx answer-key schema fix separate from the grader ruling**

The schema gap is real but orthogonal. The pre-screen summary says standard `_grade_response()` is not compatible with the current sphinx answer-key schema (`comp/results/sphinx/prescreen/prescreen_summary.yaml:21-23`). Fix it, but do not let that implementation task get conflated with the larger grader-governance decision.

## §2 — Deferrals

- **Deferred: Option B as the sole answer** — Reason: constraining question types may be a useful future lane, but it does not solve the already-observed ambiguity on existing targets and would narrow the proposition surface too early.
- **Deferred: replacing exact-match as the primary scored metric now** — Reason: the evidence base is strong enough to justify semantic-aware triage, but not yet strong enough to retire exact-match from the ratchet/champion surface.

## §3 — Malformed questions or premise errors

Q1's A/B/C framing is incomplete because the real design choice is not just "which grader is better?" but "which grader output governs which program decision?" The PRD already committed you to semantic-label-aware triage (`docs/architecture/COMP_LEARNS_STAGE3.md:55-65`), so "proceed under the current grader" is not actually a coherent option unless you mean "keep exact-match for primary scoring while using semantic labels for triage and audit." That is why my ruling is refined Option C rather than a pure A/B/C selection.

## §4 — Unknown-unknowns (MANDATORY)

What you should be asking next is whether response-format sensitivity belongs inside the program claim boundary or outside it. Right now the project implicitly treats format effects as contamination when they inflate retrieval-looking gains. That is defensible. But if a future target shows the opposite pattern — correct localization plus semantically correct answer plus chronic unparseable formatting under all conditions — you will need a preregistered position on whether the program is testing "knowledge delivery to the judge" or "gradeable answer production by the judge." Until that boundary is made explicit, some future successes and nulls will remain argument-sensitive rather than structurally resolved.

## §5 — Cross-cutting observations

The Stage 3 machinery is doing its job. The important thing sphinx proved is not that Path A failed; it is that the project can now detect when a target looks like measurement room only because the grader is collapsing prior knowledge and formatting behavior into the same `Wrong` bucket.
