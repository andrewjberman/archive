## §0 — Convergence reading

The Stage 3 direction is materially stronger than the earlier Wave 3 framing because it finally treats click as design evidence rather than as a failed optimization problem. The brief is right on three central moves: all-four-condition attribution should be the standard for the first true Phase 2 proposition test, delivered-context audit must exist before you claim to understand PATTERN C, and a prior-strength pre-screen is necessary to avoid repeating click (`docs/architecture/COMP_LEARNS_PHASE2_PROTOCOL_AMENDMENT.md:48-71`; `comp/results/dev-click-001/scoring_regime_honesty_note.md:8-18`). The largest correction I would make is to the pre-screen epistemology: H3 full-source should not be treated as an upper bound on aided solvability. It is a baseline for one specific context regime. A question can be wrong under H3 because full-source overload is bad while still being highly recoverable under structured compression. Stage 3 should be designed to discover exactly that possibility, not pre-screen it away.

## §1 — Recommendations by driver

### For CTO (`1.1.0_SA_CTO`)

**[P0] R-CTO-1 — Keep the zero-shot × H3 pre-screen, but redefine it as a triage tool, not a ceiling detector**

The four-cell table is directionally right, but the interpretation of `Wrong | Wrong` is too close to "too hard / likely ceiling." That would be a mistake given the program's stated proposition. The proposition is not "can the model solve it with full source?" It is "does the compiler improve the model's ability to find, localize, and act on the correct structural context relative to unaided exploration?" (`org/tier1_exec/1.1.0_SA_CTO/briefs/COMP_LEARNS_wave3_design_brief.md:26-39`). Full-source H3 is therefore one comparator regime, not the upper bound on what structured context could do. A question that is `Wrong | Wrong` may still be exactly the kind of question C4 is meant to rescue if full-source context is too diffuse. So:
- `Correct | Correct` = prior-dominated sentinel, exclude from primary metric
- `Wrong | Correct` = clear INCLUDE
- `Wrong | Wrong` = investigate for structured-context opportunity, not automatic ceiling
- `Correct | Wrong` = investigate for grader/context-overload artifact, not anomaly by default

This change matters because otherwise Stage 3 could accidentally exclude the very surfaces where structured retrieval has its best chance to beat raw full-source prompting.

**[P0] R-CTO-2 — Make all four conditions mandatory from the first Stage 3 primary-case dispatch**

For the primary Phase 2 proposition test, do not phase C2/C3 in later. The protocol amendment already says C2 and C3 are required before localization and contextualization can be attributed separately (`docs/architecture/COMP_LEARNS_PHASE2_PROTOCOL_AMENDMENT.md:48-60`). Your own brief now says that attribution split is the central question, not an optional refinement. Those two claims are compatible only if the first primary-case run includes all four conditions. Otherwise Stage 3 begins with an experiment that cannot answer its own main question.

**[P0] R-CTO-3 — Treat delivered-context audit as a ship-blocker, but do not force the raw text into the top-level scorecard schema**

The need is real: click PATTERN C remained underdetermined because you lacked per-question delivered context (`comp/results/dev-click-001/scoring_regime_honesty_note.md:53-66`; `docs/architecture/COMP_LEARNS_PHASE2_PROTOCOL_AMENDMENT.md:48-60`). But your concrete storage proposal is too coarse. The current `Scorecard` schema already carries high-level costs and provenance, not bulky per-question prompt payloads (`comp/bench/scorecard.py:133-160`). The better requirement is: every scored run must emit an auditable per-question, per-condition delivered-context artifact, with the scorecard carrying a stable reference to it. The ship-blocker is the auditability, not the exact storage locus.

**[P1] R-CTO-4 — Update the brief’s state claim on R-SC-2 before PRD authoring**

The brief says R-SC-2 is "in flight," but the filed honesty note marks it COMPLETE before iter-8 and names the audit artifact (`comp/results/dev-click-001/scoring_regime_honesty_note.md:72-93`). That is a premise drift, not a design flaw, but Stage 3 PRD should not carry stale dependency state into its opening assumptions.

### For COO (`2.1.0_SA_COO`)

**[P0] R-COO-1 — Define two target lanes in Stage 3: primary measurement questions and sentinel excluded questions**

The pre-screen should not merely shrink the question pool. It should partition it. Questions with strong parametric priors (`Correct | Correct`) should be removed from the primary proposition metric but retained as sentinel questions in the packet metadata. That gives the program a way to say, "we optimized for measurement room without pretending prior-dominated surfaces do not exist." Operationally, this protects Stage 3 from being accused of cherry-picking only easy compiler-win surfaces.

**[P1] R-COO-2 — Path A is the correct default, with a hard off-ramp to Path B if sphinx fails the pre-screen**

The current amendment already favors realistic larger targets with cross-file joins and non-adjacent named entry points (`docs/architecture/COMP_LEARNS_PHASE2_PROTOCOL_AMENDMENT.md:14-27`). Sphinx is the cheapest target that plausibly satisfies that and preserves operational continuity. So default to Path A. But make the off-ramp explicit: if the sphinx pre-screen yields too few INCLUDE questions or the sentinels dominate the candidate pool, Path B becomes mandatory rather than discretionary.

### For SC (`2.1.0_SC_CompLearns`)

**[P0] R-SC-1 — Stage 3 dispatch must be blocked on delivered-context audit and on integrating R-SC-2 into the pre-screen interpretation**

R-SC-2 exists conceptually, but the pre-screen design must consume it rather than reason in raw binary pass/fail terms. The honesty note already shows that q02/q11 "wrong" statuses split into semantic and format failures (`comp/results/dev-click-001/scoring_regime_honesty_note.md:53-93`). If the new prior-screen ignores that distinction, it will reproduce the same epistemic error at target-selection time. So the true ship-blocker is not just "R-SC-2 landed once"; it is "R-SC-2 semantics are wired into Stage 3 target triage."

**[P1] R-SC-2 — Add a pre-screen output label for “full-source overload candidate”**

This is the missing label in your current matrix. Some `Wrong | Wrong` questions are genuine ceilings. Others are candidates where full source is simply too much context and structured delivery may help. SC should own the rule for separating those cases or at minimum flagging them as unresolved rather than ceiling.

### For DS (`1.1.0-1.4.0_DS_CompLearns`)

**[P1] R-DS-1 — Implement delivered-context audit as a per-question sidecar keyed by condition and question ID**

You need enough granularity to answer "what exactly did the judge see?" for each question under C1/C2/C3/C4. A single top-level blob in scorecard JSON is the wrong shape. Emit a structured sidecar keyed by run, condition, and question, and reference it from the scorecard.

**[P1] R-DS-2 — Do not let H3 become the only gate on inclusion**

From an implementation standpoint, preserve the ability to run a tiny pilot on `Wrong | Wrong` questions if they are strong structured-context candidates. Otherwise the selection machinery will hard-code a philosophical assumption the program is supposed to test.

## §2 — Deferrals

- **Deferred: recommending Path B by default** — Reason: the current evidence does not justify paying the extra curation cost before sphinx has been pre-screened honestly.
- **Deferred: specifying the exact delivered-context artifact wire format** — Reason: the requirement is ship-blocking, but the implementation shape should be left to CTO/SC/DS so long as per-question, per-condition auditability is preserved.

## §3 — Malformed questions or premise errors

The brief’s dependency status for R-SC-2 is stale. `comp/results/dev-click-001/scoring_regime_honesty_note.md` marks R-SC-2 COMPLETE before iter-8, with artifact path `comp/results/dev-click-001/r_sc_2_failure_mode_audit.md` (`comp/results/dev-click-001/scoring_regime_honesty_note.md:72-93`). Stage 3 should therefore speak of integrating and extending R-SC-2, not awaiting its first landing.

## §4 — Unknown-unknowns (MANDATORY)

What you should be asking is whether the Stage 3 pre-screen is optimizing too aggressively for compiler success and thereby weakening the program’s ability to discover null results honestly. The fix is not to remove the pre-screen. It is to preregister both the INCLUDE pool and the excluded/sentinel pool before iteration begins. Then a null on the INCLUDE pool is a serious challenge to the proposition, while success only on the INCLUDE pool can be reported honestly as “success under pre-screened measurement-room conditions,” not as a universal claim.

## §5 — Cross-cutting observations

The most valuable Stage 3 design move is not sphinx itself. It is the shift from “find a harder target” to “define measurement room, attribution clarity, and null-result survivability before the next PRD exists.” That is the right correction after click.
