## §1 — Recommendations by driver

### For CTO (`1.1.0_SA_CTO`)

**[P0] R-CTO-1 — Do not let q02/q11 count toward iter-7 primary-metric evidence if the mutation injects the exact gold numerics**

`core_py.runtime_import_count: 8` and `core_py.type_checking_import_count: 1` are not retrieval aids in the narrow sense being tested here; they are direct answer payloads for q02 and q11. The source file already fixes those answers mechanically: eight distinct top-level runtime imports from internal click modules and one TYPE_CHECKING-guarded internal import (`comp/targets/click/_repo/src/click/core.py:21-48`). The answer key then asks for exactly `8` and `1` (`comp/targets/click/gold/ab_answer_key.yaml:28-32`, `comp/targets/click/gold/ab_answer_key.yaml:81-85`). Under the current grader, a PASS can be earned by echoing the number, because numeric grading is `float(full_response_text)` on the whole string (`comp/bench/ab.py:227-232`). That means a q02/q11 PASS under the proposed fact-node mutation would not support the claim "compiler aids navigation"; it would support only "compiler can preload the answer." If you want to study that intervention, quarantine it as a separate ablation, not as ratchet-critical lift.

**[P0] R-CTO-2 — Treat Q1's "node was selected" premise as only partially grounded; do not close causal attribution on H3 alone**

The brief overstates what is known. Iter-6 conclusively shows zero lift, tied-at-best selectors, and no q03 flip (`comp/dev-bundles/dev-click-001/iter-6/result.json:15-33`; `org/tier2_senior/2.1.0_SC_CompLearns/logs/2026-04-27/session_065_066_iter6_scoring_and_v0_forensics.md:77-98`). It does not directly show the exact delivered context for q03. Token-reduction similarity is suggestive, not sufficient proof that the hierarchy node survived selection and was actually attended to by the judge. So the right statement is: "current summary-node framing failed; wrong perspective encoding is a plausible leading explanation, but not yet a confirmed root cause." That distinction matters because otherwise iter-7 risks being interpreted as a decisive family test when it is still partly a localization/authority test.

**[P1] R-CTO-3 — If a corrected q03-only retry still yields PATTERN C, reclassify this click line from lift-signal target to shakedown target for this question family**

The gold headroom is real because H3-v2 misses q02/q03/q11 while getting 8/11 overall (`comp/results/dev-click-001/h3_baseline/h3_v2_result.json:9-12`, `comp/results/dev-click-001/h3_baseline/h3_v2_result.json:35-56`, `comp/results/dev-click-001/h3_baseline/h3_v2_result.json:141-149`). But once a corrected q03-only attempt still yields PATTERN C, the honest read is no longer "keep searching node phrasing on click." It becomes "this target is useful for structural-fidelity / scorer-surface shakedown, not for claiming lift on this failure mode." That is the stop-rule I would adopt.

### For COO (`2.1.0_SA_COO`)

**[P0] R-COO-1 — Split iter-7 into two different classes of work instead of one combined scored mutation**

The proposed three-node bundle mixes two incompatible intervention types: q03 hierarchy correction, which is still plausibly a retrieval/context-shaping intervention, and q02/q11 numeric facts, which are direct answer injection under the present grading regime (`comp/targets/click/gold/ab_answer_key.yaml:28-32`, `comp/targets/click/gold/ab_answer_key.yaml:81-85`, `comp/bench/ab.py:227-232`). Operationally, dispatch either:
- a scored q03-only mutation for ratchet-critical evidence, or
- an explicitly quarantined q02/q11 answer-node ablation whose output is diagnostic and non-ratchet.

Do not let one run serve both purposes, because the per-question readout will be analytically muddied from the start.

**[P1] R-COO-2 — Define the PATTERN C reclassification trigger as "two families plus one corrected within-family retry with no q03 flip"**

The family count alone is not enough; the corrected retry matters. But if the corrected q03 framing still produces zero lift and no q03 flip, you have exhausted the honest cheap search space on click for this surface. At that point, stop dispatching further wording-level mutations on this target and either (a) move the target into shakedown status for scorer/format effects, or (b) change the operator class entirely rather than staying inside fact-node wording tweaks.

### For SC (`2.1.0_SC_CompLearns`)

**[P0] R-SC-1 — Surface q02/q11 as a scoring-regime honesty issue before iter-7, not after**

The current failure is not merely "the model was wrong." H3-v2 q02 contains the correct counting reasoning but fails because the response is verbose and numeric grading requires the entire response to parse as a float (`comp/results/dev-click-001/h3_baseline/h3_v2_result.json:35-42`; `comp/bench/ab.py:227-232`). H3-v2 q11 fails for the same reason even though it ends with the correct number `1` (`comp/results/dev-click-001/h3_baseline/h3_v2_result.json:141-149`). Your own .065 log already states this directly for v0 (`org/tier2_senior/2.1.0_SC_CompLearns/logs/2026-04-27/session_065_066_iter6_scoring_and_v0_forensics.md:34-35`). That means the benchmark is honest at the run-class level (`benchmark_honest=true`) but not yet epistemically clean on these numeric items if response-format variance dominates correctness credit (`docs/architecture/COMP_LEARNS_RUNTIME_V1.md:121-130`; `docs/architecture/COMP_LEARNS_PROGRAM_PURPOSE.md:52-55`). Write that as a formal scoring note before iter-7 ships.

**[P1] R-SC-2 — Add a second label for numeric questions: semantic-correct-but-unparseable**

Right now q02/q11 collapse two distinct outcomes into one failure bucket: wrong answer and correct answer in an unparseable wrapper. The raw responses file already shows this ambiguity on q11, where some responses are plainly `1`-correct and some are `0`-wrong (`comp/results/dev-click-001/sc_q03_q11_responses.txt:20-37`). Without a separate audit label, primary-metric changes can be artifacts of answer formatting rather than evidence of improved retrieval or reasoning.

### For DS (`1.1.0-1.4.0_DS_CompLearns`)

## §4 — Unknown-unknowns (MANDATORY)

What you should have asked but did not: whether q02 and q11 still belong in the ratchet-critical pool in their current grading form. The issue is no longer only prompt wording. The benchmark presently lets response terseness decide credit on some numeric questions (`float(full_text)` parse) while other questions are effectively set/enumeration matches (`comp/bench/ab.py:218-232`). Until you decide whether ratchet-critical numeric items are supposed to measure semantic correctness, exact bare-number obedience, or susceptibility to direct answer injection, you do not actually know what a future q02/q11 improvement means.

## §5 — Cross-cutting observations

The strongest signal in this brief is not "click still has headroom." You already knew that from H3-v2. The stronger signal is that two different things are being mixed under one notion of improvement: correcting a mispartitioned class hierarchy (q03) versus coercing a parseable numeric output (q02/q11). Those need separate intervention classes and separate interpretive rules.
