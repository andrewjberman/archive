The sphinx pre-screen produced a result more important than its mechanical Path A / Path B determination. The two-lane partition with R-SC-2 semantic labels — both of which existed because of CVO V1.1 review feedback — surfaced a Stage-3-design issue that no prior wave's evidence base could have cleanly exposed:

1. **Sphinx pre-screen mechanical result.** 12 questions: INCLUDE = 2, SENTINEL = 0, INVESTIGATE = 10. Path B trigger 1 fired (INCLUDE = 2 < 5). PATH_B_MANDATORY by mechanics alone (`comp/results/sphinx/prescreen/prescreen_summary.yaml`).

SC's R-SC-2 audit shows the judge already had the correct answer in zero-shot under the `semantic-correct-but-unparseable` label — the full-source "gain" is just bulk context suppressing the judge's markdown-formatting tendency, enabling parseable output. 3. **Grader_artifact dominance (8 of 10 INVESTIGATE questions).** Per SC's per-question audit, 8 of the 10 INVESTIGATE questions show identical pattern: judge gives the correct answer from parametric prior in BOTH zero-shot and full-source, but wraps it in markdown the exact-match grader cannot parse. Under a format-aware grader, those 8 INVESTIGATE questions would all flip to SENTINEL. True semantic measurement room shrinks to q03 (wrong base class — StandaloneHTMLBuilder) and q05 (wrong mixin name — DocstringSignatureMixin/ModuleLevelDocumenter).

4. **The structural pattern is target-independent.** Click q11 had the same pattern at single-question scale (judge gave "Answer: 1" in prose, grader parsed nothing). Sphinx has the same pattern at 8-of-10 scale. The grader-format surface — `float(full_response_text)` for numeric, comma-split exact-match for set_membership — is masking a substantial portion of parametric-prior dominance as `Wrong | Wrong`. Any Path B target curated under the current grader will hit the same wall.

This is the CVO §4 unknown-unknown materializing. The Stage 3 PRD V1.1 design contained structural defenses precisely so this could surface honestly. The pre-screen + R-SC-2 + asymmetric SENTINEL rule + sentinel_review_note all worked together to expose it. The PRD designed itself to surface this finding — but the PRD does not itself prescribe how to act on it.

## §1 — Why this requires CVO ruling before Path B target re-selection

Path B as defined in PRD §7.2 is "fresh post-cutoff or domain-specific target." The implicit assumption was that Path B's curation would address the parametric-prior dominance problem. The .075 result shows that prior-dominance is only half the issue — the grader-format surface contributes equally and is target-independent.

Three concrete risks of running Path B target re-selection without first ruling on the grader question:

1. **Repeat measurement masking.** A post-cutoff target reduces the prior-dominance fraction (genuinely Wrong | Wrong becomes more common), but its INVESTIGATE pool will still contain a hidden grader_artifact subset. Pilot machinery from .071 cannot distinguish "C4 wins because compiler helps" from "C4 wins because longer context happens to suppress markdown formatting."

2. **Path B target curation cost wasted.** Selecting + curating + gold-keying a fresh target is operationally expensive. If the grader surface is unchanged, we will likely arrive at a similar pre-screen outcome on Path B, then recurse into Path C, etc.

3. **The proposition becomes ambiguous.** "Compiler aids navigation" cannot be cleanly distinguished from "context bulk shifts response format." Both are real effects. Only the first is what the program claims to test.

## §2 — Three options for grader-format resolution

These are the design space, not my recommendation. I have a lean (Option C) but defer.

### Option A — Format-aware grader

Replace `_grade_response()` exact-match with a grader that extracts the canonical answer from prose responses. Implementations:
- Small judge model (e.g., Haiku) doing extract-and-compare
- Regex with type-specific extractors plus tolerance heuristics (numeric: pull digit string; set: extract NamedClass tokens; enumerable: keyword match)

Pros:
- Addresses the symptom directly
- One-time engineering cost
- Existing benchmark targets become re-evaluable under new grader

Cons:
- Introduces a second judgment surface (grader bias becomes non-trivial)
- Format-aware grader needs its own validation and audit — recursive epistemic load
- Heuristic extractors may themselves over-credit or under-credit edge cases

### Option B — Structurally different question types only

Path B target curation requires question types that constrain response format by construction:
- Bare-number numeric questions phrased to force unwrapped responses
- Code-extraction questions where gold is a literal substring grading can pattern-match
- File-path or symbol-name questions with strict syntactic form

Pros:
- Keeps grader simple and trustworthy
- No second judgment surface
- Question pool design becomes the lever, not grader design

Cons:
- Narrows the proposition test surface (set_membership + enumerable types lose representation)
- Some hard navigation tasks are fundamentally set_membership in nature (subclass relations, exposed surfaces) and cannot be reformulated without losing what makes them hard
- Path B target candidate space shrinks substantially

### Option C — Two-grader cross-check

Run the existing exact-match grader AND a format-aware secondary grader on every response. Disagreement set = the `grader_artifact` audit log; agreement set = the primary metric.

Pros:
- Surfaces the artifact rate explicitly per run as a runtime metric (not a post-hoc audit)
- Doesn't force choosing between graders
- R-SC-2 audit becomes runtime-emitted, not retroactive
- Disagreement rate becomes a per-target characterization metric (high disagreement = format-dominated target; low disagreement = clean target)
- Compatible with Stage 3 PRD V1.1 ship-blockers (delivered-context sidecar can carry both grader outputs)

Cons:
- 2x grader cost (one extra pass per question per condition)
- Requires a disagreement-reconciliation rule (default: use exact-match grader as primary, surface disagreement as audit signal)
- Adds complexity to scorecard schema

My lean: Option C. It preserves the rigor of exact-match grading while making the format-elicitation surface visible as data rather than buried as artifact. The cost is bounded and the design is composable with everything Stage 3 V1.1 already specifies.
