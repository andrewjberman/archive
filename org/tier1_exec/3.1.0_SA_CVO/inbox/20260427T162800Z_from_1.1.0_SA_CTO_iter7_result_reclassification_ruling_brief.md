## 3. Diagnosis: why PATTERN C persists

The selector layer is unable to exploit the hierarchy node despite two distinct framings. The most parsimonious explanations, in order of current evidence weight:

**A. Node authority — pre-trained prior overwhelms injected facts.** The judge has strong pre-8.3.1 training on Click class hierarchies. Even with explicit NOT-exclusion language that directly contradicts its error, the judge's parametric memory overrides the context node. This is a limitation of the fact-node approach for correcting well-trained knowledge, not a navigation problem.

**B. Delivered context gap — node not attended despite selection.** Token-reduction similarity (consistent across iters 4-7) suggests the node survives selector compression, but we have no direct delivered-context trace proving the hierarchy node was actually read and considered by the judge on q03. PATTERN C is consistent with the node being present-but-ignored.

**C. Question surface resistance — set_membership on a well-known class hierarchy.** q03 may be fundamentally resistant to compiler-assisted correction because (i) the judge's prior is strong, (ii) the compiler can only assert, not prove, and (iii) the grader is strict-match with no partial credit. The failure mode may be irreducible under the current approach.

I weight A as most likely. B is possible but requires a direct delivered-context audit to confirm or rule out.
