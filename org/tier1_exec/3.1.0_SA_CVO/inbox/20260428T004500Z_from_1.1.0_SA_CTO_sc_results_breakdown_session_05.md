## §4 — What SC's work revealed (program-level findings)

### §4.1 Grader-format dominance is a target-independent failure surface

`.075` exposed that 8 of 10 INVESTIGATE questions in sphinx were `grader_artifact` — judge correct in both regimes, format-failed grader. This is not a sphinx-specific issue; it is a property of the exact-match grader interacting with judge response style. Any future target with question types prone to verbose responses (numeric counts, set enumerations) will show the same masking unless V1.2 §11 governance is active.

### §4.2 R-SC-2 semantic labels are the foundation of every downstream characterization decision

Without the 6-label taxonomy, the program cannot:
- Distinguish `Wrong | Wrong` cases that are recoverable vs ceiling
- Distinguish format-elicitation gain from genuine retrieval gain
- Apply the cross-regime subtype rules that drive INCLUDE/SENTINEL/INVESTIGATE triage
- Run the disagreement metric meaningfully (the metric requires the labels to compute)

The taxonomy is now load-bearing for every target intake. SC's ownership of this artifact is the right organizational locus.

### §4.3 The sentinel_review_note discipline is what surfaces target-characterization failures

When sphinx's raw `.075` showed SENTINEL=0, that was a signal — not an absence of signal. SC's discipline of authoring the review note ("the 0-SENTINEL result is a grader-surface artifact, not a true zero") forced the program to confront the grader question. Without that note, the SENTINEL=0 result would have been read as "no prior dominance" and Path B target selection would have inherited a misleading frame.

### §4.4 The capped diagnostic pilot pattern (`.082`) is reusable

Sphinx q03/q05 capped pilot under V1.2 §11.4 R-COO-1 was a model for narrow-scope diagnostic work that does NOT advance the ship-blocker checklist toward primary case dispatch. The pattern: small N, explicitly capped purpose, clear off-ramp from "diagnostic" to "scored" preventable. Future Path B targets that trigger INVESTIGATE-pool questions will use this same pattern.

### §4.5 The retroactive relabel discipline (`.080-SC` + `8c95a5b4`) preserves audit integrity through governance evolution

When V1.2 governance shipped, sphinx's pre-screen pool needed to be re-characterized under the new semantic-aware triage. SC's audit-trail-preserving relabel pattern (`original_triage_v1.1` + `post_v1.2_triage` + `reclassification_authority` + `reclassification_reason` per question) means the artifact tells the FULL story of governance evolution, not the latest-only snapshot. This discipline will matter again when the next governance evolution lands (e.g., a future 7th label or grader-architecture change).
