## THE SHARED FRAME (both seats read this first)

**The concept, in Andrew's shape:** for every framework we build, get to the **actual root — the
indivisible conceptual base**. Test that nothing sits beneath it. Establish that layer through Rule 24.
Then, when orthogonally-adjacent or above layers are created that interact with it — *especially when
those relationships are built into code* — there must be a process of **resolution**: clear, Rule-24
aligned, absolute.

**What "atom" means here, made precise (transplanted from machinery ratified this week — use it, don't
re-derive it):** an atomicity claim is a **universal claim** — *no admissible decomposition of this
concept exists* — and universal claims are never proven by failing to find. They are held the way the
estate now holds exclusion claims:

- A **challenge control** (the "splitter" — the mirror of the retirement advocate): a differently-derived
  attempt to PRODUCE a decomposition, at cite-don't-gesture specificity.
- **Typed results**: `DECOMPOSITION_FOUND` / `DECLARED_FRONTIER_EXHAUSTED` /
  `BUDGET_EXHAUSTED_WITH_FRONTIER_OPEN` / `INSTRUMENT_UNKNOWN` / `NOT_EXERCISABLE` (no differently-derived
  splitter available). Budget exhaustion routes to UNKNOWN, never to "atomic." An un-runnable challenge
  is not a run one.
- **Frontier closure over a versioned decomposition grammar**: "atomic" is always
  `ATOMIC_WITHIN(decomposition_grammar@version × scope)` — a relative, certificated claim, never
  metaphysical indivisibility. The trust-base law transfers verbatim: **the atom is where decomposition
  explicitly stops, not where nobody has yet split.**

**What "resolution" means here, made precise:** a reference from an adjacent/above layer RESOLVES iff it
points at **exactly one** live authority member, at the **declared grain**, the pointer resolves at HEAD,
the target carries the claimed content, and code surfaces **cite** the vocabulary rather than re-declare
it. This is `View_Time_Compiled` ("terms resolve, systems compile") + the registry's `resolves_via`
mechanism + the entry-bar's differentiated-by-home rule, composed into one predicate. "Absolute
resolution" = zero unresolved, zero ambiguous (two-home), zero re-declared, at a printed denominator.

**Laws that bind both seats, non-negotiable:** Rule 24 as widened AND scoped 2026-08-20 (every schema/
enum/outcome-array/predicate you author or adopt gets the four-postulate test + token-hygiene census,
with CE evaluated against the declared layer); adoption is an authoring act; the Build Ladder (reuse the
estate's instruments before writing anything); no gates manufactured (propose candidates, never
implement); characterize-not-fix (findings route to owners); **the surprise channel is CRO base** — one
line for anything out of scope, no chasing, no suppression. Everything you produce is PROPOSED until
ratified.

## BRIEF ~A — BUILD `atom_layer0` (the framework)

**Mission.** Build the atom_layer0 method package: an atom_decomp-style **mechanical workflow** for
reaching first-order principles in ontological development and epistemological execution — discover the
conceptual base, certify nothing-beneath, legislate the layer via Rule 24, and define the resolution
contract for everything that binds to it.

**Inputs to read, in order:**
1. `projects/ATOM_DECOMP/` — the mechanical template: staged gates (G0–G7 shape), fill-in templates, a
   worked case study, proving runs sequenced where being wrong is cheap. Steal the *shape*; the content
   is different (systems→concepts). Note its own history: audited, config-repaired, **never executed**
   at time of its registration brief — your framework must not repeat that (a proving run is IN scope).
2. `.claude/skills/molecule/SKILL.md` + `.claude/skills/seams/SKILL.md` — the node instrument and the
   edge instrument. atom_layer0 composes them downward: /molecule characterizes a candidate atom;
   /seams' three axes (mechanical/declarative/semantic) are the axes on which a layer *binding* can fail
   — reuse them for the resolution contract rather than inventing new axes.
3. CLAUDE.md Rule 24 (as amended today, both clauses) + `infra/system/ontology/SYSTEM_DEFINITIONS.yaml`
   header (entry bar, form) + `docs/doctrine/INTENT_DENOMINATOR_SYNCHRONIZATION.md`.
4. The GPT-exchange deliverables at this seat (RESPONSE_IV through VII, 2026-08-20) — the challenge-
   control machinery, frontier closure, typed results, the hypothesis normal form (the normalize-before-
   union rule transfers: candidate sub-concepts from different generators must normalize to one grain
   before any counting), and §1.7 of Response VII (the MECE-and-layer-coverage test you will run on
   every enum you author).

**Method sketch (adjust freely; the stages are the recommendation, the LAWS above are not):**
- **S0 — Pin the concept.** Name the concept, its claimed layer, its current authorities, its consumers
  (who binds to it today, in prose and in code). /molecule discipline: hold the record suspect.
- **S1 — Decomposition sweep.** Enumerate candidate sub-concepts via **declared generators** (definition
  analysis; usage census across the canon files; cross-derivation from independent framings; the
  incident record — a concept that failed differently in two incidents may be two concepts). Normalize
  to one grain before counting. Print the generator set and its residue.
- **S2 — The nothing-beneath test.** The splitter challenge per the SHARED FRAME: typed results,
  frontier closure over `decomposition_grammar@v`, an atomicity certificate
  `ATOMIC_WITHIN(grammar@v × scope)` or an honest lesser state.
- **S3 — Legislate the layer.** Rule 24 four-postulate record + token census + declared axis-intent and
  grain, per the widened law. The layer's member set is a population: state its denominator and its
  generation process (a predicate, never a roster).
- **S4 — The resolution contract.** For each adjacent/above layer that binds to this one: the binding's
  form (`resolves_via` pointer / view-time compilation / cited enum), its grain, its failure direction,
  and the check that detects a broken binding. Code bindings get the sharpest form: **code cites, code
  never re-declares.** Output: a per-layer resolution table the ~B census can be re-run against.
- **S5 — Proving run.** One cheap, real concept, end-to-end, before the framework touches anything
  load-bearing. Method defects surface where being wrong is cheap (atom_decomp's own M1 lesson).
  Candidate subjects will come from ~B's census (coordinate through CRO base).

**Deliverable form.** A method package mirroring ATOM_DECOMP's: spec + portable skill + fill-in
templates + the worked proving-run case. Registration as a project routes through CTO base per the
LD-0331 precedent (CRO does not own the REGISTRY lane); write the registration brief, don't register.

**Acceptance bar.** (a) The framework's own enums/arrays pass the test they prescribe — run §1.7's
MECE-and-layer-coverage pass on every one and attach the records; (b) the proving run completed with at
least one method defect found and fixed (a proving run that finds nothing is suspect — could it have
failed?); (c) every stage's output is a structured artifact a later seat can re-run, never prose-only.
