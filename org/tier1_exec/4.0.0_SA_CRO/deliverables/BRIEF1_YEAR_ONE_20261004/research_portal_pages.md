## 3. Gaps and caveats

- **Production dates before 2026-02-26 are bounds, not deploy events.** Deploy tags start at portal-v2.1.0 (2026-02-26), and continuous-integration auto-deploy on a PROD push starts 2026-03-23 (8f5b18ce).
  - 2026-01-04 is the first recorded production deploy (deploy timestamp in 6b89bdb7). An earlier release through the old `main` branch (PR #1 on 2025-12-29) cannot be ruled out.
  - The January pages were already on PROD's tip before the 2026-02-17 merge (158c468b). PROD was fast-forwarded at an unrecorded time between each page's commit and 2026-02-13. The true live date lies inside that window.
- **The first-parent method fails for January to April.** In that period the PROD and DEV first-parent chains are identical because the branches were fast-forwarded into each other. The local reflog only reaches back to 2026-07-29. I did not read the GitHub Actions run history, since vendor API calls were out of scope.
- **"Live" means reachable for at least one audience.** Advisor Intelligence, Portfolio Management, Security Scanner and Causality Engine all launched gated to Dev users or admins; the notes give the date each opened up. Partner visibility is per-firm and comes from `firmAccess.ts`, which only exists from 2026-04-15. Before that, there were no partner logins in the code.
- **Deploy tags prove a successful deploy job, not that CloudFront served the page that day.** I did not check the live site. Tag timestamps mix UTC and US Eastern time; dates are given in each tag's own zone.
- **Tabs inside a page are not listed.** For example, the Advisor Intelligence tabs and the Investor Reporting Performance and Holdings tabs. The four Advisor Intelligence partner editions are listed separately because each is its own partner module.
- **No unmerged pages exist.** Every local and remote branch's App.tsx was diffed against DEV, and no route exists outside DEV history.
- **Only the Business Overview / Asset Management dates are pre-router.** The 2025-11-18 to 2025-11-25 navigation used tab state, not URLs.
