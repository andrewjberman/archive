  <context>
    INF_D_00c.portal_leaderboard.py _aggregate_gro_firm_window (brief L678-705) and _aggregate_gro_per_advisor_window (brief L606-675) compute the firm/advisor window TWR as a single AUA-weighted ARITHMETIC MEAN over the entire 2-D set of (household x date) rows in the window: weighted_twr = SUM_rows(total_aua * return_pct_twr) / SUM_rows(total_aua); firm_return_pct_twr = weighted_twr * 100. That is NOT a window TWR. A window TWR aggregates over two independent axes: cross-sectional (within one date, AUA-weight household returns -- the code does this and it is CORRECT, keep it) and temporal (across dates within the window, sub-period returns COMPOUND -- the geometric chain-link PRODUCT_t(1 + r_t) - 1 that defines a Time-Weighted Return). The code averages where it must compound; the defect is entirely on the temporal axis (Axis 2). DE 0.4 confirmed it with three empirical tells against the 16:44Z leaderboard.json: (1) inverted monotonicity -- QTD 0.0386% > YTD 0.0090% > MAX 0.0043% (a cumulative window return must GROW with window length in a positive market; a mean of per-row returns dilutes as more -- and earlier, lower-return -- rows enter the average); (2) %-vs-$ inconsistency -- MAX firm_return_$ = $10.14M (largest; it is a .sum(), behaves cumulatively) while MAX firm_return_pct_twr = 0.004% (smallest); (3) per-advisor return_pct_twr ~0.04-0.06% for all 4 advisors while the same payload's performance.avg_twr_pct = 13.71/0.70/14.31 -- three orders of magnitude off. The INFGRO.005 HOLD is upheld; the Phase-2 portal code (d4e28cca) renders the field faithfully -- zero portal rework. The defect is gold-tier, in INF_D_00c.
  </context>
