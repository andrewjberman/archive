## Finding 1 -- [medium/merge-dedup/full]
- **Location:** `main(), lines 248-253 (ytd_map = ytd_nna.set_index('advisor_key').to_dict('index'); ytd_map.get(r['advisor_key'], {}))`
- **Mechanism:** The YTD NNA flows are joined to the advisor summary by advisor_key STRING VALUE via a dict .get() with a silent {} default. But the two producers derive advisor_key from DIFFERENT sources with no equality guarantee: account_team (INF_C_07) builds it by normalizing accounts_v2 representative_name (lower + non-alnum->'_' + slice 60, C_07 lines 191-198), while canonical_nna (INF_C_01) builds it from the hardcoded _INF_REP_ID_TO_ADVISOR_KEY rep_id->name map (C_01 lines 344-349). They coincidentally align today ONLY for the 4 known advisors (joe_brandenburg / patrick_scanlan / peter_lee / inflection_wealth_management). Any advisor whose accounts_v2 representative_name normalizes to a different string than the hardcoded map value produces a key miss -> ytd_map.get returns {} -> ytd_inflow/ytd_outflow/ytd_nna default to 0. No crash, no warning.
- **Failure scenario:** accounts_v2 stores rep 11's representative_name as 'Patrick J. Scanlan' -> account_team advisor_key='patrick_j_scanlan'; canonical_nna advisor_key='patrick_scanlan' (from rep_id 11). Line 250 ytd_map.get('patrick_j_scanlan', {}) misses -> that advisor's served ytd_inflow/ytd_outflow/ytd_nna are all 0.00 in advisor_fee_efficiency.json (consumed by INF_D_04 client_portal_summary) even though real NNA flowed. Same silent zeroing on any newly onboarded advisor whose name format differs from the hardcoded map.
- **Proposed fix:** Do not rely on incidental string-normalization parity across two independent producers. Either (a) join NNA to the advisor summary on a stable rep_id rather than the derived name string, or (b) make both producers derive advisor_key from the SAME canonical mapping, or (c) at minimum emit a WARN/telemetry count of fee_rows whose advisor_key is absent from ytd_map so a divergence is loud instead of silent.

## Finding 2 -- [medium/schema-column/full]
- **Location:** `main(), lines 180-183 (fee_rate_col = next(c for c in ['fee_rate','annual_fee_rate','management_fee_rate','advisory_fee_rate'] ...))`
- **Mechanism:** The rate-column autodetect list does NOT include 'fee_bps', which is the column name in the documented fee_rate_history restore schema (INF_A_02 docstring line 22: 'account_id, effective_date, end_date, is_current, fee_bps, fee_schedule, source', mirroring BD's A_02). INF_A_02 is currently a DEPRECATED no-op so fee_data_available is False today; but when the Orion Advisory Fees feed lands and A_02 is restored with fee_bps, fee_rate_col resolves to None -> the else branch (lines 194-195) logs 'missing rate column' -> fee_data_available stays False -> fee_earning_aua / non_fee_earning_aua / avg_fee_rate / fee_efficiency_score silently remain 0 forever. Secondary units bug: fee_bps is basis points, but avg_fee_rate treats the value as a raw decimal rate (round 6dp, lines 227-228,242) -> if the column were matched it would be ~10000x too large.
- **Failure scenario:** A_02 is un-deprecated and writes fee_rate_history.parquet with columns (account_id, ..., fee_bps, ...). Next full chain: INF_C_08 finds fee_rate_col=None, logs a WARN, sets fee_data_available=False, and every advisor's fee_earning_aua/avg_fee_rate/fee_efficiency_score serve as 0.0 -- the feature silently never activates despite live data.
- **Proposed fix:** Add 'fee_bps' to the candidate rate-column list AND branch on it to convert basis points to a decimal rate (rate = fee_bps / 10000.0) before use in avg_fee_rate. Align the detected-column list with the actual A_02 output schema.

## Finding 3 -- [low/merge-dedup/full]
- **Location:** `main(), lines 186-192 (account_fee_map = fee_rates[['account_id', fee_rate_col]]...set_index('account_id')...to_dict()) and lookups at lines 219-227`
- **Mechanism:** account_fee_map is a plain dict keyed by fee_rates['account_id'] (dtype unmanaged by A_02). The lookup keys (acc, lines 223 & 227) come from account_team['account_id'], which INF_C_07 forces to str ('.astype(str).str.strip()', C_07 line 205). If a restored fee_rate_history stores account_id as int/Int64, dict keys are ints while acc is a str -> every account_fee_map.get(acc, 0) returns 0 -> fee_aua=0 and fee_efficiency_score=0 for ALL advisors while fee_data_available is reported True (misleading). Dormant while A_02 is a no-op.
- **Failure scenario:** Restored fee_rate_history.parquet has account_id as int64 (e.g. 100234). account_team account_id is str '100234'. account_fee_map.get('100234', 0) -> 0 for every account -> fee_earning_aua=0.00 and fee_efficiency_score=0.0000 for every advisor, yet fee_data_available=true in the served JSON, hiding the fact that the join produced nothing.
- **Proposed fix:** Normalize both sides to a single account_id dtype before building/using the map, e.g. account_fee_map keyed by fee_rates['account_id'].astype(str).str.strip(), matching the C_07 account_team convention; assert non-empty overlap and WARN if zero accounts match while fee_data_available is True.

## Finding 4 -- [low/type-issue/full]
- **Location:** `main(), lines 169-170 (account_team['total_aua'] = pd.to_numeric(account_team.get('total_aua', 0), errors='coerce').fillna(0.0))`
- **Mechanism:** The .get('total_aua', 0) fallback is meant to be defensive, but when the column is absent it returns the scalar 0; pd.to_numeric(0, errors='coerce') returns a numpy int64 SCALAR, which has no .fillna method -> AttributeError, caught by the top-level except (line 286) -> sys.exit(1) -> the no-timeout gold chain hard-aborts. So the 'safe default' actually converts a would-be clean state into a crash. In practice INF_C_07 always emits total_aua (C_07 line 343), so this never fires today; flagged as a latent hole for the exemplar 'dtype pinned on populated path but not the empty path' class.
- **Failure scenario:** If a future INF_C_07 change drops/renames total_aua in account_team, INF_C_08 crashes at line 169-170 with AttributeError ('numpy.int64' object has no attribute 'fillna') instead of degrading gracefully, aborting the entire full chain.
- **Proposed fix:** Guard on column presence explicitly: if 'total_aua' not in account_team.columns: account_team['total_aua'] = 0.0; else coerce the existing Series. Avoid DataFrame.get() with a scalar default feeding .fillna().
