## Finding 1 -- [critical/unguarded-read/both]
- **Location:** `data/inf/scripts/gold/INF_D_04.client_portal_summary.py:3660 (and :3662, :3663) in build_advisor_summaries`
- **Mechanism:** acct_perf (assigned line 3631) and account_team (assigned line 3639) are bound ONLY inside the try block at line 3630. The `except Exception` at line 3650 merely logs a WARN ('summaries will emit empty distribution blocks') and does NOT re-bind them. Immediately after the except, lines 3660 (`if not account_team.empty ...`), 3662 (`account_team.groupby(...)`), and 3663 (`_build_advisor_mix_periods_quarters(acct_perf['date'].max())`) reference those names unconditionally. If the try raises before both are bound, Python raises `NameError: name 'account_team' is not defined` (or 'acct_perf'). build_advisor_summaries has no inner guard; main() calls it with no try/except (line 4260); the __main__ handler (lines 4285-4291) catches the NameError and calls sys.exit(1). INF_D_04 is a non-pull step, so run_script/run_chain hard-fail the entire no-timeout gold chain.
- **Failure scenario:** The try does two unguarded S3 parquet reads: gold/timeseries/account_performance.parquet (INF_C_03 output) at line 3631 and gold/views/account_team.parquet (INF_C_07 output) at line 3639. Neither C-stage script runs in CHAIN_INCREMENTAL (they are assumed to pre-exist). Trigger cases: (1) a first incremental run before any full chain built the C-stage outputs, or the objects were cleared -> line 3631 raises NoSuchKey -> except logs -> line 3660 references unbound account_team -> NameError -> sys.exit(1) -> whole platinum publish chain ABORTS at INF_D_04. (2) account_team.parquet absent or transiently unreadable while account_performance.parquet is fine -> line 3639 raises -> account_team unbound -> same NameError abort. (3) account_performance.parquet present but schema-drifted (missing total_aua/account_id/date) -> KeyError at the zip/max on lines 3633-3638 BEFORE account_team is bound -> same NameError abort. In every case the author's explicit graceful-degradation intent (emit empty distribution blocks) is defeated and the run crashes instead. adv_keys is non-empty on any normal run (INF_D_02 book.json exists), so the early return at line 3625 does not protect this path.
- **Proposed fix:** Initialize `acct_perf = pd.DataFrame()` and `account_team = pd.DataFrame()` BEFORE the try at line 3630 (or move all post-except consumers inside the try / behind explicit `if 'account_team' in locals()` guards). With empty-DataFrame defaults, line 3660's `not account_team.empty` is False, line 3662's groupby is skipped, and `_build_advisor_mix_periods_quarters(acct_perf['date'].max())` needs `acct_perf['date']` to still exist -- so also guard line 3663 (e.g. `acct_perf['date'].max() if 'date' in acct_perf.columns else pd.NaT`, which _build_advisor_mix_periods_quarters already tolerates via its pd.isna check).

## Finding 2 -- [medium/type-issue/both]
- **Location:** `data/inf/scripts/gold/INF_D_04.client_portal_summary.py:1137 in _build_account_distribution`
- **Mechanism:** `int(r['account_id'])` casts the raw holdings account_id with no coercion. The file elsewhere treats holdings.account_id as unreliably typed and always coerces it via pd.to_numeric(errors='coerce') (e.g. lines 2429, 3051-3052, and the comment at 3044-3048 states 'holdings.account_id has drifted to object in some periods'). Here the raw int() cast is the lone unguarded consumer. NaN is safe (groupby at line 1134 drops NaN keys and the `if r['aua'] > 0` filter applies), but a non-integer-parseable string value is not.
- **Failure scenario:** If any holdings row carries account_id as a float-formatted string (e.g. '10432.0' produced by an upstream float->str cast) or a non-numeric id, with market_value>0, then `int('10432.0')` raises ValueError inside the list comprehension. _build_account_distribution is called unconditionally from build_header_metrics (line 1284), which main() calls at step 2 (line 4203) with no try/except -> propagates to __main__ -> sys.exit(1) -> gold chain ABORTS. Because account_distribution feeds header_metrics.json (the partner-facing header), the crash blocks the firm header publish.
- **Proposed fix:** Emit the account_id as a string (`str(r['account_id'])`) or coerce consistently with the rest of the file: `aid = pd.to_numeric(r['account_id'], errors='coerce')` and skip/str-fallback when NaN, instead of a bare int() on a column the codebase otherwise never trusts to be integer-typed.
