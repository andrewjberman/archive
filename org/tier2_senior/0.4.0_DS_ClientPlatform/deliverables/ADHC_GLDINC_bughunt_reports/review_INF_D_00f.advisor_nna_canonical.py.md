## Finding 1 -- [high/empty-null-handling/both]
- **Location:** `_leaf_with_fee_split lines 399-405 (else-branch) -> aborts at main() AC-F4b.1 lines 803-818`
- **Mechanism:** When acct_dim is an empty dict (load_accounts_dim's guarded try/except returned {} because gold/dimensions/accounts_dimension_latest.parquet is absent, transiently unreadable, or its schema drifted so pd.read_parquet(columns=['account_id','household_id','first_trade_date']) raised), the `if acct_dim and ...` guard is falsy and the else-branch sets BOTH total['nmnc'] and total['nmec'] to dict(zero). This contradicts both the documented invariant (nmnc.nna + nmec.nna == total.nna) and load_accounts_dim's own log message ('all=nmec fallback'). The correct fallback (nmec=total) is exactly what build_cohort_mask already returns for empty acct_dim (all-False mask -> window_df[~mask] == full total), but the else-branch bypasses that safe path.
- **Failure scenario:** An upstream INF_A/B job renames first_trade_date (or the accounts_dimension file is absent on a fresh bootstrap / transiently fails to read). load_accounts_dim swallows the exception, logs a benign 'accounts_dim load failed -- all=nmec fallback', and returns {}. Every leaf's nmnc and nmec become 0. In main(), for QTD firm nna=$2,350,000 while cohort_sum = 0 -> cohort_delta = 2,350,000 > 0.01 -> f4b_failures populated -> sys.exit(1) at line 818, hard-aborting the entire no-timeout gold D-chain and every downstream served artifact, even though the load was nominally 'guarded' and logged as a graceful fallback.
- **Proposed fix:** In _leaf_with_fee_split, when acct_dim is empty/unavailable mirror the documented 'all=nmec' fallback instead of zero/zero: either always call build_cohort_mask (it already returns an all-False mask for empty acct_dim, giving nmnc=empty and nmec=total), or in the else-branch set total['nmec'] = {k: total[k] for k in ('nna','inflows','outflows','account_count')} and total['nmnc'] = dict(zero) so the AC-F4b.1 invariant holds.

## Finding 2 -- [medium/merge-dedup/both]
- **Location:** `build_advisor_nna_canonical state_map line 524 (no casefold normalization) -> collision guard main() lines 861-863 -> sys.exit(1) line 883`
- **Mechanism:** City names are casefold-canonicalized via _canon_city / _city_to_canon (lines 504-522) specifically because the accounts_v2 source was found (CVO W4) to carry case-variants like 'SNOHOMISH'/'Snohomish'. The sibling `state` field, read from the SAME accounts_v2 snapshot (load_account_geo line 284, raw str().strip(), no case folding), is NOT normalized. Two case-variant state strings therefore become two distinct geo_state groups/keys. The main() state dup-key guard _collisions(geo_art.keys()) (line 861) detects casefold-equal-but-unequal keys and appends a w1_failure, which hard-aborts at line 883.
- **Failure scenario:** accounts_v2 has one account with state 'Washington' and another with 'WASHINGTON' (the documented case-variance in the sibling city field makes this plausible; or a real account whose state literally is 'other' vs the 'Other' join-miss catch-all). Two state leaves 'Washington' and 'WASHINGTON' are emitted; _collisions finds the casefold collision, w1_failures = ['state case-variant dup keys: ...'], and sys.exit(1) at line 883 aborts the whole chain.
- **Proposed fix:** Apply the same casefold-canonicalization used for cities (_canon_city) to the state field before building state_map -- collapse each casefold group to one canonical source variant (most-common, tiebreak non-ALL-CAPS then alphabetical) -- so case-variants merge into a single state leaf before the collision guard runs.
