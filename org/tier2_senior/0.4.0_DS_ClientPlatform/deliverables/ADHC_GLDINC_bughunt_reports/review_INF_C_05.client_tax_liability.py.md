## Finding 1 -- [medium/schema-column/full]
- **Location:** `data/inf/scripts/gold/INF_C_05.client_tax_liability.py:139-155 (main, accounts_dim merge path)`
- **Mechanism:** The `keep = [c for c in ['account_id','household_id','advisor_key'] if c in acct_dim.columns]` filter CONDITIONALLY selects household_id/advisor_key only when present in accounts_dimension, but lines 150 and 155 then access gains['household_id'] and gains['advisor_key'] UNCONDITIONALLY. If accounts_dimension_latest.parquet lacks household_id, `keep` omits it, the left-merge never creates the column, and line 150 `gains['household_id'].astype(object)` raises KeyError -> uncaught -> the __main__ handler calls sys.exit(1). Because run_script runs all gold steps with NO timeout and hard-fails the chain on any non-zero exit, this aborts CHAIN_FULL at INF_C_05. Critically, INF_A_00 is DESIGNED TO TOLERATE a missing household_id: build_accounts_dimension guards with `if 'household_id' in dim.columns` (INF_A_00 line 237) and only logs 'WARN: missing canonical accounts_dim cols' (line 231) before writing the dim anyway -- so A_00 succeeds green while C_05 hard-crashes on the same degraded artifact. The defensive keep-filter creates a FALSE sense of guarding (it protects the merge but not the subsequent unconditional column reads).
- **Failure scenario:** accounts_v2 silver drops the household_id field (schema drift / partial Orion dim). INF_A_00 renames/builds the dim, hits `if 'household_id' in dim.columns` = False, logs 'WARN: missing canonical accounts_dim cols: [household_id]', writes accounts_dimension_latest.parquet WITHOUT a household_id column, and exits 0. INF_C_05 loads it (acct_dim is not None), builds keep=['account_id','advisor_key'], merges, then line 150 `gains['household_id'].astype(object)` -> KeyError('household_id') -> traceback -> sys.exit(1) -> 'CHAIN full FAILED at INF_C_05' -> every downstream INF_C_*/INF_D_* script and the platinum/INF_09 emit are blocked for the whole nightly.
- **Proposed fix:** After the merge, guarantee the columns exist before use, mirroring the acct_dim-is-None fallback: `if 'household_id' not in gains.columns: gains['household_id'] = gains['account_id']` and `if 'advisor_key' not in gains.columns: gains['advisor_key'] = 'unknown'` BEFORE the fillna/astype block; or explicitly branch on `('household_id' in acct_dim.columns)` and take the account_id-as-household fallback path when absent, matching INF_A_00's tolerate-and-warn posture instead of hard-aborting the chain.
