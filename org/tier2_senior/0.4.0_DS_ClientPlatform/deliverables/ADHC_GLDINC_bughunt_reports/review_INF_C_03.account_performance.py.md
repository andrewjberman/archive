## Finding 1 -- [critical/merge-dedup/full]
- **Location:** `data/inf/scripts/gold/INF_C_03.account_performance.py:233 (main, all_perf.merge(all_gains, on=['account_id','_date_str']))`
- **Mechanism:** Join-key DTYPE MISMATCH on account_id. all_perf.account_id is Int64: it is loaded from canonical_performance_{date}.parquet, and INF_C_00.canonical_performance.py:133 coerces account_id to Int64 before write (pyarrow round-trips the nullable Int64 extension dtype). all_gains.account_id is object/str: load_gains_for_date (INF_C_03:102-115) groupby's gold/account_gains/{date}.parquet, whose account_id is inherited uncoerced from canonical_holdings, and INF_B_00.canonical_holdings.py writes account_id as string (lines 293/304/531: .astype(str)); INF_B_03.account_gains.py never re-types it. Merging an Int64 key against an object key raises pandas ValueError 'You are trying to merge on Int64 and object columns for key account_id' (verified on pandas 2.3.3). Because run_chain executes every non-pull gold step under set -e with NO timeout and hard-fails the chain on any non-zero exit, the ValueError propagates through INF_C_03's top-level except (line 292) -> traceback -> sys.exit(1), aborting the whole compute chain at INF_C_03 (INF_C_04 validate_aua and the entire INF_D_* / INF_09 platinum emit never run, so served portal data does not refresh for the day). NOTE: on an older pandas that does not raise on int-vs-object merges, the same mismatch instead yields a SILENT 0-row join -> unrealized_gain and cost_basis become all-NaN for every account in the served account_performance.parquet (silent data corruption feeding I_C07 advisor_attribution + D-chain). Either way the merge is broken.
- **Failure scenario:** Any normal full/compute run in which account_gains partitions exist for the processed dates (the standard case: INF_B_03 runs successfully earlier in CHAIN_COMPUTE and writes gold/account_gains/{date}.parquet with string account_id). At INF_C_03 line 231 gains_dfs is non-empty, so line 233 executes the merge: all_perf.account_id=Int64 vs all_gains.account_id=object -> pandas raises ValueError -> INF_C_03 exits 1 -> chain aborts, no platinum refresh. (The crash is dodged only in the degenerate case where NO account_gains data exists at all, which takes the WARN branch at line 235-238 and skips the merge -- i.e. the bug is latent whenever gains are absent and fires the moment they are present.)
- **Proposed fix:** Normalize both merge keys to the same dtype immediately before line 233. Simplest: reuse the existing helper -- `all_gains = coerce_id_columns(all_gains)` (coerces account_id to Int64) right after `all_gains = pd.concat(gains_dfs, ...)` on line 232, matching all_perf's Int64. Equivalently, cast in place: `all_gains['account_id'] = pd.to_numeric(all_gains['account_id'], errors='coerce').astype('Int64')`. (Root-cause alternative: coerce account_id to Int64 at write in INF_B_03/INF_B_00 so all downstream gold keys are consistently typed.)

## Finding 2 -- [low/schema-column/full]
- **Location:** `data/inf/scripts/gold/INF_C_03.account_performance.py:212-214 (household_id backfill merge)`
- **Mechanism:** acct_dim is slimmed at line 143-144 to keep = [c for c in ['account_id','household_id','advisor_key'] if c in acct_dim.columns], so household_id is present in acct_dim ONLY if the source accounts_dimension had it. Line 212-214 then does `if 'household_id' not in all_perf.columns: all_perf = all_perf.merge(acct_dim[['account_id','household_id']], ...)`. The indexer acct_dim[['account_id','household_id']] raises KeyError if household_id is not a column of acct_dim -- but that branch is only reached when household_id is ALSO missing from all_perf, which (since all_perf comes from canonical_performance, itself sourced from the same accounts_dimension) coincides with household_id being absent from acct_dim. So the guard meant to backfill household_id instead throws KeyError and aborts the no-timeout chain.
- **Failure scenario:** Upstream A_00 accounts_dimension_latest.parquet is written without a household_id column (schema drift / a rename). canonical_performance (also fed by acct_dim) then also lacks household_id, so all_perf lacks it, the line-212 condition is True, and acct_dim[['account_id','household_id']] raises KeyError: 'household_id' -> INF_C_03 sys.exit(1) -> chain abort. Low likelihood (household_id is a core dimension column) but it is an unguarded KeyError with a concrete trigger.
- **Proposed fix:** Build the merge column list defensively and no-op when the source lacks the column, e.g. `if 'household_id' not in all_perf.columns:` then `if 'household_id' in acct_dim.columns: all_perf = all_perf.merge(acct_dim[['account_id','household_id']], on='account_id', how='left')` `else: all_perf['household_id'] = pd.NA` -- so a missing dimension column degrades to null rather than crashing the chain.
