## Finding 1 -- [critical/other/full]
- **Location:** `_load_transactions L76 (key=bronze/orion-api/{bronze_date}/transactions.csv) + _load_aua L110 (assets.csv) + _latest_bronze_date L46-72`
- **Mechanism:** INF_D_08 reads two deprecated bronze CSV paths -- bronze/orion-api/{date}/transactions.csv and bronze/orion-api/{date}/assets.csv. The current LEG-2 (2026-06-30 de-convert) chain no longer writes either: the dispatch-wired txn pull INF_API_PULL_TXN=pull_inflection_transactions_rest.py writes bronze/transactions/{date}.jsonl.gz (line 543) and the assets pull INF_API_PULL_ASSETS_V2=pull_inflection_assets_v2.py writes bronze/assets/{date}.jsonl.gz (line 414). The only writers of the orion-api CSV paths (pull_inflection_transactions.py, pull_inflection_transactions_v2.py, pull_inflection_assets.py) are absent from every chain in the dispatch catalog (CHAIN_PULL/FULL/INCREMENTAL). INF_D_08's own docstrings still describe the pre-migration 'single-day transactions.csv' model, corroborating it was never repointed. accounts_v2 silver (the third input) IS fresh, so the artifact mixes fresh cohort/existing_aua numbers with frozen NNA+AUA.
- **Failure scenario:** Nightly full chain runs after 2026-06-30. _latest_bronze_date() walks bronze/orion-api/ newest-to-oldest and returns the last frozen date that still has a transactions.csv (pre-migration backfill, ~2026-05..06). firm_nna (nna_ytd/qtd/mtd), total_aua, nmnc_aua, nmec_aua, and all window_inflows are computed from that frozen bronze. Served platinum/firm/nmec_nmnc_nna.json reports stale NNA and AUA that drift further from reality each day, with NO crash and NO alarm (the chain's ChainFailed emitter only fires on non-zero exit). Live-state confirmation of the exact staleness (head-object on bronze/orion-api/{latest}/transactions.csv vs today) should quantify magnitude, but the read-path divergence itself is source-confirmed.
- **Proposed fix:** Repoint _load_transactions to the live txn source -- silver/transactions (built by convert_transactions_to_silver from the fresh jsonl.gz) or bronze/transactions/{date}.jsonl.gz -- and _load_aua to silver/aum_snapshot (used by the dispatch freshness gate) or bronze/assets/{date}.jsonl.gz; update _latest_bronze_date to enumerate the live prefix. Add a freshness assertion (bronze/txn date within N days of today) so an orphaned path fails loud instead of serving frozen numbers.

## Finding 2 -- [medium/merge-dedup/full]
- **Location:** `main() L392-396 (adv_hh_ids = set(adv_txn['household_id'].dropna().unique()); adv_hh = hh[hh['household_id'].isin(adv_hh_ids)])`
- **Mechanism:** Per-advisor NMNC/NMEC membership is gated on transaction presence in the loaded bronze partition (adv_hh_ids comes from adv_txn), whereas firm-level nmnc/nmec are classified over the full hh table (aua outer-join accounts_v2 inception). The two use different attribution mechanisms; the per-advisor block silently drops any classified household that has no transaction row in the loaded partition.
- **Failure scenario:** A newly onboarded household with a recent accounts_v2.account_start_date (firm-classified NMNC) but no transaction in the loaded bronze partition is counted in firm total.nmnc_count/nmnc_aua yet excluded from every advisor's nmnc_count/nmnc_aua. Result: sum(advisors[].nmnc_count) < total.nmnc_count and the per-advisor 'new client' tiles under-report; firm and advisor blocks fail to reconcile.
- **Proposed fix:** Attribute per-advisor NMNC/NMEC households via the accounts_v2 rep attribution already computed for the emit block (hh_rep_attribution / hh_for_emit rep_id), so advisor membership matches firm classification, instead of transaction-presence (adv_txn).

## Finding 3 -- [medium/numeric-sign-units/full]
- **Location:** `_classify_flows L240-241 (in_window) + _lifecycle_table L306-312 (window_inflows) + nmec_mask L322 + nmec_aua L357/L412 + artifact window_days L465`
- **Mechanism:** window_inflows / nmec are derived by applying a trailing-365-day in_window filter to a transactions partition that is a single day (per the file's own docstring L269-278/L302-305 and the single-day orion-api CSV pullers that produced the path). The emitted artifact stamps window_days=365 and labels the per-HH field window_net_nna, but the underlying magnitude is one day's inflows. The in-file rationale calls window_inflows 'informational / not load-bearing' yet it IS load-bearing for nmec_mask, nmec_aua, and hh_lifecycle.window_net_nna.
- **Failure scenario:** A downstream consumer (FE, comp-validate, aggregator) reads window_days=365 and treats nmec_aua / window_net_nna as trailing-365-day New-Money-from-Existing-Clients, but the values reflect a single bronze date's inflows -- NMEC is understated / mis-scaled by up to ~365x, and nmec_count reduces to 'existing HHs that happened to contribute on the loaded date' (the same nmec_count~0 class the 2026-05-14 fix targeted). Entangled with finding 1: repointing to the cumulative jsonl.gz/silver source would make the 365-day filter genuine.
- **Proposed fix:** Source window_inflows from a true trailing-365-day transaction set (silver/transactions or the cumulative bronze/transactions spine, then filter in_window), OR set window_days / relabel the field to the real grain so the served number is not mis-scaled.

## Finding 4 -- [low/type-issue/full]
- **Location:** `_load_advisor_accounts L213 (df.get('representative_name', '').fillna('').astype(str).str.strip())`
- **Mechanism:** df.get('representative_name', '') returns the Python str '' (not a Series) when the column is absent from the accounts_v2 parquet; the chained .fillna('') then raises AttributeError: 'str' object has no attribute 'fillna'. The .get() was written to be defensive against a missing column but is non-functional -- it crashes instead of defaulting.
- **Failure scenario:** If a future silver/api_dims/accounts_v2 schema change drops or renames representative_name, INF_D_08 dies with an AttributeError at load. Because every gold/silver step runs with no timeout and hard-fails the chain on any non-zero exit, this aborts the entire full chain (fires ChainFailed) rather than degrading gracefully to blank advisor names.
- **Proposed fix:** Guard column existence explicitly: repn = df['representative_name'] if 'representative_name' in df.columns else pd.Series('', index=df.index); df['representative_name'] = repn.fillna('').astype(str).str.strip().
