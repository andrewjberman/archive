### And if AWS flips us tomorrow, we still cannot send — verified on the DEPLOYED function
`opalinvest-auth-handler` carries **no `SMS_*` environment variables at all**
(`get-function-configuration` → `Environment.Variables`). So:

- `SMS_ORIGINATION_IDENTITY` = `''` → `assertSendable` fails **CLOSED and LOUD**
- `SMS_VERIFIED_DESTINATIONS` = `''` → empty allowlist, every destination refused
- `SMS_ALLOW_UNVERIFIED` ≠ `'true'` → the release valve is off

This matters because of the hazard `sms.ts:38-44` names in its own words: *"the day [sandbox exit]
happens, every guard that lived only in the sandbox evaporates at once, and this Lambda would begin
texting arbitrary enrolled numbers with nothing in the repo having changed."* The code-level
allowlist exists precisely so sandbox exit is **not** a single silent act. It is armed. Leaving the
sandbox will require a reviewable commit + Terraform change on our side as well as the AWS approval.
