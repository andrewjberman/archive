### adv_drill

1. **Existing Data:**
   - **Parquet Files:** The primary source for advisor/client-level NNA data is `gold/views/nna_aua_by_advisor.parquet`. This file contains daily NNA, cumulative inflows, and outflows at the architect level.
   - **Client-Level Data:** `rel_architect_lookup.parquet` provides the mapping from architect to client relationships, which is essential for aggregating client-level data under each architect.
   - **Cardinality:** Typically, each architect manages between 10 to 50 clients, but this can vary. We can realistically handle this cardinality in the output.
   - **Date Range & Density:** We can provide daily data for the past 2 years, aligning with the existing `geo_drill` structure in `timeseries_chart.json`.

2. **Output Shape:**
   - **JSON Structure:**
     ```json
     {
       "adv_drill": {
         "architect_key": {
           "categories": ["client_1", "client_2", "..."],
           "data": [
             {"date": "YYYY-MM-DD", "client_1": value, "client_2": value, "..."}
           ]
         }
       }
     }
     ```
   - **Field Types:** Dates are strings in `YYYY-MM-DD` format. Values are cumulative NNA in dollars.

### cla_timeseries

1. **Existing Data:**
   - **Classification Logic:** Relationships are classified as NMNC if their `first_seen_date` is within the last 12 months. This information is available in `gold/client_dimension.parquet`.
   - **Source Fields:** The `first_seen_date` field in `client_dimension.parquet` is used to determine NMNC vs NMEC status.
   - **Aggregation Capability:** We can aggregate daily NMNC and NMEC AUM by state, city, and architect using `client_performance.parquet` for AUM data and `accounts_dimension_latest` for geographic and architect mapping.

2. **Output Shape:**
   - **JSON Structure:**
     ```json
     {
       "cla_timeseries": {
         "total": {
           "categories": ["NMNC", "NMEC"],
           "data": [
             {"date": "YYYY-MM-DD", "NMNC": value, "NMEC": value}
           ]
         },
         "geo": { ... },  // Similar structure for geographic breakdown
         "adv": { ... }   // Similar structure for architect breakdown
       }
     }
     ```
   - **Field Types:** Dates are strings in `YYYY-MM-DD` format. Values are daily AUM in dollars.

### General Notes

- **Output Location:** Both outputs will be added to `timeseries_chart.json` under their respective keys (`adv_drill` and `cla_timeseries`).
- **Caveats:** Ensure that the classification logic for NMNC/NMEC is agreed upon with DE and RD before finalizing the implementation. The current logic is based on `first_seen_date`, but any changes in business rules should be reflected in the data processing.

I look forward to DE and RD's feedback on the TypeScript interface requirements and any chart-specific constraints.
