## Work Completed

### 1. Telemetry accuracy verification (DIAGNOSE)
Traced the telemetry mechanism end-to-end: PostToolUse `*` hook → `.tools/hooks/post-tool-telemetry.sh` → per-serial `org/mcp/agent_telemetry/{serial}.jsonl` with `{ts, ts_unix, serial, tool_name, kind, serial_source, session_id}`. Confirmed: privacy-safe (tool_name only, never args/outputs, enforced by explicit `jq -nc` field enumeration); serial resolution is session-id-keyed with a fallback chain; live agents' jsonl files were fresh to the second and matched their actual work. **Verdict: telemetry is accurate, clean, and clear.** Canonical model = LD-0070 `TELEMETRY_LIVENESS_FRAMEWORK` dual-signal: LIVE = last `kind:work` <120s; SESSION_ALIVE = last any-kind <600s.

### 2. Status-quality assessment (DIAGNOSE)
The "status" = the broker `summary` (`org/mcp/liveness.json`), self-set via register/heartbeat/set_summary. Assessed all live agents: working agents declare their work clearly; the inconsistency is the **not-working → available vs blocked** distinction (many say "awaiting"/"standing by"/"/work armed" — implying idle without an explicit token; `0.7.0_AE` base was the best-formed "parked + lists external triggers"). Conclusion: good-but-loose; the fix is an explicit taxonomy + a tool that flags where it's missing.

### 3. Built `/fabric-check` (IMPLEMENT)
- **Engine `.tools/fabric-check.py`** + **PATH wrapper `.tools/fabric-check`**: pure-filesystem (reads `liveness.json` + `agent_telemetry/*.jsonl`, no MCP round-trip), so any agent runs it cheaply. **Fuses** objective telemetry-derived dual-signal liveness with the declared summary, classifying each agent into WORKING / IDLE-AVAILABLE / BLOCKED / SOVEREIGN-DECISION-REQUEST / STALE-VERIFY / NEEDS-STATUS, and flagging summary-vs-telemetry mismatch (claims-work + telemetry-STALE → STALE-VERIFY). BLOCKED detection includes soft-blocks ("holding/pending a ruling/decision"). Emits a machine `FABRIC-CHECK-RESULT` line + `ACTION-REQUIRED`. Modes: full / `--blocks` (COO triage) / `--json`. ASCII-sanitizes summaries (Windows charmap safety). `py_compile` + `ruff(py39)` clean.
- **Skill `.claude/skills/fabric-check/SKILL.md`**: documents the dual-signal model + the WORKING/IDLE/BLOCKED/BLOCKED-SOVEREIGN taxonomy + per-bucket actions + the COO `/drive` integration + the end-to-end sovereign-request flow + its role as the canonical tilde-lane liveness check.
- **Live acceptance test:** correctly read every live agent; surfaced 2 `~A` lanes with empty summaries (NEEDS-STATUS) and DS "HOLDING build for ruling on 3 decisions" as BLOCKED (a single-point hold the project narrative had as "advancing").

### 4. Chained into COO `/drive` (IMPLEMENT)
`/drive` Step 2b.0 (new): run `python .tools/fabric-check.py --blocks` FIRST each cycle; for each BLOCKED resolve-or-escalate THIS cycle; SOVEREIGN → declare to Andrew (CC MSTR); STALE-VERIFY → confirm owner alive; NEEDS-STATUS → nudge a state token. Makes the agent-state scan deterministic; 2b.1–2b.5 remain the deeper cause-classification it feeds. This is the load-bearing use — the failure mode `/drive` exists to catch is the single block that stalls a project/the fabric.

### 5. Wired MSTR `/govern` sovereign-request check (IMPLEMENT)
`/govern` Step 1 new source: sweep for COO sovereign-decision-requests (run `/fabric-check` or read `[SOVEREIGN]` inbox tags). Per LD-0090 / Constitution Art. XVI, if Andrew silent ≥1 turn MSTR issues the ruling (Directives + Stakes Matrix bound; genuine S3/S4 holds for Andrew). Closes the loop: worker declares `BLOCKED-SOVEREIGN` → COO declares up → Andrew rules, or MSTR rules after one silent cycle.

### 6. (Adjacent, same session) get_live_agents false-death incident — read-side fixed
COO relayed an Andrew-direct incident: `get_live_agents` false-deathed an alive `~A` lane → COO misreassigned its work. Diagnosed it (server.py + liveness.json): not really suffix-strip — `get_live_agents` `_clean_stale`-PRUNES entries with heartbeat `last_seen_epoch` >600s, so an actively-working `~A` lane (fresh telemetry, lagged heartbeat) gets pruned → false-death; `get_agent_status`'s base-fallback then masks it (looks like strip). Same root-cause class as the poller/exit-143 issue. **`/fabric-check` is the telemetry-based read-side fix (immune) — now the canonical tilde-lane liveness check.** Broker-core fix (migrate to telemetry-derived liveness per LD-0070) charted to CTO/infra (folds into the existing poller/liveness charter); NOT MSTR-hot-patched (broker blast radius + Art. VI).

## Decisions Made

| Decision | Rationale |
|----------|-----------|
| Liveness from TELEMETRY, not broker heartbeat | Telemetry is real tool calls — ground truth, immune to phantom-live + heartbeat-stale-prune. The summary is a claim; fusing + reconciling them is the whole value. |
| Pure-filesystem engine (no MCP) | Any agent can run it fast, no broker round-trip; reads `liveness.json` (summary) + jsonl (telemetry) directly. |
| declared-IDLE beats telemetry-quiet in bucketing | A parked/idle agent legitimately makes no tool calls; classifying it STALE would be noise. STALE-VERIFY reserved for summary-claims-work + telemetry-stale. |
| Soft-block ("holding for ruling") → BLOCKED | These holds are exactly the single-point stalls COO must catch; phrasing them as "working" would hide them. |
| Charter the broker-core get_live_agents fix, don't hot-patch | Broker code = blast radius across every caller + needs the LD-0070 telemetry-liveness wiring + testing; Art. VI govern-through-the-org. fabric-check covers the gap meanwhile. |
| Recommend (not unilaterally add) the taxonomy to org/XXX.md | Institutionalizing the status norm fabric-wide is an Andrew call; surfaced as a recommendation. |
