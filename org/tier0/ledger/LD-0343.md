## THE FIRST CROSS-SITE FINDING — and it came from the block itself

Site Z's trunk commit landed while base's identical commit was **refused**. The asymmetry is
the finding:

> **A FRESH CLONE GETS ZERO GIT HOOKS.** Git tracks nothing under `.git/`. Site Z is running
> with **no owned-paths gate, no mstr-ledger-check, no mass-deletion-check, no
> branch-content-isolation, and no stitch-refresh** — on the same shared branch as base.

Every enforcement this fabric describes as "gated" is **per-clone**, and a second device
inherits none of it. That is a larger portability gap than any hardcoded path, and it is
**invisible to a path census** — there is nothing at Z to scan. The census I ran tonight

Note the direction of the danger: **the ungated site is the one that succeeds.** An agent at Z
gets no signal that it is unguarded; it simply never sees a refusal. Base learned this only
because base is the gated one.

## AMENDMENT 3 (2026-07-29T02:10Z) — THE ANTI-THRASH PROTOCOL. One rule, because the hazard produces no merge conflict.

### The rule

> **NEITHER SITE EVER ENCODES ITS OWN PATH.** Not as a value, not as a default, not as a fallback,
> not in a comment someone later copies.

The fix is **not** *"base points at base and Z points at Z."* That is **two fixes that permanently
disagree** and re-break each other on every pull. The fix is **one codepath that asks WHERE AM I at
run time** and is therefore correct on both devices with neither site configuring anything.
**If a change would need a different value on the other machine, it is the wrong change.**

### Why coordination cannot substitute for the rule

**A device-specific edit does not conflict in git.** Same file, same line, two different string
literals — whoever pushes last silently wins. No merge marker, no gate, no error. The loser's
device breaks on the next pull and **the symptom surfaces far from the cause.**

> A hazard that produces **no conflict** cannot be managed by being careful at merge time. It has
> to be made **unrepresentable** — which is what deriving the root from the file's own location
> does, and what any agreed-upon-per-site convention would not.

This is why LD-0344 rejected `git rev-parse --show-toplevel` as well: a CWD-sensitive resolver
reintroduces ambient state, just one layer further out.

### The split is structural, not courtesy

**BASE EDITS, Z PROVES.** Base makes the code path-agnostic; Z verifies at a *different clone path*
— the half **base structurally cannot test**, because base is the machine every hardcode was
written for. A site touching a file the other is editing must `CLAIM` it on the trunk first.

Z's queue: launch proof at Z's path · `install-all-git-hooks` (Z has zero hooks) · `fix-git-fstab`
elevated, then **check the FLAGS after reboot, not the presence** (`binary,user` = not fixed) ·
report which of the remaining 41 operative path-rooted files Z actually hits, since **Z's failures
are better evidence than base's census.**

### The wrinkle, and the honest limit

**`send_message` alone does not transmit.** The MCP server writes a file; **git is the transport.**

cross devices. The **interface** is genuinely MCP; delivery is not real-time.
