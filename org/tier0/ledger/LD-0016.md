# LD-0016 — Accelerate /govern cadence to 10m + drive-each-turn posture obligation

## Decision
Andrew direction sets two coupled operating-posture changes effective
this cycle:

### Change 1 -- Cadence: 10m

Default `ScheduleWakeup` cadence for /govern moves from ~20-25 min
(`actively-driving` per Step 7 self-throttle) to **600s = 10 min**.
Quiet/idle exception unchanged (~60 min still available if work-side
is genuinely drained AND no pending receipts). The 10m default better
matches `max_cycle_duration ~10 min` (Stakes Matrix soft bound) -- a
cycle that runs 10m of work followed by 10m of wait keeps the loop
warm rather than letting the cache cool.

### Change 2 -- Posture: drive each turn

Andrew verbatim: "you will be obliged to be much more active and
actually drive some kind of progress each turn."

The track-by-artifact passive posture I'd been holding across CY-0008
-> CY-0012 (COO bottleneck observed but not acted on; Andrew flagged
it for me) is OUT. Each /govern cycle must produce at least one
**concrete progress** action from the following list:

1. **Ratify/close** a pending LD (status flip with empirical evidence).
2. **Originate** a new LD with a clear chartered action.
3. **Surface** a finding to Andrew with a specific decision-ask.
4. **Execute** a population action (spawn / kill / nudge).
5. **Verify + advance** a pending charter (rigorous artifact check;
   surface progress or block).

NOT acceptable as a driving cycle (going forward):
- Pure observation with no follow-up commitment.
- "Track-by-artifact" without an action when staleness threshold hits.
- Empty cycle records ("no findings, nothing to do, re-armed").

The COO-bottleneck-observed-but-not-actioned pattern that Andrew
caught is the canonical anti-pattern this commitment closes.

### Together

10m cadence + drive-each-turn ⇒ approximately **6 driving actions
per hour** by MSTR. With the LD-0015 Part 2 codification by CTO
landing the per-agent commit-activity check structurally, the
combination targets faster detection AND faster action on emerging
state.

## Why now
Andrew's catch on the COO 3-hour-quiet pattern (CY-0012) revealed that
my track-by-artifact mode was producing accurate observation without
driving action. The corrective is structural posture: each cycle owes
a driving action. The cadence change makes the rhythm sustainable;
the posture change makes the cycle output meaningful.

## Assumptions
- The bounds (5 LD / 3 delegations / 2 S2 per cycle) still hold; the
  acceleration doesn't relax bounds, it tightens per-cycle drive
  density.
- 10m cadence is sustainable under the Anthropic prompt-cache 5-min
  TTL. Cache will cool between cycles, but a 10-min interval is a
  reasonable trade -- close enough that loop discipline survives, far
  enough that each cycle has fresh state to process.
- The 5 driving-action types are exhaustive of what a /govern cycle
  can produce; if a cycle genuinely has none of them available, the
  cycle record records "structural-quiet" + escalates to Andrew (NOT
  a passive close).

## Alternatives considered
- **15m cadence + drive-each-turn** -- rejected: Andrew said 10m.
  No discretion.
- **10m cadence without posture commitment** -- rejected: the cadence
  alone doesn't fix the passive-observation pattern. Posture is the
  load-bearing piece.
- **Drive-each-turn with current ~20m cadence** -- rejected: same
  reason -- Andrew specified both.
- **Defer ledgering until the next driving cycle** -- rejected: this
  IS the driving action for this turn (S1 internal commitment; ledger
  before propagation per Art. V).

## Rollback plan
If 10m cadence + drive-each-turn produces excessive noise or burns
host resources, MSTR proposes a tunable in /mstr_review (e.g.,
adaptive cadence 10m active / 30m quiet); Andrew rules. Reversible
posture; not destructive.
