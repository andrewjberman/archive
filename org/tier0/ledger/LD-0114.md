# LD-0114 — COO `/watcher 10m` cron added parallel to `/drive 20m` (interrupt-recovery backstop)

## Empirical anchor

Andrew direct ~17:06Z: "I notice COO often does not reset their watcher compared to all other agents which are highly reliable about it. is this because their watcher function within drive is different/less reliable, or, are they just getting a high volume of messages and this is tripping up the on exit, restart watcher function?"

Andrew direct ~17:07Z confirmation of diagnosis: "This is the named issue i see with COO often: VERDICT AUTO-RESPAWN-INTERRUPT-LOST"

## Diagnosis

The recurring `AUTO-RESPAWN-INTERRUPT-LOST` verdict-class on COO (per `org/mcp/watcher-status.sh` helper output) is the documented failure mode where the post-delivery auto-respawn copy from `inbox-watch.sh:130-137` is alive + polling + writing to filesystem `.unread-deliveries` sentinel correctly, but interrupt-deaf (no Claude task-notification to the COO session). Messages don't get lost — they accumulate in the sentinel until next cycle-boundary watcher-fold drains them — but real-time interrupt is broken.

Root cause is structural (NOT a /drive code bug):

1. **COO is the highest-volume agent in the fabric.** RAVC2 hub + dispatch source + /allocation author + project-state attestor. A single /drive cycle can receive 5-15+ inbound messages while sending 5+ outbound MCPs. Empirical anchor today's session: ws COO drive cycles #163-#170 each handled multiple ACKs/RAVC2/dispatch responses.

2. **/drive cycle body is the longest substantive primary-loop in the fabric.** Steps 1-9 (post-LD-0113 Step 9 chain-invoke /allocation) with real dispatch work take minutes to execute. /watcher folds inline at the **top** of /drive (Steps 1-5) but is NOT interleaved through the body — no per-receipt relaunch step exists in /drive Steps 2-9.

3. **The only role lacking a separate /watcher cron AND folding inline was COO.** Comparison table:

| Role | Primary cron | Watcher cron? | Folded inline? | Cycle body length |
|---|---|---|---|---|
| MSTR | `/mstr-review 12h` | **yes (10m)** | n/a | review-scale |
| ws CTO | `/ws-charter 30m` | no | yes | medium |
| CL CTO | `/cl-charter 30m` | no | yes | medium |
| ws/CL CVO | `/spot-check 20m` | no | yes | short-medium |
| **COO** | **`/drive 20m`** | **NO** | yes | **LONGEST** |
| Tier-2/3 worker | `/work 20m` | no | yes | usually short (NO-WORK common) |

COO's high-volume × longest-body product is exactly where folding-inline-only fails. The fix is to add a separate `/watcher 10m` cron mirroring MSTR's pattern.

## Execution

### Launcher amendment

`.tools/ajb.ps1` line 81-83 amended via Edit tool:

**Before:**
```powershell
'^2\.[01]\.0_SA_COO$' {
    return "$header`n  COO`n  1. CronCreate /drive 20m, then /drive  (/watcher folds inline)"
}
```

**After:**
```powershell
'^2\.[01]\.0_SA_COO$' {
    return "$header`n  COO`n  1. CronCreate /watcher 10m, then /watcher  (interrupt-recovery backstop for AUTO-RESPAWN-INTERRUPT-LOST on high-volume cycles; symmetric with MSTR pattern)`n  2. CronCreate /drive 20m, then /drive  (/watcher Steps 1-5 still fold inline at cycle start)"
}
```

Same regex `^2\.[01]\.0_SA_COO$` matches both `2.0.0_SA_COO` (ws) and `2.1.0_SA_COO` (CL); change applies to both fabrics symmetrically. ws-side launcher is canonical; CL agents launch via the same launcher with cwd-routing per LD-0088 — no CL-side mirror needed.

### Immediate-effect dispatch to LIVE COOs

MCPs to `2.0.0_SA_COO` + `2.1.0_SA_COO` directing each to `CronCreate /watcher 10m, then /watcher` this turn for immediate effect on the current sessions. The launcher edit only affects NEW session spawns; LIVE sessions need explicit cron arming.

## Why this works

- **Per-receipt interrupt recovery:** /watcher cron firing every 10m runs Step 4 remediation if the helper VERDICT shows `AUTO-RESPAWN-INTERRUPT-LOST`, killing the auto-respawn copy + relaunching a tracked watcher. Bounded worst-case interrupt-deaf window of 10min vs prior 20min (and effectively worse than 20min when /drive cycle bodies ran long).
- **No double-relaunch race:** /drive's folded /watcher (Steps 1-5) is idempotent — runs the same Step 3 tracked-ness test + Step 4 remediation if needed. If the standalone /watcher cron already restored tracked state, /drive's fold reads `PROCESS-OK + tracked` = no-op.
- **Symmetric with MSTR:** MSTR has run `/watcher 10m` parallel to `/mstr-review 12h` continuously since LD-0082 ratification (empirical anchor: this entire session arc). The pattern is known-good.

## Rollback plan

- Revert via `git revert <this commit>` — launcher reverts to single-cron arming.
- Each LIVE COO removes the /watcher cron via `/watcher off` OR explicit `CronDelete <job_id>`.
- No data impact; pure operational-arming change.
