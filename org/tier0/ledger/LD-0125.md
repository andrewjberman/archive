# LD-0125 — Storm root-cause identified + immediate fix shipped + F-008 structural queued

## §1 — Why ws CTO's prior diagnosis missed this

The 2026-05-27T15:58 original incident was framed as "broker.py orphaned hot-loop" — F-004 shipped a parent-death watchdog. The empirical hypothesis was: orphan broker accumulated 8158 CPU-sec because its parent had died.

**The misframing**: parent-death watchdog only fires when parent dies. The broker has been hot-looping at 13.5% sustained CPU WHILE parent is alive. That's a different class entirely.

**The real load source**: `org/mcp/server.py:57` POLL_INTERVAL_S = 2.0 × N MCP servers = N/2 polls/sec on broker. With 14 agents = 7 polls/sec, generating 617 TIME_WAIT sockets per ~4min Windows TCP cleanup window. Each poll = TCP handshake + HTTP request + sqlite query + response + close.

## §2 — Diagnostic evidence

| Signal | Value | Interpretation |
|---|---|---|
| git log last 60min | 12 commits / 60min = 0.2/min | NOT a commit-rate storm |
| broker.py PID 5568 CPU | 2924 sec / ~6h = 13.5% sustained | hot-loop class |
| broker.py parent (PID 11016) | ALIVE (server.py) | F-004 watchdog won't fire |
| port 7800 TIME_WAIT | 617 sockets | massive client-poll churn |
| broker.py instances | 1 (singleton) | correct design |
| `POLL_INTERVAL_S` source | 2.0 sec | 14 × (1/2) = 7 polls/sec |

register_agent(0.0.0_AB_MSTR)                   # verify reconnect → SUCCESS

## §4 — Structural fix (RV-0017 F-008 candidate, queued for ws CTO)

**Single-line config change** in `org/mcp/server.py:57`:

```python
POLL_INTERVAL_S = 30.0  # was 2.0 -- 15x load reduction
```

Rationale:
- Broker channel push fires at send time → primary delivery path is push, not poll
- Poll loop is backstop for missed push events (rare)
- 30s backstop is adequate; matches /drive + /spot-check cadence
- 15x reduction in poll volume → 7 polls/sec → ~0.5 polls/sec → expected broker CPU drop from 13.5% to <1%

Test required (ws CTO):
- 5-trial fleet load test (all 14 agents LIVE) measuring broker CPU sustained over 30min
- Verify no message-delivery latency regressions
- Confirm broker.py CPU drops to <1% steady-state

Sized ~2hr including test. Slots into ws CTO's existing P1+ bundle (F-003 + F-005 + F-006 already authored uncommitted from prior cycle).
