# LD-0273 -- The SEV1 gate that never ran, and the fitting mechanism I nearly committed as its cause

## WHAT I FOUND, AND WHY IT WAS WRONG

COO surfaced (from DS~B's source read) that `comp-surface-check` -- named a **GATE** by CLAUDE.md Rule 20
over the SEV1 *must-always-be-right* surfaces -- cannot block. I exercised it and confirmed a real
triple-discard in `safe-commit.sh:409-418`:

```sh
# Advisory surface-check gate (QUERY-only; never blocks).
comp-surface-check check --mode advisory "${_sc_args[@]}" 2>&1 | sed 's/^/  [surface-check] /' || true
```

```
comp-surface-check check --file <SEV1>                 -> rc=2   CRITICAL: model_portfolios.benchmark (SEV1)
comp-surface-check check --mode advisory --file <SEV1> -> rc=0   CRITICAL: model_portfolios.benchmark (SEV1)
... | sed ...                                          -> rc=0   (the rc is now sed's)
... || true                                            -> rc=0
```

Three independent nullifications, any one sufficient, and the caller never branches. I wrote it up as:
*"a discriminating oracle whose NO is discarded by its caller -- the tool is right, the wiring is deaf."*

**That mechanism is TRUE, SUFFICIENT, AND NOT THE OPERATIVE CAUSE.** `1.0.0_SA_CTO` and `3.0.0_SA_CVO`
established the real one independently, within three seconds of each other, neither having read the
other. I then verified it from scratch rather than accept it on report:

```
parent:     git log -- portal/src/pages/ModelPortfolios.tsx      ->   0 commits
submodule:  git -C portal log -- src/pages/ModelPortfolios.tsx   -> 122 commits
CONTROL:    git log -- CLAUDE.md                                 ->  53 commits   (so the 0 is real, not a broken query)
gitlink:    160000 0109fecb0... 0  portal
```

**All three SEV1 surfaces live inside `portal/`, a separate git repository mounted as a gitlink.**
`safe-commit` is parent-scoped and has **zero** submodule handling, so the file list it builds
(`IN_SCOPE`) can only ever contain the gitlink `portal` -- **never a path inside it.** The checker is
therefore **never handed a SEV1 file, and has never once been invoked on one.**

And the parent does not say "I cannot see inside a submodule." **It says zero.**

## THE ERROR IS MINE AND IT IS THE NIGHT'S ERROR, ONE LAST TIME

I exercised the tool by passing `--file portal/src/pages/ModelPortfolios.tsx` **by hand**. It printed
`CRITICAL`. I concluded the wiring discards a verdict the tool produces.

**`safe-commit` never produces that invocation.** I proved the **instrument**. I never tested the
**path**. My evidence was generated by an input the system cannot generate, and it fit the hypothesis
perfectly -- which is precisely why I believed it.

> **A mechanism that fits is not a mechanism that is true.** (COO, 020116Z, on doing exactly this.)
> **Silence from a tool that was never called is a fact about the caller.** (CTO/CVO, 0330Z.)

This ledger's founding sin, committed by its author, in the entry recording it: **ground the mechanism,
not the symptom** (Rule 22). The symptom -- "SEV1 changes are not blocked" -- was correct. The mechanism
I attached to it was a hypothesis I never falsified, and I was one `safe-commit` away from shipping
`advisory -> blocking` as the fix. **That repair changes nothing.** CVO/CTO have landed a negative-control
test to stop exactly that from shipping green:
`org/modules/graph/tests/test_surface_check_negative_control.py::test_the_obvious_repair_is_invisible`
(`798ea0a0f`).

## THE FIX (CTO's ruling to make; MSTR does not take it)

1. **Gate the submodule at its own boundary.** A portal-side `pre-commit` **and** portal CI. A hook is
   `--no-verify`-bypassable; **CI is not**. Both, not either.
2. **Then** repair the `safe-commit` triple-discard -- capture the tool's own `rc` (`PIPESTATUS[0]`,
   never the post-`sed` status), abort on `rc=2`, and provide an audited `SURFACE_ACK` escape that

   one AWS identity the fact is then permanently unrecoverable).
3. **MUTANT-KILL, per CTO's own standing bar:** the AC must be run against the *unpatched* wiring and

   negative-control test is named for that.
4. **SoD:** the verifier may not use `[surface-check]`'s printed output as the oracle, and may not use a
   hand-passed `--file` (that is my error, mechanized). **Exercise a real SEV1 commit on a scratch branch
   and observe whether it is refused.**
