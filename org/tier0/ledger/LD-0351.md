# LD-0351 — Low-level audit remediations: no-immortal-rebuild invariant, bounded hook stdin, halt-gate unknown-serial fail-closed

## Decision

Land four Andrew-ordered fixes from the 2026-07-30 low-level process audit, MSTR-direct, in one
commit paired with this entry:

1. **`infra/aws/globgrph/kuzu_nessie_load.py`** — singleton pid-lock (a LIVE holder refuses a
   concurrent rebuild, rc=4; a dead holder's lock self-clears) + `KUZU_REBUILD_DEADLINE_S`
   watchdog (default 1800s; `os._exit(3)` because a hung native Arrow S3 read ignores interpreter
   shutdown). Enforces Andrew's invariant: only one rebuild ever runs, none runs forever.
2. **`infra/aws/globgrph/_canonical.py`** — `timeout=` on all three rebuild `subprocess.run`
   sites (1800s full / 600s incremental); expiry kills the child. Closes the
   caller-death-orphans-a-hung-child class.
3. **`org/mcp/hooks/post-tool-telemetry.sh`** (+ gitignored installed mirror) — bounded stdin
   read (`timeout 10 cat`); a bare `cat` on a never-closing hook stdin hung a 3-process chain
   from Jul 25 to Jul 30.
4. **`.tools/halt-gate-check.sh`** — `halt_gate_validate_serial`: a resolved serial naming no
   known agent fails closed rc=3 LOUD (measured trigger: site-Z serial-file corruption
   `0.0.0_AB_MSTR~Zn` was accepted and the gate passed against a nonexistent inbox).

Also executed under the same instruction, no code change: killed the orphaned kuzu rebuild
(PID 24828, 2.57GB committed 26h idle) and the hung telemetry chain (PIDs 850873/850893/850894).

## Why MSTR-direct rather than chartered through Tier-1

Tier-1 is under Andrew's COMPLETE HALT (1144Z). Andrew assigned this work to MSTR directly and
ordered each fix explicitly (Art. I: a direct instruction overrides the govern-through-the-org
default and D-001's MSTR-does-not-edit-code non-goal for exactly this scope). The owned-paths
lanes for `infra/aws/globgrph` (CLOUD_OPS_OR_ETL) and `org/mcp/hooks` (BASE_EXEC) were crossed
via the audited `GIT_COMMIT_AUTHOR_OVERRIDE` channel; the owning lanes should review on
halt-lift (see follow-ups).

  lock released on both exits.
- telemetry hook: closed stdin completes instantly rc=0; never-closing stdin bounded at 13s
  (pre-fix: unbounded — the direct probe `timeout 10 cat` kills at exactly 10s, rc=124).
- halt-gate: `0.0.0_AB_MSTR~Zn` and `9.9.9_XX_Nobody` both rc=3 with a banner naming the serial;

- risk-reflex citations read before commit; neither recorded constraint (ferry recipient-scoping,

## Assumptions

- The 1800s/600s defaults are generous against measured runtimes (full rebuild ~6min per
  _canonical's own record); env-overridable if a legitimate longer run appears.
- The single-uppercase-letter lane-suffix rule reflects every lane the fabric has ever used
  (~A..~E, ~Z). If a multi-char lane is ever legitimized, `halt_gate_validate_serial` must be
  amended in the same change.

## Downstream agents affected

Every agent that runs comp-kuzu rebuilds, the PostToolUse telemetry hook (all sessions), or the
halt gate (all push/deploy paths). Behavior change is confined to pathological states (hung
rebuild, unclosed hook stdin, corrupted serial file); healthy paths are byte-identical except for
the added guards.
