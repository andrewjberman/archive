# LD-0619 -- nine audit rows restored from the archive snapshot; the d12-sms deploy entry closed with V3 moved

## Decision
1. `org/law-edit-audit.log` (2 rows), `org/mass-deletion-audit.log` (3 rows) and `org/safe-deploy-bypass-audit.log`
   (4 rows) regain the rows that were absent from the live files and present only in
   `org/audit/archive/laptop/2026-10-07T060238Z/`. The three logs are committed so a later tree operation cannot
   drop their uncommitted rows again.
2. Deploy ledger entry `d12-sms-tfn-registration-and-production-access` is CLOSED. Its one open leg, V3, is the same
   act as leg SP-3 of `d12-sms-origination-identity-activation`, which stays open there.

## Provenance chain (Art. XIII)
- Finding: `0.7.0_AE_CloudOps~I` msg 106560 (9 rows, classified by timestamp, none committed in any ref).
- Ruling: `1.0.0_SA_CTO` msg 106569 ("restore those 9 from that snapshot, as the precedent @871da68fbb did, and
  commit the logs") and msg 106538 ("close the d12-sms entry with leg V3 moved to the sibling entry that already
  holds SP-3").
- Precedent: commit 871da68fbb (`0.0.0_AB_MSTR~Z`).

## Why now
The archive snapshot was the only copy of the nine rows. The deploy entry read PAST-WINDOW in every fabric-check for
a leg another entry owns.

## Cause of the loss (claim: inferred, not measured)
At 2026-10-07 15:25Z a landing script of `0.0.0_AB_MSTR` left a conflicted merge of `origin/CLOUD` open in the
shared laptop tree; it was cleared with `safe-merge.sh --abort`, which restores every path in the merge set. Audit
logs are tracked files that hooks append to without committing, so uncommitted rows in a log that origin had also
changed would be discarded by that restore. The landing scripts since then never merge in the shared tree.

## Rollback
`git revert` of the commit that carries this entry removes the nine rows again; the archive snapshot is unchanged.
Re-opening the deploy entry is `deploy_ledger.py open` with the same six legs.
