# LD-0405 -- THE REPOS ARE DEVICE-AGNOSTIC. Device-specific logic is finely scoped and rare.

## The ruling -- two deliveries, the second WIDENING the first

**(1)** > *"Yeah some of these foundational tools cannot be 'Claimed' to a specific local device,
> needs to be operational across devices."*

**(2)** > *"really the entire ajb_workspace/portal repos cannot be 'device-specific', any
> device-specific logic needs to be very finely scoped and rare"*

Delivery (1) was scoped to **foundational tools**. Delivery (2) widens it to **both repos in their
entirety**. The wider form binds. *(Recording the narrow form too, because the narrowing is exactly
how a rule like this decays: an agent who remembers only "foundational tools" will read a
device-specific portal component or data script as out of scope.)*

## What it establishes

1. **DEVICE-AGNOSTIC IS THE DEFAULT** across `ajb_workspace` and `portal`. Device-specific logic is
   an exception that must be **finely scoped and rare** -- not a style preference, a default.
2. **A CLAIM IS A COORDINATION SIGNAL, NEVER DEVICE OWNERSHIP.** The CLAIM protocol (LD-0343 A3)
   still coordinates *who edits next*; it does not make a file one device's property, and it cannot
   scope a foundational tool's behavior to one machine.
3. **A FIX THAT WORKS ON ONE DEVICE AND LEAVES THE OTHER BROKEN IS NOT A FIX.** Cross-device
   operability is part of the acceptance bar for a shared tool, not a follow-up.

## Mechanism -- what "device-specific" concretely means, and the pattern that is already right

**VIOLATIONS:** a hardcoded user path (`C:\Users\AndrewBerman\...`); a baked drive prefix (`/c/` vs
`/cygdrive/c/`); a hardcoded workspace root; device-keyed branching outside an identity resolver;
behavior that silently no-ops on the other machine.

**THE CORRECT PATTERN, already exercised in-estate:** *derive, do not hardcode.*
- workspace root -> `git rev-parse --show-toplevel` (never a baked path; the two checkouts live
  under different profiles and one contains a space)
- drive prefix -> `test -d /cygdrive/c && echo /cygdrive/c || echo /c`
- `ajb.ps1` -> `OPAL_WS_ROOT` with a derived-root fallback, exercised 3 ways (LD-0344)

**THE NARROW LEGITIMATE EXCEPTION -- "finely scoped and rare" made testable:** code whose *job* is
resolving device identity. `agentbus-sqs.sh device` resolves laptop-vs-sitez **by workspace path**
and refuses the wrong device; the per-device queue names are inherently two-sided by design. That
is device-AWARE and correct. **The test: is being device-specific this code's PURPOSE, or an
accident of where it was written?** Only the first qualifies.

## Why this is a real hazard here, not a hygiene preference

The estate has already paid for it. **LD-0340 class, 2026-07-29:** `~/bin` forwarders were
generated while a non-durable `/c` mount was live, so all 186 baked `/c/` into themselves; the
mount died at reboot and killed every one of them **at once**, while the startup PATH probe still
read 100% healthy. **A NON-DURABLE, DEVICE-LOCAL FIX THAT GENERATES DURABLE ARTIFACTS PROPAGATES ITS
OWN EXPIRY INTO THEM.** The same day, a hardcoded `/c/` in the watcher skill doc killed the inbox
Monitor arm for two seats on one fleet respawn -- **the doc was wrong, not the fabric.**

## Immediate application (this session)

The `risk-reflex` gate flagged `.tools/ajb.ps1` on the very commit carrying LD-0404, citing
**LD-0344:226 -- "Z had formally CLAIMED `.tools/ajb.ps1` on the trunk."** Reading the citation is
what surfaced this ruling. Two findings:
- That claim was **historical and correctly resolved**: site Z claimed it, then *handed it to base
  to land*. Landing shared-tool changes at base is the pattern, so there was **no live contention**.
- Under this ruling the framing is now explicit: **that was a coordination handoff, not device
  ownership**, and it must never be read as the latter.

## SCOPE -- ⛔ DIRECTION RATIFIED, REMEDIATION **NOT** AUTHORIZED BY THIS LINE

**This ruling does NOT authorize a sweep, a refactor, or a census.** Andrew stated a standing
default; he did not order a migration, and a crisp architectural line is exactly what a motivated
agent reads as licence to start rewriting paths across two repos.
- A non-conforming file is **not automatically a violation to fix now** -- surface it, do not chase it.
- **Deciding which tools are "foundational" is a Rule-24 taxonomy act** (MECE, same grain, intent
  coherence, stability frame) and needs its own authoring pass with an owner. It is **not minted here.**
- Portal is a separate repo on its own branch discipline (Rule 19); anything touching it routes to DT.
