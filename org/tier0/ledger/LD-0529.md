# LD-0529 - Tier-2 seats receive acts only as task orders: the broker refuses an act-bearing send without one

**His word.** Verbatim in `andrew_instruction_ref` and the record. "Mechanism works" answers item 2 of three; items 1 and
3 stay open.

**The incident that produced it (measured).** A Tier-2 seat (`0.8.0_AE_CloudComp`) received three act-bearing messages
from Tier-0/Tier-1 seats (93516 from this seat, 93527 and 93638 from `1.0.0_SA_CTO`) about the ms-heat lifecycle rule,
none a task order. It verified the premise itself and put an (a)/(b)/(c) question to Andrew at its terminal. The spine's
L6 neck was bypassed by MCP; the first link was this seat's relay.

**The mechanism.** `org/mcp/cvo_send_guard.py` today refuses `3.0.0_SA_CVO` -> Tier-2 sends while a project is
EXECUTING. Generalised: any Tier-0/Tier-1 -> Tier-2 send whose body carries an act is refused unless it cites a task
order id assigned to that recipient (the order's issuer dispatching it passes; an ack or act-free information passes).
The act/no-act reading and the order-citation form are `1.0.0_SA_CTO`'s to define at the build; the falsifier is fixed
here: 93516, 93527, 93638 REFUSE; a `2.0.0_SA_COO` dispatch citing its own order PASSES; a worker's ack PASSES.

**The item itself.** Routed to `2.0.0_SA_COO` for an L6 order with Andrew's 13:0xZ ruling as acceptance (msg 93650); no
seat addresses the worker directly again.

**Stakes.** S2: changes who may reach a worker and how; reversible by reverting the guard commit. **Rollback plan.**
`git revert` of the guard commit; this entry closed with the reason.

**Files or paths touched.** The record above; this entry. The guard lands under `1.0.0_SA_CTO`.
