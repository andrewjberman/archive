# LD-0075 — Scribe /mstr-kill SKILL.md (tiered-fallback kill chain)

## Decision

Per Andrew direct 2026-05-26T~01:25Z + LD-0069 MSTR thin-architecture materialization: scribe `.claude/skills/mstr-kill/SKILL.md` instituting a tiered-fallback kill mechanism that handles both MSTR-spawned (marker-tracked) and Andrew-launched (no marker) sessions through one canonical channel.

## Empirical grounding

Today's 2026-05-26T~01:20Z attempt to kill 2.0.0_SA_COO via `kill-agent.ps1` returned "nothing to kill" — Andrew had launched the session manually so no `# OPAL_SPAWN_MARKER_v1` CommandLine tag existed for the script to grep. Pre-LD-0075, MSTR's response was to surface the gap and ask Andrew for per-instance authorization on a force-kill by PID. That works but doesn't scale — every Andrew-launched session that ever needs killing requires a manual authorization turn.

The /mstr-kill skill solves this structurally: the invocation IS the authorization within skill body. Same pattern as /mstr-charter's blanket TIER0_LAW authorization within its body.

## Why a skill body authorization (not always Andrew per-instance)

CLAUDE.md / LD-0027 default: force-kill by PID is destructive-without-marker-audit class; requires Andrew per-instance authorization OR LD-charter. /mstr-kill is the LD-charter half of that "OR" — Andrew's blanket pre-authorization that within this skill's invocation, MSTR may force-kill the named serial without a separate per-instance turn.

Bounds:
- **Per-invocation scope:** one /mstr-kill = one kill of one serial. A second kill same turn = a second invocation.
- **Outside the skill:** default discipline holds — force-kill via raw PowerShell still requires explicit Andrew per-instance auth or new LD-charter.
- **Audit invariant:** every force-kill writes a FORCE-KILL line (distinct verb from kill-agent.ps1's KILL) with `authorized-via=/mstr-kill` token to org/mcp/agent-spawn-audit.log. Forensic trail preserved regardless of authorization channel.
