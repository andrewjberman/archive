# LD-0275 -- The shared-working-tree sweep class, recorded on the number the class produced

## THE ENTRY IS THE INCIDENT

This file was born a truncated stub at 04:25Z -- a false start on the commit-message finding that became
LD-0276 -- and left untracked in a working tree that `0.0.0_AB_MSTR`, `1.0.0_SA_CTO`, `2.0.0_SA_COO` and
`3.0.0_SA_CVO` all stage into. Its author then verified "all my ledgers are on origin" by **listing the
numbers he remembered** -- `0271 / 0272 / 0273 / 0274 / 0276` -- five where six belong, the missing one
between two present ones. **A gap in an enumeration reads as a complete enumeration.** COO recovered it by
iterating the SEQUENCE mechanically with an impossible-ledger control (`LD-9999 -> absent`; the predicate can
say no). The record of the sweep class is itself an artifact the sweep class nearly consumed.

## THE CLASS

All ws Tier-0/1 agents share **one working tree and one index.** A dirty file left in it -- a law file, a
ledger, a project JSON, a skill -- is swept into whatever commit runs next, under that agent's author line
and subject, silently, with `rc=0`. `safe-commit`'s pathspec scoping protects *other* files from a *given*
commit, but it does not protect a *dirty file* from being *named* by the next pathspec or a bare `git add`.

**Four instances in ~90 minutes, one root:**

| # | dirty artifact | swept into | by | result |
|---|---|---|---|---|
| 1 | the CLAUDE.md F-010 rule | `6161484aa` "…RULE LANDED" | MSTR | message claimed a file its stat omitted (F-011) |
| 2 | the same CLAUDE.md rule | `22a150bdb` "probe: not a real commit" | COO | swept, blocked, reset, unpushed |
| 3 | the same CLAUDE.md rule | `6d14f2d15` "test subject" | CTO | swept, PUSHED, and this is how the law landed -- wrong author, junk subject |
| 4 | **this file, LD-0275** | (not yet) | -- | orphaned untracked; absence read as completeness |

**F-011 -- a commit message is an unverified self-report about its own commit -- is a symptom. The shared
tree is the disease.** Nothing in the pipeline compares a message's filename claims to the commit's stat, and
nothing warns when a commit captures a file the caller's session never wrote. COO's dual F-011 remedy, routed
to CTO: (a) warn when the message NAMES a file absent from the stat; (b) warn when the stat CONTAINS a file
the session never wrote. The first catches a false claim; the second catches a silent capture. Both are
patches on a hazard the architecture creates.

## THE NON-COUNT

A sweep under a plausible subject leaves no scar (LD-0276 A2: a census of scars cannot bound a population of
injections). "Test subject" and "probe: not a real commit" are visible because they are odd; a sweep under a
normal-looking subject would not be. **The four instances are a lower bound, not a total.** Do not quote 4.

## THE ARCHITECTURE QUESTION -- ANDREW'S, NOT OURS

**Per-agent worktrees would end this class outright** -- each agent stages into its own index, and no dirty
file of one agent is reachable by another's pathspec. But it changes how *every* commit, hook, gate and
path-scoped rule in the fabric addresses paths, and it interacts with the owned-paths lane model and the
`safe-*` wrappers. That is a sovereign architecture call. **MSTR surfaces it; MSTR does not resolve it**, and
records it as the fifth structural finding tonight that reduced to a single root. `org/XXX.md` Step 1a already
warns that a lingering shared CWD "silently substitutes the WRONG repo's git history into evidence pulls" --
this is the same hazard on the index rather than the CWD, and it has now fired four times in one session.

## DISCIPLINE BANKED

- **Iterate the range, never the remembered members.** The denominator of a ledger sweep is the SEQUENCE
  (`0271..0276`), not the set of files you thought to check. MSTR applied the denominator rule to CLAUDE.md
  (checked origin) and then omitted it from the very ledger-enumeration that was checking for omissions.
- **An unlanded file does not get safer by waiting** (COO). Holding git operations protects history; the
  working tree is where the sweep happens. This file was landed pathspec-scoped, diffstat-verified, and
  confirmed on origin -- not on `rc=0`.
