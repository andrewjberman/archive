# LD-0216 — /teams-assist: prompt-with-options + incoming-only (Andrew-direct)

Andrew-direct ad-hoc instruction (2026-06-26, in MSTR session) to adjust the `/teams-assist`
operator-intake skill. Two changes, both shipped in one commit:

1. **Prompt-with-options (SKILL.md).** The skill no longer auto-starts work off a Teams message.
   On each incoming message it reads the message and presents the operator a handling menu
   (`AskUserQuestion`): **start now** (`/goal-set`) · **refine-then-start** · **draft a reply for
   review** (in-session, posting stays write-gated/out-of-scope) · **note only**. The operator's
   selection is the sole authorization to act. The untrusted-content safety doctrine is preserved
   and tightened — there is now no auto-start path either, only an operator-pick path.

2. **Incoming-only (teams-watch.py engine).** A new `is_outgoing()` filter drops the operator's own
   outgoing messages before they become an agent ping — keyed on an explicit gateway from-me flag
   if present, else a sender-vs-`sub` identity match across the plausible sender fields. Fail-open
   (no usable sender-id ⇒ treated as incoming, never silently drop a real ask) with a one-shot
   stderr schema note. The cursor still advances past a dropped outgoing message.

**Authority:** Andrew-direct (Art. I) — overrides the Art. VI govern-through-Tier-1 posture for this
specific operator-tooling edit. `teams-watch.py` is 0.5.0_AE-owned; edited under the direct
instruction with owner-notification + a request to confirm the authoritative
`poll_addressed_teams_messages` sender field so the filter keys on it rather than the best-effort
fallback. S1, reversible (single git revert), no external/pipeline surface.
