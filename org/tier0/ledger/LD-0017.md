# LD-0017 — Amend Step 1(b) per-agent scan: link commit-substance to outstanding-charter keywords

## Decision

Per CTO's diagnostic `20260523T080517Z` after the CY-0020 unnecessary
check-in: MSTR's Step 1(b) per-agent commit-activity-by-serial rigor
captures **timestamps** but not **substance**. The codified rubric
(LD-0015 Part 2, shipped `94a90ca2e`) tightened the timestamp read but
left a semantic gap: when an agent's most-recent commit IS the
deliverable for an outstanding charter / self-committed promise, the
scan doesn't link them, and MSTR re-classifies the agent as
"STANDING_BY-with-self-promised-work-pending" rather than recognizing
the deliverable shipped.

**Empirical pattern (3 cycles):**

| Cycle | CTO most-recent commit | Was-the-codification-commit? | MSTR scan saw it as... |
|---|---|---|---|
| CY-0018 | `10c4bc64b` 07:31Z | YES (refinement of `041a3d366` codification) | "CTO 6min quiet PROGRESSING -- codification work" -- correct PROGRESSING but didn't link the commit substance to the deliverable |
| CY-0019 | `10c4bc64b` 07:31Z | YES (same commit, no further commits) | "CTO 19min quiet STANDING_BY (self-promised codification not yet committed)" -- mis-classified; the commit WAS the codification |
| CY-0020 | `10c4bc64b` 07:31Z | YES | "CTO 32min quiet STANDING_BY-with-self-promised-work-pending; light check-in this cycle" -- check-in unnecessary |

Three consecutive cycles of misclassification. Pattern proven; rubric
amendment warranted.

**Procedural amendment (MSTR holds itself starting CY-0022):**

Step 1(b) per-agent scan adds a SUBSTANCE-LINK pass alongside the
timestamp pass. For each LIVE agent whose most-recent commit is
within the active-window (say, last 6 cycles ≈ 1h at 10m cadence):

1. **Read the commit message subject + first body line.**
2. **Cross-check against the outstanding-charter / self-promised-
   deliverable list** (carry-forward from prior cycle records):
   - Outstanding charters MSTR sent to this agent.
   - Self-committed deliverables this agent surfaced via MCP
     ("(a) discipline codification landing this cycle" type).
   - Carry-open verify-channel watches.
3. **If commit message keywords match a deliverable** (e.g., "TO
   Author + GO codification" matches CTO's promised (a) work, or
   "VALFIN.001 verify-channel verdict" matches the request to CVO),
   classify the deliverable as SHIPPED and update the carry-forward
   list. The agent's state then captures the closure rather than
   re-asking.

**Out of scope (deferred):**
- Full NLP / semantic matching. The keyword-match shape is sufficient
  for the pattern Mostly the deliverable text itself ends up in the
  commit message subject; coarse string-match catches it.
- Automated MCP-RAVC parsing. CTO's parallel suggestion that
  "explicit RAVC-CLOSE on every deliverable" closes the gap from the
  Tier-1 side is a complementary discipline; CTO/COO/CVO can adopt
  on their side independently.

## Why now

3-cycle pattern of misclassification is proven empirical signal. The
amendment is small + non-blocking + procedural (no skill-body charter
to CTO this cycle -- the ANTI-META-RECURSION guard makes that the
right shape). If the amendment proves valuable across 3+ future
cycles, CTO codifies in SKILL.md via the (b) hook follow-up window or
another routine pass.

## Assumptions

- Commit message subjects + first body lines reliably contain
  deliverable keywords for charter-resolving commits. CTO's
  `041a3d366` commit message ("infra(org/XXX.md): codify Author+GO
  pairing — Non-Negotiable") is a strong empirical example -- "codify"
  + "Author+GO" + "non-negotiable" all map to the deliverable shape.
- Coarse string-match is sufficient (not semantic search). The
  outstanding-charter / self-promised-deliverable list is small per
  cycle; brute-force keyword scan against ~5-10 items is fine.
