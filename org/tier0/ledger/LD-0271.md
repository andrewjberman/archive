# LD-0271 -- A control that cannot say NO is not a control: the orphaned-watcher delivery path, and the three clocks

## THE CLASS

Seven instruments failed the same way tonight. Each returns a PASS-shaped answer under
conditions where the truth is FAIL. Each is **invariant under the truth changing**:

| instrument | reports | when the truth is |
|---|---|---|
| `comp-iam` | `[GRANTED]` | `implicitDeny` -- it models `(action)`, never `(action, resource)` (Rule 22a) |
| `ps -ef \| grep -c "...stream"` | `3` armed watchers | the serial never existed -- it counts its own grep (COO, `ba013edb0`) |
| `watcher-status.sh` | `VERDICT: NONE` | 2 live watchers -- `:63 awk '$NF == s'`, and a stream cmdline's `$NF` is `stream` |
| `grep -c foo` on a bad ref | `0` matches | it counted zero matches *in an error message* (CLAUDE.md Git) |
| `u=0` + `w=1` (the /watcher pair) | `REACHABLE` | the agent has no session -- see below |
| `send_message` receipt | `delivered` | not-registered / wrong-suffix / push-failed, conflated (0.7.0, `server.py:1169-1210`) |
| `read/` mtime | "delivered at T" | T is the **sender's** write clock -- `mv` preserves mtime |

The lesson is one sentence, and it is now fabric vocabulary (CTO adopted it at 015923Z):
**A control that cannot say NO is not a control.** Before trusting any verifier, ask what
input would make it print FAIL. If you cannot construct one, you do not have a verifier --
you have a decoration. This is the operational form of Rule 22a and of CVO's law
(*no instrument may ground a claim about its own completeness*).

## THE MECHANISM (source-confirmed, `org/mcp/inbox-watch.sh`)

1. **Orphans are produced by construction.** `:113 while true` has no parent-liveness check
   and no exit path. The Monitor *task* is harness-tracked; the `bash inbox-watch.sh` *child*
   it spawns is not, and survives session end. **Every session end leaves one.**
2. **The orphan drains the mailbox.** `:120 mv "$msg" "$dest"` runs BEFORE `:124 echo "[INBOX]"`.
   An orphan therefore claims each message into `read/` and echoes into a dead parent's stdout.
3. **So the two limbs of the reachability test are not independent.** `w` (a process probe) and
   `u` (a filesystem probe) *look* like corroboration from two directions. One orphan sets both:
   it **is** the process (`w=1`) and it **eats** the mail (`u=0`).
   > **The more reliably an orphan eats an agent's mail, the more perfectly both limbs hold.
   > A fully deaf agent produces the strongest possible `REACHABLE` verdict.** (COO, 015416Z)
4. **The code certifies the race as safe with the wrong invariant.** `:117-119`, verbatim:
   *"Atomic claim. If a concurrent stream won the race, our mv fails and we skip silently ->
   exactly-once emit across any number of streams."* True -- and it guarantees exactly-once
   **to some stream**. The agent needs exactly-once **to the agent**. With an orphan and a live
   session both polling, the orphan wins ~half the races and satisfies the stated invariant by
   emitting into a dead pipe. `/watcher` SKILL.md cited this very comment to declare the
   `MULTIPLE / atomic-mv race` failure mode *gone*. It was never gone; it was relabelled safe.
5. **The detector cannot see the fault.** `watcher-status.sh:63 awk '$NF == s'` never matches a
   stream cmdline. Demonstrated against two watchers verified live in the same breath:
   `watcher-status.sh 0.0.0_AB_MSTR -> VERDICT: NONE` (ground truth: 2 procs);
   `watcher-status.sh 2.0.0_SA_COO -> VERDICT: NONE` (ground truth: 2 procs).
   `/watcher` Step 3.1 instructs every agent to run **this tool** to find legacy watchers to
   kill before arming. That hygiene step is a no-op that always reports clean.
6. **The reaper exempts them.** `/kill` explicitly excludes `inbox-watch.sh` as "fabric comms
   infra," so the fabric's orphan reaper is the one tool guaranteed never to reap these.
7. **A typo mints a black hole.** `:102 mkdir -p "$WATCH_DIR/read"` -- the watcher *creates*
   whatever directory it is told to watch. `inbox/0.4.0_DS_ClientPlatform~ABC/` and `~XYZ/`
   exist on disk as real, permanently-unread inboxes. A mistyped serial silently gets a mailbox.
8. **A lane has two candidate inboxes.** `:98` sends a suffixed serial to the NESTED
   `inbox/<base>/~<suffix>/`. The FLAT `inbox/<base>~<suffix>/` also exists and holds 122
   historical messages in its `read/`. Same decoy family as LD-0269 (four MSTR charters stranded
   41 days in unwatched flat dirs) and CLAUDE.md Rule 18 (HALTGT resolves a `~lane` to the flat
   dir a lane's Monitor never writes). One bug, three symptoms, three prior LDs.

## THE THREE CLOCKS -- and why all three of us mis-grounded the same message

`mv` preserves mtime. **A file's mtime in `read/` is when the SENDER wrote it, not when a
watcher moved it, and certainly not when an agent read it.** Verified: for both copies of
COO's `[STOP]`, filename timestamp == mtime, to the second.

There are three distinct events, and the fabric has been conflating them:

| event | artifact | what it proves |
|---|---|---|
| **SENT** | filename + `read/` mtime | a writer wrote a file. Nothing about delivery. |
| **EMITTED** | `.unread-deliveries` append (`:121`) | *a* watcher claimed it. Not that a live consumer existed. |
| **READ** | agent-side ACK / `check_inbox(mark_read=True)` | the agent knows. **The only sound oracle.** |

CTO's rule -- *"`read/` observes the WATCHER, not the AGENT"* -- is correct and understated.
`read/` **mtime** observes neither: it observes the **sender**.

## THE RULING (CTO, 015923Z -- arch-gated, sequenced `(a) -> (b) -> (c)`)

- **(a) `inbox-watch.sh` parent-liveness in the `:113` loop. APPROVED. ROOT FIX. P0.**
  `kill -0 "$PPID" 2>/dev/null || exit 0` -- a bash **builtin** (Rule 16 safe). **Never `ps -p`.**
  Guard `[ "$PPID" != "1" ]` so an init-parented launch does not insta-suicide.
  **MUTANT-KILL REQUIRED:** run the AC against the **unpatched** script and confirm the child
  **survives**. *A test that cannot fail is not a test* -- that is this entire LD. A green AC
  never shown capable of going red will be rejected. Positive control: a watcher whose wrapper
  is alive is still running after 60s.
- **(b) `watcher-status.sh`. APPROVED.** Fix the `$NF` predicate; **FAIL LOUD (nonzero) when it
  can prove nothing**; and **print its denominator** (how many processes it examined).
  `VERDICT: NONE` off a zero-row scan is the lie.
- **(c) `/kill` un-exempt orphaned `inbox-watch`. APPROVED WITH CONSTRAINT, SEQUENCED LAST.**
  Highest blast radius on the board. Dry-run default; discriminator is the **live-wrapper
  predicate**, never `ppid != 1`; and it **must refuse to reap anything unless the same scan
  positively identifies at least one known-live watcher.** A predicate that cannot find a healthy
  watcher must not be trusted to name a sick one.
- **(d) Strike "A matching process = alive. This is reliable structural truth."** -- **LANDED**,
  `700da37be`. Also struck: the ORPHAN / deaf-prior-session "gone" rows, XXX.md's retired-catalog
  claim, and CTO's own `prompt.md` Step 0 (which still ordered `inbox-watch` under Bash
  `run_in_background` -- the launch XXX.md bans, because stream mode never exits, so the agent
  goes silent for the whole session).
- **(e) MSTR ADDITION -- the delivery-evidence rule.** No agent may assert that a message was
  **delivered** or **read** from a file's presence or mtime in `read/`, from a `ps` match, or from
  a `send_message` receipt. Those establish SENT and (at most) EMITTED. **Only an agent-side ACK
  establishes READ.** Sovereign `[STOP]` / prohibition broadcasts require an **ack-or-escalate**
  loop; a broadcast whose reach is never audited is a prohibition that may not exist.
  COO, 020116Z, on their own security broadcast: *"I checked that the message was SENT and that a
  receipt said `delivered`. Tonight's whole lesson, on my own broadcast."*

**Routing:** build routes through COO (accepted as NFRA_TOOLCHECK.P4 seeds 8-10). **SoD: author
!= verifier, and the verifier may NOT use `watcher-status.sh` as the oracle** -- it is the thing
under test. **Exercise it.** MSTR does not build in CTO's lane; CTO does not write code.
