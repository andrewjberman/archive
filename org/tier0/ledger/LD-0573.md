## The four-point delta, as built

| # | point | where |
|---|---|---|
| 1 | mint ONLY on MFA success, never on password-only login | `auth.ts verifyMfa()` -- sole call site of `mintDeviceTrust()` |
| 2 | a SECOND independent cookie, 30d, HttpOnly Secure SameSite=Strict, opaque, server row for revocation | `index.ts createDeviceTrustCookie()`; row `mfa#dev#<sha256(token)>` in `opal-portal-auth-mfa` |
| 3 | read at login; valid + unexpired + THIS user + current generation -> skip the challenge | `auth.ts login()` inside the MFA gate; `deviceTrust.ts checkDeviceTrust()` |
| 4 | `/auth/logout` must NOT clear it | `index.ts` -- unchanged behaviour, comment explains why it must stay unchanged |

Revocation (**"revocable by sign-out-everywhere"**): `POST /auth/logout-everywhere` (authenticated; the
account comes from the session, never a body) -> `revokeAllDeviceTrust()` bumps the account's generation
-> every older row fails `checkDeviceTrust()` on its next presentation and is deleted then, or reaped by
its own `ttl`. Also invoked by `adminDeleteUser` and `adminForcePasswordReset`.

## Design choices that were not free, stated so they can be overruled

- **Generation counter, not row enumeration.** Forced by the table's IAM (`Get/Put/Update/Delete`, no
  `Query`) and the absence of a GSI. Costs one tiny non-expiring row per account that has ever revoked;
  buys O(1) revocation with no Terraform change. The generation row has NO ttl on purpose -- if it could
  expire inside a device row's 30-day life, a revoked device would resurrect against a re-zeroed counter.
- **Fixed window, not sliding.** A trusted login does not re-mint. His framing was "once a month"; a
  sliding window would let a daily-used device skip the second factor forever.
- **Bound to `refreshBinding(user)`, not the email.** The OP-s-11 / F-10 lesson applied: a
  deleted-and-re-created account on the same address gets a new binding and inherits no trust.
- **Token hashed as the key; the token itself is never stored.** A reader of the table cannot mint the
  cookie -- a stronger posture than the challenge rows, whose six-digit codes fall to brute force.
- **Fails toward the challenge.** `checkDeviceTrust()` returns false on absent, expired, foreign,
  revoked, malformed, and on any storage error. The worst outcome is a code the user would have skipped.
