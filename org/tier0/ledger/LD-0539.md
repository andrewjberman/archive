# LD-0539 - One commit across the fabric boundary, under a hold, because the defect was live

## Decision

Import `6228c53377` alone onto CLOUD by cherry-pick. Keep the `/integrate` merge held.

## Why this could not wait for the merge

`1.0.0_SA_CTO` raised it at msg 95105 as CURRENT rather than historical. Three ETFS workers were
live in linked worktrees on this fabric and `2.0.0_SA_COO~A` was cutting a STORED_IN retirement
cell whose entire purpose is a census.

Before the fix, `comp-find` / `comp-read` / `comp-pulse` invoked from a LINKED WORKTREE resolved
their corpus from the TOOL'S INSTALL LOCATION rather than the caller's, so they scanned the MAIN
TREE and returned a well-formed zero carrying a real denominator. Nothing in the output names the
tree it read.

That is the worst member of the comp-find false-zero family. The other three announce themselves
in the SCANNED count; this one does not, because the denominator is genuine, it simply belongs to
another tree.

## What was measured, and by which instrument

| arm | invocation | result |
|---|---|---|
| 1 | picked `comp-find`, run from the linked worktree | 1 hit across 31,372 files |
| 2 | main-tree unfixed `comp-find`, run from the SAME cwd | 182 hits across 157,988 files |

Arm 2 is the defect reproducing on demand: it answered with the main tree's hits while the caller
stood in the worktree. The denominator moving is the discriminator.

The defect was confirmed in THIS tree before acting rather than inherited from the reporting seat:
`.tools/_comprail.py` held `repo_root()` at line 125 and no `corpus_root()` at all.

## What was deliberately not taken

`org/modules/graph/INSTRUMENT_LIMITS.md` conflicted modify/delete. It is NOT a file this fabric
retired. `git log --full-history` returns ZERO for it on CLOUD, so it has only ever existed on the
SITEZ line. Taking it would have imported site Z's whole file including every earlier site-Z edit,
which is wider than the single commit authorized. It arrives with the full merge.

Consequence stated rather than left to be discovered: this fabric now holds the FIX without its
LIMIT 4 documentation.

## Rollback

`git revert` the pick. The fabric returns to the pre-existing defect, which is the state every
other seat was already operating under, so the rollback is safe rather than merely available.

## What this does not do

It does not lift the hold, import `c1a0077dd7` or `ae556f5712`, or make dispatch safe. A CLOUD-side
lane still reads the wrong worker spawn instruction until the merge runs.
