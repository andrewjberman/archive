# LD-0208 — comp-which routing audit: router reaches ~8 of 36 tools (Andrew-commissioned)

## Decision
Record the Andrew-commissioned comp-which / comp-tool-registry audit and charter the
fix to CTO (rail owner). Flag it as a **prerequisite to the [[LD-0207]] gate-hardening
enforce-ramp.**

## Finding (Rule-22-grounded: source-read + 4 empirical comp-which runs)
The **registry tagging is GOOD** -- `graph-call-manifest.yaml` carries rich `use_case`
text + a `tools_index` for ~all 36 comp-* tools. The **ROUTER is broken**: `comp-which`
reliably routes ONLY the ~8 tools in its hardcoded curated rules (comp-pipescript,
pipescript, comp-transform, comp-routes, comp-iam, comp-aws, comp-blast, comp-cache).
The manifest-fuzzy backstop meant to make the whole catalog queryable is dead, two
compounding defects:
- **A (one-line):** `_manifest_matches` reads top-level `data.get("use_cases", [])`
  (`comp-which:142`); the manifest stores entries under **`entries:`** -> iterates an
  empty list, matches nothing, always.
- **B (flow order):** the backstop is only reached for no-term questions; the
  `comp-which:273` branch runs `comp-grep` on an extracted term first when no curated
  rule hits.

Empirically (2026-06-22): "is upstream data fresh" -> raw grep "upstream" (not
comp-freshness); "artifact invariants before upload" -> raw grep "invariants" (not
comp-validate); "component expose PII" -> misrouted to comp-transform (not comp-pii).
Control "what produces canonical_prices.parquet" -> comp-pipescript io (curated, works).

## Fix (CTO scopes; direction)
(A) `use_cases`->`entries` at `comp-which:142`. (B) consult `_manifest_matches` BEFORE
falling to run-the-primitive. (C) widen curated rules for the high-value long tail +
tighten the over-broad `portal/component` rule. (D) a **per-tool routing regression
guard** -- assert comp-which routes a representative question for EACH `tools_index`
tool to that tool (the standing "every tool is accessible" oracle Andrew asked for).

## Sequencing (the governance point)
LD-0207 hardens the rail to DENY raw grep + route to comp-which. That assumes
comp-which is a good router; it routes 8/36 today. Hardening the gate toward a router
that dead-ends ~28 tools funnels agents into grep-dumps/misroutes exactly when raw grep
is denied. **Fix comp-which routing BEFORE (or in the same batch as) the Gate-1/2
enforce.** Recommend folding it into the NFRA_COMPRAIL hardening TO as a prerequisite
leg; TO-5 telemetry (comp-which-rail.log RUN-GREP vs ROUTE rate) is the before/after.

## Anchor
Full audit + the decision-flow trace + the fix detail: `docs/briefs/comp-which-routing-audit-20260622.md`.

## Rollback
The fix is additive + reversible (revert the comp-which edits). This LD is a finding
record; it changes no behavior itself.
