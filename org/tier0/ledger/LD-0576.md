# LD-0576 - /daily-sprint stitch: targeted edits off the finished copy

## His words

> "I also want to create an additional function of /daily-sprint , where it'll be "/daily-sprint stitch", the
> premise is that the automatic process will run, but i may want to add some targeted little updates without
> changing the shape of the thing as a whole, maybe it'll be an additional sprint, maybe it'll be changing out a
> diagram with a screenshot, maybe it'll be some adjustment of the headline copy, etc. I want to be able to have
> you adjust these off the finished copy, rather than having to regenerate it all again from scratch. Let's get
> that set up." (at this terminal, ~18:1xZ 2026-09-16)

## The design, and why it is this small

- **The finished copy is the served page.** The cloud run keeps no JSON; its report lives only in the `const
  DATA=` block of the published HTML. `pull` reads the served Desktop page from S3 and extracts that block into the
  canonical data file (`daily_reports/data/DAILY_REPORT_<DAY>.json`) and a base snapshot
  (`data/stitch/DAILY_REPORT_<DAY>.base.json`). A differing local edition is replaced and named; git keeps it.
- **The edit is the agent's, by hand, minimal.** A headline sentence, a chip, an added sprint item, a diagram
  swapped for a captured screenshot. No model call: the point is to keep what the automatic run wrote.
- **`diff`** prints every leaf that moved and the shape before/after (sprint categories, row counts, headline), so
  the operator reads the change against what was asked.
- **`apply`** refuses an empty diff and any move on `date`, `display_date` or `team_activity` (derived or
  census-merged), stamps `source` with ` | stitched <UTC> by <serial>: <note>` (the footer prints it), then runs
  the existing renderer (schema, derived viz contract with its type half, directive coverage, screens) and the
  existing publisher (read-back), and appends a stitch log. `--dry-run` renders and prints the plan only.
- Nothing here renders, validates or publishes on its own -- a second path for any of those is the shadow
  pipeline this estate vetoes.
