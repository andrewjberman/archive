# LD-0296 — comp-system refreshes the whole system home, not just 06 (live metrics + managed regions)

Andrew's ask (verbatim in frontmatter): the compiler should refresh tool counts, state, and anything
that goes stale -- explicitly -- not just `06_current_state`. This closes the gap the NFRA_SYSTEM
follow-through report surfaced: the sibling docs carried their OWN copies of live numbers that drifted
independently and nothing caught them. The comp-tool suite counts had drifted badly -- the docs said
`37` in `tools_index` and `56` in the ledger; live is `55` and `72`.

## What changed

- **`compute_metrics()`** (new): the canonical live scalars, one home each, grounded against the ONE
  authoritative source or honestly UNKNOWN -- `tools_index_count` (manifest mapping length),
  `ledger_union_count` (tools+meta_tools in the coverage map), `recognizers_live`, `coevolution_pairs`,
  `cse_measures`, `graph_marker`. Rendered as a `Live metrics` table inside 06.
- **Managed-region refresher** (new): a doc opts a number in by wrapping it,
  `<!--cs:tools_index_count-->55<!--/cs-->`; `comp-system` rewrites only the marked span from the live
  metric. Bounded + non-fabricating: it never touches prose, and an UNKNOWN metric is REFUSED (the
  existing number is preserved and the drift reported) so it can never stamp UNKNOWN over a real count.
- **`--check`** now also fails stale (rc=2) when a managed-region span no longer equals the live metric
  -- the drift class the source fingerprint structurally cannot see (the docs are outputs, not sources).
- **Retrofitted** `03_comp_tools.md` (title + Counts), `00_synthesis.md`, `README.md` with markers; the
  compiler corrected 37->55 and 56->72 on the first run.

## Exercised

- `comp_system.py --self-test`: 7/7 -> **9/9** (metrics grounding + refresher-safety added).
- `org/modules/graph/tests/test_comp_system_metrics.py`: **14/14** -- proves the refresher CORRECTS a
  drifted fixture span, writes nothing on a report-only run, leaves surrounding prose untouched, refuses
  to overwrite a real number with UNKNOWN, reports an unknown metric name, and is idempotent.
- `comp-system --check` -> `SYSTEM CURRENT (06: ...; managed regions: 0 drifted)` rc=0 after the run.
