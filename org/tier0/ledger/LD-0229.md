# LD-0229 — Fractal granularity + stable cross-grain node/edge definitions (the program schema-stability contract) + the COMPUNIFY tool-grain calibration deliverable

Andrew-direct 2026-06-30 (surfaced to MSTR via the ~D thread). The DEPTH axis of the NFRA_COMP*
unification, elevated to a program invariant.

## The three axes of unification (one discipline: stable definitions, no fragmentation)

| Axis | Project | The unification |
|---|---|---|
| **Breadth** (across surfaces) | GRAPHUNI (LD-0228) | one graph spanning local/git/aws/ms/trino at one marker HEAD |
| **Depth** (across grains) | **this invariant** | one stable schema across grains (resource->script->function->statement; bucket->key->object), same entity at different depths joined by CONTAINS -- never re-typed |
| **Redundancy** (across tools) | COMPUNIFY (LD-0227) | one home per tool -- now ALSO calibrated to grain |

It is **fractal** (not merely hierarchical) because the contract is **scale-invariant**: `{stable node/
edge types + a declared grain/level attribute + CONTAINS/drilldown edges}` is the same discipline at
every depth.

## The invariant (the schema-stability contract)

1. **Granularity is a DECLARED, PARAMETERIZED dimension -- never ad-hoc re-typing.** A deeper dive ADDS
   instances within a FIXED type system + a `grain`/`level` value + CONTAINS edges. Adding a level
   (e.g. statement) = a new `level` value, NOT a new node type.
2. **Edge types defined once by SEMANTIC, stable across grain.** `CALLS` = fn->fn at any depth;
   `READS_S3`/`WRITES_S3` = the same producer/consumer relation whether the endpoint is a script or a
   function (disambiguate by node grain; the edge semantic is fixed). Never overload one type across
   two semantics; never split one semantic into per-depth ad-hoc types.
3. **The proven pattern (TSGRAPH, grounded at head):** `CONTAINS` 5411, `OWNED_BY` 5410, `HAS_FIELD`
   4269, `CONTAINS_DRILLDOWN` 241 -- coarse->fine expressed by stable edge types, node concept stable
   per level. The pipeline layer mirrors it: `Pipeline -CONTAINS-> Script -CONTAINS-> Function`, with
   `{tier in {ingestion,bronze,silver,gold}, pipeline in {bd,inf,cot,mdpf}}` (the §8 full-process scope).
4. **The structural bridge:** `EC2_INSTANCE -CONTAINS/RUNS-> PipelineScript` joins the infra sub-graph
   (Kuzu CloudNode) and the compute sub-graph (TraceGraph gold/pipeline functions) into ONE graph. The
   EC2 running the gold analytics and the scripts inside it are the same entity at two grains. This
   containment edge is how GRAPHUNI's D1 (complete coverage) + D2 (re-point) actually land.

## The governance coupling

**GRAPHUNI (substrate) POPULATES the stable definitions; COMPUNIFY (map) GOVERNS them.** The per-tool
`{surface|seam, granularity, concern, distinct_from}` home schema in `comp-coverage-map.yaml` is where
the grain dimension is declared + gate-checked, so non-redundancy AND grain-correctness are enforced
together.

## NEW COMPUNIFY deliverable (Andrew-direct): tool-grain CALIBRATION

Extend the existing flat `granularity` field to the **fractal/multi-level grain set**, then **audit
EVERY COMPUNIFY tool** so each is calibrated to the grain(s) it actually traverses -- e.g. comp-aws =
resource; comp-blast = function/call; comp-xref = symbol; comp-pipescript = script + IO; comp-platinum
= full-stack (spans grains via containment). A tool whose declared grain does not match what it
traverses (e.g. should-resolve-functions but only-sees-resources) is a calibration finding. This is the
depth-axis complement to the one-home invariant.
