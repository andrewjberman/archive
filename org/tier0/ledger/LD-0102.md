# LD-0102 — Tab-title fix via wt.exe --title (LD-0101 supersede)

## What broke

LD-0101 (`1a1290ac1`) enabled `suppressApplicationTitle: true` in Windows Terminal's user-local settings.json under `profiles.defaults`. Theory: WT would ignore tab-title OSC emits from `claude.exe`, leaving whatever PowerShell set at launch in place.

Empirical 2026-05-26T~15:13Z (Andrew screenshot + verbatim feedback): AE 0.7 spawned at ~15:11Z post-LD-0101, but tab title displayed as the full path `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe` instead of `0.7.0_AE_CloudOps`. Andrew direct: "IT SHOULD APPEAR AS 0.7.0_AE_CloudOps".

## Root cause

`Start-Process powershell -ArgumentList ...` launches PowerShell via PATH-resolved `powershell.exe` (full path expands to `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`). When Windows Terminal opens a new window for this process, the auto-detected profile matching may fail (the profile's `commandline` field uses `%SystemRoot%` env-var expansion which doesn't always match the literal resolved path).

With `suppressApplicationTitle: true` + no matching profile (so no `tabTitle` and no profile `name` to fall back to) + no application OSC honored, WT falls back to displaying the literal commandline path. Our OSC 0 + `$Host.UI.RawUI.WindowTitle` emit inside the spawned shell is IGNORED by WT (per the suppression flag).

Result: tab shows ugly commandline path instead of either claude.exe's task description OR our intended agent serial.

## The fix

Refactor `.tools/spawn-agent.ps1` line 191 area to use `wt.exe` Windows Terminal CLI when available:

```powershell
$wt = Get-Command wt.exe -ErrorAction SilentlyContinue
if ($wt) {
    $innerForWt = $inner -replace ';', '\;'   # wt action-separator escape
    & wt.exe -w new new-tab --title $Serial powershell.exe -NoProfile -NoExit -Command $innerForWt
} else {
    Start-Process powershell -ArgumentList '-NoProfile', '-NoExit', '-Command', $inner   # fallback
}
```

Key properties:
- `wt.exe -w new` creates a fresh Windows Terminal window (preserves one-window-per-agent UX).
- `new-tab --title <Serial>` tells WT the tab title at creation. WT-managed; not subject to OSC override mechanics for the initial render.
- `powershell.exe -NoProfile -NoExit -Command <inner>` runs the same PowerShell as before (no other behavior change).
- Semicolon-escape `;` → `\;` ensures wt.exe doesn't parse our PowerShell statements as wt CLI actions.
- Fallback `Start-Process` path retained for non-WT environments (legacy conhost, ssh remote, environments without Windows Terminal installed).

The OSC 0 + `$Host.UI.RawUI.WindowTitle` pair INSIDE `$inner` remains untouched as belt-and-suspenders fallback for the fallback path.
