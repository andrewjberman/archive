# LD-0458 -- The register learns KEY RE-MINTING. A declared reuse is legal; an undeclared one is still a breach.

## What was wrong, and it was the CHECKER

`comp-directives check` reported `PARTITION: D8 appear in BOTH views` as a violation.
Grounded at source, the both-views state is **deliberate and declared in prose**:

| | |
|---|---|
| retired D8 | "Philosophy + benchmark modal live-edit", SITEZ, `OPAL_INVPHL` -- cut 2026-08-20 `@f866c4cde2` |
| live D8 | "Model Portfolios Pipeline Fortification", `MDPF_COTREMEDIATION` -- `@a0394e34f4`, subject reads **"D8 RE-MINTED"**, Andrew-direct 2026-08-25 ~14:20Z |

**The register was right and the invariant had no concept of a re-minted key**, so it reported a
correct act as a failure.

## Why not simply renumber

**27 messages in a single day's traffic cite `D8`** -- `1.0.0_SA_CTO`'s `/self-drive` scope resolves
to `[D0 D1 D2 D3 D5 D8 D10]`, `2.0.0_SA_COO`'s dispatches hang off it, and a live P0
(`MDPF_COTREMEDIATION`) is tagged to it. Renumbering a directive mid-flight to quiet a checker
**inverts which artifact is authoritative**. The alternative -- accept a standing violation -- is
worse still: *a checker that always shows 1 violation is a checker nobody reads*, and the next real
partition break then arrives invisible.

## ⛔ THE TRAP THAT SHAPED THE IMPLEMENTATION

The obvious move -- hand-add a marker to `DIRECTIVES_RETIRED.yaml` -- **fails twice, silently**:

1. **The serializer is an ALLOWLIST.** `_emit_retired` writes only `frozen_row` and
   `retired_vintage.{cut_at, stances_as_of, row_sha256}`. **A field it does not know is DROPPED at
   the next `retire`.**
2. **The file is SEALED.** `emit_hash` is a sha256 over every line above it; a hand edit breaks the
   seal (and self-test 6 exists to prove it does).

> **A MARKER THE TOOL DOES NOT WRITE IS NOT A MARKER.** It would have satisfied the reviewer, passed
> the check that afternoon, and disappeared at the next emit with nothing reporting its removal --
> the protection-that-exists-only-as-a-description class, one layer down in the serializer.

So the change is in **three coupled places**, not one: the emitter persists the field, the check
consults it, and a new subcommand sets it so the seal stays machine-computed.

## Rule 24 four-postulate record -- AXIS: KEY LINEAGE

Domain: *what happened to a RETIRED row's KEY.*

- **(i) MECE** -- two values: **not reused** (field absent) and **reused** (field present with
  `at` / `by_commit` / `note`). Mutually exclusive by presence; collectively exhaustive over the
  declared domain -- a retired key has either been re-issued or it has not. Hunted the uncovered
  member: *a key re-issued and then retired AGAIN* is covered, because the second retirement
  re-freezes the row and the marker describes the prior reuse.
- **(ii) SAME GRAIN** -- both values sit at the **KEY** level, not the row level and not the
  directive level. The field answers only "was this identifier re-issued," never anything about
  either directive's content.
- **(iii) INTENT COHERENCE** -- one intent: **key lineage**. It does not encode retirement state
  (that is `retired_vintage`), nor content (that is `frozen_row`), nor disposition.
- **(iv) STATE COHERENCE** -- **both views move together on a re-mint**, per the ruling: one act
  (a re-mint) writes the live row and marks the retired row, and one remedy (`mark-reused`) moves
  both into a consistent state. The values do not drift apart independently.

## What landed

- `_emit_retired` emits `key_reused_on` **when present** -- so it survives every future emit.
- `check()` PARTITION exempts a both-views key **only** when the retired row declares it, and
  **PRINTS the exemption** (`KEY-LINEAGE: D8 re-minted (declared)`). An exemption nobody can see is
  how a real breach later hides behind an old marker.
- **`comp-directives mark-reused <Dn> <note> [<by_commit>]`** -- refuses a key not in the retired
  view, and refuses a key that is not LIVE (*a key that is not re-issued is not re-minted*; the
  marker must not assert a re-mint that has not happened).

## Exercised -- both arms plus the guard

```
CONTROL  unmarked D8            -> 1 violation   PARTITION: D8 appear in BOTH views
GUARD    mark-reused D11        -> rc 2 REFUSED  (live, but not in the retired view)
MARKED   mark-reused D8         -> rc 0, retired view re-emitted and re-sealed
AFTER    check                  -> 0 violations, exemption printed
SEAL     --self-test            -> 10/10, incl. mutant 6 (hand edit must fail the seal)
```

The control arm is the load-bearing one: it proves the patch did not blanket-exempt every
both-views key, which is the way this change could have passed review while removing the invariant.

## ⛔ A SEPARATE FINDING, NOT FIXED HERE

`_load_retired` parses the file and **never verifies `emit_hash`.** The seal is written on every
emit and checked only by `check()`'s FREEZE step -- so any consumer that loads the retired view
directly gets no integrity guarantee from it. Surfaced, not remediated: it is a real gap and it is
not what this ruling authorized.

## Resolved without a remedy: the `ever_minted` question

Raised in the same card: `ever_minted` lists `D0..D9` while live is `D0..D11`. `1.0.0_SA_CTO`
directed establishing the reading **by reading the WRITER**, not the field name or its tripwire.

**The writer settles it.** `ever_minted` is recomputed **only inside `retire()`** (`comp_directives.py`
`ever = set(existing) | {live rows} | set(retired dirs)`) -- it is **EMIT-MAINTAINED**, never touched
on mint. The tool's own self-test 10 states it outright: *"ever_minted is EMIT-maintained, so D9 --
added live after the last successful emit -- correctly not yet in it."*
And CONSERVATION is deliberately **one-directional** (`ever - live - retired`), flagging silent
deletion only, so a live key absent from `ever_minted` raises nothing **by design**.

**Therefore NEITHER remedy applies -- not backfill, not rename. D10/D11 absent is CORRECT**, and
they will be unioned in at the next emit. The apparent defect was a mint-time expectation read into
an emit-maintained field. Recorded because the wrong reading was mine and both proposed remedies
would have damaged a working field.
