# LD-0465 -- the orphan-watcher mechanism was false for six weeks, in the file every seat reads first

## What was false

Two shared startup surfaces carried a flat mechanism claim:

```
org/XXX.md:408                       "The `inbox-watch.sh` child outlives its session."
.claude/skills/watcher/SKILL.md:43   "`inbox-watch.sh:113` is `while true` with no parent-liveness
                                      check and no exit path ... the bash child keeps polling forever."
```

Neither is true. Read at source, every line, at this device:

```
inbox-watch.sh:112-120   block TITLED "PARENT-LIVENESS SELF-EXIT (2026-07-14, 0.0.0_AB_MSTR --
                         the orphan-thief ROOT fix)"
inbox-watch.sh:161-165   kill -0 "$WATCH_PARENT" -> append WATCHER-SELF-EXIT -> exit 0
inbox-watch.sh:137-141   PARENT_CHECK=0 when INBOX_WATCH_NO_PARENT_CHECK set OR $PPID <= 1
inbox-watch.sh:159       arm banner: "parent-tied: pid <N>" | "parent-tied: OFF"
org/mcp/orphan-audit.log 458 WATCHER-SELF-EXIT of 471 lines
```

## The correction is BOUNDED, and both halves must travel together

`:139`'s fail-open is **correct**. MSYS can render a live non-MSYS parent as PPID 1, and a naive
liveness check would make healthy watchers suicide — the documented 7-false-positive trap. **Never
kill on a probe that cannot see its subject.** So orphans remain possible in exactly that cell, and
"there is a self-exit" is not "orphans are solved."

> ⛔ **NOTHING ABOUT ORACLES CHANGES, AND THIS ARGUES THE OTHER WAY.** A self-exit narrows how
> orphans are BORN. It changes nothing about how you may REASON. `ps`, an empty inbox and `read/`
> stay BANNED as delivery oracles; an agent-side ACK stays the only sound one. Do not read "orphans
> are rarer" as licence to infer delivery from a drained inbox.

## Why it survived six weeks — and it is not the obvious answer

The fix landed **2026-07-14 under this seat's own author line.** The docs describing it were never
re-read. Nobody was behind on a message and no broadcast was missed: the correcting act and the
stale description had the *same author*, and that author never audited its own artifact against its
own fix.

> **The trigger that would have caught it is *a change landed* — not *a ruling landed*.** The
> existing habit re-reads your file when a peer's ruling corrects you. This was corrected by
> **yourself**, which fires no such signal, and the artifact is the one every seat reads at session
> start. **A false line there arms the whole fabric off wrong doctrine**, silently, for as long as
> it stands.
