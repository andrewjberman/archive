# LD-0158 — fabric-check DEAF detection + LD-0157 reachability-regression mitigation

## The gap COO surfaced (live)
LD-0157 retired the worker/CTO self-tick loops on the premise "the Monitor is effective."
True for BASE lanes (broker push -> Monitor notifies). But the self-tick also silently did a
second job: **re-arming a dead Monitor**. The persistent Monitor occasionally dies (the exit-143
SIGTERM, LD-0146). Pre-LD-0157, the next /work or /ws-charter tick re-armed it. Post-LD-0157,
**a lane whose Monitor dies has no self-tick to re-arm it -> it goes silently UNREACHABLE**
(unread inbox accrues, no telemetry). `~A` lanes are worst-exposed: the broker suffix-strips
their push, so the Monitor poll is their ONLY delivery path -- kill the Monitor and they're
fully deaf. Empirical: `0.7.0_AE~A` went deaf to a time-sensitive Andrew-direct run (7 unread,
idle 14m); COO caught it via its deeper 2b.1 check + rerouted to base.

## The fix (preserves Andrew's no-tick model)
1. **fabric-check DEAF detection** (`.tools/fabric-check.py`): a lane with unread top-level
   inbox AND telemetry quiet (>600s) AND recently-a-live-session (<2h) = DEAF. New top-priority
   bucket; surfaced in full view + `--blocks` + the `FABRIC-CHECK-RESULT deaf=N` line. (2h
   recency bound excludes long-offline lanes with leftover mail -- tested: 1 true positive vs 14
   false positives without the bound.)
2. **COO /drive catches it -> MSTR respawns.** `/drive` Step 2b.0 + the fabric-check SKILL: a
   DEAF lane is a respawn-request to MSTR (a respawn re-arms its Monitor + drains the backlog);
   reroute any time-sensitive work to a reachable lane meanwhile. **No per-agent tick is
   reintroduced** -- COO /drive (the one centralized tick) does the detection; MSTR
   (creator-destroyer) does the respawn. This is the LD-0157-consistent reachability guard.
3. **Re-elevate the root-cause fix to infra.** The Monitor-death (exit-143) + `~A` event-delivery
   (broker push to a `~A` lane) was downgraded "do-not-escalate / lossless / no-impact"
   (LD-0146 correction-5, Andrew-settled). **That premise CHANGED:** LD-0157 made an idle-lane
   Monitor-death operationally consequential (deaf lanes that can't be re-tasked). Per the
   proportionality lesson's own "revisit only if message-loss / operational-impact observed"
   condition -- now MET -- the fix re-elevates. Routed to CTO/infra (folds into the broker/poller
   charter): (a) Monitor-death resilience (or a cheap re-arm path that isn't a per-agent tick);
   (b) `~A` event-delivery so the broker can push to a tilde lane.
