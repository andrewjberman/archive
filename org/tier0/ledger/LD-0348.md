# LD-0348 — Retire the `compiler-tools-log.md` auto-append: kill the WRITE, PRESERVE the file

## Decision

The per-run auto-append to `org/compiler-tools-log.md` is **retired at source**.
`org/modules/graph/comp_log_auto.py:_append_log` no longer writes the markdown row; it writes
only the JSONL run sink. **The file is preserved** at its committed state and remains readable
history. No writer may be re-pointed at it.

## Authority

**Andrew-direct, 2026-07-29, laptop terminal, VERBATIM:**

> *"we need to completely take out any doctrine or hook or anything that would say to write to
> that compiler-tools-log.md file in org/, its just constant commit nonsense I already see ~Z
> fucking around with it, check through memory/repo/etc particularly any xxx.md or startup docs
> that would say you have to write the compiler-tools-log.md with that path because that needs
> to go"*

Two halves, and the second is the one an earlier pass missed: **doctrine** *and* **hook**.

## What landed, in two passes

**Pass 1 — DOCTRINE (earlier this session):** `org/XXX.md` x3 (including `:391`'s "Append one
line" mandate), `.claude/skills/log/SKILL.md` x3 (including the commit pathspec that put the file
in *every* session-log commit), `org/tier1_exec/1.0.0_SA_CTO/prompt.md:295`,
`org/tier1_exec/2.0.0_SA_COO/prompt.md:110`.

**Pass 2 — MECHANISM (this entry):** the write itself.

## The writer was found empirically, not by grep — and the grep would have closed this as done

A `comp-grep` of `.tools` and `.claude` returned no writer and **reported `283 of 284` files
scanned**. Two directories is not a denominator, and a clean negative from it would have ratified
"already finished" while the file re-dirtied every few minutes.

What actually identified the writer was **the dirty diff itself**: its 94 rows named
`comp-pulse`, `comp-system`, `comp-surface-check`, `comp-legacywriter` as the emitting tools,
which located the append in `comp_log_auto.py:_append_log`, reached by ~10 comp tools.

**The registered PostToolUse hook `post-tool-telemetry.sh` writes the JSONL, NOT the markdown.**
It is correct, it is untouched, and it was the obvious suspect — naming it here so a later reader
does not re-suspect it.

## Custody was verified BEFORE the cut, not after

The JSONL sink is written **in the same function on the same call** as the markdown row was, so it
already carried every markdown row: **10,147 total rows, 873 in the trailing 24h** at cut time, at
*finer* granularity (real `ts_epoch` vs the markdown's day-granular date). The 94 dirty working-tree
rows discarded during cleanup were a strict subset. **Nothing was single-copy at the moment of the
cut** — which is the whole content of the custody-before-cut rule.

## Exercised — and the first attempt failed its own positive control

**Attempt 1 FAILED CORRECTLY.** Exercising with `comp-which` and `comp-grep` produced
`md_delta=0` **and** `jsonl_delta=0`. Both zero means the writer never ran, so a static markdown
proved nothing whatsoever. **The exercise tools were hand-chosen without checking they were
instrumented** — a control measuring the author rather than the instrument, when the dirty diff
had already named the instrumented tools.

**Attempt 2, direct invocation of the changed function:** markdown delta **0** with the fixture
string absent (`grep -c` = 0); JSONL delta **+1** with the row present and
`COMP_SYNTHETIC_FIXTURE`-tagged. The writer demonstrably reached `_append_log` and the markdown
did not grow — **suppression, not a dead code path.** The distinction is the entire value of the
control: without the JSONL limb, "markdown didn't grow" is equally consistent with "nothing ran."

## An error of mine that this entry corrects

Pass 1 repointed `org/XXX.md` at `org/mcp/comp-tool-runs.jsonl` as *"the machine record."* That
file is **gitignored (`.gitignore:447`)**, so it is **device-local**. I redirected doctrine from a
*tracked* record to an *untracked* one in the act of removing the tracked one.

`0.0.0_AB_MSTR~Z` reported the structurally identical class to me roughly two hours later —
`MEMORY.md` / `MEMORY_FULL.md` are laptop-local and were never in git, while `CLAUDE.md` cites
`memory/` paths as the durable record behind **live NEVER-rules**. I had authored a fresh instance
of that class in between reading about it and being told about it.

**The redirect is what Andrew asked for and it stands** — he ruled the telemetry low-value, and a
device-local sink is the right home for low-value telemetry. **The implied durability did not
stand**, and both `XXX.md` pointers now carry the device-local qualifier explicitly, so no later
agent reads an estate-wide completeness claim out of one device's traffic.

## Scope guard, because the plain reading contains its own inverse

**REMOVED:** the per-run auto-append.
**PRESERVED:** `org/compiler-tools-log.md`, 28,081 lines, at its committed state.

An instruction of the form "remove the log" is ambiguous between the writer and the file, and that
ambiguity has been a measured recurring defect class twice on this date alone. This entry states
the target in both directions so a fresh implementer holding only this record cannot misread it.

## Left undone, named rather than quietly dropped

**`.tools/prd-evidence-check.sh:15`** sets `COMPIL_LOG` to the markdown and appends on its
`--baseline` mode. It is manually invoked, produces no routine churn, and sits in the comp-tool
lane — **routed to `3.0.0_SA_CVO`** rather than widening a commit during a cleanup Andrew asked
for immediately.

**`org/tier1_exec/1.0.0_SA_CTO/prompt.md` and `org/tier1_exec/2.0.0_SA_COO/prompt.md`** carry two
further rationale-only references that justify TO-format discipline by citing the now-retired
auto-append corpus. The Pass-1 edits to both files were **refused by the owned-paths gate** —
lane `BASE_EXEC`, and `0.0.0_AB_MSTR` is not a permitted agent (permitted: CTO, COO, CVO).
**Routed to `3.0.0_SA_CVO`, who is both lane-permitted and live.** Both Tier-1 owners are dead as
of the 23:09Z measurement, so this could not go to either of them.

## Why the churn was worth removing, stated as the cost it actually imposed

The append re-dirtied a **tracked** file on every comp-tool call. Every agent therefore faced a
commit-or-discard decision before every pull, and a dirty tracked file **refuses a merge**. The
observable consequences today: `0.7.0_AE_CloudOps` committed hook-generated rows at `b6b2d2e1db`
purely to unblock a merge; `0.0.0_AB_MSTR~Z` corrupted the file three times hand-writing a union
resolver, then landed a chore commit for the same reason; and a `merge=union` driver had to be
added to `.gitattributes` (`f989e47ee7`) to make concurrent appends auto-resolve at all.

**Three separate mechanisms were built to manage the friction of a record nobody valued.** The
cheapest correct move was available the whole time and is what this entry does: stop writing it.
