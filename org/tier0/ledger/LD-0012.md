# LD-0012 — Charter CVO to apply verify-channel to capital_gains_ttm -$54.8M finding (D-001 PHASE 2 META trigger)

## Decision
Andrew flagged: "Capital gains coming out to -50m is definitely suspicious
as hell for a book that is only 200m. This is a case where meta analysis
would come in and you say 'that sounds strange', 3.0.0 should be all over
that with their spot check skill."

The number in question: `capital_gains_ttm -$54.8M`, surfaced by
0.4.0_DS_ClientPlatform in their broker summary as VALFIN.001 Phase-1
"Routing Ask #4" to COO (commit `c02c9c1ed`, Phase-1 session log). The
book the number applies to (Inflection, per the surrounding VALFIN.001
ADVI work) is approximately $200M. A $-54.8M realized cap-gain on a
$200M book is a ~27% drag — not a reasonable tax-loss-harvesting outcome
in any healthy advisory book this size. Mechanically functional output
(the script ran, the number is in the artifact); meta-analytically
implausible (the holistic-purpose alignment fails).

D-001 PHASE 2 v1.4 META success signal (verbatim): "A mechanically-
functional output that fails this test — e.g., a daily pipeline that
runs successfully but pulls the same 10 rows every day, or a chart that
displays values inside a healthy axis range but the values don't
represent what the chart claims — is NOT a success. It is a finding
that gets chartered to a fix. The meta-analysis is the load-bearing
test; the mechanical checks are necessary but not sufficient."

This finding meets that test. Chartering to CVO (3.0.0_SA_CVO) — the
fabric's structural verifier — to apply /verify-channel rigor:
**MECHANICAL** (artifacts exist, fresh, scaled, not-frozen),
**NOVEL** (probe the value against fresh data the producer did not
gate on), **META** (verifier ≠ fixer, sharpest-test-binds, decision-
useful meta-gate; specifically: does the holistic purpose — accurate
year-to-date realized capital gains for the Inflection book — admit
this number?).

Two-part charter:
1. **Immediate**: CVO applies /verify-channel to the -$54.8M finding
   per the methodology above. Routes the verdict (GREEN / YELLOW / RED
   with reasoning + sharpest-test artifact reference) to MSTR via
   broker, with COO + DS_ClientPlatform CC'd so the routing chain stays
   coherent.
2. **Doctrine**: CVO considers extending /spot-check sweep scope
   (currently alignment-metadata-only per `ac93b83d7` charter) to
   include substance-level meta-checks — "does this number make sense
   at this magnitude?" — alongside the existing structural sweep.
   CVO authors their own skill; MSTR proposes the doctrine
   refinement, CVO decides if/how to expand. Per Andrew's verbatim
   ("3.0.0 should be all over that with their spot check skill"), the
   intent is for /spot-check to catch this class of finding.

Fix authority remains scoped: CVO verifies + routes; if a defect is
confirmed, the FIX charters back to DS_ClientPlatform via COO
(producer-side correction; not a CVO direct-edit of the gold/silver/
bronze script).
