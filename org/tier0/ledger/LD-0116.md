# LD-0116 — Chain-of-command edict: no Tier-2/3 ↔ MSTR direct comms (Art. VI sharpening)

## Andrew sovereign instruction

Andrew direct in-session 2026-05-27T~17:36Z verbatim:

> "I also need you to hand down an edict to both Division CTOs; no tier 2 or 3 agents talk to MSTR. You can talk to them if i explicitly ask you to, which shoudl realistically never happen, but they do not need to MCP you, that breaks the chain of command if they were to do something liek that."

## The rule

**Tier-2/3 workers (DE / DT / DS / AE / RD / SC across both ws and CL fabrics) shall NOT MCP MSTR (`0.0.0_AB_MSTR`).** Any current inbound MCP from T2/3 to MSTR gets bounced by MSTR with redirect-to-COO/CTO + MSTR does not act on substantive content.

**MSTR shall NOT MCP Tier-2/3 workers** except on explicit Andrew per-instance instruction. Per Andrew: "realistically never."

## Chain that remains valid

```
Worker (Tier 2/3) → COO / CTO (Tier 1) → MSTR (Tier 0) → Andrew (sovereign)
                                                ↑
                              Allowed both directions (T1 ↔ T0)
                              MSTR may MCP T1 freely (it's the operational chain MSTR governs through)
```

The forbidden rungs:
- Worker → MSTR (no upward skip)
- MSTR → Worker (no downward skip)

Constitutional grounding: this is a sharpening of **Constitution Art. VI** ("MSTR originates strategy, charters, and priority decisions, but delegates all execution through Tier 1 (CTO / COO). It does not bypass the chain it built."). Art. VI already prohibits bypass; LD-0116 makes explicit that "bypass" includes any MCP routing — not just substantive task delegation. The chain-of-command is structural, not just authoritative.

This session arc (post-reboot 2026-05-27T~15:00Z onward) contains many T2/3↔MSTR exchanges:

- MSTR → Worker: SPAWN-WITH-DIRECTION MCPs to AE 0.7 + DS~D + DS 0.1.0 base + DS 0.1.0 tilde lanes ~A..~E + 5 CL workers (1.1.0/1.2.0/1.3.0/1.4.0_DS_CompLearns + 2.1.0_SC_CompLearns)

All operationally worked but per Andrew sovereign judgment chain-of-command discipline trumps operational shortcut. The most explicit violation was DS~C's [ANDREW-ASK via MSTR] route which I surfaced to Andrew — that's the exact pattern Andrew is now banning ("they do not need to MCP you"). The ws COO's subsequent SUPERSEDED-EMPIRICAL withdrawal of the same Q2 ask demonstrated empirically that **the COO layer absorbs T2/3 architectural questions correctly without involving MSTR or Andrew**; LD-0116 ratifies that empirical pattern as the structural rule.

## Going-forward pattern

### Spawn dispatch

**Before LD-0116:**
1. COO ALLOCATION-REQUEST → MSTR
2. MSTR spawn-agent.ps1
3. MSTR SPAWN-WITH-DIRECTION → Worker (direct MCP)
4. Worker SPAWN-ACK → MSTR (direct MCP)

**After LD-0116:**
1. COO ALLOCATION-REQUEST → MSTR (unchanged — T1 ↔ T0 allowed)
2. MSTR spawn-agent.ps1 (unchanged)
3. MSTR SPAWN-WITH-DIRECTION-SUBSTRATE → COO (single MCP with the substrate; COO forwards/authors to Worker per their lane)
4. Worker SPAWN-ACK → COO (direct to COO who dispatched the substrate to them); COO summarizes upstream to MSTR as part of next /drive cycle ground-truth

The SPAWN-WITH-DIRECTION substrate is content — MSTR composes it, but COO delivers it. Removes 2N MCPs per spawn batch (one per worker each direction); replaces with 2 MCPs per batch (MSTR→COO + COO→MSTR cycle-summary).

### Worker architectural asks

**Before LD-0116:** Worker [ANDREW-ASK via MSTR] route (DS~C Q2 pattern)
**After LD-0116:** Worker → COO → (if COO cannot resolve) → CTO → (if CTO cannot resolve) → MSTR → (if MSTR cannot resolve) → Andrew. T2/3 never directly hits MSTR; the standard escalation ladder per Constitution Art. VI + the never-stop rule.

### Inbound T2/3-to-MSTR (already-in-flight + future violations)

When MSTR receives a T2/3 MCP:
1. MSTR bounces with redirect: "Per LD-0116 chain-of-command edict, T2/3 must route through your fabric COO/CTO. Your ask: {one-sentence summary}. Redirecting to: {target T1 serial}. I am not acting on the substantive content."
2. MSTR DOES NOT process the substantive content.
3. CC the relevant T1 (COO or CTO) so they pick up the redirect.

This handles the asymmetry where workers spawned pre-LD-0116 might still MCP MSTR out of habit.
