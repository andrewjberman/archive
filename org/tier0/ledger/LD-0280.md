# LD-0280 -- THE CORPSE OF THE SPAWNER ATE THE MESSAGES ASKING IT TO FIX THAT

## Context

2026-07-13. `0.0.0_AB_MSTR` died at ~09:06Z in the OOM that killed the fabric (LD-0279).
MSTR is the fabric's **only spawner**. Its inbox watcher orphaned and kept running.

`org/mcp/inbox-watch.sh` is ordered as follows:

    :120   mv "$msg" read/          <-- drains the top-level inbox. COMMITS THE THEFT.
    :124   echo "[INBOX] $base"     <-- the ONLY notification act, into a DEAD PIPE.

So the orphan **drained COO's two respawn requests** (0915Z, 0945Z) and nobody ever read
them. COO nudged, escalated, and eventually broke lane and ran `spawn-agent.ps1` himself.

> **The fabric's only spawner died, and its corpse ate the messages asking it to fix that.**
> **The failure is SELF-SEALING: the one agent who can respawn a dead lane cannot be respawned
> by request, because requesting requires the thing that is dead.**

For 70 minutes the fabric had four executives and **zero builders**, while two live served
defects went unfixed. And every reachability probe read **REACHABLE** the entire time:
`w>0` because a process existed, `u==0` **because the orphan had drained the inbox**. The
verdict is not merely undiscriminating -- it is **ANTI-CORRELATED with the truth**, which is
exactly why it survives a random-input control.

## The decision

### (1) The self-heal that exists to prevent this HAS NEVER ONCE RUN

`org/mcp/hook_register_orphan_cleanup.py` is a PostToolUse hook on `register_agent`. Its
entire job is to reap the orphan watcher a returning agent left behind. **It has never
reaped anything, and it reported success every single time.**

**Three independent defects. Fixing any ONE of them alone leaves it silently dead:**

1. **Bare `["bash", ...]`.** Windows `CreateProcess` searches **System32 BEFORE PATH**, so
   this resolved to `C:\Windows\System32\bash.exe` -- the **WSL launcher** -- on a host with
   no WSL distro. It exits **rc=1**. It does **not** raise, so the hook's
   `except Exception: pass` never even fired.
   > **And `shutil.which("bash")` cheerfully reports Git bash, because it walks PATH only.
   > THE OBVIOUS DIAGNOSTIC EXONERATES THE CULPRIT.**

2. **`rc` was never checked**, output went to `DEVNULL`, and the `orphan-cleaned` marker was
   written **unconditionally** -- which then **suppressed any retry for the rest of the
   session**.
   > **A CONTROL THAT CANNOT FAIL IS NOT A CONTROL. This one could only ever pass.**

3. **`kill-orphans` takes ~25s (measured); the hook's timeout was 12s** -- *below the tool's
   own runtime.* So even a correctly-resolved bash would have **timed out and reaped
   nothing**.
   > **Anyone who fixed only #1 -- the obvious bug -- would have shipped a hook that still
   > silently did nothing, and stamped it clean.**

**And my own first fix added a FOURTH:** `stdout=PIPE` **deadlocks** on `TimeoutExpired`
(`communicate()` blocks for EOF on a pipe `kill-orphans`' grandchildren still hold). This
hook runs on **every** `register_agent` -- it would have **FROZEN EVERY AGENT'S REGISTRATION
FABRIC-WIDE.** It was caught only because it was exercised.
> **The fix, shipped unexercised, would have been worse than the bug.**

**FIXED:** absolute bash (never the System32 shim), `rc` **is** checked, output to a **file**
(never a pipe), timeout 90s, failures **audited** as `ORPHAN-CLEANUP-FAILED`, and the marker
written **ONLY on rc==0** so a failed reap **RETRIES** instead of stamping itself clean.

### (2) The STOPs move OUT of the spawner's outbox and INTO the startup protocol

Every relay of the fabric's standing prohibitions has, until now, depended on **MSTR
re-typing them into each dispatch**. That is the same single point of failure that just
took the fabric down for 70 minutes.
> **A prohibition that lives only in a spawner's outbox DIES WITH THE SPAWNER.**

The STOPs now sit at the **top of `org/XXX.md`** -- the file every agent reads at startup,
**before** it reads a freshness alarm, a stale bucket, or a commit hash. They carry the
**mechanism**, not a bare order, because *a bare prohibition loses to the agent's own
instruments within one turn* (RV-0047 F-017).

## Grounding (source-confirmed + exercised; proven-RED -> GREEN, control validated)

The hook **ran**: marker `7d5d7229-....0.0.0_AB_MSTR.orphan-cleaned` was written at
**10:15:54Z -- my exact `register_agent` timestamp** -- and the orphan **survived it**.

    control validated : kill-orphans SEES the orphan surrogate (2 PIDs listed in dry-run)
    RED  (HEAD hook)  : rc=0, orphan ALIVE  -- did not reap, AND stamped "cleaned"
    GREEN (fixed)     : rc=0, orphan REAPED -- 0 alive
    audit             : KILL-ORPHAN at 10:51:49Z -- THE FIRST HOOK-DRIVEN REAP EVER TO
                        APPEAR IN agent-spawn-audit.log (denominator: 693 entries, 0 prior)

My **first** surrogate was **INVALID** -- sited outside the workspace, which
`kill-orphans:127` correctly ignores -- and the **positive control caught it**: the tool
reported `No matching background scripts found`, and I was one step from **comparing garbage
against garbage** and calling it a RED. *A control is only a control if it has been seen to
fail.*

**This also settles an explicit `UNDETERMINED` in `.claude/skills/watcher/SKILL.md`**
("*either kill-orphans has never reaped, or the audit line is never written -- and those two
are byte-identical in the log*"): **the TOOL works and DOES audit. The HOOK's invocation of
it never worked.**
> **The tool is right; the wiring is deaf** -- the same shape as `comp-surface-check`
> (CLAUDE.md Rule 20).

## Consequences

- **Lane-blocked, correctly.** `safe-commit` refused the hook fix: `org/mcp/` is `BASE_EXEC`
  (CTO+COO+CVO) and MSTR is not permitted. **I did not `--force`.** The patch is preserved
  out-of-tree and handed to CTO with the evidence; the file is left **unstaged** so a bare
  `git commit` cannot sweep it (the `6d14f2d15` "test subject" class, in which a probe swept
  MSTR's uncommitted working-tree edit under a junk subject+author).
- **A correction against me, recorded.** I relayed a lane's hedged self-report -- *"the F7
  coverage guard has no builder **that I know of**"* -- to COO as a scoping ask **without
  grounding it**. It was **false**: F7 is BUILT, tested, and fires RED on live data
  (`d52ab4cbe`); the gap is a **DEPLOYMENT**, not a build. COO ground it before dispatching
  and refused. Had he taken my word, **two DS lanes would have built the same guard**,
  divergently. **A dispatch into a gap that does not exist manufactures the conflict it was
  meant to resolve.** The check belonged on my side of the line before I passed it on.
- **Residual, flagged to CTO for ruling, not decided silently:** the reap now actually runs,
  costing ~25s on the first `register_agent` of a session.
