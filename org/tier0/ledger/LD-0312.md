# LD-0312 -- Charter NFRA_GENESIS: the runnable SDK to spin up a new company's semantic system

## Context

Opal built a complete COMPILED SEMANTIC SYSTEM: a versioned graph (Nessie/Iceberg -> Kuzu projection ->
Trino federation), a C0->C3 compression ladder (FACTS/objects -> INTERACTIONS/edges -> MOTIFS -> SYSTEMS)
with a lossless-decompression fidelity gate, ~59 comp-* tools, a substrate/layer model (the same C0->C3
materialized over aws/portal/ms/pipeline; discovered C2/C3 lifted into a semctl layer), and a CLOSED
self-learning loop (observe -> measure -> promote -> materialize -> remeasure), all honesty-gated. The
SEMCTL charter's thesis is that this is a REFERENCE IMPLEMENTATION of a general pipeline, not code-
specific -- the recognizer is the reusable keystone, and only the front-end parsers + recognizers + the
`layer` set are company-specific. Andrew chartered the productization: wrap the generalized PROCESS into
a kit + runnable tooling so a new company's graph, ontology-binding, and learning loop can be SPUN UP
with a real provisioner on the proven stack.

## The locked decisions (Andrew, this session -- binding)

1. **Full runnable provisioner** -- a real `genesis up <company>`, not docs/scaffolds.
2. **Framework / Opal-as-reference** -- no concrete second company; acceptance via dry-run + a sandbox tenant.
3. **Opinionated to the proven stack** -- Nessie/Iceberg/Kuzu/Trino + AWS, parameterized; no multi-cloud.
4. **0.8.0_AE_CloudComp~A drives + owns** -- authors in-lane; exec-locked engine pieces route to CTO.
5. **Name = NFRA_GENESIS** (NFRA macro; CLI = `genesis`).
6. **Acceptance = local/sandbox proof** -- zero new cloud spend; a real second AWS apply is out of this pass.

## Shape (charter-level; the PRD refines)

- **PACKAGE + PARAMETERIZE, don't rebuild.** The generalization boundary is narrow: TWO bespoke-per-company
  pieces (the recognizer keystone; the binding adapter). Everything else is reused mechanism, made tenant-
  neutral via one `company.yaml` manifest whose schema FORBIDS per-tenant CSE algebra/Entity/Relationship
  forks (extending the algebra is a governed shared version-bump, never a per-tenant fork).
- **The SDK tree** lives under `infra/system/sdk/` (ANY_EXEC_OR_AE -- AE-committable), numbered to mirror the
  existing `infra/system/00_synthesis..07_maturity` convention: 00_manifest / 01_provision (the extracted,
  parameterized globgrph TF module + tenant template) / the recognizer-SDK re-export + front-ends / the
  packaged loop / verify / the genesis CLI.
- **Ownership + gates:** ~A owns/authors the SDK; CTO arch-gates the exec-locked engine pieces (the extracted
  TF module + the comp-tool-suite registration under org/modules/graph/**, which lands as ONE NFRA_COMPREG
  ATOMIC-BUNDLE commit); COO coordinates + keeps the governance record straight; MSTR governs the doctrine.
- **Dependency, not authorship, on NFRA_ONTOLOGY:** the SDK treats the archetype vocabulary as a pluggable
  versioned dependency (`adapter.ontology_ref`), ships on the CTO-ratified canon-patterns.yaml v0.1 now, and
  slots the LD-0311-ratified closed vocabulary at P6. GENESIS never authors/gates the ontology.

## Non-goals (explicit -- keeps GENESIS from colliding)

Not authoring/gating the ontology (NFRA_ONTOLOGY's charge); not re-platforming Opal's live graph (legacy
extractors untouched); not owning/extending the CSE algebra or COMPILERKIT (reuse as-is; enum changes are
governed shared version-bumps); not NFRA_SYSTEM (the current-state comp-system compiler -- a different axis);
not a store-abstraction/multi-cloud SDK; not a live production second company; not the OPAL_TAXONOMY naming axis.
