# LD-0211 -- NEW MACRO 'SCTY' (Security program; Andrew-direct; macro-creation record)

## Decision
Record, for the Tier-0 / macro-governance trail, the Andrew-direct creation of the
**new macro `SCTY`** -- a standing **security program-of-record** housed at `/security`,
mirroring the macro-creation precedent of [[LD-0209]] (DATA) and [[LD-0194]] (NFRA_OPLMCP).
Both execs + CVO flagged it for macro-governance.

## Premise
House Opal's security program as ONE governed, reusable macro across 4 workstreams:
external-tool/repo/MCP diligence (the novel **AI-agent-supply-chain** risk-class);
vendor/partner security diligence; own-attack-surface red-team (portal / the OAuth-JWT
gateways / APIs / AWS); and AI-agent / multi-agent-fabric hardening. SCTY **frames +
references** the project-specific security artifacts (the DATA_PLATFORM recon-ROE
[[LD-0210]], the OPLMCP gateway-auth, the NFRA_WRKFLW privacy-two-zone) and adds the
cross-cutting -- it does not duplicate them.

## Trigger (concrete + live)
CVO's isolated, read-only analysis of 2 untrusted GitHub repos found **reverse-skill = a
LIVE AI-agent-hijack toolkit** (auto-execute-on-read, ExecutionPolicy-bypass, global-config
self-injection, explicit agent-safety-suppression). It is a working specimen of the
AI-supply-chain / prompt-injection threat the fabric runs into every time an agent reads
external content -- which the DATA_PLATFORM recon crawl does constantly. Hence the urgent
first control: **external-content = untrusted DATA, not instructions; sandbox agent
tool-access; no-auto-run external MCP/scripts.** Ties to the silent-absence/fail-safe theme
(agent-safety-suppression = make-the-agent-silently-not-warn).

## Artifacts (MSTR-verified)
- `org/projects/SCTY.json` -- status active, `macro:true`, **prds-ARRAY** (correct hygiene).
- `docs/architecture/SCTY_PRD.md` -- the CTO formal PRD v0.1.
- Both committed `cc940ab0f`.
- **PENDING (COO):** the REGISTRY row + the `/security` commit + the owned-paths lane rule.

## Governance
CVO = **verifier-not-fixer** (CVO + MSTR co-hold the security-findings governance); CTO
arch-gates the control designs; COO owns the `/security` lane + decomposition; MSTR ledgers.
First chartered work (urgency-ordered): (1) URGENT -- the agent-supply-chain control
(CTO-arch-gated); (2) own-attack-surface self-assessment (OPLMCP gateway first); (3) fold
the recon-ROE + crawl-isolation under the SCTY security framing.

## Rollback
Retire the macro + this LD if Andrew de-scopes the program; the security KB already produced
(`/security`) stays useful regardless. Reversible at low cost (Phase-0 charter, no build
committed). The recording changes no operational state.
