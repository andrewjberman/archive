# LD-0543 - Running the sprint by hand so the scheduled one can exist

## Decision

Produce and publish 2026-09-10. Dated keys only. Then automate from what the run measured.

## Why by hand first

The `/daily-sprint` pipeline had never been executed end to end in one session by this seat.
LD-0541 recorded that nothing schedules it and that the packet source was an open design
question. **A run is the cheapest way to answer a design question about a pipeline**, and it
produced the day Andrew asked for at the same time.

What the run settled, which the work order could not:

| question | answer, measured |
|---|---|
| what does the Lambda actually have to do? | author the JSON. Everything else is deterministic. |
| can a Lambda clone this repo? | **No.** `.git` is 6.7 GB, pack 2.51 GiB. |
| do the render/publish scripts need heavy deps? | **No.** stdlib + `subprocess(git)` + boto3. |

⭐ **THAT KILLS THE SELF-CONTAINED-LAMBDA SHAPE ON A MEASUREMENT RATHER THAN A PREFERENCE**, and
it is the shape LD-0541 could not choose between. The censuses need git history; the history is
2.5 GB; a Lambda cannot hold it. The deterministic halves run where the repo already is.

## The day

601 commits, 46 workers, Eastern day. Two censuses, one denominator, agreed independently.
Seven items. Two of them decline to claim a win the evidence does not support -- the change
report failed Andrew's own read, and the guardrail closed with two goals named UNTESTED rather
than passed.

## Rollback

The two S3 keys are dated and additive; deleting them restores the prior served state exactly,
because there was no prior object at either key. The commit reverts in one.
