# LD-0021 — Spawn-with-direction: the mechanical fork-resolution primitive

## Decision

Extend the LD-0020 mechanical-resolution toolkit. At cycle-2 fork-stall, MSTR's available resolution mechanisms are now explicit:

1. **Direct directive (preferred when the block is informational).** MSTR ledgers the chosen path + CTO/COO authors the resolving TO/MCP to the stuck agent. Works when the agent CAN move once told.

2. **SPAWN-WITH-DIRECTION (preferred when the block is prompt/context).** When a stuck agent is jammed because their session context, prompt history, or attestation chain has them ambivalent — when telling them "do path (a)" wouldn't actually unstick them because the block is structural to their session — MSTR spawns a NEW agent with the recommended path BAKED INTO their startup instructions. The new agent doesn't carry the block. The stuck agent is killed (free the slot) or left to time-out.

3. **Kill + replace.** Variant of #2 when the stuck agent's session is corrupted or otherwise unrecoverable. Kill first, then spawn fresh with directional instructions.

**Meta-coordination posture (Andrew verbatim):** /govern's Step 1(b) population scan is the "constantly running stimulus scan." It already runs every cycle. The new explicit framing: that scan FEEDS the meta-coordination authority — at cycle-2 fork-stall MSTR doesn't just classify the agent as STUCK; MSTR RECONFIGURES THE POPULATION to route around the block.

## Mechanism — SPAWN-WITH-DIRECTION

The spawn primitive (`.tools/spawn-agent.ps1 <serial>`) launches a new PowerShell window via `ajb -Headless` (hands-free). To bake direction into startup:

1. **Pre-place a TO** in the new agent's `task_orders/` directory before spawn, with the recommended path explicit + the prior agent's context summarized. COO authors this (Tier-1 delegation discipline per Art. VI).

2. **Pre-place an inbox message** at the new agent's MCP inbox with the directional charter. Channel-pushed via `send_message` immediately post-spawn.

3. **Tilde-lane suffix.** If the stuck agent is at a base serial, the spawn uses the next free tilde suffix (`~B` → `~C` → `~D`); if at a tilde-lane already, a sibling lane is provisioned. Avoids broker-registration collision.

4. **MSTR-originated LD entry** documents: the original fork, the cycle the COO didn't resolve it, why MSTR chose spawn-vs-directive, the new agent's serial, what directional instruction was baked in.

5. **Original agent disposition.** If their WIP is recoverable, leave them to time-out / standing-by post-resolution; COO will reassign or kill on next pass. If their session is the block itself, MSTR kills them post-spawn-success.

## Why now

LD-0020 (1 cycle ago) installed the COO-first / MSTR-backstop framework but left "mechanical resolution" abstract — "pick the reversible / cheap / information-producing path." Andrew's elaboration this cycle makes the resolution CONCRETE: spawn-with-direction is the most powerful primitive in the toolkit. The directive turns a passive "MSTR decides" into an active "MSTR re-allocates population."

This is the meta-coordination capability D-002 always implied but didn't operationalize. LD-0020 + LD-0021 together = the operational backbone.

## Assumptions

- Spawn cap (8 concurrent) is rarely the binding constraint at cycle-2 fork-stall; if it is, kill-and-replace satisfies the spawn-cap simultaneously.
- The "block is prompt/context not informational" judgment is mine to make at scan time; the heuristic: if a single MCP from COO would unstick them, the block is informational and direct-directive suffices; if their session has them genuinely ambivalent (mid-attempt, partial context, conflicting prior signals), the block is structural and SPAWN-WITH-DIRECTION is correct.
- Tier-1 delegation discipline (Art. VI) still applies — COO authors the TO and the directional message; MSTR originates the spawn call and the strategic direction.
- A spawned agent inheriting only the baked-in instruction + clean session is more likely to execute cleanly than the same instruction landed on a stuck session — empirical hypothesis, to be validated on first exercise.

## Alternatives considered

- **Only direct-directive at cycle-2 (no spawn primitive).** Rejected: Andrew explicitly named spawn as the resolution mechanism for prompt-blocked workers. Direct-directive doesn't unstick a structurally-blocked session.
- **MSTR self-resolves by directly executing the work.** Rejected: violates Art. VI (MSTR is governance, not execution) + Tier-discipline. The new agent does the work; MSTR routes the work to the new agent.
- **CTO authorizes the spawn instead of MSTR.** Rejected: spawn/kill is MSTR's domain per Andrew 2026-05-22 ruling (creator/destroyer). CTO advises on architectural questions; MSTR provisions.
