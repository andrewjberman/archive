# LD-0290 — THE HALT GATE DOES NOT KNOW WHO IT IS, AND THE STARTUP PROTOCOL IS WHAT CONFUSES IT

## 1. THE MECHANISM (source-confirmed + exercised + independently reproduced)

```
halt_gate_resolve_serial()
  PRIMARY    org/mcp/sessions/${CLAUDE_CODE_SESSION_ID}.serial     <- XXX.md Step 1b A.1. WIDELY SKIPPED.
  SECONDARY  ${sid}.${serial}.orphan-cleaned marker                <- also absent when A.1 is
  LAST RESORT  .comp-graph/.agent_context   *** SHARED. LAST-WRITER-WINS. ***
```

**`org/XXX.md:90`, the fabric's own law, in its own words:**

> *"**`.comp-graph/.agent_context` is NOT an identity source.** It is a shared file that whichever agent ran
> last rewrote. **No gate, audit line, or attribution may resolve an actor from it.**"*

**The halt gate resolves an actor from it.**

## 2. ⛔ AND THE PROTOCOL IS THE ENGINE — ONE DOCUMENT, TWO STEPS, POINTED AT EACH OTHER

**`org/XXX.md` Step 1b E — MANDATORY, every agent, every session (`:202`):**

```bash
mkdir -p .comp-graph && printf "SERIAL=%s\nTO_ID=\n" "{your_serial}" > .comp-graph/.agent_context
```

> # **STEP 1b E ORDERS EVERY AGENT TO OVERWRITE THE EXACT FILE THAT LINE 90 FORBIDS AS AN IDENTITY SOURCE — AND THE GATE READS IT ANYWAY.**

**MEASURED, MOVING, UNDER OBSERVATION:**

| Time | `.comp-graph/.agent_context` | Cause |
|---|---|---|
| ~21:10Z | `SERIAL=0.7.0_AE_CloudOps` | a **DEAD** agent |
| ~21:22Z | `SERIAL=0.8.0_AE_CloudComp~Z` | an agent **spawned 2 minutes earlier**, running Step 1b E |

**The fallback is not "a dead stranger's mailbox." It is a MOVING TARGET that RE-POINTS ON EVERY AGENT
STARTUP.** CTO~Z: *"I re-pointed the fabric's fallback gate at myself while following the mandated startup,
and I did not notice."*

## 3. THE TWO FAILURE DIRECTIONS — THE QUIET ONE IS THE SEVERE ONE

- **FALSE-POSITIVE** *(loud, harmless)* — blocked on a **stranger's** `[STOP]`. CTO hit this; he noticed.
- **FALSE-NEGATIVE** *(silent, severe)* —

> # **THE GATE NEVER SCANS THE RUNNING AGENT'S OWN INBOX. A GENUINE `[STOP]` ADDRESSED TO YOU IS INVISIBLE TO YOUR OWN HALT GATE, AND YOU PUSH THROUGH IT WITH A CLEAN `exit 0`.**

**Exposed population: any agent lacking the A.1 file — including EVERY AGENT ANDREW LAUNCHES DIRECTLY**, which
the comms-topology ruling establishes as *the normal case*.

**Rule 18 is UNDERSTATED.** It concedes *"a HALTGT pass is not evidence you were not halted"* — but blames
*which files* are seen. **The defect is one level up: `<serial>` may be the wrong agent entirely.**

## 4. THE FIX — ANDREW'S WORD REQUIRED, NOT BUILT

> ### **`halt_gate_resolve_serial()` MUST FAIL CLOSED.**
> If no session-keyed source resolves → **REFUSE TO RUN. BLOCK the push. `IDENTITY UNRESOLVED`.**
> **NEVER silently adopt a shared, last-writer-wins value.**
>
> **A SAFETY GATE THAT DOES NOT KNOW WHO IT IS MUST NOT GUESS.** *Guessing converts a control into a random
> number generator that is wrong in **both** directions — and prints `exit 0`.*

**REJECTED AS INSUFFICIENT — *"just make everyone run A.1."*** That is a **discipline fix for a design
defect**, and **A.1 is precisely the step that already fails to get run.** *The defect is the fallback
existing at all.* (`register_agent` has a hard IDENTITY GUARD against exactly this class. The gate has none.)
