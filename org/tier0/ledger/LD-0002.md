# LD-0002 — Charter the COO to triage every Active row in REGISTRY.md

## Decision
Delegate to the COO (`2.0.0_SA_COO`) the D-001 PHASE 1 ground-truth step: triage
every Active row in `org/projects/REGISTRY.md` into a definitive disposition —
complete / superseded / cancelled / genuinely-active / on-hold-with-named-blocker
— authority being each project's `org/projects/{CODE}.json` plus git/artifact
state, not the row narrative. The COO's 2026-05-22 startup NOTE already flags ~20
dormant rows (zero git activity 7+ days) as "pending an Andrew working session";
D-001 now authorizes that triage to proceed. Output: every Active row resolved,
JSONs updated, a triage summary back to MSTR. This is the gate before PHASE 1
project-completion drives can be sized.

## Provenance chain (Art. XIII)
D-001 (active, ignition-valid) -> PHASE 1 scope verbatim: "first establish ground
truth: triage every Active row in org/projects/REGISTRY.md into complete /
superseded / cancelled / genuinely-active / on-hold" -> the REGISTRY is the COO
lane -> charter the triage to the COO.

## Why now
D-001 PHASE 1 names this as the FIRST action — "so 'all active work' has a
definition before it is pursued". Nothing else in PHASE 1 can be correctly sized
until the active queue is known. mandate_distance 0 — directly stated.

## Assumptions
- Per-project current state is authoritative in each `{CODE}.json` (per the
  COO's own REGISTRY NOTE).
- The COO can triage with read-only investigation + Tier-2 probes where a JSON
  is itself stale; deep per-project re-validation is PHASE 2, not this triage.

## Alternatives considered
- MSTR triages directly — the triage is read-only meta-analysis MSTR may do, but
  the row/JSON edits and any reprioritization are COO-lane; chartering keeps
  govern-through-the-org and gives MSTR an independent COO product to verify.
- Wait for an Andrew working session — superseded: D-001 is that authorization.

## Rollback plan
Triage dispositions are recorded decisions, not destructive acts; any
misclassification is corrected by a follow-up COO pass. No project is deleted —
closed rows move to Completed/Archived with a reason and remain in git history.

## Downstream
- Agents affected: 2.0.0_SA_COO (executes), Tier-2 probes as the COO scopes
- Paths touched: none by MSTR; COO will touch REGISTRY.md + project JSONs
