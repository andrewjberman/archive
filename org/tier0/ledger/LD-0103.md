# LD-0103 — Tab-title COMBO fix (wt.exe --title + suppressApplicationTitle: true)

## The empirical tree resolved

Three cumulative empirical fires today on the tab-title structural problem:

| LD | Approach | Empirical Result |
|---|---|---|
| LD-0099 §M1 | Launch-time OSC 0 emit + `$Host.UI.RawUI.WindowTitle` set in spawn-agent.ps1 + ajb.ps1 | INSUFFICIENT — claude.exe runtime OSC 0/2 emits override at runtime |
| LD-0101 | Add `suppressApplicationTitle: true` to WT profile defaults (alone, no other change) | REGRESSED — WT fell back to displaying full commandline path "C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe" because no profile match + no launch-time-WT-set title |
| LD-0102 | Refactor spawn-agent.ps1 to use `wt.exe -w new new-tab --title <Serial>` (with semicolon-escape) | PARTIAL — wt.exe --title SUCCESSFULLY set initial title at creation; but claude.exe runtime OSC override took over post-launch (tab showed "Deploy ClientPlatform v0.4.0 portal items" — a TO-context summary claude.exe emitted) |
| **LD-0103 (this LD)** | **COMBO: wt.exe --title (LD-0102) + suppressApplicationTitle: true re-enabled** | EXPECTED — wt.exe sets initial cleanly; suppression blocks claude.exe override; tab persists at "<Serial>" |

The LD-0101 regression was specifically due to suppressApplicationTitle: true ALONE without an explicit initial-title set. LD-0102 paired with re-enabled suppressApplicationTitle resolves both failure modes:
- wt.exe --title provides the initial (avoids commandline fallback that broke LD-0101)
- suppressApplicationTitle blocks claude.exe runtime override (the gap LD-0102 alone didn't close)

## The fix

User-local Windows Terminal settings.json (path: `%LOCALAPPDATA%\Packages\Microsoft.WindowsTerminal_8wekyb3d8bbwe\LocalState\settings.json`):

```diff
-        "defaults": {},
+        "defaults": {
+            "suppressApplicationTitle": true
+        },
```

(Identical edit to LD-0101's revert + this re-application; the diff is the same as LD-0101 was). 

## Affected behavior

- **NEW spawns post-LD-0103:** tab title set by wt.exe --title at creation; claude.exe runtime OSC sequences IGNORED (suppressApplicationTitle); tab persistently displays "<Serial>".
- **EXISTING spawned windows (10+ alive at edit moment):** their current titles persist until claude.exe attempts another OSC 0 emit (which will then be blocked) OR window restart. May not visually refresh immediately for existing tabs — best validated on next spawn.

## Why this is the right answer (not another iteration)

The empirical tree above is exhaustive across the three independent mechanism layers:
1. **In-shell title-set (OSC + WindowTitle pre-claude):** LD-0099 §M1 — necessary belt-and-suspenders fallback for non-WT environments
2. **WT initial-title at tab-creation:** LD-0102 wt.exe --title — provides explicit initial that WT honors at render
3. **WT runtime-override-block:** LD-0103 suppressApplicationTitle: true — blocks claude.exe + any inner CLI from changing the WT-set title

Each layer addresses a distinct failure mode. (1) without (2)+(3) doesn't survive claude.exe runtime. (2) alone (LD-0102 partial) gets overridden by claude.exe. (3) alone (LD-0101) breaks because no initial is set. ALL THREE together is the structurally complete fix.
