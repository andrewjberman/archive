# LD-0260 -- /kill storage (allowlist-only rm -rf disk reclaimer)

**What.** Third mode of the `/kill` skill (LD-0259) + `.tools/kill-storage.ps1`. Reclaims disk from known
junk areas -- dead Claude scratchpad session dirs, user/Windows temp, crash dumps by default; package caches,
workspace __pycache__, recycle bin, and docker prune as opt-ins. DRY-RUN default; `go` to delete.

**Why the model is inverted (allowlist, not denylist).** Recursive deletion is unrecoverable and on the
CLAUDE.md human-confirmation list, so the engine NEVER deletes anything that is not a strict descendant of one
of 7 vetted junk roots -- the repo tree is out of reach (except a dir literally named __pycache__ under
--pycache), reparse points/junctions are refused, and every target is re-validated at delete time. Live
sessions are protected by current-session-id exclusion + a 2h scratchpad stale-gate.

**Why S2 / irreversible.** Unlike LD-0259's process reaper (S1, reversible), deletion cannot be undone -- hence
S2. Validated DRY-RUN: ~7.3GB reclaimable on this host with the current + 6 live sessions protected (244/251
scratchpad dirs targeted), opt-ins enumerating, docker daemon-down reported skipped. No deletion executed by
this commit. Reversible-as-code by revert; the deletions it later performs are not.
