# LD-0489 — /email-check, designed against the mailbox rather than against the idea

## Decision

Ship `/email-check` (`.claude/skills/email-check/SKILL.md`) plus its allowlist
(`.claude/skills/email-check/contacts.yaml`). Keep on **sender identity**; drop everything else; **always print the
residual**.

## ⛔ Two of the original rules are NOT implementable on this gateway, and that was measured first

`list_recent_email` hard-codes its `$select` to `id, subject, from, receivedDateTime, isRead,
bodyPreview`. Consequently:
- **"Solo recipient" is not computable** — no `toRecipients`/`ccRecipients`. It would cost one
  `read_email` per message, ~60 calls per run.
- **"A reply to something I sent in the last 2 weeks" is not computable by header** — no
  `conversationId`, no `internetMessageHeaders`; and `search_email` probed as full-text, sparse and
  non-recency-ordered, so **Sent-Items enumeration is UNCONFIRMED**.

⭐ **ANDREW'S OWN SIMPLIFICATION DISSOLVED BOTH, and it is worth naming why rather than treating it as a
convenience:** allowlisting keys on `from`, the one field the API returns — **one call per page instead
of sixty reads** — and **the allowlist SUBSUMES the reply rule**, since anyone he wrote to is on the list
and their reply is kept by the sender test. The single case that escapes — a first-ever reply from a
newly-contacted person — is exactly what the mandatory residual surfaces.

## ⭐ The finding that shaped the rule: A PERSON-SHAPED SENDER IS NOT SIGNAL

Measured over ~55 messages / 3 days: `cgavigan@bairdstrategas.com`, `drissmiller@bairdstrategas.com`,
`sean.farrell@fundstrat.com` are **named humans writing "Andrew, ..."** — and all are bulk research
distribution, **12 in 3 days**. A rule that rewards a real-looking human name leaks badly. Conversely
`marketing@49financial.com` is a **real partner domain sending noise**. **So the rule must be
domain-allowlist x local-part-denylist; neither half works alone.**

**Measured signal set (8 of ~55):** Yang Liu x2 (FW: Short Sale Avail File), Manav Shah x2 (Market Update
+ Re:), Yang Liu (OCIO IC agenda), Austin Graff (OCIO IC invite), AJ Graff (RE: Automated Encryption),
and `[Opal][RED] Infrastructure Report`. **`@opalinvest.com` alone caught 7 of 8 with ZERO false
positives in the sample.**

## Three forks, and how they were ruled

1. **Automated-but-ours.** `noreply@opalinvest.dev` delivered an actionable `[Opal][RED]` report; a
   blanket noreply block drops it. **Carved out by explicit address** in `allow_addresses_automated`,
   deletable in one line.
2. **Cadence — AD-HOC ONLY.** A scheduled inbox checker that notifies IS a monitor, and that sits inside
   the standing alert/monitor moratorium. **Not scheduled, not croned, not wired to a Monitor.** A
   cadence needs a fresh Andrew word.
3. **Seeding.** `opalinvest.com` (evidenced), `thewhitelabelcreative.com` (Andrew-named),
   `49financial.com` (**INFERRED** from partner status + inbox presence, marked as inferred in the file
   so it can be deleted without archaeology). Nothing else invented.

## The residual is half the skill, not a nicety

⛔ **A FALSE NEGATIVE IS THE ONLY EXPENSIVE ERROR HERE.** A dropped real message is invisible forever; a
false positive costs one line of reading. So every run prints the dropped count and the **distinct
unknown senders**, which both exposes the expensive error and is the mechanism by which the allowlist
grows. **The skill never edits the allowlist itself** — Andrew adds the line.

## Cost, rollback, non-application

Cost: one API call per run and the two files. Rollback: delete the skill directory and the YAML; nothing
else references them. **Non-application:** it mutates no mailbox state (no read-marking, moving,
deleting, drafting or sending), persists no message bodies or subjects to the repo, and grants no egress
— `send_email`/`reply_email` remain outside it and outside ordinary autonomy.
