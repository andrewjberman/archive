# LD-0004 — Charter the CTO to extend the inbox-watch.sh agent-folder resolver to include tier0_exec/

## Decision
Delegate to the CTO (`1.0.0_SA_CTO`) a one-line extension of `org/mcp/inbox-watch.sh`
to add `tier0_exec` to its agent-folder resolver loop (currently
`for tier in tier1_exec tier2_senior tier3_junior` at lines 60-67). This is a
faithful extension of LD-0001, whose chartered outcome was "first-class broker
agent ... with a watchable inbox" — the broker resolver was patched in commit
`41a6da79f`, but `inbox-watch.sh` has its own independent folder resolver that
was not updated in the same change. Empirically falsifiable: a tracked watcher
launch this cycle (Bash task `b9ikhrvqi`) exited rc=1 with
`ERROR: No agent folder found matching '0.0.0_AB_MSTR'`.

Charter states the outcome (MSTR runs a working `inbox-watch` against the
existing `org/tier0_exec/0.0.0_AB_MSTR/` folder), not the implementation — but
the diagnostic in `inbox-watch.sh:60-67` is sufficiently precise to land the
fix without a second round-trip.

## Provenance chain (Art. XIII)
LD-0001 ratified by ship (commit `41a6da79f`, registration verified) → charter
scope "watchable inbox" not fully delivered (empirical: watcher rc=1) →
identified gap is a one-line resolver mirror of the same `TIER_DIRS` pattern
already shipped → charter the extension through Tier 1 (CTO), same lane that
shipped LD-0001. The provenance is closed: the authority is the ratified
LD-0001 scope (`authority_source: ratification`), not a new strategic move.

## Why now
This cycle. MSTR is broker-LIVE and can pull `check_inbox` / `get_agent_status`
at top-of-turn (the documented zero-watcher fallback), but real-time delivery
during D-001's mandate window requires the watcher. The fix is small, the lane
is open, and the gap was found by the first MSTR session — leaving it to the
next session would silently degrade response latency for the rest of the
D-001 window.

## Assumptions
- The same Tier-0 lane unlock used for `41a6da79f` (the
  `GIT_COMMIT_AUTHOR_OVERRIDE=TIER0_LAW` override for the owned-paths gate, or
  the standard CTO commit identity for `org/mcp/`) is what the CTO will use.
- `org/tier0_exec/0.0.0_AB_MSTR/` already exists (verified: `logs/`,
  `task_orders/`, `README.md`). No directory work needed alongside the resolver.

## Alternatives considered
- MSTR edits `inbox-watch.sh` itself — rejected: D-001 non_goals bar MSTR from
  editing code; Constitution Art. VI govern-through-the-org.
- Defer to next session / accept zero-watcher operation — rejected: degrades
  D-001's escalation chain latency without an offsetting reason; the fix is
  cheap.
- File as a generic "follow-up" rather than ledgered LD — rejected: a
  delegation is an S1+ commitment and gets a ledger entry per Constitution
  Art. V, however small.

## Rollback plan
Normal reversible commit (revert the `inbox-watch.sh` resolver edit). If
mis-scoped, MSTR amends or withdraws the charter before the CTO commits.

## Downstream
- Agents affected: 1.0.0_SA_CTO (executes), 0.0.0_AB_MSTR (gains working watcher)
- Paths touched: none by MSTR; CTO will touch `org/mcp/inbox-watch.sh`
