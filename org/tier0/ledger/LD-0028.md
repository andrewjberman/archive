# LD-0028 — Codify agent spawn/kill methodology

## Decision

Codify the working methodology for spawning + killing Opal agents into three durable artifacts:

1. **Memory entry** `reference_agent_spawn_kill_methodology.md` — cross-session reference for any MSTR (or other supply-side-authority) session reading workspace memory at startup

2. **Architecture doc** `docs/architecture/AGENT_SPAWN_KILL_METHODOLOGY.md` (chartered to CTO this cycle) — canonical operational doctrine document; pairs with the scripts' inline header comments

3. **/govern SKILL.md spawn/kill section update** (chartered to CTO this cycle) — replaces the current truncated mentions with the full methodology + kill-tracking-gap finding + tilde-lane fallback path

## The methodology (canonical statement)

**Spawn:** `.tools\spawn-agent.ps1 <serial> [optional first-message words]`
- Mechanism: opens a NEW detached PowerShell window via `Start-Process powershell.exe`
- The new window dot-sources `.tools\ajb.ps1` and runs `ajb -Headless <Serial>` (hands-free; `-Headless` drops the `--dangerously-load-development-channels` flag so no Y/N startup prompt stalls the fork)
- Each spawn writes a SPAWN entry to `org/mcp/agent-spawn-audit.log` with: timestamp, serial, spawner (`$env:OPAL_AGENT_SERIAL` if set, else 'unknown'), reason
- The spawned window's PowerShell command-line carries a trailing comment `# OPAL_SPAWN_MARKER_v1 :<serial>` — this is what kill-agent.ps1 greps for to locate kill targets
- Concurrency cap: 8 live spawned-agent windows workspace-wide (counted via `Get-CimInstance Win32_Process` + marker grep); per-spawner cap 3/60s + global cap 5/60s when invoked from another agent; manual Andrew spawns uncapped
- Audited bypass: `$env:FORCE_SPAWN = '<reason>'` writes a FORCE-SPAWN entry to audit log + proceeds
- Invocation: **PowerShell tool only** — Bash cannot run `.ps1` scripts directly (`syntax error near unexpected token 'newline'` on `param(`). Use the PowerShell tool from agents

**Kill:** `.tools\kill-agent.ps1 <serial> -Reason "<text>"` (or `-All -Reason "..."`)
- Mechanism: `Get-CimInstance Win32_Process -Filter "Name='powershell.exe'"` → filter by CommandLine LIKE `*# OPAL_SPAWN_MARKER_v1*` → match serial substring → walk process tree (powershell → claude → ...) with `Stop-Process -Force`
- Each kill writes a KILL line to `org/mcp/agent-spawn-audit.log` with: timestamp, serial, killer (`$env:OPAL_AGENT_SERIAL`), reason
- `-Reason` defaults to `"reallocation"` if omitted; required for audit discipline
- Kills are NOT subject to concurrency cap (they release budget)
- Any agent can request a kill — enforcement is by audit, not gate; spawn/kill is MSTR's domain by Constitution Art. VI + Andrew ruling 2026-05-22 ("MSTR = creator and destroyer")
- Invocation: **PowerShell tool only** (same Bash-can't-run-ps1 constraint)

**Kill-tracking gap** (empirical finding 2026-05-24T02:00Z, CY-0057):
- `kill-agent.ps1` ONLY finds windows whose command-line carries the `# OPAL_SPAWN_MARKER_v1` comment
- Windows launched outside spawn-agent.ps1 (manually started, system-restart-recovered, started before MSTR was alive in this session) do NOT carry the marker → invisible to kill-agent.ps1
- Returns: `[kill-agent] No live spawned windows for serial '<serial>' found -- nothing to kill.` even when broker shows the serial LIVE with valid PID
- Force-kill path: `Stop-Process -Id <PID>` directly via PowerShell tool (PID obtained from `liveness.json` or `get_agent_status`) — **destructive-without-marker-audit class**; requires Andrew explicit per-instance authorization OR LD-entry chartering the destructive action

**Tilde-lane fallback when kill structurally unavailable:**
- LD-0021 SPAWN-WITH-DIRECTION contemplates "original session is killed or left to time-out per situation"
- When kill-tracking gap fires on the target: spawn replacement under next-free tilde-lane suffix (`~D`, `~E`, etc.) + leave original to natural time-out
- Tilde-lane spawn DOES carry the marker (spawn-agent.ps1 launched), so future kills on the new tilde-lane work normally
- Empirically validated: LD-0027 fired this path on DS Base STALE cycle-3 (CY-0057 `17fb97415`)

**Lane discipline notes:**
- Spawned serials must match the regex `^[0-9]+\.[0-9]+\.[0-9]+_[A-Za-z]+_[A-Za-z0-9]+(~[A-Za-z0-9]+)?$` per both scripts' sanity check
- Tilde suffix preserves tier classification (`~B` of a Tier-2 agent is still Tier-2; LD-0021)
- New tilde-lane spawn: original agent's owned-paths inherit; first commit to a new path-class may need COO `.owned-paths.yaml` update per banked memory `feedback_tilde_lane_owned_paths_gap_route_to_coo.md`
- Channel push: brand-new tilde-lane MCP delivery initially shows "filesystem + broker" (no channel push) until the new agent registers via `register_agent` — full delivery resumes post-registration

## Why now

Today's session exposed two operational findings worth durable-codifying:

1. **PowerShell-only invocation** — Bash tool cannot run `.ps1` scripts (CY-0057 attempted bash invocation produced parser error). Codifying this saves future agent sessions a debug cycle.

2. **Kill-tracking gap** — manually-launched windows are invisible to chartered kill mechanism (CY-0057 empirical discovery on DS Base). Without codification, future sessions will hit the same surprise. Documenting the tilde-lane fallback gives them a clean path.

Plus Andrew's confirming "It is through launching a new powershell, yes" makes the codification opportune — the mechanism is sovereign-confirmed.

## Assumptions

- Scripts at `.tools/spawn-agent.ps1` + `.tools/kill-agent.ps1` remain canonical (any future replacement updates the codified doctrine).
- PowerShell version on the workspace remains 5.1 (per system prompt; affects script syntax compatibility).
- `ajb.ps1` continues to be the canonical agent-launcher entry point (dot-sourced by spawn-agent.ps1).
- `OPAL_SPAWN_MARKER_v1` may bump to v2 if marker format changes — codified doctrine should be marker-version-agnostic (use the "current marker" not the literal v1).

## Rollback plan

Codification is purely documentative — no operational risk. Rollback = delete the new artifacts (memory entry, architecture doc, SKILL.md section). Scripts themselves unchanged; if scripts evolve in a way that invalidates the doctrine, update the doctrine in place rather than rolling back the codification entirely.
