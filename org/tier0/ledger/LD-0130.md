# LD-0130 — Durable-cron decision for machine-sleep resilience (RV-0020 F-002)

**Opened by:** RV-0020 finding F-002 (sovereign-accepted governance review, 2026-05-28).
**Status:** OPEN — reserved for Andrew infra decision.

## §1 — The recurring failure (empirical, 2026-05-28)

A machine sleep (~2.3hr) suspended the host. On resume:
- Every agent's **session-only** CronCreate loops (`/watcher`, `/work`, `/drive`, MSTR `/govern` + `/mstr-review`) were dropped — they live in the Claude REPL's in-memory scheduler, not on disk.
- The failure was **silent**: broker registration stayed green (residual state + whichever cron happened to survive re-armed the heartbeat), while the substantive driver loop had stopped. An agent looked LIVE while frozen.
- Result: ws COO `/drive` dead → wedge; 9/11 ws FIND_INSURE workers deaf+frozen; CL Tier-1 wedged. Required three MSTR respawn interventions to recover.

This was the SECOND such event in the session — establishing it as a recurring structural risk, not a one-off.

## §2 — Proposed risk-reduction (for Andrew decision)

Option A — **durable:true on load-bearing crons.** Persist `/watcher` + `/work` (+ Tier-1 `/drive` / `/ws-charter` / `/spot-check` + MSTR `/govern` / `/mstr-review`) to `.claude/scheduled_tasks.json` so they reload on session resume. Pro: self-healing across restarts/sleep. Con: unverified whether durable reload fires correctly on THIS host's sleep/resume (vs. full process restart); per-agent change.

Option B — **sleep/resume hook.** A host-level or harness hook that re-arms the canonical loops on wake. Pro: single mechanism, explicit. Con: more infra to build/maintain.

Option C — **status quo (MSTR loop-health respawn).** Rely on MSTR detecting wedges (frozen summaries + commit-silence + watcher-status) and respawning. Pro: proven this session, no infra change. Con: manual, reactive, leaves a stalled-work window until MSTR notices; depends on MSTR itself surviving the sleep.

## §3 — Recommendation

Lean Option A for the worker `/watcher` + `/work` crons (cheapest durable win, directly addresses the deaf-worker class) + keep Option C (MSTR loop-health) as the backstop regardless. Validate durable-reload behavior on one agent across a real sleep before fabric-wide rollout. Defer Option B unless A proves unreliable.

**Andrew decision needed:** which option(s), and whether to test durable-reload on this host first.
