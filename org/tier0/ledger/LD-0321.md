# LD-0321 -- Two verification edges from the verifier's own miss: input-reachability + state-file-over-comment

## Chain

3.0.0_SA_CVO 230515Z (retraction-grade self-correction: passed a false WS-7 claim, ~Z caught it, CVO owned +
extracted the doctrine) -> flagged as a CONTROLS_OVER_CARE candidate -> MSTR ground-checked the enforce-marker
(claim genuinely false) -> folded into docs/doctrine/CONTROLS_OVER_CARE.md III-a.

## What is folded

Two edges into CONTROLS_OVER_CARE.md III-a (both quoted-block, doctrine-grade):
1. **Input-reachability** -- an exercise on an input outside the control's governed domain proves nothing;
   the input must REACH the governed case, or the GREEN is a comfort not a control.
2. **State-file > describing-comment** -- a live state (enforce-marker / applied config / live primitive)
   beats prose that describes the default; when they disagree, the state wins.

## Why it matters (the meta)

This is the deepest instance of the session's theme: the verification REGIME caught its own VERIFIER passing
a false verdict, and the verifier self-reported + banked the lesson. A control that can catch its own
controller is the strongest form of the discipline -- and the edge it revealed (a false-exercise on a
non-reaching input) is one neither the brief's discipline nor the earlier folds covered.
