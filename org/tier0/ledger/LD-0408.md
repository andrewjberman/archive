# LD-0408 -- the agentbus blind spot: a non-ASCII character could take down the only cross-device channel

## Measured symptom (two windows in one session, laptop consumer)

| # | deaf window | duration | found by |
|---|---|---|---|
| 1 | 17:12:31Z -> 20:20Z | ~3h08m | **Andrew asking** "is agentbus not working?" |
| 2 | 21:51:58Z -> 22:21Z | ~29m | proactive check |

Both windows: `TaskOutput(<consumer>)` reported **"running" throughout**; peer messages piled up as
`NotVisible`; re-arming restored delivery for minutes and then failed again.

## Root cause -- source-confirmed, not inferred

`agentbus-consumer.py:83` emits the **raw message body** to stdout. On Windows python's stdout
defaults to the ANSI codepage (cp1252) and the file carried **no encoding guard of any kind**. A
single `U+26A0` (warning sign) in a peer's body raised `UnicodeEncodeError` and killed the process.

The failure surfaced differently per path, which is why it took two windows to catch:
- `watch` (the consumer): **SILENT.** The python died; the Monitor **wrapper** survived, and the
  harness tracks the wrapper -- so the check `/agentbus` calls *"the only one that observes a
  consumer"* reported healthy against a dead reader.
- `recv`: **LOUD BUT MISLEADING** -- `aws sqs receive-message FAILED (rc=255) -- this is NOT an
  empty queue`, with the real cause (`'charmap' codec can't encode character '⚠'`) buried in
  the dump.

## THE POISON PILL -- why the safety property became the trap

The consumer's own docstring is correct that emit-then-delete means *"a death between the two
redelivers a DUPLICATE after the visibility timeout, never a loss."* True. **But the redelivered
duplicate carries the same bytes**, so it kills the next consumer too, and the next. The queue head
becomes permanently un-consumable and every re-arm dies on it within one poll.

**A design that is correct about not losing messages was silently guaranteeing they were never
delivered.** That is the whole shape of the outage, and it is why re-arming "worked" briefly and
then did not.

## The fix (both paths, because both print bodies through python)

- `.tools/agentbus-consumer.py` -- `sys.stdout/stderr.reconfigure(encoding="utf-8",
  errors="backslashreplace")` at import time, guarded so the guard itself cannot raise.
- `.tools/agentbus-sqs.sh` -- `export PYTHONIOENCODING=utf-8` at the top. **Exported, not set
  per-call, deliberately**: it must reach the exec'd consumer, the AWS CLI, and anything either
  spawns. One missed call site reopens the class.

**Verified by exercise, not assertion:** the exact message that had been killing consumers all
evening (`8e852a16`, containing the U+26A0) was delivered intact after the fix, followed by the
rest of the backlog.

## WE CAUSED IT, AND THE RULE ALREADY BANNED IT

`CLAUDE.md`: *"No emojis (no non-ASCII) in production code, logs, or anything that runs on AWS --
breaks CloudWatch/**charmap**, grep, CI stdout."* The rule names the exact failure, using the
error's own word. Both MSTR seats put `⚠`/`⛔` into bus bodies all day and took down the only live
cross-device channel with it.

**So the fix has two layers and only one of them is a control.** Senders must keep bodies ASCII --
that is the rule, and it is hygiene. But **a rule that depends on every peer remembering is not a
control**; the encoding guard is. A peer that violates the rule must now degrade one character,
never take down the channel.

## Device-agnostic by construction (LD-0405)

The defect is identical on site Z -- their consumer simply had not yet met a non-ASCII body. The fix
lives in the repo and propagates by git, which is the property LD-0405 requires of a foundational
cross-device tool. No per-device action beyond a pull.

## What this does NOT fix

- **The liveness check is still wrong.** `TaskOutput -> running` observes the Monitor *wrapper*, not
  the consumer process. A consumer that dies for any *other* reason is still invisible. This ledger
  does not close that; naming it is the honest half.
- No monitor/alerter was built (standing moratorium). The rectification is making the consumer not
  die, per Andrew's own routes-first doctrine.

## Rollback

Revert two hunks. No state, no contract change, no message-format change.
