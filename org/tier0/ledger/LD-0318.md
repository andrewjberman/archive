# LD-0318 -- Charter NFRA_SYSPARITY (system/sdk <-> reality parity) + name NFRA_ONTOCLARITY (Part 2)

## Chain

Andrew-direct this session -> MSTR 4-domain grounded parity analysis (4 analysts + live-verification) ->
brief authored (docs/briefs/NFRA_SYSPARITY_BRIEF_20260719.md) -> charter NFRA_SYSPARITY + issue to CTO for
the PRD -> name NFRA_ONTOCLARITY as the sequenced Part-2 sibling.

## What is chartered

**NFRA_SYSPARITY** -- establish + close the parity between infra/system+sdk and the live reality across the
compiler/graph plane, and convert parity-maintenance from care into a fail-closed control. Owner/PRD:
1.0.0_SA_CTO. Recommended workstreams (CTO PRD refines): WS-1 scope contract (do first) / WS-2 de-stale +
GATE 06 / WS-3 complete the drift-gate denominator / WS-4 represent the ontology / WS-5 exercise the SDK at
cloud tier or rule local-only sufficient / WS-6 incorporation-debt SLA / WS-7 describe the rail + small honest
lags / WS-8 resource-manifest cross-walk. Full findings + the per-domain parity + the scope ruling: the brief.

**NFRA_ONTOCLARITY (Part 2, named-not-yet-built)** -- a separate ontology semantic-clarity audit: no fog in
layering/nesting/definitions/processes, then correctly logged + referenced in system+sdk. Seed: the 10 fog-
spots in the brief (§8). Sequence: after SYSPARITY WS-1; feeds WS-4. To be chartered as its own project when
SYSPARITY's scope contract lands.

## Scope ruling (MSTR RECOMMENDATION -- CTO/Andrew confirm; NOT applied)

1. HOLD the declared boundary (pipeline estate + taxonomy plane stay out -- they have their own homes).
2. Rule the ONTOLOGY IN scope (it is the semantic core the compiler plane reasons in, not a sibling estate);
   its ~40% parity is a real gap to close.
3. Make every exclusion EXPLICIT + auditable in the README (sibling-class + pointer), so scoping is never
   confusable with oversight.

## Verification regime (Andrew-direct 2026-07-19, STANDING for the life of NFRA_SYSPARITY)

3.0.0_SA_CVO spot-checks EVERY assumption/finding in this brief, **BY DOMAIN** (comp-tools / infrastructure
/ engineering+learning-loops / ontology), **AS THE WORK IS DONE** -- a continuous re-grounding, not a
one-time sign-off. **Validation basis per item:** `/molecule` (atomic deep-dive on the exact unit an
assumption rests on -- the file, the value, the artifact, the live state), `/verify` (3-axis
mechanical/declarative/semantic correctness of the claim), and `/prd-delta` (project completeness vs the CTO
PRD as workstreams land). **CVO arms an ONGOING 30-MIN `/loop` in its OWN session** that nudges it to verify
MORE items each fire -- a burn-down of the per-domain assumption list, not a fixed pass; MSTR cannot arm it
in CVO's session, so CVO owns the arm (re-armed each CVO session while the project is active). **Every
finding in the brief is an ASSUMPTION until CVO independently re-grounds it; a workstream is not `done` until
its domain's assumptions are CVO-verified on this basis.** Rationale (Andrew-direct + doctrine): the project
is about whether representation matches reality, so the audit's OWN findings must be EXERCISED, never trusted
-- Rule 22a + the self-referential CHECK-LIVE-NOT-FROZEN lesson this project embodies (an audit that trusts
its own report re-certifies the exact frozen-not-live class it exists to catch). This regime is IN ADDITION
to the normal per-deliverable RAVC + CTO arch-gate, not a replacement.
