# LD-0155 — /fabric-check: fused telemetry+status display + COO /drive + /govern integration

## What Andrew asked
1. Check the telemetry function's accuracy (clean/clear). 2. If accurate, check the agent
"status" (should say what they're working on, or if not working declare available/idle or
blocked + what blocked on). 3. Build a `/fabric-check` skill displaying this — any agent ad
hoc; COO chains it into `/drive` (because the crucial `/drive` job is keeping the fabric
flowing; most is event-driven/self-healing, but single blocks hold up whole projects/the
fabric and COO must resolve them). 4. Sovereign-class blocks declared by COO; MSTR `/govern`
checks for COO sovereign-decision-requests + issues the ruling if Andrew silent 1 turn.

## 1 — Telemetry accuracy: VERIFIED CLEAN
PostToolUse `*` hook -> `.tools/hooks/post-tool-telemetry.sh` -> per-serial
`org/mcp/agent_telemetry/{serial}.jsonl` `{ts, ts_unix, serial, tool_name, kind, serial_source,
session_id}`. Privacy-safe (tool_name only, never args/outputs). Live agents' files are fresh
to the second; serials resolve correctly (session-id-keyed / fallback both land right). It
fires and is accurate.

## 2 — Status quality: GOOD but inconsistent on the idle/blocked declaration
Working agents state their work clearly. The "not-working -> available vs blocked" distinction
is loose (several say "awaiting"/"standing by"/"/work armed" implying idle without the explicit
taxonomy). `/fabric-check` infers from telemetry+keywords AND flags NEEDS-STATUS where no clear
state is declared, to drive adoption of: `WORKING: <task>` / `IDLE: available` /
`BLOCKED: <what>` / `BLOCKED-SOVEREIGN: <decision>`.

## 3 — /fabric-check (built + tested live)
- **Engine** `.tools/fabric-check.py` (+ PATH wrapper `.tools/fabric-check`): fuses objective
  telemetry-derived dual-signal liveness (LD-0070) with the declared broker summary; buckets
  WORKING / IDLE / BLOCKED / SOVEREIGN / STALE-VERIFY / NEEDS-STATUS; emits a machine
  `FABRIC-CHECK-RESULT` line + `ACTION-REQUIRED`. Modes: full / `--blocks` (COO triage) / `--json`.
- **Why telemetry-fused:** telemetry is real tool calls -> ground truth, immune to the
  phantom-live + heartbeat-staleness failures of `get_live_agents`. The summary is a claim;
  mismatch (claims-work + telemetry-STALE) -> STALE-VERIFY.
- **Skill** `.claude/skills/fabric-check/SKILL.md`: any-agent ad hoc + the taxonomy + the
  per-bucket actions + the COO /drive integration + the end-to-end sovereign-request flow.
- Live test correctly surfaced real issues: 2 ~A lanes with empty summaries (NEEDS-STATUS) +
  DS "HOLDING build for ruling on 3 decisions" caught as BLOCKED (a single-point hold COO's
  "all ADVANCING" narrative had missed). py_compile + ruff(py39) clean.

## 4 — COO /drive integration
`/drive` Step 2b.0 (new): run `python .tools/fabric-check.py --blocks` FIRST each cycle; for
each BLOCKED resolve-or-escalate this cycle; for each SOVEREIGN declare it (route to Andrew, CC
MSTR); for STALE-VERIFY confirm the owner is alive; for NEEDS-STATUS nudge a state token.
Makes the agent-state scan deterministic; 2b.1-2b.5 remain the deeper cause-classification.

## 5 — MSTR /govern sovereign-request check
`/govern` Step 1 new source: run `/fabric-check` (or read `[SOVEREIGN]` inbox tags) -> any
SOVEREIGN-DECISION-REQUEST is an open subject. Per LD-0090 / Art XVI, if Andrew silent >=1 turn
MSTR issues the ruling (bounded by Directives + Stakes Matrix; genuine S3/S4 still holds for
Andrew). Closes the loop: worker declares BLOCKED-SOVEREIGN -> COO declares up -> Andrew rules,
or MSTR rules in his stead after one silent cycle.

## 6 — get_live_agents false-death incident (Andrew-direct, via COO)
COO hit a live foot-gun: read `get_live_agents`, saw `0.7.0_AE~A` absent, concluded it died,
reassigned its work — but `~A` was alive (telemetry fresh). DIAGNOSIS (re-derived from
server.py + liveness.json): NOT really a suffix-strip. `get_live_agents` `_clean_stale`-PRUNES
any serial whose heartbeat `last_seen_epoch` > 600s; an actively-working `~A` lane that hasn't
heartbeated in >10min (poller/heartbeat lag) gets pruned -> vanishes -> false-death.
`get_agent_status`'s base-fallback (server.py:813) then masks `~A`-absence as base-presence,
which LOOKS like suffix-strip. Same root-cause CLASS as the poller/exit-143 issue (heartbeat
liveness diverging from telemetry). **Read-side fix = /fabric-check (telemetry-based, immune) —
DONE + made canonical for tilde-lane liveness.** **Broker-core fix (migrate get_live_agents /
get_agent_status liveness from heartbeat-pruning to telemetry-derived per LD-0070) = CHARTERED
to infra, folded into the existing poller/liveness fix-charter (same class); NOT MSTR-hot-patched
(broker blast radius + Art VI).** Interim doctrine (COO banking fabric-wide): verify tilde-lane
liveness via telemetry/`/fabric-check`, never get_live_agents-absence.

## 7 — Meta-pattern (Andrew-flagged, banked)
"A tool's blind spot read as ground-truth absence" -- get_live_agents heartbeat-prune +
poller ps|grep false-negative + comp-pipescript NO-MATCH-outside-its-scan-path are the same
class. Principle for comp-* + broker read surfaces: a tool's scope is X; absence OUTSIDE X is
unknown-not-absent. /fabric-check embodies it (STALE-VERIFY = "verify", not "dead"; absence of
telemetry != dead). Banked to memory.
