# LD-0624 -- MSTR auto-launch at log-on on every box, versioned; never-sleep on the Dells

## Decision
Version the site-Z layer-2 launcher (it lived only in `C:\opal-elev\` on site Z) as two `.tools` scripts that derive
the workspace root from their own location, skip any serial already running, and log to the gitignored
`org/mcp/autolaunch.log`. Install on the laptop for `0.0.0_AB_MSTR`. The Dell MSTRs install it for their own serial
and set never-sleep on AC on their boxes; site Z reports its existing always-on command.

## Provenance chain (Art. XIII)
- Andrew-direct ~17:4xZ, verbatim in the `andrew_instruction_ref` record.
- Source mechanism: `org/tier0_exec/0.0.0_AB_MSTR~Z/deliverables/CROSS_FABRIC_20260910_AUTORECOVERY/` (e222f4e4ee).

## Verification
- Both scripts: PowerShell parser 0 errors, 0 non-ASCII characters.
- Laptop: `autolaunch-task.ps1 -Serials 0.0.0_AB_MSTR` registered `OPAL_autolaunch_agents` (state Ready, log-on
  +30 s) with no elevation; `-Status` reads it back.
- Duplicate guard exercised: run while this seat is live -> `SKIP: 0.0.0_AB_MSTR already running (claude.exe PID
  19196)`; nothing launched. The acceptance is the next real reboot: a fire line in `org/mcp/autolaunch.log` and
  the seat registered on the broker.

## Rollback
`powershell -NoProfile -File .tools\autolaunch-task.ps1 -Teardown`, then `git revert` of this commit.
