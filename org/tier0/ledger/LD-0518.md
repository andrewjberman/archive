  D12  Platform Ops                               -> Platform Operations

## The claim "titles only" is ASSERTED, not asserted-in-prose

The edit walks the file line by line and rewrites only the `title:` line inside each `D<n>` block,
so the register's formatting, comments and multi-page `placement` strings are untouched. It then
re-parses and **compares every non-title field before and after, failing the run on any
difference** - members, placement, stance, version, `as_of`. It passed. **A rename that quietly
moved a member would look exactly like this one from the outside**, which is why the check is a
control and not a sentence.

`comp-directives check`: **live=13 retired=1, 0 violations**; PARTITION + CONSERVATION + FORM +
FREEZE all hold.

## His "no downstream dependency" read is CORRECT, and measured

Three consumers read the register - `directives-check.py`, `integrate-directives.py`,
`project_census.py` - and **all three key off the CODE (`D<n>`), never the title string**; titles
are display only.

Census of the old titles outside the register: `Global Pipeline Structure` 23 hits,
`Model Portfolios Pipeline Fortification` 13, `Substrate/Tooling Enhancements` 13,
`Agent Infrastructure (Process Management)` 0. ⭐ **Every hit is a PAST daily-report snapshot**
(`daily_reports/out/*.html`, `daily_reports/data/*.json`). Those are records of what the register
said on their date and were deliberately **not** rewritten - the same rule that keeps the archive
renderable under a retired enum (LD-0511). Tomorrow's report picks the new names up on its own,
because it reads the register.

## ⚠ ONE ITEM FLAGGED, DELIBERATELY NOT ACTED ON

He wrote *"I tried to structure it in a way that doesnt change anything currently registered to a
D(N) item"*. **D10 has one project registered: `GLOBALALARM`.** With D10 renamed to
**Partner Implementations**, a global-pipeline alarm now sits under a partner-implementations
directive - and his own sentence says the global-pipeline work is *"resolutely going to be in D8"*.

**Moving it would be a MEMBERSHIP change, which is exactly what he said this edit was not.** So the
row stays and the mismatch is surfaced instead. **REC: move `GLOBALALARM` D10 -> D8.** It is one
line on his word, and the COO-base tree refactor he mentions may settle it anyway.

## Rollback

Revert this commit. Titles are display strings; no membership, no attribution, no served artifact
depends on them.
