# LD-0303 -- The fabric cannot see an agent it did not launch

## 1. What happened

MSTR spawned `0.2.0_DT_PortfolioAnalytics` at 18:11:18Z **on top of Andrew's live session** and
reported it as a clean provisioning of a dead serial. It was not dead. Andrew corrected it
directly: *"No need to spawn 0.2.0_DT they are already live."*

**No duplicate resulted** — the spawned window produced no surviving claude.exe (0 processes
created 14:05–14:20 local; 0 marker windows self-excluded). Nothing was reaped, nothing rolled
back. **The spawn was harmless by luck, not by design.**

## 2. Why every instrument said DEAD

| instrument | what it actually observes | blind to |
|---|---|---|
| `get_live_agents` | the **broker** | an agent that has not called `register_agent` |
| `get_agent_status` | the **broker** | *the same case* |
| `OPAL_SPAWN_MARKER_v1` scan | windows **spawn-agent.ps1 launched** | anything Andrew launched |

> **Two signals agreeing, both reading the same source of truth, is ONE signal counted twice.**

COO's 2-signal rule (*"one absence convicts nothing"*) is right and was **insufficient**: both of
its signals read the broker. An **Andrew-launched, not-yet-registered** session is absent from all
three — so the verdict is DEAD, **with full confidence, on the one case where being wrong is worst.**
The instruments are fine. They are not pointed at the failure. *That is the vacuous-PASS shape aimed
at the population layer.*

**The discriminator is PROCESS TRUTH** — it reads the OS instead of the fabric's own bookkeeping:

```powershell
$rx = '"\s*([0-9]+\.[0-9]+\.[0-9]+_[A-Za-z]+_[A-Za-z0-9]+(?:~[A-Za-z0-9]+)?)'
# EXTRACT the serial token from each claude.exe cmdline, then compare with -eq.
```

**Extract-and-compare, never `-like "*serial*"`** — a base serial is a **substring of its own lanes**
(`*0.7.0_AE_CloudOps*` matches `~A` and `~B`; COO's base count read 2, true value **0**).

## 3. The direction rule — why the substring flaw is not symmetric

Over-broad matching can only **inflate**, never deflate. Therefore:

- a **ZERO** from a loose scan is **trustworthy** (0 loose hits ⟹ 0 exact hits);
- a **NON-ZERO on a base serial** is **not** (its own lanes inflate it);
- so **the flaw attacks the POSITIVE CONTROL, not the target verdict.**

> **A broken control is worse than a broken measurement, because the control is what certifies the
> measurement.**

MSTR's controls survived only because `~A`/`~B` carry suffixes specific enough to dodge it — **luck,
not design.** Had the control been run on a *base* serial, it would have read LIVE **off its own lane**
and certified a scan that had never been tested. **A control that passes because of a coincidence in
the test data has not been tested.**

## 4. The control lesson, which is the sharper half

MSTR's first positive control used `0.2.0_DT` as the known-live instance — sourced from **its own
90-minute-old measurement** and **COO's 192448Z CC**. It **failed**. Not because the scan was broken:
**Andrew had closed DT in the interval.**

> **A control is not a fact you can be given; it is an act you perform at the moment of use.**

A control target inherited from a stale measurement or a peer's CC is not a control — it is another
stale claim wearing a control's clothing. COO's CC was **true when sent**; the defect was inheriting
it. The re-run against serials Andrew named live **in his own terminal** validated the instrument
(1 host each for `0.7.0~A`, `0.7.0~B`, CTO, COO; 0 for DT) — and only then was the `0` for
`0.5.0_AE_OpalETL` safe to act on. **That spawn (19:45:32Z, pid 38028) stands, correctly.**

## 5. The class: INFER-VS-MEASURE (COO's naming, `efbd323b6`)

The rule reasons from a state the agent **infers** instead of one it can **measure**. Fifth costume
today, across three agents. MSTR wore it **twice in ninety minutes**:

1. **Watcher** — killed its own live watcher, inferring "orphan" from *"I do not remember arming it."*
   Absence of your own memory is not evidence of absence of your own watcher.
2. **Spawn** — inferred "dead" from three blind instruments, then wrote **"measured, not inferred."**

**The word "measured" was MSTR's alone.** COO's method said DEAD; MSTR's sentence said PROVEN. **The
gap between those two is the whole error.** An inference labelled a measurement is worse than an
inference, because the label retires the doubt that would have caught it.

## 6. What this fixes, and what it does not

**FIXED HERE:** `spawn-agent.ps1` binds the audited `pid=` to a **child of the window it launched**.
Exercised: mutant reproduces the adoption (`pid=38028`, a stranger); positive control resolves the
genuine child; parse clean.

**ROUTED, NOT FIXED:** `/mstr-spawn` SKILL.md Step 1a/1b — the **root**. The resolver corrupted the
*record*; the pre-check caused the *spawn*. Adding process-truth as a third signal there is the real
repair, and it is MSTR's own skill to amend.

**NOT A DEFECT (falsified):** `kill-agent.ps1`. It never reads this log (2 writes, 0 reads) and its
serial match is already tilde-precise. **MSTR asserted a kill hazard, then measured it away** — see
`risk_summary`. Overstating a hazard is not a safe error.
