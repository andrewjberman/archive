# LD-0500 -- enforce the no-non-ASCII rule at commit time

## The decision

A `commit-msg` hook refuses any commit whose message contains a byte outside
`\x00-\x7F`. Audited bypass `ASCII_OVERRIDE="<reason>"`; an empty value is refused,
because the reason is the point of the audit row.

## Why it needed a gate rather than a restatement

The rule was already written, in CLAUDE.md, loaded by every seat at session start,
and phrased with its replacements spelled out (`OK:` `WARN:` `ERROR:` `SKIP:`
`BLOCKED:`). It was still broken 83 times in 24 hours by 12 different agents.

> **A rule that is stated, loaded, and unenforced is a rule that is measured in
> violations rather than in compliance.** Andrew had already said it "in many docs";
> the correct response to that is not a fourteenth document.

## What it is NOT

- **NOT a content gate.** File contents are not inspected. Widening it to code and
  docs is a separate decision with real false-positive risk -- existing documents,
  vendor fixtures, data files -- and a gate that refuses legitimate content is one
  that gets disabled wholesale rather than obeyed.
- **NOT a replacement of the existing hook.** A `commit-msg` hook already existed
  (mass-deletion-check). It is chained and runs FIRST: a data-loss refusal must
  never be masked by a character refusal.

## Controls

`--self-test`, five arms, run by the installer which REFUSES to install if it fails:
clean message accepted; the exact U+2B50 that crashed the deploy gate refused;
audited override accepted; **empty override refused**; and the gate file is itself
ASCII -- a gate that violated its own rule would be the obvious failure.

## Cost and non-application

One `grep` over the message file per commit. Merges are **not** exempt: `git commit -F`
on a merge reaches `commit-msg` like any other commit, and merge messages were part
of the measured 19 percent.

## The honest part

This seat contributed 23 of the 197 characters -- fourth-largest of twelve. I had
also recommended, four hours earlier, that this rule be left unenforced, on the
grounds that the deploy gate was now hardened so a violation cost nothing. That
recommendation confused **surviving** the character with the character not being
there, and Andrew's answer corrected it.
