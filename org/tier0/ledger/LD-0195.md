# LD-0195 — Fix the send_message receipt that dropped the ~suffix (recurring false wrong-channel alarm)

## Decision
Corrected `send_message` in `org/mcp/server.py` (line ~1089) to report the ACTUAL
delivery target instead of the base folder name. A send to a `~suffix` recipient now
reports e.g. `delivered to 0.7.0_AE_CloudOps~B (inbox 0.7.0_AE_CloudOps/~B)` rather than
the prior `delivered to 0.7.0_AE_CloudOps inbox`.

## Root cause (ground-truthed against the code + live filesystem)
The recurring "~B suffix was dropped → wrong-channel GO" alarm is a **report bug, not a
routing bug.** Traced the full delivery path for `send_message(to="…~B")`:
- **Filesystem** (server.py:1024-1044): writes to the nested `inbox/{base}/~{suffix}/` dir
  — strictly private per-instance; `check_inbox`/`inbox-watch.sh` for a `~B` serial read
  exactly that nested dir. Empirically confirmed: the 06-17 cold-start ~B first-message
  (135625Z) landed in `inbox/0.7.0_AE_CloudOps/~B/read/` and was consumed by ~B's watcher.
- **Broker daemon** (server.py:1050 → broker.py:397-416): `broker_target` keeps the full
  `…~B` serial; stored verbatim in the messages table; the ~B session polls by its full
  serial. Suffix-correct.
- **Channel push** (server.py:1062-1073): filtered to the matching `~B` instance only.
- **The bug** (server.py:1089): the return string interpolated `{to_folder.name}` (the
  BASE), so EVERY `~suffix` send reported the base inbox — looking identical to the real
  ADVI_DEMOV1.005 wrong-channel-GO failure org/XXX.md documents, even though delivery was
  correct. The cost was real: a verification scramble on every `~B` send (MSTR's own 06-17
  cold-start included).

No messages were ever lost or mis-delivered by this; only the receipt misled.

  not assumed.
- `to_suffix` / `to_folder` are in scope at the return (verified: set at 1024 / 1015).

- Dispatch to DT instead of fixing directly: the diagnosis + fix are trivial and verified,
  Andrew-direct; fixing now + notifying the infra owner (CTO/DT) is faster with equal rigor.
