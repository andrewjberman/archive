# LD-0144 — FE headless-smoke fix: Playwright MCP off bun -> Node (root cause: bun cannot drive Playwright)

## Decision
Fix the fabric-wide automated FE headless-smoke outage by moving the Playwright MCP off `bunx` (bun 1.3.9, which cannot drive Playwright's browser transport) onto a portable **Node v24.16.0** runtime, with the MCP configured to use **system Edge** headless. Also repoint Opal's `.tools/frontend-dev.py` Python runner off the stale chromium-1208 to Edge.

## Provenance chain (Art. XIII)
Andrew direct sovereign instruction 2026-06-02 ("fix the FE headless smoke ... playwright being down ... /frontend-dev stopped working ... all of that needs to be fixed") -> D-001 (drive Opal to done: portal-closure visual-smoke discipline requires a working agent smoke) + D-002 (standing maintenance: fix the broken tooling) -> empirical root-cause diagnosis (bun transport incompatibility) -> the fix. Chain closed.

## Why now
The outage blocked the portal-closure-needs-visual-smoke discipline fabric-wide for ~1+ day (memory reference_fabric_headless_chrome_block); every portal close fell to Andrew manual. Andrew directed the fix this session.

## Diagnosis trail (empirical)
1. Bundled chromium 1223 binary + `--dump-dom` data URL: works in 2.9s, no GCM error -> browser healthy; the GCM log is not the cause.
2. Live MCP `browser_navigate` (data URL): hung to 180s, launching SYSTEM Google Chrome (managed v148) with GCM DEPRECATED_ENDPOINT loop -> @playwright/mcp@latest defaults to the system Chrome channel.
3. System Chrome + Edge + bundled chromium binaries all work standalone (--dump-dom / CDP HTTP via curl).
4. Playwright launch UNDER BUN (chromium.launch): ALL THREE channels timed out at 35s. bun connectOverCDP to a port-launched chrome (curl reached it): timed out 20s. => bun fails Playwright transport over BOTH pipe AND websocket, for every browser.
5. Node not installed. Installed portable Node v24.16.0. Playwright launch UNDER NODE: all three channels OK <700ms.
6. Full @playwright/mcp protocol smoke under Node + Edge config: real navigate returned a rendered `edge-smoke-ok` snapshot, zero stderr. VERIFIED.

## Assumptions
- Single-machine fabric (all agents on this Windows box) -> the machine-specific node path in .mcp.json is shared by all sessions. (If the fabric ever spans machines, replace with a PATH-resolved node or a per-machine symlink.)
- MCP config is read at connect time -> live tools switch over on next Claude Code restart / MCP reconnect.

## Alternatives considered
- Keep bun, add Chrome flags / use --cdp-endpoint: rejected — bun's transport is broken at BOTH pipe and websocket; flags can't fix it; --cdp-endpoint needs a persistent externally-managed browser (fragile for an MCP).
- Node + system Chrome (default): works under Node, but Edge chosen to avoid the managed-Chrome GCM noise + corporate-policy drift; bundled chromium rejected (its install timed out on the corporate network; Edge needs zero download).
- Resurrect the third-party /frontend-dev plugin: deferred (see Downstream) — it's superseded by .tools/frontend-dev.py and has an unconfigured memvid dependency.

## Rollback plan
Revert `.mcp.json` playwright block to `bunx @playwright/mcp@latest --headless`; revert `.tools/frontend-dev.py` two edits; delete `.tools/playwright-mcp-config.json`; (optional) remove `~/tools/node-v24.16.0-win-x64`. Single-commit revert for the tracked files.
