# LD-0178 — Charter the post-commit-GO hook build (TO-file discipline enforcement)

## Decision

Charter the AE/DT infra build of the **post-commit-GO hook** per CTO spec
`TO_FILE_DISPATCH_DISCIPLINE.md` §9 (`305abc367`). Sequenced behind the live NFRA
work (LD-0177); filed as a proper TO with `issued_to` (dogfooding the discipline).

## What the hook does

On a commit that adds/edits a `task_orders/*.md` file with `<status>` = `staged|pending`
and not already GO'd, the post-commit hook writes a GO message directly into
`org/mcp/inbox/{issued_to}/` (the assignee's inbox path — the same path `send_message`
writes). The assignee's Monitor + the broker pick it up; no running MCP server needed
in the hook (broker-outage-resilient). Result: **filing a TO IS dispatching it** — the
GO→file gap that caused the collapse cannot reopen.

## Build Scope (CTO §9, 6 ACs in §9.7)

1. Fires only on TO commits with staged|pending status, not already GO'd (§9.1)
2. Extracts `<issued_to>` exact serial incl `~lane`; missing = MALFORMED log + fail-open (§9.2)
3. Addresses the GO by direct inbox-file write, `~lane` path honored (§9.3)
4. Exact-once via gitignored `.go-sent-ledger` (no write-back/recursion) (§9.4)
5. Bare-MCP dispatch caught by `/prd-check` reconciliation, not a real-time block (§9.5)
6. Zero interference with safe-commit mutex / owned-paths / ledger-hook / headmove-guard;
   Rule-16 safe (§9.6)

## Sequencing

Behind the live NFRA queue. CTO reviews the AE/DT implementation against the 6 ACs
before it goes live. Until it lands, the LD-0177 discipline holds via manual TO filing
(COO already filed the 16-TO NFRA roster this way).
