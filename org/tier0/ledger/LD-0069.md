# LD-0069 — MSTR thin architecture: retire /govern + /compiler-ask periodic loops; repurpose to /compiler-ferry event-triggered; final architecture = 1 loop + 5 event-triggered skills

## Decision

Per Andrew architectural conversation 2026-05-25T~22:20Z-23:50Z: comprehensive MSTR architecture strip-down. /govern as periodic supervision loop is RETIRED — Tier-1 loops already do the substantive work (scan, drift, alignment, classification, spawn/kill scan), making /govern duplicative. /compiler-ask as periodic loop is also RETIRED — CL CVO /case-find absorbs its detection functions. /compiler-ask name is REPURPOSED as /compiler-ferry (event-triggered cross-fabric ferry).

## Final MSTR architecture

### LOOPED (cron-armed) — exactly 1 skill

| Skill | Cadence | Function |
|---|---|---|
| `/mstr-review` | **12h cron** (was 24h or cycle-25) | governance review; window-diff; ACCEPTED-{SOVEREIGN/CVO/PROXY} verdict + watermark advance |

### EVENT-TRIGGERED (no cron; respond to inbox/Andrew) — 5 functions

| Skill | Trigger | Action |
|---|---|---|
| `/mstr-spawn` | COO `[SPAWN-REQUEST]` MCP per LD-0042 | validate request → execute spawn-agent.ps1 → ledger LD entry |
| `/mstr-kill` | Andrew direct OR scan-driven population finding | ledger LD entry → execute kill-agent.ps1 (or force-kill per LD-0027) |
| `/mstr-charter` | Cross-fabric (ws × CL) coordination need surfaces | author cross-division charter → ledger LD → dispatch |
| `/compiler-ferry` (NEW; repurposed from retired /compiler-ask) | CL CTO `[FERRY-READY]` MCP per completed compiler | validate ferry-ready criteria → MCP ws CTO + ws CVO with ferry-bundle → ledger LD |
| **LD ratification** (embedded; not a separate skill) | every MSTR action above | each action writes its own LD per Constitution Art. V |

### RETIRED

| Skill | Status | Rationale |
|---|---|---|
| `/govern` (periodic supervision cycle) | **RETIRED** | Tier-1 loops (COO /drive + CVO /spot-check + CVO /verify-channel) cover scan + drift + alignment + classification; /govern was duplicative observation work |
| `/compiler-ask` (periodic class-6 + CL_STALL emission) | **RETIRED as periodic loop** | CL CVO /case-find absorbs class-6 archetype-cluster detection; CL_STALL_CHECK becomes signal for /case-mgmt prioritization within Case-substrate management |

### Heartbeat

`/watcher` 10m remains MSTR's heartbeat (already exists; nothing new). Keeps registration alive + monitors inbox. Event-triggered skills fire when inbox-classified messages arrive.

## Scope shifts

### To CL CVO /case-find (expanded scope)

CL CVO /case-find ABSORBS functions previously in MSTR /govern Step 1(b):
- Class-6 archetype-cluster detection (6-signal taxonomy aggregation; archetype enum + weights per LD-0043)
- Cross-fabric session-log archetype reading (both ws + CL session logs)
- CL_STALL_CHECK as a signal-class within Cases substrate management (CL CTO idle + EXPLORE/TRACE cluster coherent = high-priority Internal Case candidate)

These integrate naturally into /case-find daily cadence — no new periodic loop needed.

### To ws CTO + ws CVO (ferry-review responsibility)

ws CTO + ws CVO RECEIVE ferry-bundle MCPs from MSTR per /compiler-ferry:
- ws CVO reviews mechanically (Surface-level /verify-channel mode) + holistically (project-level)
- ws CTO reviews architectural fit + scribes incorporation paired-commit (per V1 mechanics below)
- Joint go/no-go: if PASS → ws CTO scribes paired-commit copy from `feature_clb/.tools/comp-{name}/` to `ajb_workspace/.tools/comp-{name}/`
- If CONCERN/REJECT → MSTR ferries rejection rationale back to CL CTO

- **MSTR architecture maturity arc**: from "active fabric scanner" (original D-001 ignition framing) → "meta-supervisor verifying Tier-1 loops" (LD-0056) → "event-triggered interface + 1 looped review" (this LD). Each step strips redundancy + clarifies MSTR's truly-unique role.

- **MSTR-as-cross-fabric-ferry** (/compiler-ferry + /mstr-charter) is the principal-proxy role at architectural-clarity. Cross-fabric work is MSTR's natural domain; intra-fabric work is Tier-1's.
