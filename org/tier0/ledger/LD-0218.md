# LD-0218 — Consolidate NFRA_MSGRAPH onto the single compiler agent 0.8.0_AE_CloudComp (Andrew-direct, supersedes LD-0217)

**Andrew-direct correction of LD-0217.** Verbatim: *"I knew we had made an AE for compiling, better
to do it this way because then we can relegate all compiler work across AWS and MS to one agent,
rather than having them unnecessarily split out"* + *"i already had them reregister, do not kill
them."*

**What changes:**
- LD-0217 stood up a *separate* dedicated lane `0.8.0_AE_MSGraph` for NFRA_MSGRAPH. That is
  **superseded.** NFRA_MSGRAPH is compiler/findability work over the MS doc-cloud, so it
  consolidates onto the **single existing compiler agent `0.8.0_AE_CloudComp`** — the
  CLOUD_COMP_TESTER lane Andrew created 2026-05-27 (LD-0119). One agent owns the **AWS + MS compiler
  surface**, not two split lanes.
- **My error in LD-0217:** I reused the `0.8.0_AE` base number with a new `_MSGraph` suffix; my
  spawn pre-flight checked only the exact full serial (free, because the suffix differed) and missed
  that `0.8.0_AE` was already CloudComp's. Diligence gap owned — base-number allocation, not just
  the exact string, must be checked before naming a new lane.
- **No kill.** Andrew has re-registered the agent and explicitly directed no kill. MSTR's
  kill+respawn-under-new-serial plan is cancelled; the population is Andrew-managed here.

**Routing:** COO updates the `NFRA_MSGRAPH.S1` TO `issued_to` → `0.8.0_AE_CloudComp` and fires the
S1 GO there (recon + schema; CTO arch-gates schema). The catastrophic-floor guardrail (NO MS
content/comms leak; allowlist `/sites,/drives,/driveItem` only) carries unchanged.
