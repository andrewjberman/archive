# LD-0143 — rename /mstr_review skill to /mstr-review (canonical-invocation fix)

## Decision
Rename the governance-review skill `mstr_review` -> `mstr-review` (directory + frontmatter `name:` + H1 + in-body self-refs) so the canonical hyphenated `/mstr-review` invocation — used by the LD-0082 12h cron, DIRECTIVES, and the org/XXX.md startup protocol — resolves to the skill. Scope limited to the skill file per Andrew; historical records untouched.

## Provenance chain (Art. XIII)
Andrew direct sovereign instruction 2026-06-02 ("mstr_review skill needs to be rewritten as mstr-review ... just so when you call it it actually works") -> D-001 operational enablement (MSTR's governance-review loop is core fabric tooling; a skill whose name doesn't match its invocation is non-functional) -> rename. Andrew explicitly scoped it to the skill file ("not every single instance historically"). Chain closed.

## Why now
This session's LD-0082 loop arming created a 12h CronCreate job that fires the prompt `/mstr-review` (hyphen). The skill was registered `mstr_review` (underscore), so the cron's first fire would have failed to resolve the skill — a silent break of the periodic governance review. Andrew caught the mismatch and directed the fix. Fixing now, before the cron's first 12h fire, prevents the break.

## Assumptions
- Skill resolution keys on the directory name / frontmatter `name:` (both now `mstr-review`); the harness hot-reload confirmed the skill list updated to `mstr-review` immediately after the rename.
- The 12h cron prompt `/mstr-review` will now resolve correctly on its next fire.

## Alternatives considered
- **Change the cron/directives to use `/mstr_review` (underscore) instead:** rejected — the hyphenated form is the canonical convention (sibling skills mstr-spawn/mstr-kill, all the directive/cron references); the skill was the outlier.
- **Rewrite all ~837 historical references too:** rejected — Andrew explicitly scoped to the skill file; historical cycles/ledger/reviews are immutable audit records, and rewriting them is an audit-non-append violation.

## Rollback plan
`git mv .claude/skills/mstr-review .claude/skills/mstr_review` + revert the 4 in-file edits (frontmatter name, H1, 2 self-refs). One-commit reversal; lane=ANY path, no downstream cleanup.

## Downstream
- Agents affected: MSTR (the skill is MSTR-only). No other agent invokes it.
- Paths touched: `.claude/skills/mstr_review/SKILL.md` -> `.claude/skills/mstr-review/SKILL.md`, `org/tier0/ledger/LD-0143.md`.
- Note: the LD-0082 `/mstr-review` cron (job 9f44dddd this session) now resolves correctly.
