# LD-0046 — Owned-Paths Mirror Discipline doctrine establishment

## Decision

Per Andrew sovereign ratification 2026-05-24T20:23Z of Q-A (Option A+ Mirror Discipline over Option B Tier-0 canonical lanes file), establish `org/tier0/OWNED_PATHS_MIRROR_DISCIPLINE.md` as canonical reference doc codifying the cross-fabric owned-paths discipline.

### A — Substance

Both fabrics maintain own `.owned-paths.yaml` (matches current state since 2026-04-24). Discipline:

1. **Lane-class definitions are fabric-shared canon** — must mirror across both fabrics:
   - Lane name (BASE_EXEC, COMP_LEARNS, ANY_CTO, TIER0_LAW, INTER_FABRIC, etc.)
   - `permitted_agents` list
   - `description` field
2. **Path-to-lane mappings are fabric-local** — each fabric maps own paths to lane names; path classes need not exist in both fabrics
3. **Cross-fabric drift detection** runs at MSTR /govern Step 1(b) — MSTR scans both `.owned-paths.yaml` files each cycle; surfaces lane-section drift as META observation
4. **Mirror updates are paired** — any lane-class change in one fabric MUST be mirrored to the other; routed via ws COO + CL COO coordination

### B — Doctrine doc location

`org/tier0/OWNED_PATHS_MIRROR_DISCIPLINE.md` — canonical reference doc, **NOT TIER0_LAW lock**. Operational tuning surface; amendable via successor LD-NNNN without TIER0_LAW commit ceremony. Lives at tier0 because the discipline binds cross-fabric per CONSTITUTION Art. XV fabric-shared canonical pattern.

### C — Why Option A+ over Option B (Andrew's call)

Andrew verbatim: *"Its far betteer to keep ownedpaths separate in mirrored format."* Operational reasoning surfaced in MSTR analysis:

| Option B drawback | Why Option A+ avoids |
|---|---|
| Option B's cross-fabric file-read dependency at hook-execution-time is operationally fragile (if feature_clb is checked out without ajb_workspace adjacent, hook breaks) | Option A+ each fabric's file is locally self-sufficient |
| Option B introduces a Tier-0 canonical file requiring stricter amendment discipline | Option A+ keeps owned-paths as operational tuning surface |
| Option B drift-detection needs cross-fabric sync logic at runtime | Option A+ drift-detection is read-only scan at MSTR's /govern (no runtime cross-fabric coupling) |
