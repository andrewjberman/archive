### C — MSTR session-resume protocol (new /govern Step 0 sub-step)

At MSTR invocation by Andrew:
1. Read most recent SS-NNNN record from `org/tier0/sessions/` (most recent by SS-NNNN ordering OR last-modified)
2. Cross-check current state vs SS-NNNN frontmatter via §2 queries:
   - `git log -1 --pretty=format:"%H" -- org/tier0/CONSTITUTION.md` vs `last_tier0_commit_hash`
   - `git tag -l 'mstr-review-*' | sort -V | tail -1` vs `last_review_tag`
   - `ls -t org/tier0/cycles/CY-*.md | head -1` should be the last entry in `cycle_range`
   - `git log --since="<closed_at>" --all --oneline` — surface commits since session close (any unexpected work? CTO scribe pass landed? Tier-2 commits?)
   - `cat org/mcp/liveness.json` — should be EMPTY at MSTR-restart-clean-state OR carry only agents Andrew spawned manually (rare exception)
3. **Spawn prerequisite agents (default list + session-specific) per §1 + §7 spawn-order.** Each spawn carries `OPAL_SPAWN_MARKER_v1` per LD-0028 + LD-0036.
4. Issue initial charters to re-spawned Tier-1s per §3 open-work-items mapping (re-spawn-with-direction pattern per LD-0021 / LD-0027 — first-spawn carries resume-state context in initial inbox message)
5. First /govern cycle proper begins (Step 0 Constitution + STAKES_MATRIX + DIRECTIVES read in full, etc.)

This protocol amends /govern Step 0 with a "Step 0a session-resume check" sub-step. Implementation lands in /govern SKILL.md amendment paired with v1.9 + v1.10 (per LD-0034 ship-paired precedent OR in a subsequent re-spawn-ws-CTO cycle).

### E — Two-layer state validation principle

Andrew's framing: MSTR uses TWO LAYERS to validate position:
- **Layer 1: Most recent session log (SS-NNNN)** — authoritative MSTR-side record of intent + closing state
- **Layer 2: Most recent commits (git log since session close)** — empirical ground truth of what actually happened (e.g., post-close commits by re-spawned Tier-1s, CTO TIER0_LAW commits, etc.)

If Layer 1 ≠ Layer 2 (state has drifted), MSTR resolves before spawning agents — could be:
- Tier-1 commit landed post-session-close (e.g., ws CTO v1.9+v1.10 ratification commit) → adjust spawn-list/initial-charters accordingly
- Andrew manually intervened → read intervention in commits; align session-resume to match
- Some unexpected state → surface to Andrew + halt origination until reconciled

This is the LD-0036 spawn-originator discipline + LD-0034 unified-comms + session-log-resume converging into a coherent re-entry protocol.
