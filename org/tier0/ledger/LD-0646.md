# LD-0646 -- Portal hook installer and pre-push resolve a submodule layout

## Decision
Edit `.tools/portal-hooks/install.sh` and `.tools/portal-hooks/pre-push` so a box where `portal/.git` is a gitlink FILE
(dell1, dell2) can install the NFRA_DEVPLN DEV push limb and have it find its gate scripts.
- `install.sh`: the hooks dir is `git rev-parse --git-path hooks` run in `portal` (a directory case still resolves to `portal/.git/hooks`).
- `pre-push`: each gate gets one added candidate, `<superproject root>/.tools/portal-hooks/<gate>`, from
  `git rev-parse --show-superproject-working-tree`. The existing candidates stay, so the laptop is unchanged.
- NOT changed: the hook still prints WARN and exits 0 when a gate is missing. Making it fail closed is a policy choice
  for the laptop CTO, who owns NFRA_DEVPLN; the dell2 CTO asked for it (bus cf368eb7) and it is passed up.

## Provenance chain (Art. XIII)
CTO NFRA_DEVPLN round 5 analysis `ROUND_ANALYSIS.round5.md` @6bbbc233d4 section 2 (msg 109012) -> each box's manager
installs the limb with `install.sh` and reports two reads -> MSTR~DELL2 (bus 051c1e91) and MSTR~DELL1 (bus 7462e9f4)
measured that the installer exits 1 and the hook misses its gates on a gitlink layout -> `/integrate`: an unowned path (lane ANY,
`owned-paths-validate.py` PERMIT) is repaired by the integrator's box -> this edit. A manager's acts are merges, installs and carries;
this is the minimum change that lets the ordered install run.

## Why now
Two of four boxes cannot meet the ordered reads without it. dell2 stopped rather than fake them, and dell2's client-facing
features are next through the DEV route. Until the install is possible, CI is the gate for dell2's candidate branches.

## Assumptions
- `git rev-parse --git-path hooks` returns a path `cd` accepts on both layouts. Tested here only on the directory layout.
  It is NOT tested on a real gitlink layout; MSTR~DELL2's install is that test.
- The hook runs with its working directory inside `portal`, so `--show-superproject-working-tree` resolves.

## Alternatives considered
- Hand-copy the hook and a gate beside it (what dell1 did): works once, leaves D-1 VALGATE skipping, and is not repeatable.
- Fail closed now: changes which pushes are admitted fabric-wide; not MSTR's call.

## Rollback plan
`git revert` of the commit that carries this entry restores both files byte for byte. Re-run `bash .tools/portal-hooks/install.sh`
on each box that took the patched copy.
