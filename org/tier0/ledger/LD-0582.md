# LD-0582 - /cleanup: recurrent disk-space pool skill

## His words

> "We need a skill called /cleanup that identifies these recurrent storage pools and remediates
> them, which is usually just deleting them. The only one that requires more review is the active
> worktrees, and policy surrounding their deletion."

## What was built

- `.tools/cleanup-disk.ps1` -- a small pool registry (extend it as new recurring bloat classes are
  found, never grow an existing pool's identify logic to cover a different class):
  - `terraform-provider-temp` (AUTO-DELETE): leftover `%LOCALAPPDATA%\Temp\terraform-provider*`
    files from Terraform runs that did not clean up after themselves.
  - `orphaned-worktree-dirs` (AUTO-DELETE): directories under a known worktree-staging root that
    `git worktree list` no longer knows about.
  - `merged-worktrees` (AUTO-DELETE): registered, non-live worktrees whose HEAD is an ancestor of
    BOTH `origin/CLOUD` and `origin/SITEZ` -- content fully preserved by the merge.
  - `unmerged-worktrees` (REVIEW ONLY): registered, non-live worktrees carrying at least one commit
    on neither shared branch -- the only copy of that content. The engine lists these (path, branch,
    commits ahead, size) and stops; it contains no code path that deletes here. Disposal policy per
    Andrew's own instruction: route each to a per-commit SUPERSEDED-vs-UNIQUE content verdict
    (`3.0.0_SA_CVO` or the project's own owner) before anything is removed.
  - LIVE definition, binding on every pool: a worktree modified within the last `-LiveWindowHours`
    (default 6) is untouched, full stop. The heuristic can only fail toward under-cleaning.
- `.claude/skills/cleanup/SKILL.md` -- the invocation table, the worktree policy written out in
  full (not just referenced), and discipline notes.

## Bugs the dry run caught before anything was trusted

1. **Root-discovery false positive.** The first version derived worktree-staging "roots" from
   every registered worktree's parent directory. A stray worktree at `Desktop\scty-build` made
   `Desktop` itself a candidate root, and `-DryRun` printed `OPAL_WORLD_MODEL`, `ADVI_REFACTOR` and
   several personal transcript folders as orphan-and-deletable. Fixed: a directory is only a root if
   2+ registered worktrees share it, plus a hard denylist of `USERPROFILE`/`Desktop`/`Documents`/
   `Downloads` regardless of what shares it. Never reached a live run.
2. **Ghost registration crash.** A worktree can be registered in `git worktree list` while its
   directory no longer exists (removed by hand, or by another live seat's own cleanup, without
   `git worktree remove`) -- the fabric was actively draining worktrees while this was being built.
   The engine crashed calling `git -C <gone-path>` on one. Fixed: such rows are detected before any
   git call, reported as `GONE`, and cleaned with `git worktree prune`.
3. (Also found and fixed, cosmetic but real: an earlier attempt to suppress a stray return-value
   dump accidentally swallowed every `Write-Output` line inside the worktree-split function, since
   PowerShell functions emit to the same output stream as `return`. Fixed by removing the trailing
   `return @{...}` instead of capturing the call.)
