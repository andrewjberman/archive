# LD-0176 — No overnight watcher agents; review artifacts next morning

## Sovereign Directive (Andrew direct 2026-06-10)

> "we're not going to have any agents manually check any of that stuff while it's
> running, we'd just check the next morning, there should be associated artifacts
> that we'd review."

## Principle

A **scheduled run** — nightly gold chain, EventBridge cron, Fargate derive-runner —
is not something an agent watches in real time. It runs autonomously and writes
durable artifacts. Review happens the **next morning** by reading those artifacts.
"Owns tonight's watch" is **NOT** live-pending-work and does not justify keeping an
agent alive or respawning one overnight.

## Allocation-Model Change

COO's `/drive` + `/allocation` live-pending-work test (LD-0158) must **stop counting
"overnight watch of a scheduled run" as work**. An agent whose only remaining task is
to watch a cron fire is a KILL/let-end candidate, not a KEEP/respawn. The morning
review is the work — and it is event-driven (the operator or a spawned agent reads
the artifacts when the day starts), not an overnight standing session.

## Tonight's Application

Stand down the COO respawn-request for DS_CP / AE_PE / DS_MI. Let them stay ended.
The three overnight runs proceed unattended; their artifacts are reviewed in the
morning:

| Run | Time | Morning-review artifacts |
|---|---|---|
| ADHC_GLDINC night-4 | ~01:00–05:00Z | clean_night_counter.json, watermark.json, preflt_events.parquet (first persist), post-chain shadow scorecard, gold logs |
| ADVI_COTETL nightly | 02:00Z | cot gold chain A_00→D_04 outputs, pipeline logs, pipeline-complete marker |
| NFRA_GLOBGRPH cron | 02:00Z | graph_metrics (untyped==0 gate), Nessie main HEAD commit, node/edge counts, CloudWatch logs (0 AccessDenied) |

(DS_MI's FIND_DUALBIZ is Andrew-direct interactive work, not an overnight watch — it
resumes when Andrew next drives it, not via an overnight respawn.)

## Exception

If a specific run genuinely needs real-time **intervention** (not just observation) —
e.g., a known-flaky step that must be caught and restarted live — Andrew authorizes a
targeted session for that one case. The default, fabric-wide, is no overnight watcher.
