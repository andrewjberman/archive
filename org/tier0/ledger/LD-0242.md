# LD-0242 -- fix the skill-canonical Project Dashboard generator (working-time engine break)

**What.** Andrew asked in-session for the /registry-check + /to-check HTML dashboards on his Desktop,
as a repeatable function of the skills. Provenance investigation found the generators ALREADY exist
(`.claude/skills/registry-check/render_dashboard.py`, `.claude/skills/to-check/render_to_dashboard.py`)
and are ALREADY linked from their skill.md -- so the "function of the skill" structure was already in
place. The real defect: today's working-time patch (`6938340ce`) changed `build_rows()`'s signature,
silently breaking `render_dashboard.py` (the Project generator) -> the dashboard went stale over the
holiday. The TO generator was unaffected.

**The fix.** Pass `now` + `holidays` (from the engine's `resolve_asof` + `load_holidays`) into
`build_rows(now, holidays)`. Regenerated both dashboards fresh to the Desktop via the canonical
skill-linked generators; visually QA'd both (render clean -- 56 projects / 32 TOs).

**Why S1 / not gated.** directive_execution under D-002 (standing governance-tooling maintenance);
a reversible, internal, read-only-tool code fix (writes one local HTML file on demand). MSTR owns
this tooling per the same-day Andrew-direct handoff. Banked lesson: read the skill.md (the map)
BEFORE trusting a raw-grep 0-hit (the territory) -- the comp-grep false-negative nearly drove a
duplicate build.
