# LD-0452 -- THE TAG SURFACE HAS NO IDENTITY WRAPPER: agent deploys are recorded under Andrew's name by DEFAULT, not by exception

- **Status:** FINDING RECORDED / GATE CANDIDATE ROUTED -- **NOT BUILT, NOT AUTHORIZED**
- **Author:** `0.0.0_AB_MSTR`
- **Date:** 2026-08-25 ~08:5xZ
- **Corroborated by:** `2.0.0_SA_COO` (69778, the originating measurement), `1.0.0_SA_CTO` (69769),
  `0.4.0_DE_ClientPlatform~C` (69804, source-confirmed the absence)

## The finding

`.tools/safe-commit.sh` stamps an agent serial onto **commits**. **Nothing stamps a tagger.**

```
safe-commit.sh mentions "git tag"            0     POS CONTROL: "git commit"     9
a .tools/safe-tag* wrapper exists            0     POS CONTROL: .tools/safe-*.sh 8
GIT_COMMITTER_NAME / TAGGER set in .tools/   0
```

Every zero above carries a positive control that fires, at two seats independently
(`0.0.0_AB_MSTR`, `0.4.0_DE_ClientPlatform~C`).

**Consequence, measured over the 12 most recent annotated tags per repo:**

```
ajb_workspace : 10 of 12 tagged "Andrew Berman"
                  incl. bd-v2.55.0, shared-infra-v1.46.0, opal-assets-v0.44.0,
                        yang-pipeline-v1.5.4, yang-pipeline-v1.5.8
                 2 of 12 tagged "0.0.0_AB_MSTR"
portal        : github-actions[bot]  (CI-cut -- correctly attributed, and the contrast case)
```

`git var GIT_AUTHOR_IDENT` on this box returns `Andrew Berman` (COO measured the same at
their seat). An unwrapped `git tag -a` therefore inherits the human's git config.

## Why this is larger than the override-audit defect it descends from

COO found `to-proof-of-spec-check.sh:34` stamping `GIT_AUTHOR_IDENT` into the override audit,
so an override taken by CTO was recorded against the dark seat CTO had authored as. That log
holds **one row**.

⛔ **Rule 6 mandates `git tag -a` after EVERY 0-diff apply.** So the tag surface is the estate's
**highest-volume identity-bearing artifact**, and:

> **THE OVERRIDE LOG NEEDS AN EXCEPTIONAL ACT TO MISATTRIBUTE. THE TAG SURFACE MISATTRIBUTES ON
> THE DEFAULT PATH AND NEEDS NOTHING TO GO WRONG.**

The failure direction is the one MEMORY.md already names as the durable hazard: **a false
attribution of a GOOD act (a clean deploy) is never contested, so it is never corrected.**

## The remedy is ONE decision across TWO surfaces

**If only the override log is fixed, the larger leak stays open while the record reads repaired.**
That is tonight's recurring shape -- a partial fix that presents as complete -- landing on the
remedy itself. Any tagger stamp must be decided together with CTO's caller-field candidate
(69769) and COO's widening of it (69778: populate the caller field unconditionally, because
"when they differ" is adjudicated by the same unreliable ident).

## ⛔ WHAT THIS LEDGER ENTRY DOES NOT DO

**It does not authorize a build.** CLAUDE.md forbids implementing any gate without Andrew's
explicit word; CTO framed their sibling candidate as "routing, not building" and this follows it.
No wrapper was written, no hook installed, no tag rewritten. **Historical tags are NOT to be
re-tagged** -- rewriting attribution to fix attribution is self-defeating, and the tags are
pushed.

**Routed to Andrew as an open call.** Owner if approved: CTO (law + gate routing).

Surfaced while pushing `parked/v2.1.165-etf-promote-held-20260824` to preserve the held 12:50Z
