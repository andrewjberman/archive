### M1 — Tab-title default

> "when you launch new agents, I want their serial in the tab title of powershell by default. When you load 1.0.0_SA_CTO, it should literally display 1.0.0_SA_CTO in the powershell tab of the new window."

**Pre-existing state.** `spawn-agent.ps1:184` already set `$Host.UI.RawUI.WindowTitle = '$Serial'` in the outer-shell command pre-ajb-dot-source; `ajb.ps1:177` already set the same in the ajb-function pre-`& claude`. Both per LD-0079.

**Failure mode.** `$Host.UI.RawUI.WindowTitle` is the Win32 console-title API. Windows Terminal reads this for tab title BUT also honors OSC 0 escape sequence (`ESC ] 0 ; TEXT BEL`) as last-write-wins. `claude.exe` console writes during session interactive operation may emit their own OSC sequences that override the pre-set title.

**Hardening shipped this commit.** Both `spawn-agent.ps1:184` outer-shell AND `ajb.ps1:177` pre-claude block now emit OSC 0 escape sequence via `[Console]::Write` PAIRED with the existing `$Host.UI.RawUI.WindowTitle` set. Belt-and-suspenders coverage: emit BOTH protocols; last-write-wins for Windows Terminal binds to the OSC 0 emission immediately before `& claude` runs, giving the best probability of session-long tab-title persistence.

**Empirical verification deferred.** Post-LD-0099 spawn cycles should display the serial in tab titles consistently. If `claude.exe` still overrides during interactive session, follow-on hardening via background-job title-refresh OR Windows Terminal profile binding will be pursued (LD-0NNN).
