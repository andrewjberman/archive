# LD-0367 -- The Integration Window: hourly clean-tree git sync, both fabrics

## Decision
Andrew-direct 2026-07-31: institute an hourly INTEGRATION WINDOW so shared-worktree agents do not lose uncommitted work and the two fabrics' branches reconcile cleanly instead of diverging.

## Verbatim (Andrew)
> "We also need to think how to sequence the pushes/pulls between the fabrics so agents dont lose uncommitted work. Maybe we relegate a period each hour, like the last 5 minutes of the hour where agents have to make sure all of their work is committed by e.g. 13:55, and then from 13:55 to 14:00 the pushes and pulls integration occurs." + "design it and then issue that design to MSTR~Z over agentbus, with a message that they are to disseminate this to the tier 1 agents, and COO on the respective fabrics disseminates to the tier 2 workers."

## The problem it fixes
Shared worktree, many agents committing to one local branch. `git pull --merge` (to integrate origin before pushing) REFUSES when the tree has uncommitted changes to files the merge touches -- and those changes belong to OTHER agents, so they cannot be stashed or discarded (blast radius). Net: nobody integrates, `local-ahead`/`origin-ahead` both climb, cross-fabric commits stall. The current failure is "cannot integrate," not "work lost" -- the window prevents the NEED to ever force a merge over live work.

## The mechanism
A per-hour window that manufactures a guaranteed clean-tree moment:
- **:00-:55 -- NORMAL WORK.** Commit continuously to your own committable SEAMS.
- **:45 -- 10-MINUTE WARNING.** The integrator MSTR runs a REAL-TIME CLOCK MONITOR (polls ~once per minute -- the timing engine, so no agent has to watch the clock). At :45 the MSTR issues a 10-minute warning to Tier-1; COO cascades it to the Tier-2 workers -- "ten minutes to the commit deadline; reach a committable seam or stash to .runtmp/."
- **:55 -- COMMIT DEADLINE.** Clean tree for your lane: every change committed to a seam, OR stashed to your own `.runtmp/` (which the integrator never touches). NEVER commit a broken/half-written state to hit the clock.
- **:55-:00 -- INTEGRATION PASS.** Agents HOLD -- no commit, no push. The fabric's INTEGRATOR (its MSTR) runs `git pull --merge` (never rebase) then `git push` on the now-clean tree -- a clean tree cannot block the merge.
- **:00 -- RESUME** + pop any `.runtmp/` stash.

## Rules
1. **Commit to a SEAM, not mid-work.** If you cannot reach a clean stopping point by :55, stash to your own `.runtmp/` and pop at :00. Never a broken commit to beat the deadline.
2. **Only the INTEGRATOR pulls/pushes during the window.** Agents committing+pushing individually at :55 race into rejections. Commit by :55, then HOLD; the MSTR integrates.
3. **Both fabrics run the SAME WALL-CLOCK window.** Host is UTC-4; the :55 boundary is the same instant on both devices (computed offset, never a typed `Z`). The two MSTRs coordinate the pass over the agentbus.
4. **The agentbus is the real-time tier; git-sync is hourly.** Urgent cross-fabric coordination rides the bus, NOT the window. An agent needing a specific cross-fabric commit mid-hour fetches it BY HASH (`git fetch` + `git cat-file/show <hash>`) -- no branch sync required.
5. **Content conflicts are out of scope.** The window fixes uncommitted-blocking, not two agents editing the same file. Edit your own lane's files (owned-paths already encourages this); when a content conflict arises the integrator resolves or routes it, never forces.

## Roles + dissemination
- **INTEGRATOR** = the fabric's MSTR (base MSTR for the base device, MSTR~Z for site-Z).
- **Dissemination (both fabrics):** MSTR disseminates to Tier-1 (CTO, CVO, COO); COO disseminates to Tier-2 workers.

## Enforcement
Convention first (announce-then-enforce). If missed, escalate to a :55 pre-integration check (a hook/gate). A CronCreate at :55 arms the integration pass as the standing trigger.
