# LD-0367 -- The Integration Window: hourly clean-tree git sync, both fabrics

## Decision
Andrew-direct 2026-07-31: institute an hourly INTEGRATION WINDOW so shared-worktree agents do not lose uncommitted work and the two fabrics' branches reconcile cleanly instead of diverging.

## Verbatim (Andrew)
> "We also need to think how to sequence the pushes/pulls between the fabrics so agents dont lose uncommitted work. Maybe we relegate a period each hour, like the last 5 minutes of the hour where agents have to make sure all of their work is committed by e.g. 13:55, and then from 13:55 to 14:00 the pushes and pulls integration occurs." + "design it and then issue that design to MSTR~Z over agentbus, with a message that they are to disseminate this to the tier 1 agents, and COO on the respective fabrics disseminates to the tier 2 workers."

## The problem it fixes
Shared worktree, many agents committing to one local branch. `git pull --merge` (to integrate origin before pushing) REFUSES when the tree has uncommitted changes to files the merge touches -- and those changes belong to OTHER agents, so they cannot be stashed or discarded (blast radius). Net: nobody integrates, `local-ahead`/`origin-ahead` both climb, cross-fabric commits stall. The current failure is "cannot integrate," not "work lost" -- the window prevents the NEED to ever force a merge over live work.

## The mechanism
A per-hour window that manufactures a guaranteed clean-tree moment:
- **:00-:55 -- NORMAL WORK.** Commit continuously to your own committable SEAMS.
- **:45 -- 10-MINUTE WARNING.** The integrator MSTR runs a REAL-TIME CLOCK MONITOR (polls ~once per minute -- the timing engine, so no agent has to watch the clock). At :45 the MSTR issues a 10-minute warning to Tier-1; COO cascades it to the Tier-2 workers -- "ten minutes to the commit deadline; reach a committable seam and commit, or if you cannot, leave your work in your working tree (never stash, never .runtmp)."
- **:55 -- COMMIT DEADLINE.** Committable-clean for your lane: every change you can reach a seam for is committed. Work you CANNOT reach a seam for stays IN YOUR WORKING TREE, untouched -- NOT stashed, NOT moved to `.runtmp/`. NEVER commit a broken/half-written state to hit the clock.
- **:55-:00 -- INTEGRATION PASS.** Agents HOLD -- no commit, no push. The fabric's INTEGRATOR (its MSTR) runs `git pull --merge` (never rebase) then `git push` on the now-clean tree -- a clean tree cannot block the merge.
- **:00 -- RESUME.** Uncommitted work is untouched in your working tree; continue where you left off.

## Rules
1. **Commit to a SEAM, not mid-work.** A commit is the durable, preferred path -- it lives in `.git/` and it guarantees your work cannot block the integrator's merge. If you cannot reach a clean stopping point by :55, LEAVE your work in your working tree, untouched -- do NOT `git stash` (Andrew-direct 2026-07-31: popping a stash has broken our sessions) and do NOT move it to `.runtmp/` (gitignored+untracked = the class destroyed twice on 2026-07-31; `git clean -fdx` wipes it). It is safe there for the window: the integration pass runs ONLY `git pull --merge` (non-destructive -- it REFUSES rather than clobbers) then `git push`, never `git clean`/`reset`/`checkout --`. Tell the integrator "open work in <files>." Never a broken commit to beat the deadline.
2. **Only the INTEGRATOR pulls/pushes during the window.** Agents committing+pushing individually at :55 race into rejections. Commit by :55, then HOLD; the MSTR integrates.
3. **Both fabrics run the SAME WALL-CLOCK window.** Host is UTC-4; the :55 boundary is the same instant on both devices (computed offset, never a typed `Z`). The two MSTRs coordinate the pass over the agentbus.
4. **The agentbus is the real-time tier; git-sync is hourly.** Urgent cross-fabric coordination rides the bus, NOT the window. An agent needing a specific cross-fabric commit mid-hour fetches it BY HASH (`git fetch` + `git cat-file/show <hash>`) -- no branch sync required.
5. **Content conflicts are out of scope.** The window fixes uncommitted-blocking, not two agents editing the same file. Edit your own lane's files (owned-paths already encourages this); when a content conflict arises the integrator resolves or routes it, never forces.

## Roles + dissemination
- **INTEGRATOR** = the fabric's MSTR (base MSTR for the base device, MSTR~Z for site-Z).
- **Dissemination (both fabrics):** MSTR disseminates to Tier-1 (CTO, CVO, COO); COO disseminates to Tier-2 workers.

## Enforcement
Convention first (announce-then-enforce). If missed, escalate to a :55 pre-integration check (a hook/gate). The integrator MSTR runs a real-time clock Monitor (~1/min poll) that fires the :45 warning and the :55 pass; a CronCreate is a fallback trigger.

## The cross-fabric handoff protocol (base MSTR <-> MSTR~Z, in the :55-:00 window)
Both fabrics push to ONE origin/CLOUD. The two integrators SERIALIZE and adjudicate any overlap by correspondence on the agentbus -- never by a silent force. GOAL: the two fabrics touch DISJOINT artifacts (ESTATE-main vs CORE-site-Z trees; owned-paths reinforces it), so overlap should be rare; the protocol is the mechanism for when it is not.
1. **:55 READY HANDSHAKE.** Each integrator posts "READY: <fabric> tree CLEAN @<HEAD>." Neither pushes until BOTH are ready.
2. **DETERMINISTIC ORDER (no per-window negotiation): base MSTR pushes FIRST, MSTR~Z SECOND.**
3. **FIRST (base):** git pull --merge -> git push -> post "PUSHED: base @<hash>."
4. **SECOND (site-Z):** on "PUSHED: base," git pull --merge (now has base's commits) -> git push -> post "PUSHED: site-Z @<hash>."
5. **OVERLAP (both touched the same artifact):** the second integrator's merge conflicts. It does NOT force or auto-resolve -- it posts "OVERLAP: <file> -- base[summary] / site-Z[summary]." Adjudicate by precedence: (a) git auto-merged non-overlapping hunks -> proceed; (b) same-line conflict -> the artifact's OWNER wins (owned-paths lane / home fabric), the non-owner re-applies on top; (c) ownership unclear or both substantive+incompatible -> ESCALATE to Andrew. Never a silent overwrite.
6. **DEAD-PEER FALLBACK (two triggers -- a timeout must key on the EVENT it depends on and measure ELAPSED from it, never an absolute clock; both MSTRs hit this class from opposite sides, window 1 + window 2):** (i) if a peer has not HANDSHAKED by :57 (ABSOLUTE is correct here -- never-handshaked-at-all is a property of the window, not of any peer event), the live integrator proceeds SOLO + posts "SOLO: <fabric>, <peer> silent"; (ii) if the peer handshaked but "PUSHED: base" has not arrived within 120 SECONDS OF THE HANDSHAKE (ELAPSED from the handshake, NOT an absolute :58), site-Z (structurally second) posts "SOLO: site-Z, base handshaked but did not push" and proceeds. Two failure modes closed: without (ii), a base death AFTER handshake but BEFORE push deadlocks the second pusher; with an ABSOLUTE (ii), a late-but-live handshake (e.g. :57:53) gives the peer ~7s and misfires a SOLO that races the peer's own live push -- the same peer behaviour getting a different verdict by WHEN it spoke. A dead peer never blocks the live fabric; a live one is never raced.
7. **:00 DONE:** both post "INTEGRATED: <fabric> done"; agents resume.
