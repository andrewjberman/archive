# LD-0043 — COMPILER_ARCHETYPES canonical doc establishment (Beat 2 of inter-fabric channel design)

## Decision

Per Andrew sovereign direction + multi-turn joint design conversation closing 2026-05-24T19:45Z with Opal CTO (1.0.0_SA_CTO) at lock, establish `org/tier0/COMPILER_ARCHETYPES.md` as the canonical cross-fabric reference doc for the archetype-tag emission taxonomy + numerical aggregation weights.

### A — Locked enum (8 archetypes + MIXED)

| Archetype | Definition | Shape-weight |
|---|---|---|
| `EXPLORE` | Searching, grepping, reading to find something / understand structure | 3.0 (HIGH) |
| `TRACE` | Following dependencies, call chains, data flow across files/systems | 3.0 (HIGH) |
| `DIAGNOSE` | Debugging, post-mortem, root-cause investigation | 2.5 (MEDIUM-HIGH) |
| `VALIDATE` | Running checks, probes, cross-references, fidelity tests | 2.0 (MEDIUM) |
| `DEPLOY` | terraform / lambda / EC2 / S3 artifact operations | 1.5 (LOW-MEDIUM) |
| `IMPLEMENT` | Actual code edits, file authoring | 1.0 (LOW) |
| `COORDINATE` | MCP, inbox, cross-agent ratification, dispatch | 1.0 (LOW) |
| `SCRIBE` | Authoring docs / PRDs / briefs / session logs | 1.0 (LOW) |
| `MIXED` | Dominant archetype genuinely unclear; multi-classed work | 1.875 (unweighted mean of all 8) |

### B — Locked emission format (single-line header)

Single line at the top of each session-log entry, immediately after the title:

```
**archetype:** EXPLORE
```

Optional secondary line for genuine high-mixed cases:

```
**secondary_archetypes:** TRACE, VALIDATE
```

No scoring on emitter side. Pick dominant. Default to MIXED if genuinely unclear. Under-classify is fine; over-classify wastes the signal.

- Numerical weight scheme (HIGH=3, MEDIUM-HIGH=2.5, MEDIUM=2, LOW-MEDIUM=1.5, LOW=1) is the right initial tuning; first class-6 surface empirically validates or surfaces refinement need
- CL CTO will concur on cross-fabric uniformity (V1.1 §5.4-mapping alignment + class-6 explicitly captured in their signal-class table makes concur expected); counter routes back to MSTR for joint iteration

- Forward-only cutover doesn't impair MSTR's existing class (1)-(5) Source A signal detection (those use git-log + RAVC + comp-validate mining unchanged); class-6 begins surfacing post-cutover once tag corpus accumulates

## Alternatives considered

- **Lock as TIER0_LAW.** Rejected: the enum is operational tuning surface, not constitutional law. Future enum refinements are META-cycle work, not Andrew-only amendments. Reserving Tier-0 law lock for the three load-bearing docs preserves the discipline boundary.
- **Retroactive backfill of existing session logs with archetype tags.** Rejected: META work without paired-operational value (the existing log corpus is already usefully mined by classes 1-5; class-6 retro-tagging burns cycles re-classifying activity already analyzed).
- **Per-entry tagging instead of per-file.** Rejected: explodes scan from O(file_count) to O(entry_count); per-file dominant + optional secondary_archetypes gives MSTR a tractable groupby.
- **MIXED handled as zero-weight.** Rejected: emitting MIXED is informationally weaker than committing to a dominant archetype, but never zero-cost-signal (MSTR still sees the emission). Unweighted-mean handling preserves the signal without over-weighting MIXED.
