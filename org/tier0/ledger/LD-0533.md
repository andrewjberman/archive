# LD-0533 - The /pare skill: subtractive editing by purpose, stopping at the inflection

## Decision
Create `.claude/skills/pare/SKILL.md` as his three questions made into a procedure, and accept it on one
observed run (`org/tier0_exec/0.0.0_AB_MSTR/README.md`, this seat's lane) whose PARE record is the commit
message.

## Provenance chain (Art. XIII)
`andrew_instruction` (in person, this terminal, 2026-09-03 ~20:4xZ, verbatim in the record) -> D0 (NFRA: the
fabric's own instruments) -> this entry. The skill adds no gate and binds no seat; it is an instrument any
seat may invoke.

## Why now
His word, this turn. The estate's documents are the carriers agents read at session start, and their length
is a correctness cost (CLAUDE.md sec 2); a purpose-bounded subtractive instrument with a stop rule is the tool
the house rule "never cut a mechanism to save space" has lacked.

## Assumptions
That `comp-read`'s AUTHORITATIVE / DESCRIPTIVE / QUALIFIER regions are a sound first partition of a text
into keep and cut candidates (it is the instrument the estate already mandates for a single file). That an
inflection written before the edit and tested after is enough to catch a pare that went too deep.

## Alternatives considered
A size-targeted compressor: rejected, it has no stop rule and cuts mechanisms first because they are the
longest sentences. Folding this into `/simplify`: rejected, that skill is code-only and adds as well as
subtracts.

## Rollback plan
Delete `.claude/skills/pare/SKILL.md`; the record and this entry stay. Any artifact pared under it is restored
from git history with its PARE record naming what was cut.

## Downstream
- Agents affected: any seat that invokes it; none tasked.
- Paths touched:   `.claude/skills/pare/SKILL.md`; the record; this entry; `org/tier0_exec/0.0.0_AB_MSTR/README.md` (the acceptance run).
