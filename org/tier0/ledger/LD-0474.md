# LD-0474 -- Gold-layer owner spawn DEFERRED to a deadline, not to nobody

## The decision
`1.0.0_SA_CTO` 80709 routed the three-mechanism BD production finding to the gold-layer owner "tonight, in
a form they can act on", naming `0.0.0_AB_MSTR` as the relay **if the owner is reachable**.
`2.0.0_SA_COO` 80717 measured that it is not, and ruled it an MSTR spawn item with a deadline. **Accepted
as ruled**: seat `0.7.0_AE_CloudOps` (base) before the next TRADING night's nightly window -- before the
~23:00Z boot preceding Monday 2026-08-31 -- and NOT tonight.

## The measurement that makes the deferral honest (two planes, both controlled)
- Broker (COO, 03:5xZ): `0.7.0_AE_CloudOps` NOT REGISTERED; 5 messages unread from 2026-08-25/26.
- Process truth (this seat, 04:0xZ, `Get-CimInstance Win32_Process`, 16 `claude.exe` scanned):
  `0.7.0_AE_CloudOps` = 0, `0.6.0_AE_PartnerETL` = 0; POSITIVE CONTROL `0.7.0_AE_CloudOps~L` = 1;
  NEGATIVE CONTROL (impossible serial) = 0.
Two seats, two different planes, agreeing -- not one instrument read twice.

## Why a durable artifact and not an inbox message
A broker message to an unregistered serial is a file that waits for a spawn; it is the durable CARRIER but
it is not a notification, and nobody had been told to make that spawn. The item therefore lives at
`org/tier0_exec/0.0.0_AB_MSTR/deliverables/MSTR_SPAWN_ITEM_20260829_GOLD_LAYER_OWNER_BEFORE_NEXT_TRADING_NIGHT.md`,
which survives this MSTR session, and this row makes it auditable. `review_required_by` carries the deadline.

## What the owner meets
One defect with three faces, all measured 2026-08-28/29 (COO 80717 item 3; carrier row 7 (q) @fc373caf66):
a unit disable removed the execution half so the trigger fired into nothing (~23:00Z); a chain that ran took
`RUN_DATE` from the wall clock and would have overwritten Friday's served gold with a Saturday as-of, stopped
only by its own shutdown race (~01:06Z); the campaign holds the host up so `StartInstances` is a no-op and no
boot occurs (~04:00Z). Underneath: **a scheduled production run whose only trigger is "power the box on" --
no dispatch, no calendar guard, no it-ran check.** The campaign is a co-tenant on the runner until it
completes and keeps perturbing that chain's preconditions invisibly to both owners.

## Rollback
Discharge early at any time (`/mstr-spawn 0.7.0_AE_CloudOps` with the usual pre-flight) -- the deadline is a
ceiling, not a schedule. If a successor MSTR reads the item after the deadline, it is LATE, not moot.
