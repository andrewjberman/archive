# LD-0082 — Deterministic loop arming via launcher first-message injection

## Decision

Per Andrew direct 2026-05-26T~03:10Z + Q1-Q7 resolution set: implement role-specific deterministic loop arming at the launcher surface. Get-AgentLoopDirective helper in `.tools/ajb.ps1` (and feature_clb sibling for `.tools/clb.ps1`) maps serial → role → CronCreate directive list, appended to the launcher first-message. Every agent launched via `ajb`, `clb`, or `spawn-agent.ps1` gets a deterministic loop-arming directive at startup, not just a /watcher directive that relies on org/XXX.md follow-through.

## Authority chain

Source-of-truth precedence preserved:
- **`org/XXX.md` §F worker-arming table** — canonical reference for what to arm
- **`.claude/skills/*/SKILL.md`** — canonical body for each skill (cadence + body)
- **`.tools/ajb.ps1` + `.tools/clb.ps1`** — launcher injection that GUARANTEES the canonical arming actually fires at every launch (belt + suspenders; mechanical execution layer)

No new authority introduced. Launcher just mechanically enforces what XXX.md + skill bodies already specify.

## Implementation

### ajb.ps1 (ws-fabric launcher; CLOUD commit)

```powershell
function Get-AgentLoopDirective {
    param([string]$Serial)
    $base = $Serial -replace '~[A-Za-z0-9]+$', ''  # strip tilde-lane
    $header = "DETERMINISTIC LOOP ARMING (LD-0082) -- after /watcher self-heal, arm canonical loops via CronCreate before proceeding with org/XXX.md balance:"
    switch -Regex ($base) {
        '^0\.0\.0_AB_MSTR$'  { return "$header`n  role: MSTR (Tier-0)`n  1. CronCreate /watcher 10m ...`n  2. CronCreate /mstr-review 12h ..." }
        '^1\.0\.0_SA_CTO$'   { return "$header`n  role: ws CTO ..." }
        # ... (full body in code)
        default              { return "$header`n  role: UNRECOGNIZED ... WARN MSTR ..." }
    }
}
```

Helper invoked inside `ajb` function; output appended to `$firstMessage` after the existing watcher-directive.
