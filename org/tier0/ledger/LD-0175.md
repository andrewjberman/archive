# LD-0175 — Zero loops armed at agent launch (fabric-wide)

## Sovereign Directive (Andrew direct 2026-06-10)

> "I don't want any loops initiated at launch ... if I want a loop to run, I will
> initiate the looped skill (e.g., drive, work, etc), don't need it at launch."

## State Before This Decision

The fabric had already retired most launch loops (LD-0157 `/work` + `/ws-charter`;
LD-0164 `/mstr-review` + `/spot-check`; LD-0166 `/watcher` → arm-once; LD-0157 COO
`/drive` → ad-hoc). **Three launch-armed crons remained** in `ajb.ps1`
`Get-AgentLoopDirective` (the deterministic per-launch injection):

| Serial | Launch cron | Prior authority |
|---|---|---|
| `1.1.0_SA_CTO` (CL CTO) | `CronCreate /cl-charter 30m` | LD-0066 queue-pull |
| `3.0.0_SA_CVO` (ws CVO) | `CronCreate /verify-channel 2h` | LD-0062 baseline |
| `3.1.0_SA_CVO` (CL CVO) | `CronCreate /verify-channel 2h` + `/case-find 24h` | LD-0062 + LD-0082 Q5 |

## Decision

**No serial arms ANY cron at launch.** All three retire to ad-hoc invocation.
`/watcher` (persistent inbox Monitor, armed once at load — NOT a cron) is the only
standing launch mechanism. Every loop (`/drive`, `/work`, `/ws-charter`,
`/spot-check`, `/verify-channel`, `/cl-charter`, `/case-find`, `/govern`,
`/mstr-review`) is now Andrew/operator-initiated on demand.

## Implementation

1. `.tools/ajb.ps1` `Get-AgentLoopDirective` — strip the `CronCreate` lines from the
   `1.1.0_SA_CTO`, `3.0.0_SA_CVO`, `3.1.0_SA_CVO` branches; update the SUPERSESSION
   header comment ("Standing crons that REMAIN: NONE").
2. `org/XXX.md` Step 1b §F — reconcile the loop-arming table + the LD-0062 "each
   agent arms a role-appropriate primary cron loop" framing (now false) + the
   loop-hygiene retired list + the CL inheritance note.

## CL Fabric Consequence (flagged to Andrew)

CL `/cl-charter` + `/case-find` were the autonomous queue-pull drivers (LD-0066).
Removing their launch-arm means the CL pipeline no longer self-runs — it is
manual-init like every other loop. Andrew accepted this in the directive; a
one-word countermand re-exempts CL if desired.

## Skills Retain Loop Capability

This removes only the *launch auto-arm*. Each skill keeps its loop body — invoking
`/drive 20m`, `/verify-channel queue 2h`, `/cl-charter 30m`, etc. still arms the
loop on demand. No capability is lost.
