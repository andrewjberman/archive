## §3 -- Operating principle banked

When shared-resource contention manifests in multi-actor scenario, ASK FIRST: "can the shared resource be split?" before adding mediation tooling. Strip-at-source > mediation-at-checkpoint.

**Why split-at-source wins when applicable:**
- Eliminates contention class entirely (no contention possible if resource not shared)
- Permanent (no ongoing mediation maintenance)
- Cheaper (no mutex acquire/release overhead, no queue flusher process)
- Simpler invariant (presence/absence vs synchronization protocol)
- Composable (each fabric independent vs coupled-through-mediator)

**When mediation is correct anyway:**
- Shared resource cannot be split (e.g., single underlying database table)
- Split would lose required coordination semantics
- Cost of split exceeds cost of mediation
- Resource is intrinsically global (broker, registry, etc.)
