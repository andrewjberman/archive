## The defect catalog (every case)

### Class A — Query/display conflation ("collapse under base")
- **A1 `server.py:813` `get_agent_status`** — `info = data.get(agent_serial) or
  data.get(folder.name)`. A suffixed query (`~C`) whose tilde entry is absent
  **silently returns the BASE agent's liveness+summary**, rendered under the `~C`
  header (`# Status: ...~C`). A dead/never-registered lane looks alive as base.
  **FIX:** a suffixed query looks up ONLY the exact suffixed key; absent → explicit
  "NOT REGISTERED (lane ~C)". Keep the base-fallback ONLY for an unsuffixed query.
- **A2 `get_live_agents` / `get_org_summary`** — iterate `data.items()` and print
  whatever summary is stored, so a base key polluted with a tilde summary (via B1/B2)
  displays "base — <tilde summary>". **FIX (enhancement):** group base + its ~lanes
  visually so a stray base-with-tilde-summary is obvious; surface the lane set
  explicitly (cf. `list_agents`' `[LIVE xN: base, A, B]` badge — port that clarity).

### Class B — Write-side fallback clobber ("~C summary surfacing under base")
- **B1 `server.py:545-548` `heartbeat`** — backward-compat fallback: if the full
  serial (`~C`) is not in `data` but `folder.name` (base) is, it sets
  `live_serial = folder.name` and writes the heartbeat summary onto the BASE entry.
  So a tilde lane's heartbeat — once its own entry is pruned by `_clean_stale`
  (quiet >600s) or never created — **CLOBBERS the base agent's summary with the
  tilde lane's.** This is the root of the live RD reproduction.
- **B2 `server.py:588` `set_summary`** — identical fallback
  (`live_serial = agent_serial if agent_serial in data else folder.name`). Same clobber.
- **FIX (B1+B2):** never fall back to base for a SUFFIXED write. A suffixed
  heartbeat/set_summary for a missing entry re-creates its OWN suffixed entry (or
  returns "re-register"), never writes onto base. Base fallback allowed ONLY for an
  unsuffixed caller (genuine pre-tilde backward-compat).

### Class C — Channel-push over-broad fan-out
- **C1 `server.py:1063-1073` `send_message`** — for a BASE-addressed send
  (`target_suffix = None`) the channel-push loop matches EVERY live entry sharing
  the base (base + all ~lanes) and pushes to all of them — while the broker
  delivery (`broker_target = base`) and the filesystem inbox (base dir) reach base
  ONLY. A base-addressed message interrupts every tilde lane's session for a message
  those lanes will never see via `check_inbox`/poll. **FIX:** channel-push targeting
  must match broker/fs routing exactly — suffixed send → exact instance; base send
  → base only.

### Class D — Workarounds that mask, not fix
- **D1 `live_agents_by_marker.json`** — stale/unmaintained; its sole justification
  ("broker can't be trusted on suffixes") is FALSE (broker is suffix-clean). **FIX
  (decide in implementation):** once the query path is suffix-correct, either
  (a) RETIRE it and point the 4 consumer skills back at the now-trustworthy
  broker/`get_live_agents`, or (b) if kept for marker-based liveness independent of
  registration, fix its update hooks so it can never go 17h stale. MSTR
  recommendation: (a) retire + repoint, removing a standing liability. (The 4 skill
  edits — allocation/fabric-check/mstr-spawn/mstr-kill — span owner lanes; route
  per owner.)

### Class E — Duplicate / dead code carrying the same bugs
- **E1 `complearns_server.py`** — dead (0 live refs; unified to `server.py` per
  LD-0034) but a full duplicate of the buggy suffix logic = future-fixer clobber
  risk. **FIX:** delete (confirmed 0 refs) or move to an `attic/` with a RETIRED
  header.
- **E2 `agent-poller.py:225-227`** — still switches CL serials to the retired
  `complearns-agent-comms` channel via `_switch_to_cl_channel()`. Dead routing
  (no CL broker since LD-0034). **FIX:** remove the CL-channel switch; all serials
  use the unified `opal-agent-comms` broker.

### Class F — Divergence / robustness (adjacent; CTO judgment)
- **F1** — `liveness.json` (json) and the broker DB clean up independently and
  drift (live: json=7, broker=8 with a lingering dead `~B`). So `get_live_agents`
  (json) and `fabric-check` (broker) can disagree on the tilde set. Consider
  unifying the cleanup / single source of truth.
- **F2** (not suffix, flagged for the record) — `_safe_json_loads` returning `{}`
  on a corrupt `liveness.json` means a subsequent write WIPES all entries. A
  hardening item for the same file.

## Acceptance criteria (MSTR drives verification)
1. A suffixed `get_agent_status` for an absent lane returns "NOT REGISTERED
   (lane ~X)" — never the base agent's state (A1).
2. A tilde-lane heartbeat/set_summary for a pruned/absent entry NEVER mutates the
   base entry's summary; re-test by pruning a `~X` entry then heartbeating `~X`
   and confirming base is untouched (B1/B2).
3. A base-addressed `send_message` channel-pushes to base ONLY (not all lanes);
   a suffixed send pushes to the exact instance only (C1).
4. `complearns_server.py` removed/retired with 0 live refs (E1); poller CL-channel
   dead-switch removed (E2).
5. Marker-artifact disposition decided + executed (retire+repoint or fix-hooks) (D1).
6. Fabric-wide: after the coordinated restart, all live agents reachable; no
   messaging regression (canary send to a base + a tilde lane both deliver
   correctly and are visible in the right inbox/query only).

## Rollout caution (load-bearing)
Running MCP sessions keep OLD `server.py` code until their session/MCP server
restarts (LD-0195 banked). So the fix lands as a **coordinated fabric-wide restart**,
not an instant cutover. Stage it: land + unit-test the new code, validate on a
canary/second broker port, then restart sessions in a low-traffic window. Messages
persist in `broker.db` until delivered (no loss across restart).

## Rollback
Per defect: `git revert` the `server.py`/`agent-poller.py` change + restart broker
& sessions; restore `complearns_server.py` from git if E1 over-reached; re-point
skills to the marker artifact if D1 retire regresses. All individually reversible.
This LD is superseded (not deleted) if the approach changes.
