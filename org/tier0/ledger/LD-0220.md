# LD-0220 — Tier-0 Utility framework + UA role (Andrew-direct, ratified in-session)

Reframes **Tier 0 as the principal's utility / meta-coordination layer** and introduces the **UA
(Utility Agent)** role. Andrew authored the design in-session and ratified the two load-bearing
choices via AskUserQuestion: (1) "Reframe tier0 as the utility layer," (2) "+ propagate to blueprint
kit."

**What landed (workspace reference):**
- `org/tier0_utility/README.md` — the framework spec: tier0-as-utility framing, the UA role, the
  `0.0.N_UA_<toolset>` convention, the launcher+brief agent anatomy, and the inherited safety posture.
- `org/tier0_utility/0.0.1_UA_mstools/` — M365 utility (README + brief): launches `/teams-assist`
  + the M365 gateway; briefed on Outlook triage/drafting, Teams intake, SharePoint/OneDrive exploration.
- `org/tier0_utility/0.0.2_UA_awstools/` — AWS/portal-data utility (README + brief): read-only AWS +
  comp-tools; briefed on locating/explaining served portal data with provenance.
- `org/ORG_CHART.md` — numbering scheme + role codes updated with Tier 0 (utility) + `UA`.

**Design intent:** UA agents are *useful the moment they launch* — pre-armed skills + a pre-loaded
domain brief — and are principal-facing (not in the PRD→TO dispatch chain). MSTR stays in
`tier0_exec/` (governance utility) for continuity; UA agents live in `tier0_utility/`.

**Handoff:** the framework + the two reference UAs propagate into the agent_org_blueprint kit
(separate commit + re-zip) so an Opal employee gets `mstools`/`awstools` adapted to their own access.

**Post-commit correction (same session):** the UA prompts' protocol reference was fixed
`RAVC2`→`RAVC` to match the WORKSPACE convention (`org/ref/RAVC_PROTOCOL.md`; the workspace uses
RAVC, the kit uses RAVC2). The KIT copies under `templates/utility_agents/` correctly retain RAVC2.
Kit propagation shipped: `ARCHITECTURE.md` (tier0_utility tree + UA role + utility-layer paragraph)
+ `templates/utility_agents/{README,0.0.1_UA_mstools,0.0.2_UA_awstools}` + ship-zip re-built
(267 entries, testzip clean). Follow-up flagged to COO: add an `.owned-paths.yaml` rule for
`org/tier0_utility/**` so future UA commits don't need the audited override used here + at the
framework commit.
