# LD-0411 -- keep the box alive = SELF-HEAL ON RESTART (staged; one console session away)

Full runbook: `org/tier0_exec/0.0.0_AB_MSTR/deliverables/SITEZ_CONSOLE_VISIT_RUNBOOK_selfheal_and_tailscale_20260814.md`
Design + gaps: `C:\opal-elev\AUTORECOVERY_DESIGN.md` on the box.

## The decision

The recurring crash class is undiagnosable after the fact (LD-0409) and cannot be prevented. **So the
fix is to make recovery automatic** -- a restart costs minutes, not the 18h it cost 2026-08-12. Three
layers, and only the first needs elevation:

| layer | mechanism | status |
|---|---|---|
| **1 auto-login** | Autologon (LSA secret) / `AutoAdminLogon` | **the only elevated step** -- waits for the console |
| **2 auto-launch** | logon task -> `ajb -Headless` for the two serials | staged, verified autonomous |
| **3 bloomberg login** | AWS-secrets GUI sign-in | **deliberately OUT of the boot chain** -- see below |

## Andrew's blocker is CLOSED, empirically not just by design

His concern: the box runs Claude in bypass-permissions mode, which shows a "Yes I accept bypass
permissions" fork at instantiation that a human must click. Measured on the box:
- `ajb -Headless` mode **drops that fork** and disallows `AskUserQuestion`/`EnterPlanMode`/`ExitPlanMode`
  so an autonomous agent cannot strand.
- Both suppression flags true **for the auto-login user** (`Opal_Bloomberg`): `settings.json
  skipDangerousModePermissionPrompt=true`, `.claude.json ... hasTrustDialogAccepted=true`. OAuth token
  persists (`.credentials.json`). Same-user verified -- interactive user == flag/token profile ==
  auto-login user; the setup script hard-gates on this.
- **Empirical control** (beats the flag values): MSTR~Z spawned COO~Z and CRO~Z **headless** on
  2026-08-12 and both registered clean, no human clicking accept.

*(Path-form note: the first flag read used a backslash key and false-negatived -- the same path-form
class caught repeatedly tonight. The forward-slash key reads true.)*

## The INV-B simplification (Andrew's, load-bearing)

**Bloomberg login is NOT a routine boot step.** The terminal entitlement survives a reboot (proven
2026-08-13). The AWS-secrets sign-in is a fragile GUI-coordinate **emergency** remedy for a DAPI
outage; auto-firing it unattended risks a **locked Bloomberg account** (a support call). It stays
human-supervised, out of the boot chain. This made the plan smaller and safer.

## Staged, not armed

`C:\opal-elev\`: `setup-autorecovery.ps1` (idempotent, before-state restore point, hard-precondition
gate, `-Teardown`), `autolaunch-agents.ps1` (`ajb -Headless` x2, 8s stagger, BG serial roster-confirmed
`0.0.3_BG_BBGTerminal`), `AUTORECOVERY_DESIGN.md`. Plus `install-tailscale.ps1` from LD-0409 work.
Verified not armed: `AutoAdminLogon=''`, no logon task.

## Why one session does everything

Elevation is proven in-person-only (LD-0409: no Intune/WinRM/AMT that is Andrew's; UAC bypass declined
as EDR-noisy). That single elevated console -- the same one Tailscale needs -- runs both pastes:
Tailscale + self-heal. Plus the BIOS AC-recovery flip and UPS from LD-0409 complete the picture.

## Rollback

`setup-autorecovery.ps1 -Teardown` removes auto-login + the task. Nothing is armed pre-session.
