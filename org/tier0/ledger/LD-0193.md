# LD-0193 — Governance: exit-143 live-watcher-reap rectified (register-hook scoped) + DS graph-module owned-paths convention

**Andrew-direct fabric-disruption fix, shipped + MSTR-verified.** The recurring exit-143 reaps of live inbox-watch watchers are rectified at source.

## Root cause (MSTR ground-truth, not CTO's first framing)
The killer was **not** MSTR's `kill-agent`/reallocation (0 KILL lines this session; `spawn-agent.ps1` calls no reaper). It was the **`.claude/settings.json` `register_agent` PostToolUse hook running `kill-orphans --stale --force` fabric-wide on every registration** — so each spawn's new-agent startup swept and SIGTERM'd peers' live watchers. `kill-orphans` was also silent (no audit), which is why the source stayed "undetermined." This corrects CTO's initial attribution while confirming the mechanism class CTO named (`--force` reaping live watchers).

## Fix shipped (CTO `84b381c56`, Andrew-direct + empirically validated) — MSTR-verified on disk
1. `kill-orphans --serial <S>` — tilde-EXACT match (`~A` reaps only `~A`, never base/`~B`); **every reap now audit-logged** (was silent).
2. New `org/mcp/hook_register_orphan_cleanup.py` — reaps ONLY the registering serial's orphans, per-session V4 marker (`CLAUDE_CODE_SESSION_ID`) so re-register never self-kills the agent's own live watcher.
3. `settings.json` register-hook re-pointed to the scoped cleanup, **replacing** the fabric-wide `--stale --force`.

MSTR spawn machinery needs no change — a spawned agent's own `register_agent` now fires a self-scoped cleanup, so spawns no longer reap peers.

## Standing convention (COO+CTO, RV-0034 F-002 close)
A DS-assigned graph-module tool (`org/modules/graph/**`) gets a **DS-inclusive owned-paths lane authored at PRD-decomposition** — closes the recurring `ANY_EXEC` lane-gap that produced most of this session's commit-scope BLOCKs (and RV-0033 F-002's `manifest_check` gap). DS graph-tool work stops requiring overrides/BLOCK-reroutes.

## Distinct follow-on (NOT closed here)
The 2026-05-30 `kill-agent found=0/watchers_reaped=1` hazard — a reallocation `kill-agent` reaps a live-session watcher by serial even when no claude process is found. Real latent hazard, lower priority (the register-hook was the recurring cause). CTO to author the live-liveness guard on `kill-agent` (skip a serial fresh in liveness.json); MSTR adopts + ledgers on ship.
