# LD-0358 — Lane-comms header/attribution fixes: To: carries the full serial; the URGENT drain names its owner

## The two defects (LD-0202 family, new variants)

1. **Compose (server.py:1633):** `**To:**` wrote `to_folder.name` — the agent FOLDER, which
   never carries a ~suffix — so a lane-addressed message routed correctly to the nested lane
   dir while its own header claimed the BASE held it. A lane reader could not tell the message
   was theirs (0.7.0_AE_CloudOps~B held on exactly this ambiguity, live).
2. **Retrieval (`_drain_piggyback`):** the URGENT block prepends the CALLING session's own
   queued broker mail onto whatever tool response comes next — including a get_agent_status
   render for a DIFFERENT agent — with no recipient labels. The caller's own mail reads as the
   queried agent's (measured live twice: CVO's 215623Z finding, and MSTR's own 13-message block
   rendering under "# Status: 1.0.0_SA_CTO~C" this same evening). The double-claim shape.

## The fixes

- To: now carries the FULL ADDRESSED SERIAL (halt-gate's LD-0131 filter base-strips before
  comparing, so compatible by construction).
- Every URGENT drain names the session it was queued for and every message names its addressed
  serial — a misdelivered or misattributed message is now VISIBLE instead of silently
  double-claimed.

deployed-not-running, picks up per session restart): E1 direct `_drain_piggyback` call →
