# LD-0177 — Staff NFRA: spawn DS + reuse idle AE_CloudOps + restore TO-filing discipline

## Sovereign Direction (Andrew direct 2026-06-10, via CTO relay + live confirm)

Bring NFRA workers online — the macro is unstaffed and the one live worker
(`0.7.0_AE_CloudOps`) sits idle with an empty queue because TO-filing collapsed.
Andrew amended CTO's spawn rec: **spawn DS only**; the existing idle AE_CloudOps
covers the AE-lane work (do NOT spawn `~B`).

## Root Cause (CTO diagnosis, accepted)

~280 commits/48h of decomposed+dispatched work were dispatched via MCP messages,
not filed as TOs with `issued_to`. So `/to-check` returns ~0 and there is no
queryable "which agent owns which NFRA TO" roster — the live worker has nothing to
pull, and the mapping has to be reconstructed from memory. Spawning alone does not
fix it: **the NFRA TOs must be FILED into the spawned/idle agents' queues.**

## Actions

1. **Spawn `0.4.0_DS_ClientPlatform`** — DS-lane NFRA work (DTAFLP P3 classification-prep TO-1b; further DS items as COO files them).
2. **Reuse idle `0.7.0_AE_CloudOps`** — AE-lane NFRA: GLOBGRPH Item-2b incremental updater (unblocked), COSTAWS W1/W3/W4/W5 + R1/AC5, COMPAWS cert-loop. No `~B` spawn.
3. **COO files the NFRA TOs** into both queues (DS + AE_CloudOps), with `issued_to` set, so `/to-check` becomes the roster.
4. **CTO authors the GO->TO-file discipline standard** — every dispatch produces a filed TO with `issued_to` (post-dispatch hook), so no agent sits idle-with-empty-queue again and the roster is always queryable.

## Hold Guardrail (DTAFLP not back-door-released)

The DTAFLP irreversible execution remains HELD pending the separate explicit Andrew
go. COO files only NON-HELD NFRA work + DTAFLP P3 **classification-prep** (TO-1b, a
non-destructive analysis). The irreversible DTAFLP TOs — P1 `orion->data/inf` rename,
P3 TO-2 (sever `opal-data-bd->opal-data-cot` S3 mirror), P3 TO-4 (drop FIRM_ID) —
stay OUT of the queue until the DTAFLP go lands. This LD does NOT release them.
