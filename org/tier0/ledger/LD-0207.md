# LD-0207 — Harden the comp-tool rail: comp-tooling more explicit/gated (Andrew-direct)

## Decision
Per Andrew-direct ("make sure you are all following Rule 22 and religiously using the
compiler tools... I think we need to make comp tooling more explicit/gated"), CHARTER
a hardening of the NFRA_COMPRAIL rail. CTO (rail owner) proposes the specific stronger
gate batch; COO decomposes it into a NFRA_COMPRAIL hardening TO; Andrew approves the
gate design before enforce.

## The key insight — Rule 21 and Rule 22 are ONE discipline
The empirical anchor (CVO's honest self-assessment, 2026-06-22): CVO raw-`Grep`'d
`DistributionTab` instead of `comp-transform schema-check DistributionTab`, then
claimed the geo donut "shows an Unassigned slice that reconciles" from the artifact
data — a mechanism/render claim grounded on the wrong layer; DE's render caught it.
**The rail-skip and the grounding-slip were the same failure.** `comp-transform`
(components), `comp-blast` (functions), `comp-pipescript io` (pipelines) ARE the
mechanism-grounding tools Rule 22 ([[LD-0206]]) demands. Raw-grepping the source
instead of running them IS the grounding skip. So:
- **Rule 21 (comp-which-first) = the LOOKUP layer** — find the coupled thing.
- **Rule 22 (ground the mechanism) = the REASONING layer** — don't conclude a
  mechanism from output without the producer + graph.
- Same connection-blindness thesis. Enforcing them together is the point.

## Gaps the incident exposed (what "more explicit/gated" must close)
1. **native Grep/Glob = nudge-and-proceed is too soft.** A Tier-1 agent (CVO)
   proceeded raw past the HUD nudge multiple times. Nudge without teeth doesn't change
   behavior under load.
2. **broad repo-grep in Bash = STAGED, not denying.** It let CVO's Bash-greps
   through, a couple WITHOUT the required `# rail-checked:` marker.
3. **the Rule21<->Rule22 linkage is unenforced.** A mechanism/render claim about a
   component or lambda is currently accepted without a `comp-transform`/`comp-blast`
   citation — the grounding tool is optional where it should be mandatory.

## Design direction (CTO scopes the mechanism; this is the intent, not the spec)
- **broad-repo-grep STAGED -> DENY** (the already-announced ramp; this incident is the
  trigger to flip it), keeping the `# rail-checked:` audited escape.
- **native Grep/Glob nudge -> GATE when the target is an estate-coupled path** — the
  `_comprail.classify_path` set (gold/silver/bronze scripts, lambda source, .tsx /
  portal components, .tf/infra, served artifacts) already exists; gate those, leave
  generic/non-estate search free.
- **mandatory comp-tool citation in CVO's `grounding:` field** for component/function
  mechanism claims: wire `comp-transform` (components) + `comp-blast` (functions) into
  Rule 22's WHY-trigger, not just `comp-pipescript`/Read. A render/behavior claim about
  component X without a `comp-transform X` citation = `INFERRED` (non-actionable).

## Lane + sequencing
- **CTO (rail owner):** propose the specific gate batch (which tier, what mechanism,
  classify_path integration). Announce-then-enforce per the TO-3/TO-4 precedent.
- **COO:** decompose into a NFRA_COMPRAIL hardening TO (this is a new leg under the
  existing project, not a new project); dispatch + RAVC.
- **Andrew:** approves the gate design before enforce (the gating shape is his call —
  this LD records the directive + direction, not a finalized mechanism).
- **CVO:** the TO-5 coverage telemetry (already running off `comp-which-rail.log`) is
  the post-enforce measurement that tells whether the harder gate actually moved
  behavior.

## Why this matters (truth-over-progress)
The under-gating risk is the REALIZED one: a Tier-1 agent's ungrounded render claim
nearly shipped, caught only by a peer's render. A rail that a senior agent can
nudge-past under load is not yet load-bearing. Rule 22 made the standard law; this
makes the tooling enforce it rather than suggest it.

## Rollback
Relax the gate tiers + revert this LD if the bar proves mis-set (friction outweighs
the grounding gain). Reversible; each tier is independently CTO-verifiable as TO-4 was.
