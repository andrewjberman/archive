# LD-0345 — THE MISSION REGISTER IS A RECORD. Its GOALS are still a commitment.

## What Andrew asked for, and the one correction to it

Andrew granted sovereign authority to fix MSTR's blocked writes to `org/missions/**`, naming
`.owned-paths.yaml` as the file and citing CTO being busy.

**`.owned-paths.yaml` was never the blocker, and I did not change it.** Measured directly:

```
$ echo "org/missions/MISSIONS.md
        org/missions/INFRASTRUCTURE/TOOLS/state.yaml" \
    | python .tools/owned-paths-validate.py --check-agent "0.0.0_AB_MSTR" .owned-paths.yaml
  -> zero violations
```

MSTR is already permitted there, and has been committing to `org/missions/` all session. The gate
that actually fired is **`mstr-ledger-check.sh`**, which classifies every staged path as RECORD or
STRATEGIC and requires a Decision Ledger entry in any commit touching a strategic path.
`org/missions/**` was on neither allowlist, so it fell to the `*)` default and was treated as a new
strategic commitment **every time** — including when the edit was *correcting a stale line*.

I applied the instruction to the correct file. Reporting the divergence rather than silently
executing the literal words: the intent (*stop this friction*) is unambiguous, the named mechanism
was not the mechanism.

## The change

In `.tools/git-hooks/mstr-ledger-check.sh`, two `case` clauses, **order load-bearing** (`case` takes
the first match):

```sh
org/missions/GOALS.yaml) STRATEGIC=1 ;;   # goals stay strategic -- listed FIRST
org/missions/*)          : ;;             # the rest of the register is a record
```

**The split is the whole point.** The register has two kinds of content:

| content | class | why |
|---|---|---|
| `commits.jsonl` | RECORD | machine-written by `comp-missions scan` |
| `MISSIONS.md` | RECORD | **compiled**, never hand-authored |
| `state.yaml`, `execsum.yaml` | RECORD | stance + prose *about* work whose decisions are ledgered separately (LD-0341 + amendments) |
| **`GOALS.yaml`** | **STRATEGIC** | **Andrew-approved mission goals. Changing one IS a new commitment and still requires an LD.** |

Same reasoning and same authority as the `org/tier0_exec/*/logs/*` line directly above it
(Andrew sovereign-authorized 2026-07-07, LD-0258): **a record of decisions is not itself a decision.**

## Exercised, with negative controls

| staged | expected | result |
|---|---|---|
| `state.yaml` + `MISSIONS.md` | PASS, no LD | **PASS** |
| `GOALS.yaml` alone | **BLOCK** | **BLOCK** |
| `infra/aws/lambda/foo.tf` | **BLOCK** | **BLOCK** |

The two negative controls matter more than the pass: a change that only ever *loosens* a gate is
indistinguishable from breaking it, so both halves were shown to still hold.

## What earned this — the second-order cost was the real one

Four blocked commits in one session, each on a register correction. But the cost that forced it was
not friction on me:

> **`org/missions/**` is refreshed by a POST-COMMIT HOOK in a SHARED WORKTREE.** Every commit by
> any agent re-dirties those files. If MSTR cannot commit them without authoring a ledger entry,
> they stay dirty — and a dirty shared tree **blocks other agents' pushes.** `0.2.0_DT_PortfolioAnalytics`
> reported exactly that at `020142Z`, mid-MDPF-P0.

A gate calibrated for MSTR's own discipline was taxing **the fabric's throughput**, through a
coupling nobody designed: auto-refreshed files + shared worktree + a per-commit ledger requirement.
**The register was built to make state cheap to read; the gate made it expensive to keep TRUE.**

## Scope bound

This changes **classification only**. It does not touch `.owned-paths.yaml`, does not alter who may
write the register, does not weaken record-integrity validation (LD frontmatter schema checks are a
separate pass, untouched), and does not exempt any path outside `org/missions/`.
