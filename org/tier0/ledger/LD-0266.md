# LD-0266 -- Batch C: attempted, blocked by two gates, fully dispatched. Nothing tracked moved.

**Outcome.** No tracked directory was archived. Two gates refused it, both correctly, and **neither was
foreseen**. Only the untracked `factor_scanner/` tree (449 files, 80MB) moved, filesystem-side, touching no
gate. Root went 82 -> 41 entries on the strength of batches A and B.

## Gate 1 -- a move breaks IGNORE RULES, not just pointers

`research/` and `models/` were moved into `archive/`, staged, and the staged diff **read before committing**.
It showed the rename would silently **ADD** files `.gitignore` currently ignores:

```
models/    -> 300 new additions   (tax_strategy outputs, CSV dumps)
research/  ->   4 new additions
```

`.gitignore` names the OLD paths (`models/tax_strategy/output/v*/`, `/projects/*`). Nothing ignores
`archive/models/**`. The commit would have landed 300 build artifacts under an innocuous "archive stale
dirs" message -- **exactly the class of silent, unattributed bulk change this session opened by cleaning up
after (LD-0262).** Both moves were reverted. `.gitignore` is lane `BASE_EXEC`; MSTR is barred.

## Gate 2 -- `owned-paths-check.sh` BLOCKS an undeclared destination

`timeseries/` was clean (79 R100 renames, zero additions), so it was committed. The hook refused every file:

```
VIOLATION: archive/timeseries/vix.json -- UNDEFINED (no matching path rule; agent=0.0.0_AB_MSTR)
```

**`archive/**` has no rule.** Until `.owned-paths.yaml` declares it, no tracked file can live there --
for any agent. And `.owned-paths.yaml` is lane `ANY_EXEC_OR_AE`, which MSTR is not in. **Batch C is
structurally impossible for MSTR to perform**, in any order, without an override. It was not overridden.

The gate is *right* to refuse. A Tier-0 agent editing the file that defines who may edit what is precisely
the separation of duties the lane system exists to enforce.

## The fifteenth instantiation, and MSTR authored this one

Before attempting the commit, this ledger asserted that undeclared paths **"WARN (exit 0)"**. That was
false, and here is where it came from:

```
line  8:  #   warn  (default / Phase 1): violations printed to stderr + audit log; EXIT 0
line 29:  MODE="${OWNED_PATHS_MODE:-block}"   # phase-2 flip 2026-04-30: was warn, flipped to block
```

**I read the comment. The comment has been wrong for over two months.** The enforcing expression is on line
29; the human-readable claim is on line 8; they disagree, and I trusted the one written for me.

That is 0.7.0's sentence, exactly: *"Two sources of truth, and the one humans read was the one that lied."*
It is the same defect as `DryRun` promising a probe it never implements, `BLOCK_AFTER_EPOCH` printing WARN
while blocking, `comp-iam` reporting DESIRED as applied, `kill-storage` asserting `locked/in-use` for
MAX_PATH, LD-0262's blast-radius model read from documentation instead of source, and my telling 0.5.0 that
`AmazonS3ReadOnlyAccess` was invisible to Terraform.

**A control's enforcing value and its reported value must be the same expression, not two expressions that
agree today.** Where they cannot be, the comment must be generated from the code, or deleted.
