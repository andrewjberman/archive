# LD-0040 — Liveness-check-before-spawn refinement to MSTR session-resume protocol (LD-0036 + LD-0039)

## Decision

Per Andrew sovereign instruction 2026-05-24T18:21Z verbatim:

> *"Also amke sure that part of MSTR startup is a scan to see what agents are live, that way if there is an agent that mstr wants to spawn, but if its already live/responsive, then there is no need to clear it and restart."*

Refine LD-0036 (MSTR sole spawn-originator) + LD-0039 (canonical session log format + resume protocol) with the **liveness-check-before-spawn** sub-step:

### A — Refined resume protocol (Step 0a, amends LD-0039 §C step 3-4)

**Old step 3 (LD-0039 §C):**
> *"Spawn prerequisite agents (default list + session-specific) per §1 + §7 spawn-order. Each spawn carries `OPAL_SPAWN_MARKER_v1` per LD-0028 + LD-0036."*

**New step 3 (LD-0040 amendment):**

3a. **Read `org/mcp/liveness.json` + per-serial `get_agent_status` for each prerequisite-spawn-list agent.** Classify each:
- **LIVE-responsive** (last_seen < 120s AND summary present AND not stale) → SKIP spawn for this serial; use as-is
- **LIVE-stale** (last_seen > 120s OR summary stale OR registered but unresponsive) → SKIP spawn but flag for resilience-check (post-spawn-loop, send a ping via MCP; if no ack within 1 cycle, classify FORK-STALLED + escalate)
- **NOT-LIVE** → spawn via `.tools\spawn-agent.ps1 <serial>` carrying `OPAL_SPAWN_MARKER_v1`

3b. **For each NOT-LIVE serial in step 3a**, execute spawn per LD-0036 marker-tracking discipline.

3c. **For each LIVE-responsive serial in step 3a**, send acknowledgment MCP confirming "MSTR session resumed; you're already live + leveraged as-is; no respawn needed; continue any in-flight work."

3d. **Liveness-check audit trail in cycle record:** log per-serial classification (LIVE-responsive / LIVE-stale / NOT-LIVE) at session resume time. Cycle record §population_scan extends with `resume_classification` column for the first cycle post-session-resume.

### B — Marker-tracking gap discipline under this refinement

LD-0036 established marker-tracking elimination of kill-tracking gap when MSTR is sole spawn-originator. LD-0040 introduces an exception class: **already-LIVE agents at session resume that were NOT MSTR-spawned in this session don't carry the `OPAL_SPAWN_MARKER_v1` marker for the current MSTR session.**

**Operational handling:**
- MSTR leverages these LIVE-responsive agents as-is (Andrew's direction: no need to clear + restart)
- If MSTR later needs to KILL one of these (work complete, reallocation, etc.), `kill-agent.ps1` will return "no spawned windows found" per LD-0027 kill-tracking gap
- Fallback: tilde-lane spawn under same serial OR PID-based force-kill per LD-0027 destructive-without-marker-audit class (requires Andrew per-instance authorization)
- Most common case: LIVE-responsive agents continue until their work concludes, then close naturally OR Andrew closes them; if MSTR needs forced replacement, the tilde-lane fallback handles it

**Net structural shape:** marker-tracking is the SPAWN-side discipline (every MSTR-spawn carries marker), and liveness-check is the KILL-side bridge (don't unnecessarily kill already-LIVE agents just to enforce marker-tracking; leverage as-is, replace via tilde-lane if necessary later).

### C — SS-0001 §7 + LD-0039 §C update

Both artifacts (SS-0001 first-cycle agenda + LD-0039 resume protocol) update inline to reflect this sub-step. Updates land THIS commit alongside LD-0040 (record-only commit; pre-reboot landing critical).

### D — Discipline framing

This refinement is the operational version of "use what's working, don't break what's working" — MSTR's authority structure (creator/destroyer + sole spawn-originator) is preserved; the structural-enforcement layer (marker-tracking) applies to NEW MSTR-originated spawns; the operational layer (use already-LIVE agents) reduces friction at session boundaries.

**Why now (Andrew direction explicit):** the post-reboot first-cycle (SS-0002 CY-0081) might have lingering processes that survived the reboot or were Andrew-spawned manually pre-MSTR; MSTR should leverage them, not unnecessarily kill-and-respawn. Andrew is structurally optimizing the session-resume friction case.

LD-0036 (population reset + MSTR sole spawn-originator) → LD-0039 (canonical session log format + resume protocol) → Andrew sovereign instruction 2026-05-24T18:21Z verbatim refining spawn discipline → LD-0040. Authority source = andrew_instruction; closed trace.

## Why now

Pre-reboot landing critical: this refinement must be on origin BEFORE the reboot so the post-reboot MSTR session reads it as part of the resume protocol. Without LD-0040 committed pre-reboot, MSTR would default to spawn-everything-from-fresh per LD-0036/LD-0039 baseline — potentially killing-and-respawning agents that survived the reboot or were manually launched, contrary to Andrew's intent.

## Assumptions

- `get_agent_status` and `org/mcp/liveness.json` are reliable indicators of agent liveness + responsiveness; if either misclassifies, MSTR surfaces the classification miss to Andrew
- LIVE-responsive classification (last_seen < 120s + summary present) is the right threshold; if it produces false-positives or false-negatives, /govern Step 1(b) refinements iterate
- The LIVE-stale → ping-then-classify path doesn't add operational tax beyond the existing /govern stimulus scan (it folds into Step 1(b) population scan)
- Marker-tracking discipline still applies to MSTR-originated spawns; the LD-0036 audit trail integrity preserved

## Alternatives considered

- **No refinement; spawn-everything-fresh per LD-0036 baseline.** Rejected by Andrew explicit direction: "if its already live/responsive, then there is no need to clear it and restart."
- **Kill-all + respawn-all unconditionally at session-resume.** Rejected: clean structural discipline (marker-tracking universal) but creates operational friction; Andrew's direction is the simpler shape.
- **Always-prefer-existing-process; never spawn at session resume.** Rejected: undermines LD-0036 spawn-originator discipline + means MSTR can't recover from agent crashes / window exits / dead sessions.

## Rollback plan

1. If LIVE-responsive classification creates false-positives (MSTR leverages dead-but-marked-LIVE agent): surface to Andrew; refine classification thresholds; consider tighter responsiveness probes
2. If LD-0027 kill-tracking gap on leverage-as-is agents creates operational friction: pivot to scheduled-respawn-at-cycle-boundary OR tilde-lane fallback for unmarked agents
3. Andrew override on any spawn-skip preserved per Art. I
