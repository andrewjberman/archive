# LD-0368 -- INTEGRATOR-ONLY push/pull gate (enforces LD-0367 rule 2)

## Decision
Andrew-direct 2026-07-31: build a gate so that ONLY `0.0.0_AB_MSTR` agents (base MSTR and site-Z MSTR~Z -- the two integration-window integrators) may `git push` or `git pull` a SHARED branch. Every other seat commits to a seam and lets the hourly INTEGRATION WINDOW (LD-0367) move it. This converts LD-0367 rule 2 ("only the integrator pulls/pushes") from a convention into a mechanical gate.

## Verbatim (Andrew)
> "We need to make a gate where only 0.0.0_AB_MSTR agents have push/pull rights"

## Why -- proven by integration-window #1, measured not confessed
Window 1 (2026-07-31) surfaced the exact failure the gate prevents: a seat that pushes early PUBLISHES EVERY OTHER SEAT'S LOCAL COMMITS with its own. CTO~Z pushed and its push carried MSTR~Z's held commit (MSTR~Z's `380192d3d` was an ancestor of CTO~Z's HEAD; CTO~Z's push published it). Neither party chooses it and the pusher cannot see what it carried -- so "just this one push" is never local. **A gate, not a convention, because the violation is INVISIBLE to the violator** (a convention fails silently exactly here).

## Mechanism -- GATE 5 in `.tools/hooks/never-rules-gate.sh`
Rides the existing PreToolUse `Bash|PowerShell` hook (no new settings.json wiring; co-located with the rebase / stash / clean / terraform / commit-msg gates). A PreToolUse hook is the correct layer -- it has no shell, so it catches both bash and PowerShell, which a PATH shim never could.
- **Match:** `git push` / `git pull` in COMMAND POSITION (reuses the file's `_GIT` anchoring), so `echo "...git push..."` and a commit message mentioning it PASS. Combined-regex `(push|pull)`.
- **fetch is NOT blocked** -- LD-0367 rule 4 (everyone fetches-by-hash mid-hour).
- **SHARED branches only** (CLOUD/DEV/PROD/main/master); a scratch branch is the worker's own business.
- **rebase-pull** is already denied for everyone by GATE 1 (runs first, exits) -- no double-handling.
- **Identity, FAIL-CLOSED:** the caller's serial is resolved from THIS call's own `session_id` (hook input JSON -> LD-0290 per-session serial file, the reliable source; the SHARED `.agent_context` is not), then `$OPAL_AGENT_SERIAL`. Allowed iff it POSITIVELY matches `^0\.0\.0_AB_MSTR(~[A-Za-z0-9]+)?$`. UNRESOLVED -> DENY. A false-deny is loud and the integrator fixes it in one step; a false-allow silently republishes the whole tree -- so the failure direction is DENY.
- **Audited override:** `# never-override: <reason>` on the same simple command (house consistency; logged to `org/git-author-override-audit.log`). The deny message states it still republishes the tree and must be coordinated with the integrator first.

## Exercised (13/13 PASS, both cells + controls) -- 2026-07-31
`bash -n` clean. On the live CLOUD branch, crafted-input exercise:
- MSTR base / MSTR~Z push+pull -> ALLOW (positive control: the gate must not block the integrator).
- non-MSTR (`0.1.0_DS_Test`) push+pull -> DENY.
- unresolved serial (empty) -> DENY (fail-closed).
- `git fetch` / fetch-by-hash -> ALLOW (not over-blocking).
- `echo "...git push..."` and a `safe-commit -F ... # doc: git push` -> ALLOW (negative control: does not block the brief reporting the hazard -- this file's own doctrine).
- session-file NON-MSTR beats env MSTR -> DENY; session-file MSTR beats env NON-MSTR -> ALLOW (proves the session file is authoritative over the env, both directions).
- override -> ALLOW + audit line written (`rule=PUSHPULL_AUTHORITY`).

## Primary-resolver bound -- found cross-fabric, closed (CVO~Z, window 2)
CVO~Z's independent site-Z suite (9/9, with its own harness controls: a mutant proving MSTR-allow does NOT widen into a blanket exemption, a negative control, an explicit ALLOW-vs-dead-script liveness check) surfaced a real bound: all 9 cells used SYNTHETIC session_ids -> file-not-found -> every cell exercised only the FALLBACK resolver (`OPAL_AGENT_SERIAL`). The PRIMARY resolver (session_id -> per-session serial file), which PRODUCTION uses, was unexercised. My base 13/13 DID exercise it via the two session-file cells above -- but the 5-cell PROSE harness I relayed to CVO~Z had dropped them, so the bound arrived through the RELAY, not the test.
**DESIGN RULE (re-verified 2026-07-31), for the two session-file cells:** env and file must DISAGREE, and the result must FOLLOW THE FILE (file=non-MSTR + env=MSTR -> DENY; file=MSTR + env=non-MSTR -> ALLOW). A cell where env and file AGREE is green under EITHER resolver and proves nothing about which one fired. When CTO folds the cells into `test_never_rules_gate.sh`, the session-file cells MUST keep env != file.
**Lesson:** a suite testing only the fallback leaves the production path unbounded -- bounded-the-method-not-the-corpus, arriving inside the instrument. Also: `git push --dry-run` is correctly DENIED (a dry-run is still a push; fail-safe), so it cannot serve as an independent second oracle -- the JSON-injection decision-function exercise is the one sound oracle.
