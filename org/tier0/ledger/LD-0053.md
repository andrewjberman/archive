# LD-0053 — MSTR-emit `[COMPILER-ASK]` parity capability (V3 amendment per Andrew direct sovereign 2026-05-24T~2348Z)

## Decision

Add MSTR as second Input 1 originator at parity with Opal CTO. Mechanism per Andrew direct sovereign instruction:

### (a) CL-stall trigger criterion (mechanical, deterministic, daily)

Per /govern Step 1(b) cross-fabric stimulus scan, every cycle MSTR runs:

```
CL_STALL = (
  # No active R&D phase (commit-activity dimension)
  zero CL-fabric commits with archetype IMPLEMENT/DEPLOY/VALIDATE
    in trailing N hours (V1 N=6h)
  AND
  # No pending CL TOs in active state (queue dimension)
  CL TO queue: zero `active` status across
    1.1.0_SA_CTO + 1.{1,2,3,4}.0_DS_CompLearns + 2.1.0_SC_CompLearns
  AND
  # Input 3 floor not absorbing (cascade dimension)
  CL continuous-cycle Input 3 (OSS case studies per CL CTO V1.2 PRD §3)
    hasn't advanced in trailing M hours (V1 M=12h)
  AND
  # NOT blocked-class (distinguishes from BLOCKED waiting on external)
  no CL agent surfaced `[BLOCKED]` subject prefix
    OR named blocker-dependency in trailing window
)
```

The AND structure preserves Andrew's "stalling, not blocked" distinction. Initial V1 thresholds (N=6h + M=12h) tunable empirically; refines post first ~3 trigger fires per /mstr_review reporting (parallel to class-6 §2.2 threshold-tuning expectations).

### (b) EXPLORE/TRACE telemetry aggregation (signal source)

Post-archetype-cutover (2026-05-25T00:00Z UTC = NOW), every ws session-log entry carries `**archetype:** TAG` per LD-0043. The aggregation per /govern Step 1(b):

1. Read ws fabric session logs for trailing 5-day window
2. Filter entries with primary archetype EXPLORE OR TRACE per `org/tier0/COMPILER_ARCHETYPES.md` (EXPLORE weight=3.0; TRACE weight=3.0 — the two highest-cost discovery archetypes)
3. Cluster by topic: component / file-path-anchor / domain (grep on entry titles + body anchors)
4. Top-1 cluster by weighted entry count = candidate compiler-ask topic
5. If cluster concentration ≥40% of trailing-window EXPLORE+TRACE weighted-sum (same threshold as class-6 brief-surface per §2.1 — preserves parity with established threshold tuning baseline), the cluster is coherent enough to ask against

Pairs cleanly with existing class-6 detection — same input substrate (archetype headers), different output path. Class-6 fires brief-candidates via §3 packaging; MSTR-emit fires `[COMPILER-ASK]` per §6.4 (new this V3).

### (c) /govern Step 1(b) integration (where it lands)

After existing class-6 aggregation, add new sub-step:

```
CL_STALL_CHECK (deterministic every cycle):
  IF CL_STALL (per criterion above)
  AND EXPLORE/TRACE cluster coherent (per aggregation above)
  THEN MSTR-emit `[COMPILER-ASK]` MCP same shape as §6.1 + §6.1.1:
       - from_agent = 0.0.0_AB_MSTR
       - to_agent   = 1.1.0_SA_CTO
       - subject    = `[COMPILER-ASK] {short title of cluster}`
       - body       = cluster substance + EXPLORE/TRACE evidence + MSTR's read of compiler-shape opportunity
       - Self-ack-back NOT applicable (MSTR is both originator + Ack-recipient is moot)
       - Ledger as LD-NNNN with directive_ref D-003 v1.12 scope item xviii + authority_source: directive
  ELIF CL_STALL but no coherent cluster:
       - Log in cycle record "CL_STALL detected, no coherent EXPLORE/TRACE cluster, no ask emitted"
       - Re-check next cycle (trigger is per-cycle)
  ELSE (CL not stalled):
       - No ask emitted; cycle continues normal Step 1(b) flow
```

Mechanical = no judgment on whether to RUN the check (runs every cycle); judgment on emission is in cluster substance.

### (d) MSTR-emit ack-shape (§6.4 new, mirrors §6.1.1)

Since MSTR is both originator + dispatcher, the §6.1.1 Opal-CTO-ack-receipt-shape isn't needed. CL CTO's ack-back to MSTR on receipt is the standard MCP ack pattern — confirming ferry-bound or judgment-counter-route per §3.3 implicit-accept / §3.4 counter-route mechanism unchanged.

### (e) Cap on MSTR-emit volume

V1 ceiling: max 1 MSTR-emit `[COMPILER-ASK]` per /govern cycle. Andrew clarification on Opal CTO mechanism applies analogously: rare event, no required cadence; one substantive ask per cycle far exceeds the "this is biting now" threshold (false-positive cost = ~5min CL CTO triage; false-negative cost = pattern persists). Tuning expectations: re-evaluate after first 3 MSTR-emit fires per /mstr_review reporting.
