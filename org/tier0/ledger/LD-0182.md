# LD-0182 — Manual `ajb` sets WT tab title to the agent serial

## Decision

Extend the spawn-agent tab-title mechanism to the **manual** `ajb <Serial>` launch path, per Andrew direct.

## Why the gap existed

| Path | Title mechanism | Under suppressApplicationTitle:true |
|---|---|---|
| spawn-agent.ps1 | `wt.exe --title` at tab creation (terminal layer) | survives (suppression protects it from claude's overrides) — WORKED |
| manual `ajb` | in-tab OSC 0 + `$Host.UI.RawUI.WindowTitle` (process layer) | suppressed/discarded — NEVER SHOWED |

The user's Windows Terminal (Store install) has `suppressApplicationTitle: true`, so the only mechanism that sets a tab title is `wt --title` at creation — i.e. a new tab.

## Fix

When `ajb` is run interactively in WT (not `-Headless`, not already relaunched), it re-launches the same invocation in a new titled tab of the current window:
`wt.exe -w 0 new-tab --title <Serial> powershell -NoProfile -NoExit -Command "<dot-source ajb + ajb <Serial>>"`.

Guards: `-not $Headless` (spawn-agent path untouched), `AJB_NO_WT_RELAUNCH=1` (no recursion), wt-absent / non-WT → falls through to in-tab OSC. Escape hatch `AJB_NO_WT_RELAUNCH=1` keeps claude in the current tab.

Committed under /govern PROCEED (LD-0090).
