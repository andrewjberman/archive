# Tier-1 tilde-lane home directories (owned-paths path-shape fix)

**Authority.** Andrew-direct 2026-08-10 ~1905Z at the laptop MSTR terminal, VERBATIM: *"yes fix
the owned-paths gap"* — answering a finding `1.0.0_SA_CTO~B` surfaced and did not act on.

## The defect

Every tier-1 exec home is a **literal** path rule (`org/tier1_exec/1.0.0_SA_CTO/**`). A tilde
lane's own directory (`org/tier1_exec/1.0.0_SA_CTO~B/**`) therefore matched **no rule at all**
and `safe-commit` returned UNDEFINED — refusing a seat's own deliverable.

**Tier-1 was the only tier with this defect.** Measured 2026-08-10:

| tier | rule shape | tilde dirs |
|---|---|---|
| tier-0 | `org/tier0_exec/**` (broad) | covered |
| tier-2 | `org/tier2_senior/0.4.0_*/**` (serial glob) | covered **incidentally** |
| tier-1 | `org/tier1_exec/1.0.0_SA_CTO/**` (literal) | **match nothing** |

15 tilde directories carrying 199 tracked files exist under tier-2 today purely on that glob
accident. Coverage in tier-1 was also **partial**, which made the failure harder to read:
`org/tier1_exec/*/task_orders/*.md` **is** a glob, so a tilde seat could always write
`task_orders` and never `deliverables` or `logs`.

## What was granted

Seven rules, one per enumerated tier-1 exec home, each carrying its base home's lane **verbatim**:
`1.0.0_SA_CTO~*`, `2.0.0_SA_COO~*`, `1.1.0_SA_CTO~*`, `2.1.0_SA_COO~*`, `3.0.0_SA_CVO~*`,
`3.1.0_SA_CVO~*`, `4.0.0_SA_CRO~*` — all `/**`.

**This grants no new authority.** The agent side of `.owned-paths.yaml` already strips one tilde
(header ~line 43: *"`1.0.0_SA_CTO~C` needs no entry to commit wherever `1.0.0_SA_CTO` may"*), so a
tilde seat could **already** write everything in its base's home. It simply could not use its own
directory. This is a path-shape fix, not a privilege expansion.

**Deliberately NOT an `org/tier1_exec/*/**` wildcard.** LD-0331's rule stands and is restated in
the CRO home note: the registry is **enumeration-based, not tier-based** — a title is not a grant.
`<serial>~*` binds one named exec's own lanes and cannot reach another exec's home.

## Grounding

Exercised, not read — the real gate (`.tools/git-hooks/owned-paths-check.sh`) via its
`OWNED_PATHS_STAGED_FILES` test seam, audit redirected to scratch:

| # | agent | path | verdict | |
|---|---|---|---|---|
| 1 | `1.0.0_SA_CTO~B` | own `~B` home | PASS | the fix |
| 2 | `0.4.0_DS_ClientPlatform` | CTO's `~B` home | **BLOCK** | did NOT widen |
| 3 | `1.0.0_SA_CTO` | base CTO home | PASS | base unaffected |
| 4 | `1.0.0_SA_CTO~B` | `data/bd/scripts/gold/` | PASS | pre-existing, see below |
| 5 | `1.0.0_SA_CTO~B` | CRO's `~A` home | PASS | by design (CRO note: CTO+COO retain write) |

**Case 2 is the load-bearing one:** a BLOCK proves the new rules bind **lane membership**, not
merely path shape. A rule that passed everyone would have passed case 1 too.

Schema: `OK -- 55 lanes, 237 path rules, all lane refs resolve`.

## Surfaced, not adjudicated

**Case 4** — a non-DS seat passing on `data/*/scripts/gold/**` — is **not caused by this change and
not fixed by it.** Verified on the diff itself: seven rules added, all under `org/tier1_exec/`, none
removed, no `data/` rule touched. Whether that agrees with CLAUDE.md Rule 13 (DS owns the full
commit→QA-deploy cycle for `data/*/scripts/{gold,silver,bronze}/*.py`) is a separate question — it
may be a deliberate lane composition. Recorded so it is visible, not resolved by whoever reaches it
first.

## Provenance

Found by `1.0.0_SA_CTO~B` on 2026-08-10: its deliverable was refused, it relocated the file into
base's home and committed there (`a778b15cc1`, renamed `CTOB_...`). **The gap therefore presented as
"write it somewhere else" rather than as a broken rule — which is why it survived every prior tilde
spawn.** The same seat also identified the mechanism that made it visible at all: `safe-commit`'s
**abort path leaves the pathspec staged**, so an owned-paths refusal silently leaves a dirty index
that blocks an unrelated merge later, at a different seat, with no visible link to the refusal.
That second finding is banked, not fixed here.

**SoD holds:** CTO~B raised it and did not author its own grant; `0.0.0_AB_MSTR` is grantor.
