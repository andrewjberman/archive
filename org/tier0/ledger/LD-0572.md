# LD-0572 -- a resolution rule that read POSITION and never COUNT, and deleted rows on the case it could not see

## What was wrong

`.claude/skills/integrate/SKILL.md` Step 4 carried, since 2026-08-27:

> ⛔ IDENTICAL BASE-SIDE RANGES = ONE DEFECT CORRECTED TWICE. **PICK, NEVER UNION.**

The rule is right about the case it was written from (two fabrics independently correcting the same
sentence) and wrong about a case it never names, because **it keys on where the range sits and never
on how many base rows it consumes.**

```
-N,0  (ZERO count)   neither side consumed a base row -> APPEND COLLISION -> UNION, keep both
-N,M  (M >= 1)       both sides replaced the SAME rows -> two renderings  -> PICK one whole
```

Both render as "identical base-side ranges". Only the second is two renderings of one thing.

## The instance, which is the peer's

`0.0.0_AB_MSTR~Z` found it on the 2026-09-15/16 cross-fabric assessment, against its own live
conflict set: `org/XXX.md` at `-463,0` on **both** sides, where each fabric had appended a
**different** Step 1b-F loop-authorization row. Under the unqualified rule the resolution is PICK,
and PICK drops one fabric's row.

**Step 1b-F is the only source of truth for live loop arming.** So the failure mode is not a visible
mess -- it is a fabric that reads clean, cites a table that looks whole, and arms nothing. The loss
leaves no conflict, no error and no diff to review, which is the same silent-by-construction shape
Step 4's own "audit the LOSING rendering" block was written for one case earlier.

## The mechanism, which is this seat's, measured not taken on report

The finding arrived over the agentbus as a peer's claim. A peer's claim is not a measurement, so the
mechanism was re-derived here on a throwaway two-branch repo, with both arms:

```
POSITIVE  cloud -3,0 / sitez -3,0   identical, ZERO count
          PICK(cloud) yields 4 rows; the SITEZ row is gone. Union yields 5. Row count is the oracle.
NEGATIVE  c2    -2,1 / z2    -2,1   identical, NONZERO count
          both replaced base row 2. PICK is correct here; union would stack two fixes of one defect.
```

The negative arm is what makes this a qualifier rather than a reversal: the original rule keeps the
whole domain it was correct on, and loses only the cell it could not distinguish.

**The instance is the peer's, the mechanism is independently measured, and the two arms are what
separate the cases.** Neither seat's read alone would have landed it: `~Z` had the live conflict and
declined to edit the skill; this seat had the skill and no instance.
