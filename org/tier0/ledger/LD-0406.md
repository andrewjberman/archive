# LD-0406 -- the second leg of a cross-fabric reconcile SHIPS CODE

## The finding

Site Z's CLOUD→SITEZ push (leg 2 of the 2026-08-12 reconcile) carried ~100 files under
`data/*/scripts/**` that were new **to their branch**. The pre-push `safe-deploy` gate did exactly
its job and **deployed them**, reporting *"all files deployed and verified."*

**This is NOT a fault.** The S3 artifacts now correctly match the merged tree. **The defect is that
it is invisible in the protocol** — the integrator believes they are reconciling *git* and does not
realise they are shipping *code*.

## Grounding (mine, not relayed)

The relayer carries the grounding obligation (XXX.md): a routed finding is treated as grounded by
the receiver. So this was verified at the artifact before landing.

**`comp-pipescript` structurally could not test it** — it reports deployed-vs-repo **content** match
(ETag/sha), never an object's **LastModified**, and the claim was **temporal**. A designed-domain
mismatch: no way of calling it differently answers *"when was this written."* Hence a rail-checked
raw call, using `head-object` rather than `s3 ls` so the timestamp arrives in **explicit UTC** with
no timezone inference in the chain:

| object | LastModified |
|---|---|
| `s3://opal-data-inf/code/silver/build_billing_dim.py` | **Wed, 12 Aug 2026 16:56:18 GMT** |
| `s3://opal-data-inf/code/gold/INF_D_02.advisor_client_detail.py` | **Wed, 12 Aug 2026 16:55:45 GMT** |

Site Z's leg-2 report is stamped **16:57:47Z** — the writes land **~90 seconds before it, inside the
push window**. Today's writes: 3 of 21 inf silver, 2 of 110 inf gold, 0 bd gold.

## AMENDED 2026-08-12T17:25Z — THE MAGNITUDE, NOW MEASURED AT BOTH SEATS: **28, NOT ~100, NOT 5**

The first report said *"~100 files deployed."* **Wrong — and wrong in an instructive way.**

- **100** = files under `data/*/scripts/**` **in the merge diff** — the **exposure CEILING**
- **28** = objects the gate **actually WROTE** to S3 — the gate deploys **what DIFFERS**, not what
  the merge carries

*Two different denominators, and the first was labelled with the second's meaning.* Self-corrected
by `0.0.0_AB_MSTR~Z`, who re-measured rather than leaving it as an unverified figure of their own,
then **independently re-derived at base and agreeing exactly**:

| tree | written | denominator |
|---|---|---|
| `opal-data-inf/code/gold/` | **24** | 170 |
| `opal-data-inf/code/silver/` | **3** | 22 |
| `opal-data-bd/code/gold/` | **1** | 179 |
| `opal-data-bd/code/silver/` | 0 | 25 |
| **total** | **28** | **396** |

**ATTRIBUTION CONTROL — what makes 28 *caused-by* rather than merely *concurrent-with*:** every
object written to those trees on 2026-08-12 landed between **16:55:09 and 16:56:19 GMT**; writes
that day outside the push window: **ZERO**. The window and the whole day return the same set.

### My own earlier figure was ALSO wrong, by the same mechanism — and this is the third instance today

I reported *"2 of 110"* for inf gold. **`aws s3 ls` WITHOUT `--recursive` counts only top-level
objects**, silently excluding `runners_inf/` and `lib/` — where most of the deploy landed. The truth
was **24 of 170**. The output was well-formed and carried **no hint that it had answered a narrower
question than the one asked.**

**My "5 confirmed" survived only because it was labelled a FLOOR.** Had it been rounded up to "a
handful," or had site Z's 100 been accepted to be agreeable, the skill would now carry a wrong figure
with two seats' names on it. **A partial verification carried as a partial verification is what let
the correction land instead of propagating.**

## A false start that would have refuted a true finding

The first probe used `s3://opal-data-inf/code/scripts/silver/` and returned **empty**. That is the
wrong prefix — the real one is `code/silver/` (`safe_deploy_core.py:82-84` `CODE_TREES`).

**An empty `s3 ls` on a GUESSED prefix is byte-identical to a real absence.** Taken at face value it
would have produced a clean-looking negative that **refuted a true finding**. Caught by printing the
denominator and re-deriving the prefix from source rather than from memory — the
put-the-control-on-the-retrieval rule paying for itself on a live claim.

## What landed in `/integrate` Step 5

1. **Stop-block:** the second leg's push is a deploy event; it writes live production S3.
2. **Pre-push enumeration:** `git diff --name-only HEAD@{1} HEAD -- 'data/*/scripts/**'`.
3. **THE ORDER DECISION WAS SILENTLY A DEPLOY DECISION.** The first leg is usually inert (its files
   already deployed from that fabric); **the second leg is where the shipping happens.** Step 4 chose
   the merge order without knowing it was choosing **which fabric ships**. Now stated: weigh it, and
   say out loud which fabric takes the deploy.
4. **A push timeout tells you nothing about whether it landed** (measured: >2 min, timed out, had
   landed). `git ls-remote` is the oracle; **never a blind retry** — that turns a completed deploy
   into a confusing second one.
5. **NEVER `git stash`** to clear a dirty tree for the merge — named explicitly *because it is the
   reflex*. Site Z's backup-before-touch of 16 modified files (9 cleared as machine churn) is the
   recorded pattern.

## Residual risk — UNCHANGED, now VISIBLE

**If the two fabrics ever hold DIFFERENT content for the same script, the second leg's push silently
rewrites S3 with its merged view.** This ledger does not close that; it makes it legible and puts
the enumeration step in front of it. No gate added, no deploy behavior changed, **no remediation
authorized here.**
