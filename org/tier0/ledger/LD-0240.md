# LD-0240 -- comp-debt DESIGN (Andrew-direct estate-debt tool -> CTO arch-gate)

**What.** Andrew directly charged MSTR (2026-07-02, routed via CTO) to design + build `comp-debt`
-- a generalizable comp-tool that renders GROUNDED estate-DEBT verdicts. First consumer
NFRA_PIPELINE (§5 dependency); then powers the cloud-wide NFRA_DEBTSCAN expansion. This LD records
the CHARTER + the MSTR-authored DESIGN going to CTO for arch-gate.

**The design in one line.** comp-debt is a FUSION over existing signal-sources + a GUARD, not a
new scanner: it CALLS comp-dups, ADOPTS pipescript's debt-flags, FEEDS DEBTSCAN (its estate-wide
consumer), new-builds only 3 signals (CLOUDTRAIL/GIT-HEAT/TF-DRIFT), and its keystone is the
dormant-by-design-vs-dead guard + a NEW keep-dormant registry with a fail-safe default.

**Why S2 / not gated.** Directive-decomposition; the DESIGN phase is read-only (no build, no
runtime change; CTO arch-gates before any code). The eventual tool is EMIT-ONLY and any
decommission it feeds is human-confirm-first for unrecoverable classes. MSTR owns the design +
the governance-critical guard (a keep-vs-kill judgment is MSTR's domain -- why Andrew routed it here).

**Issued to:** `1.0.0_SA_CTO` (arch-gate the signal-fusion + verdict schema + dormant-guard). CC
`2.0.0_SA_COO` (NFRA_PIPELINE decomposition consumes comp-debt). Build delegates to a builder-lane
under MSTR ownership + CTO arch-gate AFTER the gate.
