# LD-0581 - Retire dead comp-aws references in the comp-tool-hud advisory hook

## His words

> "look into the infra-grep alternatives, that should just be comp-find --corpus aws"

## What was investigated before changing anything

`comp-aws` (referenced in the `aws_dynamodb`, `infra_grep` and `lambda` HUD classes) has been
DEPRECATED FOR AGENT USE since 2026-09-09
(`org/tier1_exec/1.0.0_SA_CTO/deliverables/ANDREW_DIRECT_20260909_191xZ_NO_LAPTOP_GRAPH_REFRESH_COMP_AWS_WRITE_PATHS_RETIRED.md`);
its own wrapper prints the deprecation notice on every invocation and points agents at `comp-kuzu`
reading the served cloud graph. So far, his correction is right.

But the literal proposed replacement, `comp-find --corpus aws`, does not answer the question the
old text was actually pointing at. All three dead references claimed comp-aws gave "edges /
blast-radius / consumers" -- a graph-traversal question. `comp-find`'s `_aws_corpus()` function
(`.tools/comp-find:125-155`) is a flat in-process regex over each live node's `name + arn + props`,
with no edge or relationship traversal at all -- it cannot tell you what depends on something.
Tested against the estate's own router, `comp-which`, with three natural-language phrasings of
"blast radius" / "consumers" / "what depends on this": it picked `comp-blast` and
`comp-estate --resource` every time, never `comp-aws` or `--corpus aws`.

## The fix landed

`.tools/hooks/comp-tool-hud.sh`, three classes:

- `aws_dynamodb`, `infra_grep`, `lambda`: `comp-aws` replaced with `comp-blast <fn-or-arn>` /
  `comp-estate --resource <key>` for the edges/blast-radius claim -- the tools the router itself
  already prefers, dead reference retired with nothing lost.
- `infra_grep` only: `comp-find --corpus aws '<pattern>' [NODE_TYPE]` ADDED as a separate clause,
  for the genuinely different question -- "is this declared thing actually live in AWS right now,
  and what is its drift class" -- which none of the old text asked and which his instruction was
  reaching for.

Exercised: `bash -n` clean; three synthetic PreToolUse JSON arms (a single-file `.tf` grep, an
`aws dynamodb describe-table`, and a directory grep confirmed to hit the earlier `repo_search` gate
instead) all render the new text correctly with proper backtick escaping; a grep of the file after
the edit finds no live `msg=` string still recommending `comp-aws`.
