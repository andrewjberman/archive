# LD-0265 -- `/kill storage` gains an opt-in `-WorkspaceScratch` switch (8.46GB reclaimable, dry-run only)

**What.** `.tools/kill-storage.ps1` can now reach the regenerable workspace scratch roots -- `.runtmp`
(5.3GB / 399,772 files), `.playwright-mcp` (265MB), `.frontend-dev` (8MB), `.ruff_cache` -- behind an
opt-in `-WorkspaceScratch` switch. Children only; the directories survive, because four skills reference
`.runtmp` as a scratch path. **Nothing has been deleted.** Dry-run reports **8,459 MB** reclaimable.

**Why extend rather than bypass.** A direct recursive delete was refused at the permission layer, and
that refusal was right. The tool's whole design is an *inverted* safety model -- an allowlist, not a
denylist, because recursive deletion is irreversible. The correct response to "the safe tool cannot
reach my path" is to widen the allowlist *deliberately, in the tool's own shape*, not to route around it
with an ad-hoc `rm -rf`.

**One guard added that the existing `-Pycache` path lacks.** `Assert-ScratchRoot` refuses any root that
`git check-ignore` does not confirm as **ignored**. `-Pycache` can delete git-tracked `.pyc` files -- its
own comment says so. This new path cannot delete anything git tracks, by construction. The asymmetry is
deliberate and is now stated rather than discovered later.

**The guard immediately earned itself:** `.ruff_cache` is untracked but *not git-ignored*, so the guard
refused it and printed why. A skip is not a failure; an unexplained skip would have been.

**Fits the session's through-line.** Today produced thirteen instances of one class: *an instrument
reporting confidently on something other than what it claims to measure.* A cleanup tool whose printed
allowlist and whose enforced allowlist are two different expressions would be the fourteenth. Here they
are one: `$WS_SCRATCH_NAMES` is the allowlist, `Assert-ScratchRoot` reads it, `Assert-Deletable` reads it,
and the delete-time re-validation reads it again. There is no second copy to drift.

**Stakes.** S1, reversible, dry-run default, no auto-run. `-Execute` remains an explicit operator action.

## Post-execution finding (2026-07-09T20:20Z) -- the tool named a cause it had not measured

Andrew authorized `-Execute`. It reclaimed **3,515 MB** and then printed:

```
FILES: deleted 2148, skipped 24 (locked/in-use), ~3515 MB reclaimed.
```

**The 24 were not locked.** Every one was a `node_modules` path exceeding Windows' 260-character MAX_PATH
(`portal-promote-*/…/eslint-visitor-keys.cjs`, `createProjectService.d.ts`). `Remove-Item` fails on those
regardless of locking. The summary line asserted `locked/in-use` -- **a cause it never measured** -- and an
operator reading it would have concluded a live process held the files and left ~1GB on disk forever.

Fixed here: the delete loop now retries through the `\\?\` extended-length prefix (which the .NET
`Directory.Delete` API honors) before reporting anything, and the summary no longer names a cause. It prints
the count and defers to the per-line reason, which is measured. Manual `\\?\` clearance of the 24 recovered a
further **1,030 MB**; total reclaimed **5.0 GB** (C: free 19.17 -> 24.17 GB). `.runtmp` is empty and the
directory survives, as the four dependent skills require.

**This is the fourteenth instantiation of the session's through-line, and it was in MY tool, in the very
commit that ratified the doctrine.** *An instrument reporting confidently on something other than what it
claims to measure.* The tool built to clean up after the mess printed a diagnosis it had not performed.

The generalization, now stated as a rule and not an observation: **a control may report a cause only if it
measured that cause.** "Skipped" is measured. "Locked/in-use" was inferred, and inferred wrongly. Where a
tool cannot determine why, it must say so -- `SKIP: <path> -- <the actual exception>` -- rather than supply a
plausible reason. A confident wrong cause is worse than an honest unknown, because it terminates the
investigation. That is the same failure as `DryRun` promising a probe, `BLOCK_AFTER_EPOCH` printing WARN
while blocking, `comp-iam` reporting DESIRED as applied, and LD-0262 asserting a blast-radius model read from
documentation rather than source.
