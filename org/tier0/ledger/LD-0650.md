# LD-0650 -- merge-resolve-known.py: cross-adjudication records join the known classes

## Decision
Add class 5 to `.tools/merge-resolve-known.py`: a path matching `org/critical_paths/cross_adjudication/<name>.md` that is an
ADD/ADD (no base) resolves to CLOUD's copy when the two copies are byte-equal after CRLF->LF and trailing-blank-line
normalisation, and the caller named the CLOUD side with `--cloud`. Any other input (a changed word, an extra line, a base, a side
absent, no `--cloud`) returns UNRESOLVED, so the pass HOLDS exactly as before. Ten fixtures in `.tools/test-merge-resolve-known.py`.

## Provenance chain (Art. XIII)
My box pass HELD at 06:2xZ on `XA-20261014T054803Z-7d27` (one record, written as a 4163-byte LF copy on box/laptop and a 4224-byte
CRLF copy on CLOUD; `diff --strip-trailing-cr` showed only one extra trailing blank line) -> repaired by hand in a drain worktree
(c9fd69b9a4) -> reported to the laptop CTO (msg 109085) -> CTO ruling: the class joins "with ONE rule ... only when equal after
EOL normalisation; any other difference HOLDS", tooling is the integrator's under an LD with a fixture for each arm -> this edit.

## Why now
A record written on two boxes under one id collides on every concurrent drain. The first collision cost a HELD box pass and a
hand repair; the rule makes the harmless case automatic and keeps the dangerous case (two different rulings) held.

## Assumptions
- The CTO's "root fix" (xadj.py writes its record with newline='\n') is already true: `.tools/xadj.py` writes the ruling record at
  one site with `newline="\n"`, and every other record in the directory has 0 carriage returns. The CRLF copy on CLOUD was written
  by another writer on dell1; unidentified, asked of MSTR~DELL1. NOT changed here.
- A lone `\r` line ending is not normalised.

## Alternatives considered
- Treat the whole directory as append-only: wrong, a ruling record is not a log.
- Resolve any difference to CLOUD's copy: rejected by the CTO; a real disagreement between rulings must never be auto-picked.

## Rollback plan
`git revert` of the commit that carries this entry; the resolver then reports the path "not a known multi-writer class" and a pass HOLDS.
