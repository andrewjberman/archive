# LD-0159 — /fabric-check expanded to a 4-script whole-fabric suite (agent + project axes)

## What Andrew asked
Expand fabric-check: cover HOT projects (worked <72h, not closed) + COLD projects (>72h, not
closed), <=2 sentences each, deterministic + structured; a telemetry agent-activity script
mapping agents -> projects with a one-line what-they're-doing; and a commit-scraper enriching
what agents did for hot/cold. "In essence 4 scripts."

## The 4 scripts (all read-only, deterministic, structured: human + --json)
1+2. **`fabric-projects.py`** (HOT + COLD): reads `org/projects/*.json`, keeps not-closed
     (status not in complete/closed/cancelled/merged), partitions by 72h last-activity
     (= max(JSON mtime, latest commit for the code)). Each project: status, hot/cold, owner
     (JSON field or dominant recent committer), last-activity age, commit count, latest commit,
     and a <=2-sentence status (first 2 sentences of current_phase + BLOCKING + latest-commit
     fallback). `--hot` / `--cold` / both / `--json`. Live: 14 hot, 5 cold.
3.   **`fabric-check.py --agents`**: each live agent (LIVE/ALIVE) mapped to its project +
     one-line what-it's-doing. Project inference (deterministic, best-effort): exact code in
     summary -> distinctive code-token in summary (unique token len>=5, e.g. MDLP/GLDINC/DEMOAUTH)
     -> latest commit's code -> dominant commit code -> (unmapped). Folded into the full
     `fabric-check.py` run too.
4.   **`fabric-commits.py`**: `git log` -> {code: [commits]} + {author: [commits]}. Project-code
     match is longest-first-with-consume (ADHC_COMPIL_V4 beats ADHC_COMPIL) and multi-code aware
     (close(A + B)). The shared enrichment layer for 1-3. `--project` / `--by-author` / `--json`.

## Definitions (deterministic)
- **Not closed** = status not in {complete, closed, cancelled, merged, superseded, done}.
- **Worked on** = max(project-JSON mtime, latest commit referencing the code) within 72h -> HOT,
  else COLD. (Commit recency is the primary signal; JSON mtime the floor.)
