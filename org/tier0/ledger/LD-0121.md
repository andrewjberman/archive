## Statement

Oracle pre-validation is the primary value-extraction event for V0.1 candidate-pool authoring. Running the pool's `oracle.command` against actual substrate before V1.0 freeze surfaces a four-class failure taxonomy PRE-FREEZE: (i) ecosystem fan-in → scope-narrow question construction; (ii) candidate empty-pool → (c+a) HYBRID skip + companion-class; (iii) CLI semantic divergence → canonical-source binding ARCH-ASK; (iv) conceptual substrate mismatch → re-scope to actual substrate location. The pre-validation step converts V0.1 candidate-pool into either publishable V1.0 freeze OR structurally-amended V0.2+ that survives empirical contact.

## Four-class taxonomy

| # | Class | Mitigation |
|---|---|---|
| (i) | Ecosystem fan-in (substrate richer than scoped) | Scope-narrow question construction (split into N+1 sub-questions per ecosystem slice) |
| (ii) | Candidate empty-pool (substrate empty at hypothesized location) | (c+a) HYBRID skip + companion-class on adjacent substrate |
| (iii) | CLI semantic divergence (tools disagree on cardinality) | Canonical-source binding ARCH-ASK + commit-of-record lock |
| (iv) | Conceptual substrate mismatch (wrong pipeline layer hypothesis) | Re-scope to actual construction-/emission-site preserving lift semantic |

## Symptom-class vs root-cause-class refinement (v0.2 meta-note)

Classes (i)-(iv) are **symptom-classes**, not **root-cause-classes**. Root cause may reside one or more layers up from the surfaced symptom. Instance (iii) is the canonical exemplar: surfaced as CLI-divergence (iii); root-caused as keying-break (ii)-shaped upstream of the cycle classifier. Future instances should mark both symptom-class at surface AND root-cause-class at resolution; banking both preserves cross-instance pattern visibility. Standalone LD-0122 abstraction candidate if 2+ future instances exhibit divergence.
