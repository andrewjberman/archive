## AMENDMENT 1 (2026-07-29T03:05Z) — SAME CLASS, ONE LAYER OUT: the `~/bin/aws` forwarder baked TWO MSYS path flavors into one line, and every `aws` call in every agent shell was dead

Andrew-direct: *"yes we need to fix the aws path."*

**Symptom:** any `aws ...` from an agent shell died with a **Python SyntaxError reading a bash
file** — `File ".../bin/aws", line 7 ... SyntaxError: invalid syntax`.

**Root cause.** The generated forwarder strips `~/bin` from PATH before re-invoking `aws`, so
`.tools/aws`'s self-discovery cannot mistake the forwarder for the real CLI. That strip compared a
**generation-time string**:

```sh
export PATH="$WS/.tools:$(... | grep -Fxv "$BIN" | ...)"
#              ^^ expanded to /cygdrive/c/...   ^^ expanded to /c/Users/...
```

**Two flavors of the same directory, in the same generated line.** PATH at run time carried the
`/cygdrive/c/...` form; the strip searched for the `/c/...` form; string equality across flavors
never matches; **the strip silently no-opped and the exact loop it exists to prevent fired.**
Compounding it, the `.tools` PATH entry rendered with **no drive prefix at all**.

**Fix — run-time self-resolution, identical principle to this entry's main body:**

```sh
_self_dir="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
export PATH="$(... | grep -Fxv "$_self_dir" | ...)"
```

`cd && pwd` returns the flavor the **current** shell understands by construction, so it matches its
own PATH entry regardless of flavor. **No path string is compared across time.** The `$WS/.tools`
prepend stays baked — this file lives *outside* the repo and must point home — but is now
**guarded** by `[ -x "$WS/.tools/aws" ]`, so a stale bake degrades to "use whatever `aws` is on
PATH" instead of breaking every call.

**Verified (output, not rc):** `--version` -> `aws-cli/1.44.44`; `sts get-caller-identity` ->
`arn:aws:iam::313476888478:user/Andrew_Berman`; `ec2 describe-instances` -> `i-07dccb1615503ac99`
(the exact call that exposed the break); SyntaxError/Traceback count **0**. 94 tools x2 forms
regenerated.

### Causation: stated, not hidden — and not claimed

I wrote Git's `etc/fstab` earlier tonight (LD-0340 A1). **That file did not previously exist**, and
adding a `C: /c` entry alongside the compiled-in `/cygdrive/c` mount is a plausible trigger for
MSYS changing which flavor it renders Windows PATH entries into.

**I have not proven that, and I will not claim it.** I did not capture the PATH flavor before the
fstab write, so **the before-state is unrecoverable** — the capture-the-baseline discipline failing
in the one direction that cannot be repaired afterward.

> **What IS certain: the shim was always one flavor-flip away from this**, because it compared two
> independently-expanded absolute paths. **The fstab may have pulled the trigger; the generator was
> the loaded gun.** The fix removes the gun and is correct under either causal story — which is why
> it did not wait on resolving causation.

**Class count: this is the THIRD distinct instance tonight** of *a path baked at write time that
must be resolved at run time* — the launchers (main entry), `install-closeout-comp-state.sh`
(LD-0343 A1), and now the PATH shims. **Three independent authors, three files, one defect.** That
is no longer a bug; it is a missing convention.

## AMENDMENT 3 (2026-07-29T04:05Z) — `.tools/aws` dispatched on what a file is CALLED, not what it IS. The class is FOUR, not three.

**Post-fix confirmed by `~Z`** (`amb-z-0007`): my `8b61042af6` (the `~/bin` forwarder flavor bug)
landed in Z's clone and `aws` was **still dead there**, byte-identical error. That upgraded Z's
claim from hypothesis to **post-fix confirmation** — the strongest form, because the competing
explanation had been eliminated by landing it.

**The bug.** The exec dispatch branched on the `*.exe` **filename suffix**. On AWS CLI v2 boxes
`which -a aws` returns two entries with the **extensionless alias first**; the resolver breaks on
the first hit, so `$REAL` carried no `.exe`, and the fallback arm ran `python` against a **native PE
binary**:

```
SyntaxError: Non-UTF-8 code starting with '\x90' in file ...AWSCLIV2\aws.exe
```

`\x90` is the PE header. The AWSCLIV2 directory contains **only `aws.exe`** — the extensionless name
is a PATHEXT alias for a file that does not exist under that name, **so the suffix test keyed on a
name with no corresponding file.**

> **~Z's FRAMING, ADOPTED — MY "THREE-FOR-THREE" IS FOUR.** The launchers baked **where they were**
> at write time; this bakes **what something is**. `*.exe` is a write-time **textual** property
> standing in for *"is this a native binary?"*, which is a **run-time property of the file's
> content**. **A path-flavor audit could never find it — the defect contains no path literal.** The
> class is not "hardcoded paths"; it is *a write-time stand-in for a run-time fact*.

**Fix:** read the first two bytes. `MZ` is the DOS/PE magic every Windows native executable carries
regardless of name. Suffix test retained as a fallback for unreadable paths.

**Verified both directions, including the one that matters for base:**

| file | first 2 bytes | arm taken |
|---|---|---|
| `python.exe` | `MZ` | native — correct |
| `.tools/aws` (a shell script) | `#!` | not native — correct |
| **base's own `aws` entrypoint** | **`#!`** | **python arm — correct, no regression** |

Base's entrypoint is an **extensionless python script**, i.e. exactly the case that must *not* be
treated as native. `aws sts get-caller-identity` returns the same ARN after the change.

### THE RULE

> **INSIDE THE REPO: derive at run time. Never a device literal, and never an env var standing in
> for one. OUTSIDE THE REPO: a bootstrap may point home, but it must be GENERATED (never
> hand-edited) and must DEGRADE LOUDLY.**

**Andrew proposed env-varring the device username** (he had deliberately mirrored the workspace

username-substitution **still assumes everything else** -- that the repo sits at
`Users/<name>/Desktop/ajb_workspace`. It breaks on a clone elsewhere, a worktree, a UNC share,

have helped -- `Opal Bloomberg` contains a **space**, and matching the layout does not remove that;
the failure was quote-stripping in a `-Command` string, not the username.

**Keep the mirrored layout anyway, for DIAGNOSIS not mechanism:** identical layout makes the two
devices comparable, so a divergence means a real defect rather than a layout difference.

**What is legitimately device-specific, and only this:** the `~/bin` forwarders. They live *outside*
the repo, so they must carry an absolute pointer home -- nothing in the repo can derive it for them.
Bounded to a **generated** bootstrap that is never committed, now carrying the both-flavor fallback.
`OPAL_WS_ROOT` is the escape hatch for genuinely odd layouts and should stay **unset**.
