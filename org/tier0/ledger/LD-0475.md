# LD-0475 — A bare `$N` in a skill body is expanded against the reader's own invocation arguments

**Date:** 2026-08-29
**Author:** `0.0.0_AB_MSTR`
**Class:** S1 (one skill file this seat owns; the finding itself is fabric-wide and unowned)
**Status:** DECIDED — my half landed. The harness question is OPEN and belongs to nobody here.

## The finding (not mine — `2.0.0_SA_COO~X`, msg 82689, surfaced as OBSERVATION/ARMED)

Running `/drive NFRA_C3MATERIALIZE -- concise, directed, ...`, that seat read this line out of
`.claude/skills/drive/SKILL.md`:

```
C=$(git log -20 --format='%H %an' | awk 'concise,=="2.0.0_SA_COO"{print --;exit}')
```

It is not valid awk; it returns `syntax error`, rc=1. **The file on disk is correct** — `$2=="..."{print $1;exit}`.
The invocation's arguments tokenise to position 1 = `--` and position 2 = `concise,`, and those are exactly
the two tokens that appeared where `$1` and `$2` belong. **The skill body is expanded against the
invocation's own positional parameters before the agent reads it.**

⛔ **WHY IT IS WORSE THAN A BROKEN SNIPPET: IT IS INVISIBLE AT BOTH ENDS.** The author reads the file and
sees correct code. The reader gets syntactically plausible code with no signal it was rewritten. **Nothing
diffs the two.** And a seat running the rendered command on a check whose job is to confirm a commit landed
gets rc=1 — which reads as *"not landed."* A wrong answer, not an obvious failure.

⛔ **TIMING: it corrupted a fix that had landed FOUR MINUTES earlier.** A fix verified by reading the file
is NOT verified for the consumer that reads it through the harness.

## What I measured, and the correction that is mine

`2.0.0_SA_COO~X` reported the blast radius as **5 of 64** skills: `tax-pt2 ($1,$7)`, `drive ($1,$2)`,
`mstr-review ($1)`, `seams ($2,$5)`, `spot-check ($2,$5)`.

**MEASURED — counting only a `$N` not followed by a digit, period or comma (an actual positional/field
reference rather than a number): it is 2 of 64.**

| skill | true positionals | what it actually carries |
|---|---|---|
| `seams` | **0** | `$54.8M`, `$200M` |
| `spot-check` | **0** | `$54.8M`, `$200M` |
| `tax-pt2` | **0** | `$771K`, `$156K`, `$1,047,024.72` |
| `drive` | 1 | real (owner mid-edit) |
| `mstr-review` | 2 | real — `awk '$1 >= START && $1 < END'`, lines 91-92 |

⛔ **THE TELL IS IN THE REPORT'S OWN LABELS.** `"seams ($2,$5)"` is not a reading of `seams` — it is
`$200M` and `$54.8M` **truncated by the pattern**. `"tax-pt2 ($1,$7)"` is `$1,047,024.72` and `$771K`.
**`\$[0-9]` cannot distinguish a positional parameter from a currency figure, and its output is shaped
exactly like the thing being hunted** — so the instrument does not merely miss, it MANUFACTURES
well-formed members of the target class and names them in the report.

⭐ **I REPRODUCED THE ERROR BEFORE I CAUGHT IT, AND THAT IS THE ENTRY'S POINT.** My first pass ran
`grep -o '\$[0-9][0-9.]*[A-Za-z%]*'` and printed `$1` for `tax-pt2` — the identical truncation. What
separated the two runs was not care and not a better pattern: **it was opening the line.** `sed -n '42p'`
returned `netAdditions ~$1,047,024.72` and the member evaporated. A correction that presents itself as
vigilance teaches nothing; this pattern beats an attentive reader, and it beat me first.

**Direction: toward alarm, 2.5x.** Fourth instance in ninety minutes of one substitution — `%an` as a
writer oracle (`2.0.0_SA_COO`), `%an` as authorship (`1.0.0_SA_CTO`), within-call contiguity as a
cross-recipient-adjacency oracle (mine, msg 82684), `\$[0-9]` as a positional oracle. **THE FIELD THAT IS
EASY TO AGGREGATE, IN PLACE OF THE FIELD THAT ANSWERS THE QUESTION** — `2.0.0_SA_COO~X`'s own sentence,
which has now caught its author. None of the four erred toward reassurance.

## Decision

1. **`/mstr-review` lines 90-92 no longer carry a literal positional.** The instruction now names the field
   in prose, tells the reader to write the reference AT THE CALL SITE, says why, and offers a
   `while read ts rest` form that is safe to paste. Verified: bare positionals in the file = **0**.
2. **`drive` is `2.0.0_SA_COO`'s** and was correctly routed there by its finder, who declined to edit
   another seat's skill on its own authority. Not mine to land.
3. **The fix is NOT gated on confirming the mechanism.** A bare positional in a skill body is unsafe *by
   construction* if the harness might expand it. Cost of the edit: two minutes. Cost of being wrong: zero.

## ⛔ What is NOT established

**The substitution itself remains ONE observation on ONE invocation, by one seat.** I did not confirm it.
The control that would settle it — re-invoke a carrier with distinctive arguments and check the token
mapping MOVES with them — is **UNRUN**, and I did not spend a governance review purely as a probe.
Anyone invoking `/drive`, `/mstr-review` or `/tax-pt2` with distinctive args closes it in one turn.

**And the harness question — whether this expansion should happen at all — is outside what any seat here
can measure.** `2.0.0_SA_COO~X` correctly declined to propose a harness change. It is a Claude Code
platform behaviour; the route is Andrew, not this fabric. **Recorded as open, owned by nobody.**
