# LD-0451 — `ajb2`, the Codex-seat launcher

`.tools/ajb2.ps1` -> `function ajb2` -> `org/mcp/start-codex-seat.ps1`

**Built to his ask**, in the shape he named: *"maybe ajb2 instead of ajb for the alias?"* — so it is a
peer of `ajb`, not a replacement, and the two read as siblings:

```
ajb  <serial>   ->  claude seat
ajb2 <serial>   ->  codex seat
```

## What was measured before writing it

- The five Codex-host files exist on this fabric (`start-codex-seat.ps1` 5,022 B and siblings).
- `ajb2` is not already taken — only `.tools/ajb.ps1` exists.
- `ajb` is a **dot-sourced function**, invoked `ajb -Headless <Serial>`; `start-codex-seat.ps1` is a
  **script** taking `-Serial/-ThreadId/-Workspace/-Port`. `ajb2` bridges the two shapes.
- `start-codex-seat.ps1` runs `codex` **inline and blocking**, reaping its background children
  (app-server, heartbeat, bridge) in a `finally`. **So `ajb2` must not background the call** — doing
  so would orphan three processes. That is recorded in a comment at the call site.

## The one design decision worth recording

`ajb.ps1` carries an explicit note that its root resolution is *"deliberately NOT `git rev-parse`"*
because it must work before/without git. **I mirrored the order rather than substituting the
"better" primitive.** A documented decision in the thing you are pairing with is a constraint, not
an oversight — and a launcher that resolves its root differently from its sibling is exactly the
kind of divergence nobody notices until the two disagree on one machine.

## Exercised, with controls both ways

```
parse                          OK

NEG  'not-a-serial'            REFUSED, named reason
NEG  -Workspace C:\no\such\dir REFUSED, named reason
NEG  '4.0.0_SA_CRO~'           refused (trailing-tilde edge case)
POS  4.0.0_SA_CRO~A            accepted   <- the serial he named
POS  0.0.0_AB_MSTR             accepted
POS  0.4.0_DS_ClientPlatform~H accepted
starter path resolves          True
```

**My first negative-control run reported a false PASS** — `-ErrorAction SilentlyContinue` swallowed
the very error the control existed to observe. Re-run with `-ErrorAction Stop` and the refusals
appeared. *A control that cannot see the thing it is testing for reports success.*
