# LD-0541 - The Daily Sprint has never run itself, and the reason not to build tonight

## Decision

Record the measurement and the pattern. Build nothing until Andrew answers where the packet
comes from.

## What was measured

The viewer is real and deployed. Nothing runs the generation.

| evidence | reading |
|---|---|
| gateway Terraform schedules | 2, neither the sprint |
| laptop scheduled tasks | 2, neither the sprint |
| published days in the bucket | 9 consecutive, then a 4-day hole, then 1, then none today |

**The hole is the finding.** A scheduled job does not miss four days and resume. It ran while a
person drove it and stopped when nobody did.

⛔ **A FALSE ZERO ON THE WAY, BANKED.** My first bucket read used `daily_reports/`, the LOCAL folder
name; the served prefix is `daily-reports/` with a hyphen. It returned empty with no error, which is
byte-identical to a real absence, and I would have reported "nothing published". The bucket-root
control caught it.

## Why not build

The sprint's substance is what the fabric did today: `comp-state`, a two-fabric git census, the
directives dashboard, open-TO totals. **A Lambda has none of that** — no checkout, no `org/mcp`
telemetry (gitignored), no broker.

Three packet sources are possible and they produce genuinely different products. Choosing one is a
design decision with Andrew, not an implementation detail I can settle by picking the convenient
one. **A scheduled job built on a guessed source publishes the wrong thing every day, unattended,
to a served prefix** — strictly worse than the manual gap it replaces.

## Rollback

Nothing was built. The work order is a record; deleting it costs nothing.
