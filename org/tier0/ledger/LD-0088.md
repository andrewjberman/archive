# LD-0088 — CL Tier-1 session-routing pattern (feature_clb-pinned + extended broker reach + skills mirror)

## Decision

All CL Tier-1 sessions live in `feature_clb/` cwd. The `opal-agent-comms` broker (currently ws-rooted) is extended to be reachable from feature_clb cwd. `.claude/skills/**` is mirrored (or symlinked) into feature_clb's skill-discovery substrate so the same workspace-shared skills load identically in either cwd.

Single coherent session model per CL agent. Cross-fabric authorship attribution preserved by existing branch-isolation hook (commits from feature_clb cwd into feature_clb worktree → COMP branch, unchanged). Unified broker reach achieved without forcing:
- (d) dual-pinned instance — doubles spawn complexity
- (e) output-staging-area — staging-rot risk + picker-agent automation
- (f) feature_clb-as-submodule — cross-fabric authorship attribution distortion

## Forks resolved by this single decision

Five previously-deferred architectural forks all collapse to downstream-symptoms of the same root (per CL CVO `[TARGET-B+D CONSOLIDATED REPORT]` §2.4 unification 20260526T~04:45Z):

2. **`.spot-check-checkpoint` write blocker** — sister to cases_queue. Same resolution.
3. **Cross-fabric feature_clb read blocker** — ws-cwd CL CVO couldn't read `feature_clb/org/foundations/CL_CONSTITUTION.md` for consumer-side ratify. Resolution: feature_clb-cwd CL CVO reads natively (no submodule needed).
4. **V1.0 AUTHORITATIVE body-delivery dependency** — required CL CTO to MCP body inline due to read-access gap. Resolution: feature_clb-cwd CL CVO reads directly; no body-ferry needed.
