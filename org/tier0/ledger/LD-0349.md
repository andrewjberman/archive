## The state it corrected

Bare `pipescript` was deprecated by Andrew 2026-07-29 (*"we are deprecating base pipescript"*,
*"pipescript needs to be categorically renamed"*) and carries a standing flat prohibition.
`.tools/pipescript` is now a **retired rc=2 stub** naming its successor. Meanwhile the LAW told
agents to use it, and `tool_index.py` still registers the bare name `'status': 'canonical',
'routable': True` — so it also surfaced in `comp-which`'s near-tie list.

**Three copies, three answers: the prohibition, the retired stub, and the law — and the law said
use it.** A retraction is only as dead as its last surviving enforcing copy. This was the one a
fresh agent reads first, at startup, before any tool tells it otherwise.

The edit also records two things the bare rename would leave ambiguous: **`comp-pipescript` is a
DIFFERENT tool, not a synonym** (three separate CLAUDE.md rows use it legitimately, and collapsing
them would break deploy-parity guidance), and the engine's **keys are re-derived live while NAMES
come from a snapshot the tool itself declares stale past 14 days.**

## An over-claim of mine, withdrawn

On finding this I reported the prohibited tool was reachable and that only a missing `~/bin`
forwarder stood in the way — "luck, not a control." **That was wrong, and I withdraw it.** Reading
the file showed two real controls: `.tools/pipescript` is a deliberate loud rc=2 stub, and
`provision-path-shims.sh` derives its set from `.tools/comp-*`, which structurally excludes the
bare name. The stub's own docstring had already measured `pipescript -> command not found, rc=127`.

I had inferred the mechanism from the PATH absence instead of opening the file — Rule 22, on the
same night the estate's own taxonomy measured that class. **The stale-law finding survives; the
severity framing does not.**
