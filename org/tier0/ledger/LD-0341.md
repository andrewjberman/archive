# LD-0341 — THE MISSION REGISTER: a layer above the Macro/Project Registry, MSTR-owned, costing every other agent nothing

**Andrew-direct, MSTR terminal, 2026-07-28.** Register created at `org/tier0/MISSIONS.md`.

## The instruction — structural clauses verbatim

> *"This is going to be a new architecture that sits on top of the Macro/Project Registry and is
> largely attached to it but not necessarily 1:1. The premise is that there are a handful of very
> large scale missions that need to be addressed, these are widespread initiatives at Opal that many
> macros/projects can fall beneath. Sometimes these items are closer to the macro/project level, other
> times they are aggregations of many project codes, and sometimes even aggregations of macro_project
> codes with disparate macros."*

> *"Our task will be to enumerate both the structure for how to log and assess the progress on these
> major items, and also log these items and get them into the system."*

> *"We need this document to be managed by you primarily, because I don't want to add more process
> architecture and bullshit for the tier1 agents to have to do. It is something that, at startup, you
> will essentially assess the state of the repo/system/and various properties and how they relate to
> the content of this major project state doc, and you will keep it in order."*

Four groups, named by Andrew: **Portal · Infrastructure · Debt · External.**

Content clauses preserved verbatim in `MISSIONS.md` at the objective they govern — the AUA
four-category aggregation (ETF Models / SMA Strategies / Custom Models / Non-Model Residual), the
365-day TWR gross-and-net daily basis and the intent to supplant Black Diamond and Orion, the
per-tool coverage universe, the canonical-taxonomy-and-coverage-enumeration problem, the
decommission-as-you-migrate direction with its agent-confusion cost, and the three client
subdivisions. **They are quoted at the point of use rather than collected here, so a reader working
one objective sees the sovereign phrasing without having to find this file.**

## The two design decisions I made, and why

**1. Zero obligations on anyone else.** This follows directly from the instruction and it is the
load-bearing constraint. The register has **no gate, no hook, no new field on any project JSON, no TO
type, and nothing that reads it programmatically.** MSTR derives every value from artifacts the fabric
already produces — commits, project JSONs, PRDs, ledger entries, live state.

> **Corollary, and it is the useful one: if a mission's state cannot be derived from what already
> exists, that is a finding about our INSTRUMENTATION — not a request for someone to file a form.**
> The register's inability to see something is diagnostic. This is the same principle as a tool's
> silence being the defect rather than the trace.

**2. Three independent axes, never a percentage.** Each objective is stanced on **DECIDED / BUILT /
SERVING**, values `NO` / `PARTIAL` / `YES`, **every non-`NO` carrying an anchor** (commit-ish,
artifact key, ruling ref) or reading `ASSERTED` and being non-actionable.

They are separated because collapsing them is exactly how this estate has been burned, repeatedly and
expensively: *"it is deployed and it works" is not an architecture*; a green suite describes a file
while a deploy is about a runtime; *"the chain ran" is not "the product is fixed."* A single
percentage would fuse all three into a number whose axis nobody could state — the failure mode
VERIFICATION LAW (6) names.

Supporting fields: **FRONTIER** (the one next thing, not a plan), **BLOCKED-ON**, and **GROUNDED**
(the date it was last re-derived). **`UNASSESSED` is legal and is never silently upgraded to `NO`** —
"I have not looked" and "it does not exist" are different claims, and only one of them is evidence.

## What the register found on day one — the justification, unplanned

Authoring it against real codes rather than described ones surfaced two defects immediately:

1. **`MDPF_CHANNEL_INDEPENDENCE` has a PRD, is cited as law in `CLAUDE.md`, is driving live P0 work
   today — and has NO project JSON and ZERO rows in `REGISTRY.md`.** Independently found by
   `3.0.0_SA_CVO` in its `/spot-check` earlier today (F-1) and confirmed here against both artifacts.
   **A load-bearing initiative invisible to every registry instrument we own.**
2. **`MDPF_DEBTSCAN`, named in the instruction, does not exist.** The real neighbours are
   `MDPF_DEBTCLEAN` (active) and `NFRA_DEBTSCAN` (complete). Attached to the live one and **flagged
   rather than silently resolved** — guessing which code a sovereign meant is how a register starts
   lying, and a register that quietly corrects its own source is worse than one that asks.

> **A layer whose first act is to find two things the layer below could not see is the argument for
> the layer.** Recorded because the justification is measured, not asserted.

## Scope boundaries held

- **This does not supersede `org/projects/REGISTRY.md`.** The registry answers *what work exists*;
  the register answers *are the big things moving, and what moves them next.*
- **Missions are not dispatched from here.** Routing and sequencing remain CTO's and COO's. MSTR

  at the objectives they bind (0824/0833 never-add/never-substitute at `PORTAL.ADVISOR_INTELLIGENCE.O2`; the Schwab

## AMENDMENT 21 (2026-07-29T03:25Z) — VIEW-TIME COMPILE. The post-commit hook no longer writes any tracked file.

**Andrew-direct:** *"maybe what really needs to happen is we make the compilation tagging of relevant
git commits a 'view-time' compile instead of just constantly editing the doc with every individual
commit."* Landed.

### What was wrong

`emit` and `compile` ran from the post-commit hook and wrote `execsum.yaml`, `commits.jsonl` and
`MISSIONS.md` — **all tracked**. Measured churn was **three lines per sub-group**:
`anchor_commit` / `anchor_time` / `anchor_author`, a pointer to the latest attributed commit.

> **The defect was storing a VOLATILE DERIVED VALUE in version control.** Every commit by any agent
> re-dirtied the register, and **in a shared worktree a dirty tracked file blocks `git pull` for
> everyone.** It blocked `0.2.0_DT_PortfolioAnalytics` **twice** during an MDPF P0, and it
> re-dirtied itself **within seconds of the commit that cleaned it** — because that commit is itself
> a new anchor. **A register whose job is to be TRUE cannot cost a commit every time the repository
> moves.**

### Why not auto-commit / auto-push — rejected on mechanism, not preference

A pre-push hook that commits creates the commit **after** git has computed which refs to push, so it
never ships and the tree stays permanently ahead — and the commit **re-fires this very hook**,
regenerating the files. It chases its own tail. **Auto-push treats the symptom; view-time removes
the source.**

### The change

The hook now writes one **gitignored** marker, `.comp-graph/missions-refresh-due.json`, recording
the HEAD at which a refresh became due. It touches nothing tracked. Compilation happens when someone
**looks**: `.tools/comp-missions emit && .tools/comp-missions compile`.

### The tradeoff, accepted deliberately

`org/missions/` is now **stale-by-design between compiles.** Safe for exactly one reason: **the board
carries its own anchor commit, so staleness is VISIBLE rather than silent.** A derived artifact that
could not show its own vintage would not be safe to leave stale; this one can.

Full restructure (moving `commits.jsonl` out of the tree, dropping the anchor lines from
`execsum.yaml`) is deferred until after tonight's MDPF fires. This is the minimal reversible half
that stops peers being blocked **now**.
