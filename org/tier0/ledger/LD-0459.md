# LD-0459 -- Codex seat lifecycle: false readiness made inexpressible

## The defect, in one line

**A value and a guess shared one type**: three seats broadcast the identical hardcoded
summary "WORKING: Codex non-consuming inbox monitor active" while only one had a monitor
-- the sentence was an argparse DEFAULT (`codex-agent-heartbeat.py:47`), observed by
nothing, refreshed every 30 seconds by a process structurally unable to know it was false.

## Root cause -- four coupled mechanisms, all confirmed at source

1. **`--discovery-timeout` defaulted 120s and raised on expiry.** A fresh TUI's thread is
   not in the state DB until the operator's first persisted turn, so every fresh launch
   raced a human against a fixed clock. Measured live: CRO base + ~B bridges dead with
   exactly the reported stderr line.
2. **The detector is a CHILD of the bridge** (`detector_lines` spawns it). One timeout
   killed both -- which is why "detector never existed" always co-occurred.
3. **The launcher fire-and-forgot the bridge.** `Start-Process`, no supervision, no
   readiness gate; an early bridge death changed nothing in the launcher's output.
4. **No consumer-side conjunction existed.** Liveness freshness, broker connection and
   the (lying) summary were all producer-side; every partial probe read green on a deaf
   seat -- the anti-correlated class this estate keeps measuring.

## Proofs (the RETURN contract)

- **Tests**: 30/30 (12 pre-existing + 18 new), independently re-run by `4.0.0_SA_CRO~A`: 30/30.
- **Live before/after**: base+~B heartbeat-only false-green -> bridges SUPERVISING + truthful
  `DEGRADED` summaries; ~A rebound -> `codex-seat-status` GREEN rc=0 (9/9), base RED rc=1.
- **Real-traffic delivery**: the repair report itself dropped as an inbox file -> detector
  emitted -> bridge `[turn/start]` -> CRO~A woke, ACKed with the notice's SHA-256, moved the
  file only after acting, replied via `codex-send` (the positive arm), and RAVC-closed.

## Remaining limitations (stated, not papered)

- A from-zero interactive `ajb2` launch needs a human terminal by design; the acceptance
  instrument for that keystroke is `codex-seat-status` rc=0.
- `codex-send` deliveries carry the broker's honest "Sender-unverified" stamp (the registered
  process is the heartbeat). A seat-token protocol in `server.py` would remove it -- deliberately
  not built (build-ladder; the stamp is true and the local gate is the control).
