# LD-0078 — Fix spawn-agent.ps1 extras-quoting fragility

## Decision

Per Andrew direct 2026-05-26T~02:13Z + LD-0077 follow-up: accept Path (a) — fix the underlying primitive in `.tools/spawn-agent.ps1` rather than push burden to /mstr-spawn skill body or drop --say capability entirely.

## Empirical anchor

LD-0077 canonical first-use of /mstr-spawn fired 3 sibling-agent spawns 02:06:13-23Z (ws CTO + AE 0.7 + ws COO). All 3 reported `[spawn-agent] launched` and the audit log appended `SPAWN` entries. **But claude.exe never started underneath** — the PowerShell windows were alive holding concurrency-cap slots, broker showed all 3 NOT_REGISTERED, marker scan found the PowerShell PIDs but not the expected claude.exe children.

Andrew surfaced the actual error by viewing one of the deaf shells: the inner PowerShell parser rejected the command line:

```
At line:1 char:165
+ ... n - read inbox: WB-1 AE 0.7 authorization landed; 3 artifacts RATIFY  ...
+                                                         ~~~~~~~~~
Unexpected token 'artifacts' in expression or statement.
```

**Root cause:** `spawn-agent.ps1` line 157 built `$extraStr` by raw-joining the `--say` words with spaces, then line 167 injected it into the inner command:

```powershell
$extraStr = if ($Extra) { ' ' + ($Extra -join ' ') } else { '' }
...
$inner = ". `"$ajb`"; ajb -Headless $Serial$extraStr $marker`: $Serial"
```

The spawned PowerShell parses `$inner` as a script. PS `;` is a statement separator. My --say text contained `; 3 artifacts RATIFY` → PowerShell split on the `;` and tried to parse `3 artifacts RATIFY ...` as a fresh statement. Parser error → ajb call never executed → claude.exe never launched.

This is a class bug: any --say text containing `;`, `:` (in some positions), unescaped parentheses, `&`, `|`, `<`, `>`, `,`, or other PowerShell metacharacters triggers the same failure.

## Fix

Replace line 157 with single-quoted-literal wrapping:

```powershell
if ($Extra) {
    $extraJoined = ($Extra -join ' ')
    $extraQuoted = $extraJoined.Replace("'", "''")
    $extraStr = " '$extraQuoted'"
} else {
    $extraStr = ''
}
```

Then the inner becomes (example with `;`-containing extras):

```
. "ajb.ps1"; ajb -Headless 1.0.0_SA_CTO 'Per LD-0077; 3 artifacts RATIFY...' # OPAL_SPAWN_MARKER_v1: 1.0.0_SA_CTO
```

Single-quoted PowerShell strings are literal — no variable interpolation, no statement parsing. The only escape is `''` (doubled) for a literal single quote inside. `ajb` receives the entire --say text as one string argument, regardless of content.

In-code comment explains the empirical anchor so future maintainers see the bug-history at the fix-site, not just in the LD ledger.

## Test-by-construction

PowerShell language spec: single-quoted strings are verbatim. The only edge case is a `'` in the input, escaped via doubling. The fix handles that explicitly. No `;`, `:`, `&`, `|`, `(`, `)`, `<`, `>`, `,`, `*`, `[`, `]`, `{`, `}`, `\``, `$`, `"`, `@`, `#` — none of these break a single-quoted string.

No new test needed; the next /mstr-spawn invocation with `--say "Per LD-NNNN; multi-clause text:"` exercises the fix and would fail if the quoting is wrong.

## Followup

Banking observation: **shell-injection-class bugs at primitive boundaries are easy to miss in design review and surface only at empirical first-use with realistic content.** Pattern worth noting for similar primitives: any time MSTR-owned tooling concatenates caller-provided text into a downstream shell/script invocation, default to quoting + escape. Add to /mstr-spawn skill body §Discipline section as a forward-looking note if the pattern recurs in other primitives.

No other affected primitives identified this cycle. spawn-agent.ps1 was the only place this concatenation pattern was used in the population-primitive path.

## Rollback

`git revert` the fix commit; restores the prior raw-join behavior. Operational impact of revert = back to "--say only safe with alphanumeric content" — caller burden. Reversible per single commit.
