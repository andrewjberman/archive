## 2 — fabric-check SOVEREIGN-classifier precision fix
Verifying the post-reap fabric-check, 2 FALSE-POSITIVE SOVEREIGN flags appeared:
- `0.4.0_DE` "...Total Holdings ... per Andrew ruling. Verified served" -- a REPORT of a past ruling.
- `0.7.0_AE` Total-Holdings blend-split status -- a status report.
The classifier matched "andrew ruling" / "sovereign decision" anywhere = report-mentions read as
sovereign-decision-REQUESTS. **Impact:** /govern's sovereign-sweep (LD-0155) would have falsely
escalated these to Andrew. **Fix:** tightened SOVEREIGN markers to request-phrasing only --
explicit `blocked-sovereign`/`[sovereign` token, or a request verb (needs/awaiting/pending/
requires) + andrew/sovereign. Dropped the bare "andrew ruling"/"sovereign decision"/"sovereign
ruling" (report-matching). Result: sovereign 2 -> 0 (the genuine taxonomy = `BLOCKED-SOVEREIGN:`
prefix still matches). py_compile + ruff clean.
