### Why ws-side doc (vs CL-side)

Two complementary docs because the channel has two consumption perspectives:
- CL CTO V1.1 §5 covers the **contract** — what CL CTO does with what MSTR delivers (consumption side)
- MSTR Input 1 channel arch doc covers the **mechanism** — how MSTR detects + packages + routes + reports (orchestration side)

Both are canonical; neither is sufficient alone. Cross-fabric uniformity on substance preserved via cross-references in §0 + §8.

### Path location reasoning

`org/tier0/` (not `docs/architecture/`) because:
- **Lane discipline routes ANY_CTO-permitted paths through CTOs.** `docs/architecture/` is ANY_CTO owned-path lane (CTO + ~B CTO + COMP_LEARNS CTO authorize); MSTR is not in permitted_agents (empirical lane-gate block during this cycle's commit attempt). Routing the doc authoring through a CTO would add a step without substantive value.
- **org/tier0/ is MSTR-writable + structurally appropriate** as cross-fabric companion alongside `COMPILER_ARCHETYPES.md` (LD-0043) at tier0 root. Tier-0 path designates "cross-fabric canon" not "Tier-0 law lock" — the three TIER0_LAW docs (CONSTITUTION + STAKES_MATRIX + DIRECTIVES) remain the law canon; other docs at tier0 are cross-fabric reference companions.
- **Operational tuning surface preserved.** Doc remains amendable via successor LD-NNNN or sub-version stamp without TIER0_LAW commit ceremony; not promoted to Tier-0 law status.
