# LD-0123 — /watcher Step 5 amended to include LD-0099 ferry diagnostic

## §1 — Trigger (the empirical miss)

2026-05-27T22:45Z + 22:49Z: CL COO 2.1.0_SA_COO sent two critical post-reboot SPAWN-NEEDED briefs to MSTR via LD-0099 cross-org-root filesystem-direct ferry (CL→ws). Both landed at `org/mcp/inbox/0.0.0_AB_MSTR/`. MSTR's `inbox-watch` atomic-mv'd them to `read/` and fired Bash task completion notifications.

For the next ~17 minutes, MSTR's `/watcher` cycles ran `check-inbox` ("No pending messages") and `get_agent_status` (no URGENT messages) — both probes blind to the ferry delivery class. Multiple watcher-exit notifications fired but MSTR repeatedly concluded inbox empty. Andrew flagged at ~23:00Z: "did you get the CL CTO 2.1.0_SA_COO message? They need agents."

## §2 — Root-cause distribution

Three correct components combined into a blind spot:

1. `check-inbox` reads top-level of inbox/ only — by design, top-level is the unprocessed-pending area
2. `inbox-watch` atomic-mv's freshly-arrived files into `read/` and fires a Bash task notification — by design, this is delivery
3. LD-0099 ferry sends bypass the broker (sender's MCP server can't resolve cross-org-root recipient, falls back to `Write()` direct) — by design per Andrew rationale 23:05Z to prevent cross-fabric message crossing

Three correct designs → one structural delivery-visibility gap.

## §3 — Fix (Step 5 amendment)

Edit at `.claude/skills/watcher/SKILL.md` Step 5: replaces the prior two-probe wording ("check-inbox + get_agent_status — either can hold a message the other misses") with three-clause wording explicitly enumerating:

- `check-inbox` blind spot: top-level only; post-mv files invisible
- `get_agent_status` blind spot: broker-channel only; ferry never enters broker
- LD-0099 ferry diagnostic: watcher-exit fired + both probes empty = scan `ls -t org/mcp/inbox/{serial}/read/ | head` against session-memory of handled files

The third probe is conditional (only triggered by the diagnostic combination), not unconditional — keeps quiet loops quiet.

## §4 — Sibling artifacts updated

- `memory/feedback_check_inbox_misses_ld0099_ferry_messages.md` (new this cycle pre-Andrew-edit): corrected to remove the incorrect ".unread-deliveries-as-sentinel" claim. The file IS an append-only delivery history log, NOT a currently-unread sentinel. Diagnostic = read/-newest mtime vs last-handled.
- `memory/MEMORY.md` Fabric architecture section pointer added at memory-bank time, retained.

## §5 — Why not fix the broker instead

Andrew rationalized 23:05Z: per-org-root broker isolation is deliberate, to prevent COMP_LEARNS work and Opal work from message-crossing in the same registry. Fixing the broker to be fabric-wide would re-open that cross-contamination class. So fix at the recipient's discipline layer (/watcher Step 5), not the broker layer.
