# LD-0215 — Object + Process Analytics commission (Andrew-direct): deliver the workflow-scoping brief to CTO + decompose its object equivalent

## Decision
Record the Andrew-direct (2026-06-25) commission to CTO: take the MSTR-authored PROCESS-side scoping riff
(`docs/briefs/oplmcp-workflow-scoping-20260624.md`, committed this session) and produce an **OBJECT +
PROCESS analytics** decomposition. MSTR delivers the brief + relays Andrew's comments; CTO owns the PRD /
scoping / TO candidates.

## The two sides (Andrew, verbatim intent)

### Object side — repo/filesystem HYGIENE analytics
- **Hourly freshness snapshots assessed by WRITES** (git history or other methods) — a write-activity
  **heat_map** over the estate (what's hot / recently-written vs cold/stale).
- **Cluster items by filesystem location** — group by directory/locality.
- **Output = archive/delete recommendations** ("what we want to archive/delete") — *essential directory
  hygiene*, so `ajb_workspace` stops "accruing a bunch of bullshit everywhere."
- **Hard guardrail (MSTR carry-in):** ADVISORY only — recommends, never auto-deletes. Inherit the
  DEBTSCAN NEVER-auto-delete + verify-before-delete chain ([[LD]] DEBTSCAN; orphan-invocation /
  name-vs-edge blast-radius). A hygiene tool that auto-purges is the designed-out failure mode.

### Process side — high-traffic process audit as an MCP-server analytics SCHEMA
- The workflow-scoping brief's L0-L5 (capture -> sessionize -> mine -> classify/rank -> interview ->
  synth) **formalized as a first-class analytics schema in the OPLMCP gateway** — high-traffic process
  audit, baked into the MCP server.
- Rides the already-built substrate the brief source-grounds: the 100%-coverage `app/tools.py` audit
  hook + R8 audit-lake (`opal-mcp-audit` / Athena) + the two-zone privacy model (de-identify at the
  distillation boundary; no identity persisted).

## The unifying concept
One **activity/freshness analytic ("heat_map") applied to two domains**: OBJECTS (files/artifacts in the
estate -> hygiene) and PROCESSES (MCP traffic/workflows -> workflow mining + audit). The estate's
self-knowledge, both halves.

## Hand-off
- **Delivered:** the process-side brief is committed + relayed to CTO with Andrew's comments.
- **CTO owns:** the decomposition — object-side hygiene-analytics scoping (write-freshness heatmap +
  cluster-by-location + archive/delete advisory) + the process-side audit-schema scoping; PRD / project
  or macro placement / TO candidates; the object/process split.
- **Then:** COO decomposes/routes per CTO's scoping; MSTR spawns when lanes are named.

## Rollback
Recording changes no operational state. Reverses by abandoning the decomposition (CTO/feasibility no-go).
The object-side guardrail (advisory-only, never auto-delete) is the load-bearing safety carried into design.
