# LD-0504 — the register fed nothing, and it failed by going quiet

## Decision

`daily_reports/scripts/project_census.py`, four changes, one commit.

## ⛔ THE BUG THAT MATTERS: THE CODE IS THE KEY, AND THE LOADER THREW THE KEYS AWAY

`load_membership()` read `org/missions/DIRECTIVES.yaml`, did `list(rows.values())` — **discarding
the mapping keys, which ARE the directive codes** — and then skipped every row that lacked a `code:`
field, the identity it had just discarded.

**MEASURED 2026-09-02: 0 of 13 rows carry a `code:` field.** So the register contributed **zero**
mappings and the entire census ran on a PRD-path glob plus 9 hardcoded `EXTRA` entries. Of the
register's **37** declared project→directive mappings, **20 were invisible** — including
`ETFS_GUARDRAIL -> D8`, committed that same morning at `f3359d12e6`.

⛔ **THE FAILURE MODE IS THE POINT: AN EMPTY MAPPING DEGRADES TO "UNATTRIBUTED", NEVER TO AN ERROR.**
Editing `DIRECTIVES.yaml` appeared to work — the file changed, the commit landed, the gates passed —
and changed nothing downstream. Nothing in the chain could fail, so nothing did. **A loader whose
empty result is a legal output cannot report its own breakage**, and this one had been silently
answering with a heuristic for as long as the register has been a mapping.

Conflicts between register and prior map: **0**. The fix is purely additive; no commit changes the
directive it was previously reported under.

## The other three

- **`LIVE` is DERIVED from the register, not `range(12)`.** The literal covered D0–D11 while the
  register carries D0–**D12**, so rules 2 and 4 rejected every D12 token. Proven in the wild: on
  09-01 `org/projects/D12_PHONE_OTP_ALL_AWS.json` sat in the residual **with the directive token in
  its own filename**. A literal cannot track a register that grows.
- **The path arm of the project-code match is word-bounded.** It was `if code in f` — a bare
  substring — while the subject-line arm of the *same rule* was already `\b`-anchored. Two arms of
  one rule disagreed about what a match is.
- **Andrew's work streams (CALL 2).** `docs/briefs/` -> `PLANNING`; `org/tier*_*/<serial>/logs/` ->
  `AUDIT`. Tested BEFORE the project-code match, because a session log whose path mentions a project
  code is still a log — his ruling is about what the artifact IS, not what it names.

## ⭐ THE AXIS WAS RENAMED SO HIS RULING WOULD NOT LAND AS THE DEFECT THIS PASS DIAGNOSED

`PLANNING`/`AUDIT` sitting beside `D0..D12` on an axis **called "directive"** mixes two grains — a
directive and an activity class — on one axis. That is *precisely* the Rule-24 break this same
investigation found in `commit_census`'s enum (values named for work, measured from the author).
Declaring the domain as **WORK STREAMS** makes every value one grain, MECE, with `UNATTRIBUTED` as
the named residual. **His ruling lands unchanged; only the axis stops overclaiming.**

They ship in a NEW `by_stream` field rather than merged into `by_directive`, because
`by_directive` rows are `[int, title, count]` through the schema, the renderer **and both
templates** (which colour by `PCOL[n%12]`). A string id there would break four consumers **silently
at render time**. Additive now; the contract change is sequenced separately.

## CALL 3 — no edit was required, and one limitation is recorded rather than forced

Every LIVE surface already reads D8, measured: `org/projects/ETFS_GUARDRAIL.json` `"directive":
"D8"`; the register has it in D8 and **not** in D4; `docs/architecture/ETFS_GUARDRAIL_PRD.md:6`
says **"Not D4"** explicitly. With this commit the census resolves `ETFS_GUARDRAIL -> D8` too — it
could not before, which is the whole point of the bug above.

The only remaining D4 pairing in the estate is **6 lines, all inside the append-only ledger**
(`LD-0502`, `LD-0503`) — where a superseded decision belongs.

⚠ **NOT FIXED, AND NOT FORCED:** `LD-0502`'s `decision_summary` reads *"under D4"* with
`status: active`, so a reader landing on it alone reads D4 as current. The obvious repair —
pointing `LD-0503.supersedes` at it — **would be wrong**: `superseded_by` is a DERIVED field
(`org/standards/isck/ledger/engine.py:68`), the derivation is all-or-nothing, and LD-0502 also
carries the **still-live SES terminal-failure carve-out**. Marking it superseded to fix a placement
clause would silently retire an authorization Andrew granted. The ledger's supersede model cannot
express a partial amendment; that is a real limitation and it is recorded here instead of being
worked around.
