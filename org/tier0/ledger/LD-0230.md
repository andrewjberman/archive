# LD-0230 — Size-invariant granularity (scale-free cognition): a foundational / constitutional-class invariant of the cognition substrate

Andrew-direct 2026-06-30, routed up by CTO arch-assessment. The general law behind LD-0229.

## The principle (one statement)

**The graph's node/edge TYPE SYSTEM and its INVARIANTS are invariant to scale.** Granularity is a
**declared `level` coordinate** on a stable `CONTAINS` ladder, **never a fork in the type system** — the
same edge semantics, the same invariants, and the same tools operate at every zoom level. This is why
**ONE graph + ONE toolset + ONE gate-set serves every granularity** without per-level re-engineering: the
substrate is **scale-free**. LD-0229 (the graph schema-stability contract) is its first operative
instantiation; this is the general law.

## The four invariants (operatively CTO-ratified as §9/§10; verified live @ head)

1. **Granularity = a declared `level` + a stable `CONTAINS` ladder.** A deeper dive ADDS levels within
   FIXED types — never re-types by depth.
2. **Edge types defined ONCE by SEMANTIC, stable across grain.** Same relation / different depth -> same
   `edge_type` + a `level`; never split a semantic by depth; never overload one type across two semantics.
3. **Grain-consistency rollup = EXISTENTIAL, CHECKABLE.** A coarse edge EXISTS iff >=1 fine edge rolls up
   to it (`EC2 READS S3_BUCKET` iff EXISTS an internal `Function READS_S3 S3Key OWNED_BY` that bucket).
   Defects: UNSUPPORTED (coarse, zero fine) / COARSE-INCOMPLETE (fine, coarse absent). A generalized
   COMPDRIFT seam invariant — this is what makes scale-invariance *verifiable*, not aspirational.
4. **One-home + non-redundancy hold at EVERY scale** (the COMPUNIFY `comp-coverage-check` gate, extended
   with the `level` dimension + the no-split-by-depth rule).

## The three boundary conditions (the declared SCOPE — it is precise, not absolute)

A. **Semantic-shift.** Each `edge_type` is grain-STABLE, but the type SET **grows by SEMANTIC, never by
   depth.** Zooming in can reveal a genuinely NEW relation (statement-grain control-flow branch/loop is a
   different semantic, not a deeper `CALLS`) -> mint a new scale-stable type; do NOT force-fit it into an
   existing one. ("Stable types" != "frozen type set.")
B. **Materialization.** Size-invariant in **LOGIC**; **BOUNDED** in **MATERIALIZATION.** Derive deep grain
   lazily/locally (on-demand), not eagerly estate-wide (the statement/row combinatorial fan-out). The law
   mandates stable types + invariants **where** a level is materialized — not that every level is
   materialized.
C. **Grain-meaningfulness.** Drilldown depth is **type-specific** — different types bottom out at different
   levels (a React Field has no sub-grain; an IAM policy may bottom at statements). Size-invariance !=
   infinite drilldown; it = *where* a drilldown exists, it uses stable types + `level`.

## The populate / govern / read split

- **GRAPHUNI POPULATES** the size-invariant substrate (one graph, one head, the drilldown ladders).
- **COMPUNIFY GOVERNS** the definitions (the node-schema gate enforces invariants 1-4 at every scale).
- **Tools READ** at the one marker head, each calibrated to a `level` (comp-aws=resource;
  comp-pipescript=script/IO; comp-blast/trace/xref=function; comp-platinum=cross-grain).
