## Security Notes

- All access is **tailnet-only**. The 100.x.x.x addresses are not routable from the public internet. Enabling additional services (SSH, WinRM) on these boxes would only expose them to tailnet devices, not the world.
- For defense in depth, Windows Firewall on each box can be restricted to allow inbound connections only from the tailnet subnet (100.64.0.0/10), and Tailscale ACLs can limit which devices may connect.
- RDP (port 3389) is currently the **only** remote service running on the cluster boxes. SSH (22) and WinRM (5985/5986) are not enabled.
- Credentials for sitez/dell1/dell2 were supplied in chat on Oct 10 and used transiently (not saved to Secure Vault unless requested).

## Recommendations

### 1. Enable OpenSSH Server on the cluster boxes (recommended)

This is the single biggest improvement available. OpenSSH Server is built into Windows 10/11 -- it just needs to be turned on:

```powershell
# Run as Administrator on each box:
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Start-Service sshd
Set-Service -Name sshd -StartupType 'Automatic'
```

Once enabled, command execution becomes reliable (no GUI needed), and automation (checking agent status, restarting workers, pulling logs) can be done via SSH instead of screenshots.

**Security:** SSH would listen on the tailnet interface only. Not exposed to the public internet. Can be further restricted via Windows Firewall and Tailscale ACLs as noted above.

### 2. Optional: Enable PowerShell Remoting (WinRM)

If you prefer PowerShell-native remoting over SSH:

```powershell
# Run as Administrator on each box:
Enable-PSRemoting -Force
```

Same tailnet-only exposure as SSH.

### 3. Keep RDP as fallback

RDP remains useful for visual checks (screenshots of agent windows, limit dialogs). No change needed there.
