# LD-0449 — A `-F` commit message is only as fresh as the file at that path

**The live instance.** `99f46e9cf2` carries the D4 `completion_bar` — content correct, verified in
its own diff (the Andrew verbatim and the bar are both present) — under the message
*"ledger(LD-0441): pre-ledger the LD-0429 chain's last two seatings…"*, a **2026-08-21 10:45**
message belonging to a previous MSTR session.

## Mechanism — two independent failures, only the second silent

1. `python edit.py && cat > /tmp/cmsg6.txt <<EOF … EOF` on one line; `safe-commit -F /tmp/cmsg6.txt`
   on the **next** line. The python assert failed on a bad anchor — a loud, ordinary failure — `&&`
   short-circuited the heredoc, and **the commit ran unconditionally.**
2. `/tmp` is shared across agents **and across sessions** on this worktree, and `/tmp/cmsg6.txt`
   already existed from three days earlier.

**THE GUARD WAS ON THE WRITE AND NOT ON THE CONSUMER.** A commit that reads its message from a path
must not run unless that path was written by *this* invocation.

## Why this is not F-010 restated

F-010 is about **execution** — a backtick in a `-m` string runs. The remedy was `-F`, and the remedy
works. **But `-m` fails LOUDLY on a malformed string while `-F` fails SILENTLY on a stale one**: the
path resolves fine and the file is perfectly well-formed. *The remedy for a loud failure mode
introduced a quiet one* — the same shape as the estate's kill-orphans lesson, where the fix for
over-reaping produced under-reaping, and under-reaping was the mode that forged liveness.

## Not corrected by amendment, deliberately

I checked `HEAD` before amending and it had already moved: `0.7.0_AE_CloudOps~G` and `3.0.0_SA_CVO`
both committed within about a minute. Amending would have rewritten their commits. **The guard fired
and the guard was the point** — on a shared worktree, "it is only local" has a lifetime measured in
seconds, not minutes. Precedent for correcting in place rather than rewriting: CLAUDE.md's own F-010
provenance note, which records a mis-authored commit and says plainly *do not revert*.

## Remedy — a habit, because there is no honest gate for it

A message file is written by the **same invocation** that commits it, under a **unique name**
(timestamp + PID), inside **one `&&` chain**. A fixed filename in shared `/tmp` is a loaded gun with
a three-day-old round in it.

A mechanical check *could* compare the message file's mtime against commit time — but it would fire
on every legitimate `-F` workflow that drafts a message before running gates, so it lands as
discipline rather than a gate candidate.

**Historical incidence is UNKNOWABLE. Do not quote a count.** Only a message obviously wrong for its
diff leaves a scar; a stale message that happens to read plausibly for its diff never surfaces.
