## AMENDMENT 1 (2026-08-30 21:3xZ) — five of six diagrams shipped as "undefined", and the pipeline could not have caught it

**Andrew caught it in the browser**, which is where it was visible: the published page's diagrams read
`undefined`. The report's numbers, text, sums and date were all correct; the pictures were not.

**MY ERROR, precisely.** I authored the viz params by copying the KEY NAMES used in earlier reports and did
not read the generators' VALUE SHAPES. Read at source afterwards in `daily_reports/templates/_shared_viz.js`:

| type | the generator actually reads | what I passed |
|---|---|---|
| `compare` | `rows[i].label` + NUMERIC `.before` / `.after` | arrays of three strings -> `String(r.before)` = `"undefined"` |
| `steps` | `{state: done\|now\|next, t, s}` objects | plain strings -> `s.state`, `s.t` undefined |
| `tree` | `top`/`mid` single `{t,s,c}` objects, `leaves` a list of them | a string and arrays of strings |
| `link` | `left`/`right` `{t,s}` objects | arrays of strings |
| `coverage` | `pct` as a FRACTION (`done = round(48 * pct)`) | `100` |
| `flow` | `stages` strings **and** `footer` as `[label, value, colour]` triples | stages right, footer a string |

**A SECOND DEFECT THE FIX EXPOSED, and it is about meaning rather than shape:** the thirteen-accounts item
used `link`, whose generator draws a **green tick between its two nodes** — it asserts a CONNECTION, while
the whole finding is that those accounts are in NEITHER Schwab book. A correctly-shaped `link` would have
drawn a confident picture of the opposite of the measurement. Replaced with `matrix`, which shows the
absence and carries both controls (5,787 of 5,791 known accounts found; an invented account correctly not
found). The parity `compare` was likewise re-based on counts measured exactly (16 -> 11 disagreeing, 0 -> 3
exact) instead of approximating ">10 bp" into a bar; the 0.000007 bp figure rides the caption where it is
stated rather than drawn.

**VERIFIED IN A BROWSER, not from the render's exit code** — the same instrument Andrew used: the local
bytes were served over loopback and all six items stepped through; SVG present with **0 `undefined` and 0
`NaN`** on every one, and the mobile page likewise (6 hosts, 8 SVGs, none containing it). The single
remaining `undefined` in the mobile HTML is the page's own script comparing `name[n] !== undefined`.
Re-published: 2/2 pages, size + ETag MATCH.

⛔ **THE GAP THAT LET IT SHIP, named for the template's owner and NOT fixed here.** `render_daily_report.py`
validates the census sums, the process-state enum, the card-headline length and the derived `display_date` —
**it does not validate viz param shapes at all.** So five malformed diagrams passed validation, rendered,
published and were read back with matching ETags: every gate in the chain was green because every gate was
measuring something else. A shape check per viz type (the table above is the contract) belongs beside the
sum checks; the renderer is the CTO surface and this entry names the item rather than editing it.
