# LD-0023 — First v1.6 cycle-2 mechanical resolution: VALFIN-001 Phase B → fee-rate values

## Decision

Per D-001 v1.6 fork-stall escalation framework, MSTR mechanically resolves the VALFIN-001 Phase B three-branch fork at cycle-2:

**Phase B portal type swap consumes the fee-rate values branch.**

Three options surfaced by CVO META-3:
1. **fee-rate values** ← chosen
2. fee-status bools (is_fee_earning flags)
3. fee-independent (Phase B doesn't consume fee data)

## Provenance chain (Art. XIII)

D-001 v1.6 (chartered authority for cycle-2 mechanical resolution) → FORK-STALL ESCALATION clause → VALFIN-001 three-branch fork (first_observed_at 2026-05-23T16:16Z UTC; first-line routed via COO MCP to DS Base 16:16Z) → DS Base silent across CY-0039 + CY-0040 (`consecutive_fork_stall_cycles = 2`) → MSTR mechanical resolution at cycle-2, path (a) direct directive (operational, informational block). Authority source = directive (D-001 v1.6).

## Why now

CY-0040 is the second consecutive cycle the fork sits unresolved. DS Base has been heads-down on VALFIN.009 + .010 pickups + the .008 field-rename queue; the three-branch question is a one-line answer they would give when they surface for air — but downstream Phase B work cannot proceed without the input-source decision. The v1.6 framework chartered MSTR to mechanically resolve at this boundary precisely so the fabric doesn't stall waiting for an heads-down agent's attention.

## Reasoning — heuristic application (reversible / cheapest / most-information-producing)

- **Most-information-producing:** fee-rate values carries the richest downstream signal — dollar amounts are interpretable both for advisor-level reporting and aggregation; status-bools collapse to a 1-bit signal that downstream consumers must re-enrich; fee-independent forecloses the entire information channel.
- **Reversible:** all three branches are swap-equivalent at the input-source layer — if DS Base surfaces with a different read, the portal Phase B swap reconfigures by changing the consumed-field reference; no migration required.
- **Cheapest:** all three branches have approximately equivalent implementation cost at Phase B consumption.
- **Risk-avoidance bonus:** fee-status bools carry the known LD-0018 F1 placeholder-zero filter class defect (61% wrong first-known-fee-status dates per CVO YELLOW verdict; F1 fix VALFIN.010 still in flight). Choosing the bools branch right now would entangle Phase B with the F1 fix's correctness window; fee-rate values avoids that coupling entirely.

## Assumptions

- DS Base would answer this question OPERATIONAL not ARCHITECTURAL (consistent with COO's classification — information-ask, not product-strategy decision).
- The empirical fee-rate-values data exists and is queryable from the same upstream source DS Base would naturally pull from for Phase B (this is the COO/DS Base-validated assumption — if invalid, DS Base counters and we swap).
- "Mechanical resolution" in v1.6 explicitly contemplates this case — a fork where the answer is knowable and the stuck-agent is heads-down on other work, not architecturally ambivalent.
- DS Base's authority to counter is preserved — this LD is the working ratification, not a final architectural lock-in.

## Alternatives considered

- **Wait another cycle for DS Base.** Rejected: v1.6 framework was designed to prevent exactly this — heads-down silence is indistinguishable from architectural-block from downstream's perspective; the framework chartered MSTR to break the impasse mechanically.
- **MSTR picks fee-status bools.** Rejected: known F1 placeholder-zero filter defect makes the bool branch wrong-by-construction in the current window.
- **MSTR picks fee-independent.** Rejected: forecloses the highest-value downstream signal; reversibility is no advantage if it requires re-deciding later.
- **Escalate to Andrew as architectural.** Rejected: COO + CY-0039 MSTR classified OPERATIONAL; fork doesn't commit the fabric to a structural pattern.

## Rollback plan

If DS Base surfaces and counters with a different branch read: (1) MSTR ledgers LD-NNNN reversing LD-0023 to DS Base's choice; (2) COO updates Phase B portal-swap input source via Tier 1 TO authoring; (3) any in-flight Phase B work points at the new input source on next implementation pass. Estimated wall-time for swap: <1h if no Phase B implementation has landed yet; <4h if early Phase B implementation needs source reference updates.
