# LD-0146 — Persistent-Monitor inbox-watch migration (arm-at-load, no loop)

## Decision
Replace the exit-on-delivery bash inbox watcher with a **persistent Monitor task**
running `inbox-watch.sh <serial> stream`, armed **once at session load** by
`/watcher`. The watcher never exits; the Monitor tool surfaces each `[INBOX] <file>`
line as a chat notification. The recurring `/watcher` loop is retired — there is no
loop to keep alive.

## Provenance chain (Art. XIII)
Andrew direct ("can we use a monitor… it works way better" → "build it fabric-wide,
I trust you" → "we dont need a watcher loop either, arm it at load") → D-002 (standing
fabric maintenance / reliability of the agent-comms substrate) → build the stream mode
+ collapse /watcher + update the startup/loop protocol + the design doc + scribe this
LD. Andrew holds a proven reference implementation (more reliable, survives compaction,
batch-safe, never-off); rather than port across machines he authorized MSTR to build it
fabric-wide to match those three properties. Chain closed.

## Why now
The Monitor tool's capability changed: it is now **non-blocking / event-push** ("each
stdout line is an event — you keep working and notifications arrive in the chat"). That
is exactly the background-interrupt mechanism the 2026-04-30 brief said was missing when
it rejected Option 4. With that constraint lifted, the exit-on-delivery design — and the
entire failure-mode catalog and `/watcher` loop it necessitated — is strictly dominated.

## What changed (paths touched)
- `org/mcp/inbox-watch.sh` — ADDITIVE `stream` subcommand: persistent poll, mv-consume
  each `*.md` to `read/`, append `.unread-deliveries`, emit one `[INBOX] <file>` line,
  never exit. Legacy exit-on-delivery default UNCHANGED (protects in-flight agents).
- `.claude/skills/watcher/SKILL.md` — rewritten to the arm-at-load model: register +
  TaskList presence check + arm-Monitor-if-absent; no recurring loop; legacy interval
  forms accepted but cancel any stale `/watcher` cron.
- `org/XXX.md` — Step 1b §C rewritten (persistent-Monitor arm, decisive test = TaskList);
  §F cron table (MSTR + worker + non-worker rows no longer arm a `/watcher` cron); the
  two-loop guard made moot; `/loop` Step 0 sentinel + Step 2 watcher-health + the
  compaction note all updated; startup summary updated.
- `org/mcp/watcher-status.sh` — header reframed to "transition-only helper" (enumerates
  legacy bash watchers for /watcher to kill; does not see the stream Monitor).
- `org/mcp/INBOX_WATCH_DESIGN.md` — new CURRENT-MODEL section at top; Option 4 marked
  ADOPTED; everything below marked HISTORICAL.

## Assumptions
- A persistent Monitor survives in-session context compaction (it is a session task);
  it ends only when the session ends. Andrew confirmed his version "lasts through
  compaction." A fresh session re-arms at load, so arm-at-load fully covers lifetime.
- Atomic `mv`-on-emit makes delivery exactly-once across any number of concurrent
  streams/legacy watchers for the same serial.
- Inbox volume is low enough that the Monitor's auto-stop-on-flood does not trigger
  (one emit per genuine new message, deduped by mv).

## Alternatives considered
- **Port Andrew's reference implementation across machines:** he chose "build it
  fabric-wide, I trust you" instead — avoids a cross-machine transfer and matches the
  three stated properties directly.
- **Keep the loop as a backstop:** rejected — the loop exists only to re-check a watcher
  that can silently die; a persistent Monitor that survives compaction removes the reason.
  A redundant idempotent loop would just burn cycles.
- **Flip the legacy loop in place (no `stream` subcommand):** rejected as migration-unsafe
  — if `inbox-watch.sh` stopped exiting, agents still on the old /watcher (Bash
  run_in_background, notify-on-exit) would go silent. The additive subcommand keeps both
  paths valid during the transition.

## Rollback plan
Revert the 5 touched files + delete this LD. Legacy exit-on-delivery mode is retained
and remains a working fallback even without a revert.

## Downstream
- Agents affected: all (fabric-wide delivery mechanism). Transition is graceful — agents
  pick up the new model the next time they invoke `/watcher` (session start / restart);
  legacy bash watchers keep working until their sessions end.
- Follow-ups banked:
  1. Bare-path guard hook needs a `stream`-mode carve-out (no `$0`-propagation / auto-respawn
     risk in stream mode, so the relative-path ban is over-broad there).
  2. Remove `watcher-status.sh` + the legacy `inbox-watch.sh` exit path once no
     pre-migration bash watchers remain in the fabric.
  3. Sweep the stale `unread/` orphan dirs (older convention; not on the active path).
