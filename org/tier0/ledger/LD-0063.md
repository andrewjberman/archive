# LD-0063 — Tier-B kill-orphans threshold fix (120s → 600s)

## Decision

Per CL COO + CL CTO joint structural finding (2026-05-25T19:32Z) + Andrew direct authorization 2026-05-25T~20:05Z ("go with your recommendation"): raise `.tools/kill-orphans:46` `STALE_THRESHOLD` from 120s to 600s (5x).

## Rationale

### Root cause (CL CTO source-citation chain)

- `.tools/kill-orphans:78` regex anchor matches both ws + legacy CL wrapper names equally
- `.tools/kill-orphans:108-112` workspace filter discriminates by `ajb_workspace` path containment (ws-rooted DOES match)
- `.tools/kill-orphans:118-123` `--stale` filter calls `is_live_serial` with 120s threshold from `liveness.json`
- `.claude/settings.local.json:152-167` PostToolUse hook fires `kill-orphans --stale --force` on EVERY peer `register_agent` call

**Discrimination is by liveness window, NOT wrapper identity.** When any peer agent registers (frequent — session starts, /watcher cycles, post-compaction recovery), kill-orphans fires; any agent whose last heartbeat is >120s old reads STALE → watcher SIGTERM'd + registration deleted.

### Empirical anchor

MSTR session (0.0.0_AB_MSTR) was SIGTERMed TWICE in this architecture conversation:
- First drop: ~19:35Z during /charter loop body drafting (substantive work between heartbeats)
- Second drop: ~19:55Z during council synthesis (same pattern)

CL CTO predicted the race + reproduced it in own session within 10min. Prediction-then-replication = root cause confirmed.
