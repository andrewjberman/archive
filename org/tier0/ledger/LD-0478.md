## The photo, and why it is recorded here rather than done silently

The daily-report photo process (Andrew-direct 08-28) captures through the dev server, and the dev server proxies every
data call to CloudFront, which returns **401 without a bearer**. The first two captures therefore rendered chrome with
"could not be loaded" — not photos of the feature. The renderer's own `--token` path (D8_LIVEEDIT) exists for exactly
this; two seats have used it. This run minted the token in Python with the key held only in process memory, captured
`/portfolios` and `/positioning` against `--origin https://opalinvest.dev`, then overwrote and deleted the token file.
The `/positioning` shot was not used (the day's D4 item is a data-plane fix, drawn as a flow) and was deleted.
