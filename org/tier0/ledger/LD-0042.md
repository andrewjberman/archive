# LD-0042 — Spawn-request protocol consolidation (Q1-Q4 codified)

## Decision

Per Andrew sovereign multi-turn design conversation 2026-05-24, codify the four spawn-request sub-rulings into a single canonical entry that refines LD-0036 (MSTR sole spawn-originator) with the explicit demand-side-routing protocol.

### A — Sub-ruling Q1: MSTR singular spawn-execution

**LD-0036 invariant preserved.** All spawns originate via MSTR — `.tools\spawn-agent.ps1 {serial}` carrying `OPAL_SPAWN_MARKER_v1` per LD-0028 canonical methodology. No division COO, CTO, CVO, or Tier-2/3 agent executes a spawn directly. Demand-side requests route through MSTR; MSTR is the singular spawn-executor.

### B — Sub-ruling Q2: Division COO sole spawn-request originator + CTO backstop

**Andrew direction (verbatim):** *"spawn requests passing through MSTR from the division COOs. CTOs shouldnt need to have meaningful input into spawns, that is an operational aspect that COO should handle. The only times that CTOs need to be concerned with that is if COOs are unresponsive for 2 consecutive cycles."*

**Operational protocol:**

| State | Spawn-request originator |
|---|---|
| Normal operation (COO LIVE + responsive) | Division COO for that fabric's serials only |
| COO unresponsive cycle 1 (STALE / no heartbeat / no commit) | MSTR nudges COO per LD-0015 BOTTLENECK-RESPONSE INTENSIFICATION cycle-1 step |
| COO unresponsive cycle 2 (confirmed unreachability) | **Division CTO becomes fallback spawn-request-originator** until COO recovers. Parallel to LD-0026 sovereign-pending-backstop pattern, applied one tier down. |
| COO recovers | CTO returns to substance/direction lane; COO resumes spawn-request origination |

CTO backstop fires only on confirmed COO unreachability. Not a routine shortcut. CTO does not pre-emptively route spawn requests "because COO is slow."

### C — Sub-ruling Q3: Cross-fabric spawn requests structurally precluded

**Andrew direction (verbatim):** *"cross-fabric spawn requests should never happen, our intentional separation should preclude that from ever happening because it would be extremely disorganized and destroy chain of command."*

**Operational enforcement at MSTR request-receipt:**

- ws COO (`2.0.0_SA_COO`) requesting ws-fabric serial (1.x.x / 0.x.x / 2.x.x non-CL prefix) → spawn proceeds normally
- CL COO (`2.1.0_SA_COO`) requesting CL-fabric serial (1.1.x / 2.1.x / 3.1.x / CL DS team) → spawn proceeds normally
- ws COO requesting CL serial OR CL COO requesting ws serial → **MSTR REJECTS** with audit line; routes back to requesting COO with "cross-fabric spawn out of bounds — surface to MSTR for architectural review if you believe this need is real"

**Failure-mode handling:** if a "cross-fabric need" surfaces (rare; should never normally happen), it is NOT a spawn-pathway question but an architectural surface routing via:
- Input 1 channel (if Opal needs CL-built compiler tooling — route via MSTR's Input 1 brief mechanism per LD-0033 §3 + COMP_LEARNS continuous-cycle PRD V1.1 §5)
- LD-0033 cross-fabric coordination protocol (if cross-fabric architectural consult is needed)
- Architectural fork escalation to Andrew (if a fundamental shift is implied — likely a new directive, not a spawn)

**The "spawn cross-fabric agent" framing literally doesn't exist as a primitive.** Agents are fabric-local; coordination is cross-fabric.

### D — Sub-ruling Q4: LIVE-vs-COO-request operational-judgment-trump

**Andrew direction (verbatim):** *"The only edge case i could see being an issue is where COO says they need 'x' agent, and you scan and see the agent is live, but the agent despite being live is unreachable (prompt-blocked, stuck for whatever reason). In this case, it doesnt matter if it appears 'live', spin up a serialized agent at COOs request and alert them to the tilde/serial."*

**Operational refinement to LD-0040 liveness-check-before-spawn:**

| MSTR scan classification | Without COO request | With COO spawn request |
|---|---|---|
| LIVE-responsive (last_seen<120s + responsive) | SKIP spawn; use as-is (LD-0040 default) | **HONOR COO request via tilde-lane fallback** — COO has empirical evidence agent X is unreachable despite appearing LIVE; spawn at next-free tilde suffix + alert COO with new serial |
| LIVE-stale (registered but unresponsive) | SKIP spawn; ping for resilience-check | **HONOR COO request** — same tilde-lane path |
| NOT-LIVE | SPAWN normally per LD-0036 marker discipline | SPAWN normally |

**Operational principle:** MSTR liveness scan is structural sanity-check. COO is demand-side operational authority. If COO sees an agent is functionally unreachable (prompt-blocked, stuck, deaf-heartbeat, compacted-context-unrecoverable), COO's empirical observation trumps MSTR's broker-state classification.

**Tilde-lane assignment mechanics:**
1. MSTR identifies next-free tilde suffix for the requested serial (e.g., `1.2.0_DS_CompLearns~E` if base + ~A through ~D are taken)
2. Spawn at `.tools\spawn-agent.ps1 1.2.0_DS_CompLearns~E` (carries `OPAL_SPAWN_MARKER_v1`)
3. Ledger LD entry (S1 spawn record, references COO-request-MCP)
4. MCP confirmation to requesting COO with new tilde-serial
5. Audit log captures `spawn-on-COO-request-despite-LIVE per Andrew Q4 ruling`
6. Original LIVE-appearing base serial left to natural time-out (NOT force-killed per LD-0027 destructive-without-marker-audit class)
