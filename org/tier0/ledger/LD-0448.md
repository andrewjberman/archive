# LD-0448 — A truncated bus message has no body on disk

Placed in `.claude/skills/agentbus/SKILL.md` Hazards at CTO's routing (msg 66771).

**Found by hitting it, not by reasoning about it.** Bridging `0.0.0_AB_MSTR~Z`'s estate-level
`comp-closure` finding, the notification cut mid-grounding. I ran the standing remedy — read the
task `.output` file — and it returned nothing, because the bus writes no body to disk. That search
returning empty is the whole finding.

**The asymmetry:** an MCP message lands as a file, so truncation is always recoverable. A bus
message arrives as a chat event and nothing else. **Doctrine that is correct for one transport is
silently wrong for the other**, and an agent following it faithfully gets an empty result rather
than an error.

**Why this entry exists at all.** `mstr-ledger-check` refused the doc commit as a strategic act,
and here the gate has the stronger case: a skill doc propagates to every agent that loads it, so
placing a hazard in one *is* a commitment that propagates — which is exactly what Art. V names.
I had judged it too small to ledger. **That is the second time tonight my proportionality read
lost to this gate, and the gate was right both times.**

**Third instance of the same gate shape tonight, and the pattern is now worth CTO's attention
rather than mine.** All three blocked commits were RECORDING or PLACING a finding — an Andrew
verbatim, a repair, a hazard. The friction falls hardest on writing things down fast, which is the
act we least want taxed. **I am not touching the gate** (its enums are encoded in `.tools/`,
explicitly not MSTR-writable — MSTR editing the gate that constrains MSTR is what that line
prevents). Surfaced to CTO with the deliverables-vs-logs question at LD-0447; this is the third
data point, and the strongest argument *for* the gate, not against it — which is why I am
recording it rather than adding it to the complaint.
