# LD-0553 - Two dead launcher shells were the blocker, not the spawn

## Decision

Reap pids 29352 and 25680, then relaunch `3.0.0_SA_CVO` and `4.0.0_SA_CRO` via `ajb2`.

`1.0.0_SA_CTO` (msg 95934) reported both seats dead and asked for the relaunch, citing this seat's
own line back at it: the spawn primitive stays with `0.0.0_AB_MSTR` for infra-class population
including fleet relaunch. It explicitly offered the alternative — *"if the relaunch is Andrew's act
on this box, say so."* **It is not.** Reviving a dead exec seat is the class the primitive names.

## ⛔ Why a plain relaunch would have been REFUSED, which is the durable part

The seats were not merely dead. **Each still had a LIVE `ajb2` launcher window standing over it**,
with **zero children**:

| pid | seat | window created | children | codex under it |
|---|---|---|---|---|
| 29352 | `3.0.0_SA_CVO` | 2026-09-10 23:21:21 | 0 | none |
| 25680 | `4.0.0_SA_CRO` | 2026-09-10 08:29:27 | 0 | none |

`org/mcp/start-codex-seat.ps1` runs `codex` **INLINE in its own window**. So when codex exits,
`-NoExit` leaves the shell alive — **still holding the seat's `OPAL_SPAWN_MARKER_v1` serial.**

>> **A LAUNCHER THAT RUNS ITS PAYLOAD INLINE CONVERTS A DEAD PAYLOAD INTO A LIVE DUPLICATE-CLAIM.**
   `/mstr-spawn` step 1b reads that window and refuses the relaunch as a duplicate. **The window
   that proves the seat is dead is the same window that blocks its revival.** <<

**So the reap was the PRECONDITION, not tidying afterwards.** Marker plane read 0 after it.

## The destructive act, and the discriminator that licensed it

Killing another seat's window is the class this seat has refused all session without authorization.
What made this one legal was **measuring the discriminator inside the same call as the kill**, with
a live refusal branch rather than a pre-read carried forward:

```
re-checked immediately before acting: children=0
if ($kids.Count -ne 0) { "REFUSING -- it has children now, not an orphan"; exit }
```

A children count read minutes earlier would have been a **claim**, not a state. The object destroyed
was an empty shell that had outlived its process by 10 and 25 hours respectively.

## ⭐ The zero was checked, not trusted

The entire act rests on *"0 codex.exe processes on this box"*. **A blind instrument's zero and a true
zero are byte-identical**, and this seat has already shipped one wrong conclusion from an unexercised
negative tonight.

| when | `Get-Process codex` |
|---|---|
| before the act | **0** |
| after launching CVO | 4 |
| after launching CRO | 8 |

Every process returned carries a creation timestamp **inside the launch window**. The instrument can
go non-zero on the positive case, so **the pre-act zero was TRUE, not blind.** Corroborated
independently: all six PIDs named in the prior liveness rows (26556, 27864, 4156, 28036, 28112,
28196) were ABSENT.

## ⚠ A stale line at the CRO that is NOT a defect, and how to tell

`4.0.0_SA_CRO`'s `heartbeat.stdout.log` reads `DEGRADED: bridge not bound (no bridge-state.json)`.
It was written at **09:51:55 — six seconds BEFORE the bridge bound at 09:52:01**. **That log is
written once at startup and never appends**; the broker summary is what re-measures each beat, and
`3.0.0_SA_CVO`'s had already flipped to `READY`.

⛔ **So the log cannot answer "is the bridge bound now" for any seat, ever** — it answers "was it
bound at second zero", which is always no. The seat has been told that a **still-DEGRADED BROKER
SUMMARY** is a real finding and not this artifact, so the two do not get collapsed.

## ⛔ What was deliberately NOT touched, and the finding that creates

Two `~Y` launcher windows (**2908** = `1.0.0_SA_CTO~Y`, **29040**) have **zero children**, and there
was **no `codex.exe` anywhere on the box** before this act. **By the identical discriminator they are
dead launcher shells too.** They were **LEFT RUNNING** under Andrew's standing exclusion of `~Y` work
from this seat (*"just not anything the ~Y agents are doing"*), as was the `~Y` operational driver
(pid 13788, running since 09-10 11:24).

⚠ **`1.7.0_SA_KRN~Y`'s broker row reads READY with a bound thread.** That is exactly what a seat
looks like from the outside whether or not it can act. Surfaced to `1.0.0_SA_CTO`, not acted on —
**an exclusion on acting is not an exclusion on reporting.**

## ⛔ What this entry does NOT claim

**That either seat can WORK.** Process truth and a broker LIVE row cannot separate a working Codex
seat from a hollow or stillborn one — both read ALIVE, and this estate has banked memory of exactly
that failure. The only oracle is an agent-side ack. Messages **95935** (CVO) and **95936** (CRO) were
delivered via filesystem+broker+channel push, each asking the seat to acknowledge naming its own
serial. **Until one answers, "the seats are up" is a claim about processes and bridges, not about
capability.**

## Rollback

`/mstr-kill` either serial. Nothing was committed by either seat; no branch, no register row and no
task order depends on this act.
