# LD-0100 — /mstr-spawn SKILL.md scanner-self false-positive fix (empirical first-fire bank)

## Defect

`/mstr-spawn` SKILL.md Steps 1b (per-serial marker scan) + 1c (concurrency-cap headroom scan) both used CommandLine pattern matching against `*# OPAL_SPAWN_MARKER_v1*`. The Get-CimInstance scan executes inside a PowerShell process whose own CommandLine contains the search-pattern argument literally — so the scanner counts itself, inflating per-serial marker count by 1 (Step 1b) and concurrency count by 1 (Step 1c).

Pre-fix empirical (2026-05-26T~13:48Z, /mstr-spawn 0.6.1_AE_PartnerETL inaugural P1 fire):
- Step 1b `MARKER_FOR_0.6.1_AE_PartnerETL=1` — false positive (no actual spawn for 0.6.1; the hit was the scanner-self PID 14504 whose CommandLine contained the `*# OPAL_SPAWN_MARKER_v1: 0.6.1_AE_PartnerETL*` query literal).
- Step 1c `CONCURRENCY_LIVE=7/16` — actually 6 spawned agents (MSTR + 3 ws Tier-1 + 2 CL Tier-1 visible to ws-broker; CL CTO+CVO+COO partial visibility due to LD-0099 broker-asymmetry pre-fix) + 1 scanner-self.

Worked around at runtime by manually inspecting hit PIDs + CreationDate to identify the scanner self-hit; spawn proceeded cleanly post-confirmation.

## Fix

Both Step 1b + Step 1c scans add `$selfPid = $PID` + Where-Object filter `$_.ProcessId -ne $selfPid`. Step 1b also gains diagnostic-fallback prose distinguishing legitimate spawn-marker windows (marker at CommandLine END as the trailing comment of the spawned PowerShell -Command argument) from one-shot scanners (marker EMBEDDED in the Where-Object argument).
