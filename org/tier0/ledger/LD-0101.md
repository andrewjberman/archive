# LD-0101 — Tab-title structural completion via WT suppressApplicationTitle

## The gap

LD-0099 §M1 shipped OSC 0 escape sequence (`[Console]::Write("$([char]27)]0;<Serial>$([char]7)")`) paired with `$Host.UI.RawUI.WindowTitle = <Serial>` set BOTH in `spawn-agent.ps1` outer-shell pre-ajb-dot-source AND in `ajb.ps1` ajb-function pre-`& claude` invocation. Belt-and-suspenders coverage at launch.

**Empirical observation 2026-05-26T~14:35Z (Andrew screenshot evidence):** despite the launch-time title-set, tab titles in Windows Terminal did NOT display the agent serial automatically. Andrew manually renamed all 7 spawned-agent tabs (`1.0.0_SA`, `2.0.0_SA`, `0.6.1`, `0.1.0_DS`, `0.2.0_DS`, `3.0.0_SA`) to identify them. Andrew direct query: "I want the agent serial to automatically be loaded in that tab by default at launch. is that possible?"

**Root cause:** `claude.exe` (the Anthropic CLI running inside each spawned PowerShell shell) emits its own OSC 0/2 escape sequences during interactive runtime to set tab title to context-relevant values (likely the current cwd or task description). These runtime emits override the launch-time title that ajb.ps1 set just before `& claude`. The OSC escape mechanism is last-write-wins; claude.exe wins every cycle.

## The fix

Windows Terminal supports a per-profile boolean setting `suppressApplicationTitle` (default false). When set to `true`, WT IGNORES tab-title OSC sequences from running applications AND keeps whatever title was set via PowerShell at launch (`$Host.UI.RawUI.WindowTitle` or direct OSC emit before the application started).

Edit applied to user-local Windows Terminal settings.json (path: `%LOCALAPPDATA%\Packages\Microsoft.WindowsTerminal_8wekyb3d8bbwe\LocalState\settings.json`):

```diff
-        "defaults": {},
+        "defaults": {
+            "suppressApplicationTitle": true
+        },
```

This sets the flag for ALL Windows Terminal profiles. Effective immediately on save (WT auto-watches settings.json + reloads).

## Affected behavior

- **NEW spawns post-edit:** title set at launch by `ajb.ps1` (OSC 0 emit + `$Host.UI.RawUI.WindowTitle`) sticks through the entire claude.exe session. Tab displays agent serial automatically.
- **EXISTING spawned windows (7 alive at edit moment):** unchanged — their current titles (Andrew's manual renames) stay until natural respawn. No retroactive title-set unless an external mechanism is invoked.
- **Non-agent windows:** also subject to the global flag — any PowerShell/CMD/WSL window where the running application would normally set the tab title will now keep whatever was set at launch. If Andrew finds this too restrictive for non-agent use, the flag can be moved to a specific profile (e.g., only the auto-spawn-agent profile) rather than `profiles.defaults`.

## Rollback

Two paths:
1. **Full revert:** flip `suppressApplicationTitle` back to `false` (or remove the key) in settings.json. Tab titles will then be application-driven again (i.e., claude.exe wins).
2. **Scope narrowing:** if global flag is too broad, move it from `profiles.defaults` to a specific profile created for agent spawning. Requires creating a dedicated PowerShell profile + updating spawn-agent.ps1 to launch into that profile via `Start-Process` arguments — more complex but allows non-agent terminals to keep dynamic titles.

Both rollback paths are user-local config edits; no workspace-state mutation requires rollback.
