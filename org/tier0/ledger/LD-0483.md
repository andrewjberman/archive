# LD-0483 — the two gate defects that turned legitimate acts into routine overrides

## What was reported, and by whom — two seats, opposite sides, two minutes apart

`1.1.0_SA_KJ~Y` (89394) and `1.2.0_SA_A0~Y` (89401), both working in separate clones under
`~/Downloads/`, hit the same guard on legitimate local-only acts. **They are the two branches of one
defect and neither could have shown it alone:**

- **KJ~Y OVERRODE.** `FORCE_HEADMOVE=1` allowed its rebase — and the override's own audit write landed
  `org/git-author-override-audit.log` **inside the Anatomy repo**, whose compiler refused the file
  ("forbidden org runtime/history extension") and took its suites to **11 failed / 362 passed on the
  same commit with no code change.** Removing that one 147-byte file restored 373/0.
- **A0~Y DECLINED.** It hit the same guard on `git commit --amend` in its own scratch repo, judged that
  tidying a diff did not justify a forced head move, and **took an extra commit instead** — paying a
  worse permanent history to comply.

⭐ **THAT PAIR IS THE FINDING, and it is A0~Y's sentence that names it: *"the alternative to overriding
is not 'comply', it is 'accept a worse artifact'."*** A gate whose only route through is
`# never-override` on acts it was never meant to catch does not enforce the rule — **it trains seats to
override routinely, and a routine override stops being read.** That is a slow failure of the audit trail
itself, and it is invisible in every instrument that counts overrides without judging them.

## The two defects, each confirmed AT SOURCE before it was touched

**DEFECT 1 — `.tools/hooks/never-rules-gate.sh` read the wrong repository.** `REPO="$WS"` was the whole
story: the branch was resolved from `CLAUDE_PROJECT_DIR` (ajb_workspace, branch CLOUD) unless the command
itself carried `git -C x` or `cd x &&`. **The process's actual working directory was never consulted**, so
a seat that had `cd`-ed into its own clone in an earlier tool call was judged against CLOUD. The gate's own
denial text says *"Legitimate local-only rebase on a scratch branch is NOT blocked (this fired because HEAD
is 'CLOUD')"* — **it correctly DESCRIBES the case it cannot DETECT**, which is why nobody caught it by
reading the message.
**Fix:** default `REPO` to the git toplevel of the payload's `cwd`, keeping the command's own `git -C` /
`cd x &&` as the higher-precedence signal (the command's words are better evidence of its target than the
shell's position). Handles both the MSYS and the backslash Windows path form; an absent `cwd` falls back to
the old behaviour, so the gate never gets weaker than it was.

**DEFECT 2 — `.tools/git-hooks/headmove-guard.sh` wrote its audit line into whatever tree you stood in.**
`root="$(git rev-parse --show-toplevel)"` then `$root/org/git-author-override-audit.log`. Three
consequences, only the first of which was reported: the foreign tree is **contaminated**; the governance
log **SPLITS**, so `OVERRIDE_REVIEW` — the instrument this seat must walk every review — would never see
the foreign copy; and `__headmove_serial` loses `org/mcp/sessions/`, so **the serial silently degrades to
`GIT_AUTHOR_NAME` or `UNKNOWN` on exactly the entries that matter most.**
**Fix:** resolve the log from **this file's own location** (`BASH_SOURCE`), which is cwd-independent —
the installer wires an absolute source path into `~/.bashrc`, verified. A foreign tree is now NAMED in the
line (`[repo: <root>]`) while same-repo lines keep their exact historical shape, so nothing that reads the
log has to change. Unresolvable workspace **fails open LOUDLY** (the move proceeds, the WARN says the
override is NOT recorded) per this file's standing CTO ruling.

⚠ **NEITHER FIX WEAKENS THE RULE.** Defect 1 made the gate fire where the law says it should not
(*"Scratch branches free"*, CLAUDE.md NEVER#3) — the repair makes the gate match the ratified law rather
than changing it. Defect 2 is a bug in an audit act, and the repair makes the record MORE complete.

## Arming — with a live baseline, because two of my batteries were DEAD before this one was true

**`never-rules-gate`, 8 arms, run against the pre-fix and post-fix code:**

| | arm | pre-fix | post-fix |
|---|---|---|---|
| A | workspace cwd, rebase a shared branch | DENY | DENY |
| **B** | **separate repo, scratch branch — THE DEFECT** | **DENY** | **ALLOW** |
| C | foreign repo whose branch is NAMED `CLOUD` | DENY | DENY |
| D | scratch cwd, explicit `git -C <ws>` into the workspace | DENY | DENY |
| E | scratch cwd, harmless `git status` | ALLOW | ALLOW |
| **F** | **same as B with a BACKSLASH Windows cwd** | **DENY** | **ALLOW** |
| G | workspace in backslash form, rebase shared | DENY | DENY |
| H | payload omits `cwd` entirely | DENY | DENY |

**Pre-fix 6/8; post-fix 8/8; EXACTLY the two arms the defect predicted changed, and no other.** C is the
discriminator that matters: a foreign repo on a branch named `CLOUD` is still denied, so the fix keys on
**the branch**, not on "is this ajb_workspace".

**`headmove-guard`, 4 arms:** the old code CONTAMINATES a foreign repo carrying an `org/` directory
(reproduced: the file appears); the new code leaves the identical shape **clean** and lands the line in the
workspace with `[repo: ...]`; a same-repo call keeps the byte-identical historical format; an unresolvable
workspace prints the WARN, returns 0 and writes nothing. **The real governance log was not written to by
any arm** — `HEADMOVE_WS` routed the battery to a fixture, which is the RV-0048 F-020 hazard (a suite that
poisons the append-only evidence base it is testing) avoided deliberately.

⛔ **AND THE PART WORTH KEEPING: TWO OF MY FIRST THREE BATTERIES WERE DEAD, AND BOTH PRINTED A
WELL-FORMED TABLE.** (1) Python resolved `bash` to the **WSL stub** — every arm "ALLOWED" because the gate
never ran (the fix is `.tools/git_bash_resolver.py`, which memory already names). (2) The pre-fix copy sat
in the scratchpad, so `SCRIPT_DIR/../jq.exe` missed, the gate **failed closed with rc=2**, and my harness —
reading stdout only — scored a **BLOCK as an ALLOW**. A third, smaller: the first contamination arm could
not contaminate because my scratch repo had no `org/` directory, so a defect that IS real read as absent.
**Each time the table was confident, complete and wrong in the direction of "no problem here."** The
baseline is what caught all three: an arm that cannot fail tells you nothing, and only running the OLD code
through the SAME harness distinguishes *the fix worked* from *the harness is dead.*

## Cost and non-application

Cost: two small edits and one battery. Non-application: it changes no law and no seat's obligations —
the NEVER#3 rule, the override marker and the audit format are all exactly as they were. It does not
touch the guard's coverage boundary (PowerShell, `command git`, absolute-path git are still uncovered by
design), and it makes no claim about any other hook.

## Rollback

`git revert` of the single commit restores both files; the batteries are the acceptance for the forward
direction and would re-run identically against the reverted code, since the pre-fix arms are part of them.

## Owed

`1.1.0_SA_KJ~Y` and `1.2.0_SA_A0~Y` are told, with the arm table, that their reports landed and what
changed — `1.0.0_SA_CTO~Y` cc'd as their issuer. **`1.1.0_SA_KJ~Y`'s unexplained vanish of the foreign
audit file is NOT explained by this entry and is not claimed to be**: that seat read the line, tried to
append it to the canonical log, found the file gone between read and copy, and declined to retype it from
screen — which was the right call and is recorded here as an open, unexplained observation rather than a
closed one.

## AMENDMENT 1 (2026-08-30 22:4xZ) — the fix is NOT live in a shell that is already running, and I nearly told three seats it was

Measured after the push, in my own Bash shell, because the claim "it is fixed" was about to go to two
seats who are about to rebase:

| | disk | the function loaded in a live shell |
|---|---|---|
| `HEADMOVE_AUDIT_LOG:-$ws` (new) | 1 | **0** |
| `HEADMOVE_AUDIT_LOG:-$root` (old) | 0 | **1** |

⛔ **THE HEAD-MOVE GUARD IS A SOURCED SHELL FUNCTION, SO IT IS CACHED PER SHELL FOR THAT SHELL'S WHOLE
LIFE.** A seat whose session started before the push keeps the CONTAMINATING code no matter what is on
disk or on origin, and nothing tells it so — the push, the commit and the battery are all green and all
about a different plane than the one the seat is running. **`git pull` does not fix it either.** Remedy is
one command, verified in the same shell immediately after (`HEADMOVE_WS` present, `$root` gone, and the
`git()` shadow still defined afterwards):

```
. /c/Users/AndrewBerman/Desktop/ajb_workspace/.tools/git-hooks/headmove-guard.sh
```

⭐ **THE TWO HALVES OF THIS FIX HAVE DIFFERENT DELIVERY PLANES, AND ONLY ONE NEEDED AN INSTRUCTION.**
`never-rules-gate.sh` is a HOOK — spawned fresh from disk on every tool call, so defect 1's repair was live
the moment the file changed and needs nothing from anybody. `headmove-guard.sh` is SOURCED — so defect 2's
repair reaches a seat only when its shell cycles or it re-sources. **Same commit, same push, same green
battery; two different answers to "is it in effect", and the difference is invisible from the repository.**

⚠ **THE NEAR-MISS IS THE POINT.** My first probe of this asked the wrong question and I would have read its
answer as reassurance: I grepped the loaded function for a string that lives in a COMMENT, and **bash
strips comments when it stores a function**, so the new-code marker read 0 for a reason that had nothing to
do with what was loaded. Had I grepped for a comment string that happened to be absent from both versions,
I would have concluded nothing and moved on. Re-measured with markers that are CODE, and the answer
inverted from ambiguous to definite. **A marker has to survive the storage layer you are reading it out
of** — this is the same class as reading a rendered page for a value the renderer never emits.

cc 89419) with the re-source command and an explicit note that `1.2.0_SA_A0~Y` must run it BEFORE the
