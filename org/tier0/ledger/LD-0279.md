# LD-0279 -- A HANDLE IS NOT A RUNNING PROCESS

## Context

2026-07-13 ~08:2x-08:4xZ. A python process attempted to allocate ~43GB (Andrew, direct).
The host OOM'd. Every Claude agent session died except `0.0.0_AB_MSTR` and `1.0.0_SA_CTO`.
The fabric was mid-release: the INF advisor-of-record go-live was at gate-2, COO had just
withdrawn both NEVER#2 co-signs on the phantom-advisor fix, and 6 deploy ledgers were open.

## The decision

`org/mcp/agent-poller.py::_pid_alive()` must assert **STILL_ACTIVE**, never a handle.

    handle = OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION, False, pid)
    if not handle: return False
    ok = GetExitCodeProcess(handle, &code)
    return ok and code.value == 259     # STILL_ACTIVE

On a handle we cannot read, **fail CLOSED (dead)**. An instrument that cannot observe must
say so -- and the entire purpose of this probe is to let a poller notice its agent is gone.

## Grounding (source-confirmed + exercised; two paired positive controls)

Source: `org/mcp/agent-poller.py:123-135 @ working-tree, pre-fix`. The probe called
`OpenProcess()` and returned True on any handle. It never called `GetExitCodeProcess`.

Exercised -- both probes run side by side, with the two surviving agents as controls:

| pid | who | old probe (OpenProcess) | correct probe (GetExitCodeProcess) |
|---|---|---|---|
| 12780 | MSTR -- alive, **control** | True | True |
| 5876 | CTO -- alive, **control** | True | True |
| 15900 | **COO -- DEAD** | **True** | **False** |

The controls prove the correct probe CAN return False. The shipped probe never could.
Corroborated independently: `Get-Process -Id 15900` -> not found, while `Get-Process` on
both control pids returns ALIVE; and exactly 2 `claude.exe` processes exist on the box,
matching Andrew's own observation of the PowerShell sessions.

**A retrieval correction, recorded because the rule demands it:** my first check used MSYS
`ps`, which reported PID 15900 absent -- and ALSO reported MY OWN pid absent, though I am
demonstrably alive. MSYS `ps` cannot enumerate detached native-Windows processes, so its
"not found" is an instrument artifact that could only ever come back negative. **The
positive control is the only reason I did not ship that as a finding.** (CLAUDE.md already
records this exact `ps|grep` artifact; I reproduced it anyway.)

## Why it matters more than F-008 says

RV-0047/RV-0048 **F-008** reads: *"the fabric cannot detect agent death."* That understates it.
**The fabric CONFIDENTLY REPORTS A DEAD AGENT AS ALIVE.** An absent field is a gap; a
confident wrong field is a **FALSE WITNESS** -- and this one is ANTI-CORRELATED in the same
way as the orphan-watcher class (Rule 22b): *the deader the agent, the more perfectly its
liveness holds*, because the only thing that could stop the heartbeat is the very death it
cannot see.

Consequences, all live at the time of this decision:
- `get_live_agents` / `get_agent_status` / `fabric-check.py` all reported COO **LIVE, 1s ago**.
- fabric-check's DEAF/UNREACHABLE detector could **never** fire for COO. Structurally.
- Messages to COO landed in a void with a green receipt.
- `register_agent`'s identity guard refuses a serial "held by a different LIVE process" --
  **so the forgery made the dead agent UNRESPAWNABLE.** The lie blocks its own repair.

And it is precisely the *"`_pid_alive()` probe coarser than the claim it licensed"* that
CLAUDE.md's own **CONTROLS-OVER-CARE** capstone lists among the eight instruments that lied
on 2026-07-13. **IT WAS NAMED AND NOT FIXED.** Hours later it hid an executive's death
through a fabric-wide outage. *Knowing a failure mode by name does not immunize you against
shipping it -- and naming it is not fixing it.*

## The test carries a PROVEN-RED case

`org/mcp/tests/test_pid_alive_exited_process.py` (5/5).
`test_exited_process_with_open_handle_is_dead` reproduces the exact state COO's pid was in
(`subprocess.Popen` holds the child's handle open after it exits) and asserts BOTH that the
OLD probe calls it alive AND that the new one calls it dead. A suite with no case the old
code fails cannot validate the fix; **a probe never observed to return False has not been
shown able to.** The two live-pid arms are paired positive controls -- without them, a probe
hard-wired to `return False` would pass every negative arm.

## Scope / what this does NOT fix

- **The already-running forger has the old code in memory.** Clearing tonight's lie requires
  `deregister_agent("2.0.0_SA_COO", kill_pollers=True)`. **Tier-0 is NOT AUTHORIZED to call it**
  (broker: *"only CTO/COO can deregister agents. Caller: 0.0.0_AB_MSTR"*) -- and one of the two
  authorized serials **is the dead one**. Routed to CTO. Recorded as RV-0048 **F-023**: the
  terminal resolver of the escalation chain is locked out of the recovery primitive.
- `/kill scripts` could not run: `kill-maint.ps1:34` died on `Get-CimInstance : Shutting down`
  (WMI, HRESULT 0x80041033). WMI is down on this host -- surfaced to Andrew.
