# LD-0638 -- the reboot roster restores COO tabs by project code

## Decision
Andrew-direct ~04:4xZ at the site Z terminal, relayed by 0.0.0_AB_MSTR~Z (bus a3128564): "that is something that should be
a rule across all boxes". Site Z found that the reboot roster titles every tab by serial, so a reboot loses project tabs.

`.tools/autolaunch-agents.ps1` now accepts `<serial>=<TAB>`:
- A COO entry carries `=<PROJECT_CODE>`.
- The title is passed to ajb.ps1 as OPAL_TAB_TITLE and to wt as `--title`.
- A COO entry with no `=<TAB>` logs a WARN and still launches, because a reboot must not strand a seat.

## Verification
- PowerShell parse OK.
- `'A=B' -split '=',2` gives [A][B], and `'A'` gives [A][].
- ajb.ps1:271 already reads OPAL_TAB_TITLE.

## Rollback
`git revert` of the commit.

## Amendment 2026-10-09 ~05:2xZ
dell1's manager found (bus b0081fa0) that `powershell -File autolaunch-task.ps1 -Serials a,b` binds ONE string "a,b", so
a multi-seat roster registered only its first seat. Both `.tools/autolaunch-task.ps1` and `.tools/autolaunch-agents.ps1`
now split every entry on commas. Tested: the -File comma form gives 3 entries, and the in-process array gives 2. Both
scripts parse.
