## Per-division workflow patterns

### WS DIVISION (REPAIR-AMENDMENT pattern; parallel PRDs)

```
/spot-check (20m) + /verify-channel (event + 2h) surface findings
   ↓ findings classified: REPAIR-AMENDMENT trigger? (per LD-0065 ws CTO AMEND-scope refinement)
   ↓ if YES → inbox to ws CTO
/ws-charter (30m cron) — Step 4 reads inbox:
   - REPAIR-AMENDMENT trigger present → author amendment to existing PRD
   - FIX class → bug-fix TO within active project
   - NOVEL → requires Andrew direction (else HALT)
   - CLEAN-SWEEP → attest
   - Multiple PRDs in flight simultaneously OK
```

### CL DIVISION (NEW-PRD pattern; sequential PRDs)

```
DAILY:
/case-find (CL CVO daily) — scans Observations + external sources → adds Cases to queue
/case-mgmt (CL CVO daily, sequential after /case-find) — ranks Cases per Decision #6 + CVO discretion

PER /cl-charter TICK (30m):
   Read top Case from queue (Internal Cases preferred; pull External Cases if <3 unaddressed Internal)
   IF prior PRD pending /verify-channel PASS-mechanical + PASS-holistic acceptance:
     CONTINUE-attest (no new authoring this tick)
   ELSE:
     Author NEW PRD from top Case
     Ship → triggers /verify-channel PRE-EXECUTION mode
   
ON PRD-SHIPPED EVENT:
/verify-channel runs PRE-EXECUTION (mechanical + holistic acceptance):
   - PASS-mechanical + PASS-holistic → CL CTO unblocked for next Case
   - CONCERN/COUNTER → amendment recommendations to PRD scope; CL CTO addresses
```
