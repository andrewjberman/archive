# LD-0605 -- a per-case LEGACY-READ waiver in the naming gate: proposal routed, nothing built

## Why this is a proposal and not a commit of code

The ruling asked MSTR to *name a repository-tooling implementer and route a concrete narrowly
bounded audited proposal to CTO*. ⛔ The gate in question refuses commits estate-wide and is in
ENFORCE mode on this box (`org/mcp/naming-gate.enforce` PRESENT). **A change to it is not mine to
land on my own judgment, and CLAUDE.md's NEVER on disabling a correctly-firing gate is not
satisfied by good intentions** -- so the shape goes to the CTO first, refusable, before a line is
written.

## The case in one line

`2.0.0_SA_COO~M` cannot commit a legitimate READ of `silver/api_dims/accounts_v2/` at
`holdings_snapshot.py:709`, because that literal sits under the live `ADVI_FIRMBKTS` remediation and
the matrix says REFUSE-unless-the-diff-removes-it. ⭐ **The gate is RIGHT; the diff cannot comply.**
Removing the literal breaks a working read, and repointing it is the "guessed source repoint" the
ruling already refuses.

## What was measured before proposing (neither claim inherited)

- **No per-case mechanism exists**: enumerate over the gate's 1,065 lines for
  `exempt|exception|allowlist|waiver|override|legacy` -> **4 hits, all DOCSTRING or COMMENT, DEF=0
  CODE=0**, every hit a fragment of a longer value. The CTO's claim holds.
- **ENFORCE mode is live here**, so the lane is hard-stopped rather than warned.

## The one structural fact that makes the shape proposable

`naming-gate.py:850` computes `rem` **only when `not new`**, and the NEW-literal REFUSE returns at
`:851-852`, one line ABOVE the branch the waiver would hook. ⭐ **So "a waiver can never reach a NEW
or CHANGED literal" is guaranteed by WHERE the hook sits, not by a check someone has to remember.**
Had that not been true, the proposal would have needed a guard I could get wrong, and I would have
said so instead.

## The bound accepted in advance

Six invariants each get a built arm, plus two vacuity arms (data file ABSENT, then EMPTY) so the
mechanism cannot pass for a reason unrelated to itself. The hard one is distinguishing a READ from a
WRITE at a literal's line. ⛔ **If that arm cannot be built soundly, I report that the mechanism
CANNOT be built to the ruling's standard rather than ship a waiver with a green test beside it.**
That is named here, before the work, so it cannot be quietly dropped after it.

## Cross-fabric, because this file is not this fabric's property

`.tools/naming-gate.py` is LGIC_ENFORCE's build and LGIC_ENFORCE is SITE-Z-placed. I asked before
touching it: `0.0.0_AB_MSTR~Z` measured LGIC_ENFORCE NOT live, no worktree, no seat holding it, a
clean working tree on that file, and cleared this fabric to implement while undertaking that site Z
will not touch it meanwhile. ⚠ **That clearance is point-in-time and ages**; if implementation slips
past this session I re-ask rather than rely on it.
