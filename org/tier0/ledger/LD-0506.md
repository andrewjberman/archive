# LD-0506 — the work-mix was a picture of who was awake

## Decision

`commit_kind` is derived from the paths a commit touched. Ordered rules, first match per FILE,
majority of file-votes wins the commit. Enum in `daily_reports/README.md`; four-postulate record
rewritten there; `scripts/commit_census.py` and the schema's `method` description updated.

## What the old axis actually measured

The rules matched the AUTHOR STRING (`_DT_` -> FRONTEND, `_SA_(CVO|CRO)` -> VERIFICATION) while
the enum was named for kinds of work. **Rule 24 (iii): one axis, one intent** — this had the axis
*"who committed"* wearing values from *"what the work was."*

Same 293 commits, 2026-09-01, seat-derived vs file-derived:

```
  VERIFICATION   65 ->  2      only TWO commits touched a test, battery, probe or
                               certification path all day
  DATA           51 -> 11
  BACKEND        57 -> 19
  ARCHITECTURE   42 ->  3
  FRONTEND        3 ->  3
```

⛔ **ANY READER COMPARING A PRE-09-02 REPORT TO A LATER ONE IS COMPARING TWO DIFFERENT
MEASUREMENTS THAT SHARE A LEGEND.** That is recorded in the README record too, because the
legend is the only thing a reader sees.

## The split, and why it was put to him rather than landed

A straight file-derivation put **167 of 293 (57%) into COORDINATION** — replacing a flattering
number with an uninformative one. Rather than ship a degenerate axis onto his morning report, the
choice went to him with the measured preview. He chose the split.

⭐ **His follow-up question is what made the split correct rather than invented.** He asked
*"Coordination is so heavy what accrues there exactly?"* — and the answer had to be censused, not
guessed:

```
  agent-home deliverables/   102 touches   -> DELIVERABLES
  agent-home task_orders/     53           -> COORDINATION (dispatch, which is what the word means)
  org/critical_paths/         24           -> OPS
  org/projects/ + org/tier0/  30           -> GOVERNANCE
  agent-home drive_pairs/     14           -> COORDINATION
```

**The bucket was heavy because it was holding four different activities.** Splitting on a guess
would have produced plausible names over the wrong boundaries.

Result on 09-01: DELIVERABLES 80, AUDIT 69, COORDINATION 43, TOOLING 22, BACKEND 19, OPS 15,
GOVERNANCE 14, DATA 11, PLANNING 9, FRONTEND 3, ARCHITECTURE 3, VERIFICATION 2, UNATTRIBUTED 3.
Sums to 293; timeline series re-checked against their counts.

## ⛔ The reuse of the old names overrides a written constraint, in the open

The superseded record said, in its own words: *"A content-classified axis would be a different
enum and must not reuse these names."* **This enum reuses them.** The override is Andrew's — he
asked to keep the names he reads each morning — and it is stated at the top of the README record
rather than glossed. The ambiguity that clause feared is answered by the `claim` and `method`
fields, which now read `inferred` and `files touched -> work kind`. **A silent reuse would have
been the defect; naming the override is the discharge.**

## claim: measured -> inferred

The FILES are measured; the KIND is a path heuristic over them — exactly the shape
`project_census` has always labelled `inferred`. The old `measured` was defensible only about the
author field it then read, while the field it labels is consumed as a kind of work. **A claim
field that outlives the thing it described is worse than none, because the consumer cannot reject
on it.**

## Controls run before landing

- **Positive control on every value, 15/15 arms correct** — including `DECOMP`, which read **0**
  on 09-01 and would otherwise be indistinguishable from a broken rule. A rule that never fires
  and a rule that cannot fire look identical in a census.
- **Grain exception exercised:** an Andrew-authored commit with no matching path -> `OPERATOR`.
- **Negative control:** an agent-authored commit with no matching path -> `UNATTRIBUTED`, NOT
  `OPERATOR` (the author arm must not leak into the residual).
- **Uncovered members hunted against real data:** a 14-day census of 12,414 file-touches over 100
  prefixes drove the rules. The first exercise still left 14 residual commits, **12 of them COO
  `drive_log_*.md` sitting at the agent-home ROOT rather than under `logs/`** — a rule written to
  the directory convention missed the files that do not follow it. Residual after: 3 of 293 (1.0%).
- **Rule 24 token census** on the new names (DECOMP 73, GOVERNANCE 9, DELIVERABLES 2, OPS 1,
  TOOLING 11, PLANNING 3, AUDIT 134): all hits are prose or path fragments, none a competing enum
  value in a consumed schema.

## Stated, not hidden

`PLANNING` and `AUDIT` now exist on BOTH this enum and `project_census`'s work-stream axis, so a
brief or a session log reads the same on both cuts. The axes still separate for product commits
(stream `D2`, kind `BACKEND`), but **a reader must not treat the two as independent evidence
about the same commit.**

## Rollback

Revert this commit. Both censuses are read-only over `git log`; no served artifact changes until
a day's JSON is authored from them.
