# LD-0370 -- Promote the /draw skill from user-level ~/.claude into the repo

## Decision
Andrew-direct 2026-07-31: duplicate the `/draw` skill into the repo's `.claude/skills/` "where we have all the other skills," so it propagates to every checkout.

## Verbatim (Andrew)
> "no i created the /draw skill and it lights up blue in the terminal when i type it, and we use it all the time, CTO is using it right now"
> "just duplicate it into this directory" / "where we have all the other skills"

## Root cause it fixes (why site-Z did not have it)
`/draw` lived ONLY at `~/.claude/skills/draw/SKILL.md` (user-level, laptop home, created 2026-06-10). A user-level skill is PER-MACHINE and is never git-tracked, so:
- it works for every base-machine session (that is why CTO has it live), and
- the site-Z machine's separate home `~/.claude/` simply never had that folder, and git could not carry it.

The estate's own lesson class -- a single-carrier artifact that exists on one device and silently does not on another (same shape as the device-local audit logs, the untracked comp_re hook, the Windows-Terminal title setting). The durable fix is the shared carrier: the repo.

## What landed
`.claude/skills/draw/SKILL.md` copied byte-for-byte (5831 bytes) from the home copy into the repo, alongside the other ~50 tracked skills. It is a general house-style ASCII system-diagram generator (two-plane build/query layout + analogy table) -- no machine-specific or personal content. Reaches site-Z at its next pull; any future checkout gets it via git.

## Note on the two copies
The laptop now carries both `~/.claude/skills/draw/` (user-level, original) and `.claude/skills/draw/` (repo). They coexist harmlessly; the repo copy is the source of truth going forward. Andrew may delete the home copy to avoid drift, or leave it -- his personal dir, not touched here.
