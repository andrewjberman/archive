# LD-0231 — comp-which surface-aware posterior router (NFRA_COMPLEARN delta)

Andrew-direct 2026-06-30, off a live observation: 0.4.0_DE routing comp-cluster questions through
comp-which and hitting a fuzzy-match miss. The deeper question Andrew posed: route on **not just the
query tokens, but where in the system the agent is operating** + **a super-light ranking function**
over query x surface-of-operations.

## The thesis

comp-which today = `score(tool) = fuzzy(query, keywords)` + curated RULES + **silent argmax**. Upgrade
to a light **posterior**: `w_q*query_match + w_s*surface_prior + w_h*history_affinity`, argmax with a
**margin-disambiguation gate** (near-tie -> surface both candidates with their `concern`, never guess).
The surface PRIOR is read for free from the live, CI-guarded `comp-coverage-map.yaml` + agent role +
working-set + session trajectory; the LEARNED term reads the now-live `tool_activity` Trino catalog.

## Two live mis-routes ground it (two distinct failure modes)

- **A (within-margin, cross-tool):** "panel to drilldown tree" -> comp-transform not comp-cluster (both
  portal/component grain; scores within noise; silent wrong pick). The PRIOR fix.
- **B (same-surface, pure-likelihood):** comp-drift self-query -> comp-aws (both AWS-CLOUD; the prior
  CAN'T separate them). The LIKELIHOOD + margin fix. Proves prior is necessary-not-sufficient.

## Why a delta to COMPLEARN, not a new project

COMPLEARN brief Section 5a already makes the comp-which RULES a champion-config surface (LD-0226 = the
worked routing-rule iteration). This deepens the mutation space from "propose a RULE" to "tune a
posterior" (the weights, epsilon, the affinity table), scored on the same rail-escape-reduction signal.
With P0 live (tool_activity catalog), comp-which becomes the loop's **first live CONSUMER** -- a
near-term payoff, not a warm-up.

## Folded from 0.4.0_DE's P2-3 brief (Andrew-steered)

- The **routing regression test is the acceptance gate** (DE: 33/35 -> 34/35) AND unifies with the
  loop: each margin disambiguation = a new test case + a tool_activity training row. comp-drift rule
  takes it to 35/35 now.
- Curated cluster + comp-drift rules land now as **cold-start priors** (cheap, unblock today).
- **Governance fork routed to CTO/COO~B (Section 9):** comp-tool AUTHORING vs LANDING -- the owned-paths
  gate blocks a DE from landing the infra engine (AE lane) + the exec-owned manifest. MSTR rec:
  relocate read-side comp-engines to a lane-portable home + shell to `comp-kuzu --json`; keep ledger
  registration the COMPUNIFY governor's act (one-home discipline). CTO/COO~B ratify.

## Scope boundary

This LD + the brief are a COMMISSION (scoping), not an implementation -- the router/substrate are
unchanged by this commit. CTO folds it into the NFRA_COMPLEARN PRD; the implementation carries its own
gates.
