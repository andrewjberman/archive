# LD-0310 -- Charter NFRA_ONTOLOGY: a universal, agnostic, relational-archetypal ontology (the C3 language / rule bank)

## Context

Arose from the C3-relationship question -- "where does firm-twin/fork-shadow language derive from; do we
have a C3 ontology bank that deterministically explains these relationships?" Ground truth: a PARTIAL,
distributed, CTO-ratified (v0.1, 2026-06-18) deterministic ontology exists across `canon-patterns.yaml`
(vocabulary: 23 node-types + 16 edge-types; 4 pattern-classes; per-pattern twin_shadow_guard),
`suppression_v1.yaml` (90 adjudicated-FP classes), and `graph-call-manifest.yaml` (base vocab) -- but it
was PURPOSE-BUILT for the debt/canon-deviation scorer and is AWS/Opal-scoped. Andrew chartered the
elevation: a true universal ontology.

## The three design principles (Andrew-stated, binding)

1. **AGNOSTIC** -- the ontological language is NOT opal-scoped, NOT aws-scoped; it would describe any system.
2. **PLAIN-ENGLISH semantics** -- human-readable relationship terms, not typed-schema jargon.
3. **RELATIONAL-ARCHETYPAL** -- designed around universal relationship archetypes, not platform types.

## Shape (charter-level; PRD refines)

- **Layered:** universal archetype layer ABOVE; canon-patterns.yaml demoted to the AWS-binding adapter.
- **Ownership:** ~C builds/authors the language (deep-work lane, spawned 2026-07-18); base coordinates +
  feeds (reserved per LD-0305, NOT re-tasked); CTO arch-gates; MSTR governs the doctrine.
- **Arch guardrails (CTO, 020752Z):** the archetype set must be CLOSED + orthogonal enough to bind every
  concrete type without a catch-all leak; keep DISTINCT from OPAL_TAXONOMY (ontology = what a node IS
  relationally; taxonomy = what it is CALLED -- they compose, not merge).
- **Consumers:** canon-deviation scorer + COMPSIMILAR node-summary C3 enrichment (the C3 clause is HELD
  pending this layer; C2 motif+role proceeds independently to CTO gate + ~D build).
