## 4. DOCUMENT-SPECIFIC FINDINGS

**4.1 — Incident 2 is a live Rule 22b violation caught in the act, by the agent who owns Rule 22b.**
MSTR observed CTO's gate verdict sitting in DS's **top-level** inbox (not `read/`) at the crash
instant and wrote *"unread → DS never saw it."*

**That is the SENT≠READ conflation exactly.** The file location is a **producer/delivery** signal,
blind to the consumer. DS's own ACK (`142324Z`) later confirmed DS **read the message and correctly
digested all three parts** before CTO could resend. Corrected within minutes by CTO.

> **This is the single cleanest instance of M7 in the corpus**: the observer took the *artifact's*
> position as evidence about the *agent's* state. It is the same shape as the orphan watcher
> (`REACHABLE` because the inbox was drained) — and it was committed by an agent who had that
> doctrine in front of them.

**4.2 — The resilience finding is a genuine positive and it is banked in the wrong tier.** *"A host
crash does not drop in-flight inbox messages — they are on disk and are read when the recipient
session comes back."* That is a **design property of the filesystem-inbox**, established by
accident, and it lives in a dated incident file. It is an argument for the current comms design and
nothing in the doctrine tier cites it.

**4.3 — "Why no work was lost" is the only place the corpus states a POSITIVE control that worked
by habit rather than by design.** Both DS and CTO had committed *and pushed* within ~8 minutes of the
crash. The file draws the right lesson: **"Commit + push cadence is the disaster-recovery backstop …
Frequent pushes turn a fabric-wide crash into a respawn, not a loss."**

**4.4 — Clean kill, zero orphans — and the corpus never reconciles this with its own orphan
doctrine.** Process-truth census found **no** orphan `claude.exe` and **no** orphan spawn-marker
windows surviving the crash. Yet the watcher doctrine (`.claude/skills/watcher/SKILL.md`, and
CLAUDE.md Rule 22b) is built around orphans outliving sessions. **A host crash produces a CLEAN kill;
an ordinary session end produces orphans.** That is a real, unexplained asymmetry — the watcher
doctrine's own note concedes *"session end SOMETIMES orphans; the discriminator is unknown"* — and
this file holds the cleanest datapoint on it and does not connect them.

**4.5 — Mitigation 4 is an open, unowned item.** *"Recurrence is likely — `0xc000027b` XAML crashes
are a known Windows Terminal bug. Open mitigation options (not yet actioned) … Flagged to Andrew."*
**Flagged, no owner, no expiry — which is exactly what TRIGGER_LAYER (file 07) forbids.**
