## R25.3 FROZEN CONTRACTS

**Y1 SOURCE COMPARE BY CLASS.** `source_compare.py` keeps its round-24 contract and gains `--probes FILE` (optional; absent = the round-24 behavior byte for byte). Probes: `{"schema":"gateway_source_probes/1","probes":[{"tool","class":"graph"|"integration"|"store","instrument":str,"fact":str,"value":str,"answer_value":str}]}` written by the issuer from independent reads (a graph tool against the owner's own mailbox, calendar or files read through a second route; an integration against the vendor's own API read once outside the gateway; a store against a direct DynamoDB read). For a tool with a probe, the entry reports `source` as the first source of its set, `instrument` as the probe's, `agrees` true when `value` equals `answer_value` after trimming and case folding, false otherwise, `reason` the fact compared, `source_dates` []. A probe naming a tool absent from the census, a class that does not match the tool's source kind, or two probes for one tool exits 2. S3 sources with no date token are compared BY KEY: when the result's `answer_source` carries an object key (a string with a final path segment containing a dot) and the listing under the source prefix contains exactly that key, `agrees` is true with `reason` "object key present in the listing"; when the listing is non-empty and does not contain it, false; when the answer carries no key, null with the round-24 reason. Counts and stdout line unchanged. Same input, same bytes.

**Y2 TEST-SEND GRADING.** In `tool_battery.py`, a RESULT may carry `"readback": {"agrees": true|false|null, "instrument": str}` beside `"sent": true`. A result with `sent` true is PASS when `readback.agrees` is true (the tester read the message back in their own mailbox or chat), and FAIL of class `send_unconfirmed` when `readback` is absent, null or false. A result with `sent` false is graded as before. `send_chat_message` with no sent result and a preview or absent result is PREVIEW-ONLY, never FAIL for lack of a send, and the REALIZED line of the grade names it (stdout gains `PREVIEW-ONLY TOOLS:` as today; the graded file's `preview_only` lists it). A `readback` on a result with `sent` false is refused (exit 2). No other verdict or class moves; the round-22/23 fixtures grade byte-identically.

**Y3 GROUP-MAP LINK FORM AND STORE VOCABULARY.** In `emit_catalog_v02.py`: (i) a `links` entry of a members/pending entry may be a mapping `{group: {bucket, vendor, firm}}` that expands, at emit time, to the entity ids of every catalog row whose `bucket`, `vendor` and `firm` equal the key (sorted, exactly the ids the line-per-row form would list); the line-per-row form still works; a group key that matches no row refuses the emit. This form names no firm token per link, so the naming gate does not grade it. (ii) The bucket vocabulary admits the C-GROUP store words `dynamodb`, `graph`, `amgt-scoped-api` (alongside the existing S3 bucket check) for a row whose source is a store, taking the value from the row's own source field; a store row carries its table (or, for the scoped API, its route) in `table`. (iii) Entity ids drop the doubled prefix: a row for the table `etf-classifications` is `dynamodb_etf_classifications`, never `dynamodb_dynamodb_etf_classifications` (entity ids in `catalog_entries/` and any reference to them in `members.yaml` / `pending_members.yaml` move together, shown by a grep census in the cell report). (iv) The scoped-API row `published_analysis_scoped_api` becomes bucket `amgt-scoped-api`, `table` the route it reads through, vendor opal. Existing emit output for rows and tools outside these changes is byte-identical (the dry emit before and after is diffed in the cell report).

**Y4 LINK RULE FOR NON-S3 SOURCES AND TEMPLATED OR TWIN PREFIXES.** In `routing_table.py`: a pair (tool, row) is ROUTED when (i) the row's `bucket` is a store word (`dynamodb`, `graph`, `amgt-scoped-api`) and the tool has a source of kind `store` or `integration` whose name (`store` or `integration` field) equals the row's `table` after lower-casing and treating `-` and `_` as equal; (ii) the row prefix holds a `<firm>` (or any `<...>`) segment and an `s3` source has the same bucket and a prefix that matches the row prefix with each `<...>` segment standing for exactly one path segment; (iii) the row prefix and an `s3` source prefix of the same bucket are equal after treating `-` and `_` as equal. Everything else is unchanged: the round-24 table on the round-24 inputs differs only in the pairs these three rules now route (`counts` and the `link` class move; `code` and `display` do not), shown by a before/after diff in the cell report. The three `--plant` modes still fire on the fixtures.

**Y5 HARVEST DATE ATTRIBUTION.** `harvest_date_attribution.json`, schema `gateway_harvest_date_attribution/1`: `{"schema","tool":"harvest_query_columns","answer_as_of":str,"source_newest":str,"cause":"code"|"catalog"|"battery"|"data","owner":str,"evidence":[str,...],"fix":str}`.
