1. **What the listener can do while armed.** A second uvicorn server in the SAME process, bound to `127.0.0.1:8099`, serving `POST /probe/etfs_compare_peers` and `POST /probe/client_get_transactions` for one fixed principal while an SSM lease (`/opal-gateway/probe/lease`, 60 minutes or less, holding an order id and ONE `****<last4>/<vendor>/<alias>` account reference) is valid. Any process on the host that can reach loopback can call it while armed; unarmed it answers 403 `probe_not_armed` and serves nothing. The SSRF audit `OG-sec-1` (`SSRF_AUDIT.json`, CLEAN, 0 of 18; the real denominator is 20 with two config-sourced JWKS fetches, row `Z-S384`) is the reason a host-local forgery is not a known path.
2. **The probe bypasses the tool wrappers' guard chain (row `Z-W146-S2`).** It calls the functions behind the two MCP tools directly, so `tools.py` `_run`'s policy guard and its per-user Graph token step do not run. The listener substitutes its own checks: the lease, the two-tool allowlist, the account equal to the lease's account, and its own audit line labelled `probe:<order>`. The CVO should read this as "the entitlement path of the MCP wrapper is not exercised by the probe", which is also why the probe measures heap and not entitlement.
3. **The two-tool limit is an allowlist in the module (row `Z-W146-S1`)**, not a stored restricted profile (code cannot create one). **The principal is built in code with an Opal-domain display address `opal-gateway-probe@opalinvest.com` (row `Z-W146-S3`)** because the client tools admit on the Opal email domain; the address exists in no directory. Any future code that admits on the Opal domain alone would also admit it; the exposure is bounded by the lease and the loopback binding.
4. **The audit write is inline on the shared loop (row `Z-W147-S1`)**: `audit._emit` appends the JSONL floor and, when `AUDIT_S3_BUCKET` is set, calls `put_object` with default timeouts, and `probe_call` calls it without a thread. If this stays unrepaired the ask says so; the issuer cuts a repair (amendment A2 of `OG-pr-1`: the audit call goes through the threadpool inside `probe_listener.py`) before the GO unless the CTO rules otherwise.
5. **The instance role.** `ssm:GetParameter` on `/opal-gateway/probe/lease` was NOT measured by the workers. Phase A of `OG-ap-40` reads the role's policy; if the grant is absent the release STOPS (a denied read fails closed as `probe_not_armed`, indistinguishable from no lease) and the IAM act is a separate order.
6. **Disarm timing.** Deleting the lease parameter closes the listener within the 5-second cache window, not instantly; the Phase B check of "the next call is refused" waits 6 seconds.
7. **Rollback.** Redeploy the live ref's tree; delete the lease parameter. With no lease the listener is inert.
