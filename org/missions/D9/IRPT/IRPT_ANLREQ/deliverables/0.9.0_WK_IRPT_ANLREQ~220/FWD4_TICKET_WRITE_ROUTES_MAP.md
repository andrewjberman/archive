## Answers to the two questions

(a) Is there a free-text or status field on an analysis-request ticket that a service principal may write and the page shows? Yes for two fields, and neither is a failure note. The drafter's text (draft_commentary, row 5, displayed at AnalysisRequestParts.tsx:651) is written once on the success path. The description (row 16, a hover title only) is the requester's text. The events log, which carries every service write as an activity entry, is not displayed (SILENT). The status cannot be moved by any service principal after CREATE (NOT-APPLICABLE).

(b) Which FWD-1 hops 6 to 14 already hold a principal that could write a failure note? Hops 6 to 9 hold none: the resident has no ticket-service principal in the code read. Hops 10 and 11 hold svc-commentary, whose only ticket write (row 5) accepts two keys and refuses a note. Hops 12 to 14 hold svc-irpt-packager, whose only ticket write (row 6, allowlist row 7) refuses a note. So no hop in 6 to 14 holds a principal whose existing route can carry a failure note on the ticket. A failure note would need a new route or a new field, which is a design question for the CTO and is not proposed here.
