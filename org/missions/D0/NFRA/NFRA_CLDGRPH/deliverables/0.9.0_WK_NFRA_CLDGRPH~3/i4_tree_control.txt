returns rc!=0 while the same test on any sibling file in this directory returns rc 0).

WHY IT EXISTS. The comp-rail once resolved its corpus from the TOOL'S install location,
so a census run from a linked worktree scanned the MAIN checkout and returned a well-formed
zero over the wrong tree. The fix is present in this checkout by content, but a census that
depends on that fix must not depend on my having read it: i4_census.py walks the tree with
its own os.walk and must find THIS file in its hit list. If it does not, the sweep is
reading a tree that does not contain this branch's work and every number it prints is void.

THE CONTROL STRING, a dated archive key carrying a discriminator that no live object has:
  s3://opal-313476888478-globgrph/snapshots/20260909/graph-20260909.tar.gz
  ETag 00000000000000000000000000000000
  LastModified 1999-01-01T00:00:00Z
  ContentLength 1

It is deliberately impossible. i4_census.py counts this file as the CONTROL and EXCLUDES it
from the classification population, printing the exclusion beside the denominator -- a
denominator that does not say what it excluded is refused at the flip. The exclusion is safe
precisely because the string is impossible: were it ever to classify as STILL_VALID, the
classifier would be broken.
