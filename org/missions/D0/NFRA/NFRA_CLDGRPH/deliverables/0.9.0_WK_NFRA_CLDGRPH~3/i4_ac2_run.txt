THE THIRD THING, NAMED BECAUSE NEITHER ORDERED REMEDY COVERS IT
------------------------------------------------------------------------------
  Neither remedy makes an ALREADY-LOST byte recoverable, and neither prevents the
  NEXT loss on any other key in this bucket. The only mechanism that does either
  is bucket VERSIONING (or object lock), which s3.tf says is off ON PURPOSE and
  justifies by the unique-key property the producer does not provide. So the
  versioning decision and the writer defect are ONE question, not two, and
  fixing the writer is also what makes the versioning-off decision true.
  This is NOT proposed as a third remedy here: it is outside the domain the cell
  declared, it is an infrastructure act under a standing egress hold, and its
  owner (AE 0.7.0 / 0.8.0_AE_CloudComp with the CTO's ruling on the record) is
  not this worker. Named so the two-way comparison is not read as exhaustive.
