## C. CG-s-13 -- the AuthKind, named (V2-AC6)

> ## `AuthKind.NONE`

**Defined at `infra/aws/ec2/opal-gateway/app/integrations/base.py:44` @`a1af5d70c2`:**

```python
class AuthKind(str, Enum):                                              # base.py:41
    DELEGATED_USER = "delegated_user"   # per-request caller token (M365 Graph)
    SHARED_SECRET = "shared_secret"     # one server-held credential from Secrets Manager (YCharts)
    NONE = "none"                       # no external auth (read-only in-estate source)   <-- :44
```

**This is not an inference from the enum's shape -- the framework names our exact case three times:**

1. `base.py:5-6` (module docstring): *"this framework generalizes that so new sources (YCharts now; **kuzu/nessie/
   iceberg read-only later**) plug in without touching the core dispatch."*
2. `base.py:18`: *"`NONE` : no external auth (e.g. **a read-only in-estate graph surface**)."*
3. `docs/architecture/NFRA_INTEGRATIONS_STANDARD.md:60` -- the §3 table's `NONE` row, whose *example column* reads
   **"read-only in-estate graph (kuzu/nessie/iceberg)"**.

And `registry.py:37` already holds the slot:
`# Future (read-only in-estate graph surfaces): kuzu / nessie / iceberg -> register here.`

**The one it does NOT fit, and why: `SHARED_SECRET`.** Per `STANDARD.md:59` and `base.py:12-17`, SHARED_SECRET means
*one server-held credential from Secrets Manager is used for every call.* An agent's Cypher traversal against our own
artifact has **no external credential to hold** -- reaching the serving service is in-VPC HTTP (CG-s-11) and reaching
the artifact is IAM-role-based, not credential-per-call. Choosing SHARED_SECRET would oblige a `secret_id` that does
not exist, and `validate_integration_spec` **refuses exactly that**: `base.py:176` --
`if spec.auth_kind is AuthKind.SHARED_SECRET and not spec.secret_id`. So the wrong choice fails closed rather than
silently mis-registering, which is worth knowing.

`DELEGATED_USER` also does not fit, for a different reason: it means the call runs as the requesting user's own token
against an external service that enforces that user's permissions (`base.py:9-11`). There is no external IdP here.
Under `NONE`, **caller identity is still resolved** for audit and the SCTY tier gate (`STANDARD.md:60`,
`base.py:93-139`) -- so choosing NONE surrenders no attribution. WHO is still known; there is simply no WHICH.
