# ACT B -- the continuation `/2` rewrite, then the dossier rewrite

## B1. THE RULE, READ AT HEAD

`lib/research/corpus/continuation.py`: `METHOD_VERSION = "amgt-corpus-continuation/2"` @`:127`;
object name = `sha16({method_version, inputs})` @`:162`; the reader's selection is
`_select_stored` @`:920` behind `read_latest` @`:939`.

`_select_stored`'s rule, in its own words: among input-matching candidates it prefers those whose
`method_version` equals the current one, newest by `LastModified`; **and "when NONE carries the
current method version, the pre-existing behaviour stands -- the first key in sorted order -- so a
table is never left unserved by this preference."**

**I checked the failure arm before signing, because a reader that could leave a name unserved would
be a different act entirely. It cannot: the fallback is explicit and total** (`min(candidates,
key=key)` @`:937`). `read_latest` raises `LookupError` only when NO object matches current inputs at
all -- never because of the method preference. **This is CRPS-i-1 doing exactly what round 6's
`Z-S45` required, and the reader is the right fix rather than the rewrite.**

## B2. BOTH BRANCHES

**(i) WHAT CHANGES:** with `/2` current and no `/2` object present, `gold_put` performs a put for
every resolved name -- **95 `put_performed`, 0 `existed`** -- each new object's pillars and KPI rows
carrying `terms`; both readers then select the `/2` object (`current_method_available 95`,
`stale_pick 0`). Then every name writes one new dossier object, **373 -> 468**, and `read_dossier`
serves it as the last write, 95 of 95. Figures adopted from the COO's before-state.

**(ii) WHAT IS UNCHANGED:** every `/1` object stays in place (no delete, by B4's rollback), and a
name whose put raises keeps serving its `/1` object by `_select_stored`'s fallback -- **which is
exactly why limb 4 below exists.**

## B3. THE GATE I REQUIRE BETWEEN STEP 1 AND STEP 2 -- this is the substance of this half

The COO half states `current_method_available 95 / stale_pick 0` as an **after-the-run
discriminator**. **It must be a GATE between step 1 and step 2, and here is the mechanism.**

`_select_stored`'s fallback is per-name and benign in isolation: a name with no `/2` serves its `/1`
and no table is unserved. **But step 2 then writes 95 dossier objects, each baking in whichever
continuation its name happened to serve.** A partial step 1 -- say 60 puts land and 35 raise --
therefore produces a dossier corpus that is **60 names on `/2` terms and 35 on `/1` terms**, written
once, on one `as_of` date.

**The mix is RECOVERABLE but NOT DECLARED.** The dossier records the continuation input as uri+sha,
so the method is recoverable by dereferencing 95 objects; **no field on the dossier says
`method_version`, so no consumer can reject on it.** That is precisely the failure
`A_VALUE_MUST_CARRY_ITS_CLAIM` describes, and it is `Z-S45`'s split-brain moved one hop downstream
into a write-once artifact -- where the cheap fix (revert `METHOD_VERSION`, re-read) no longer
reaches it, because the dossier objects for today already exist.

**4. STOP LIMB -- THE GATE: if step 1 does not read `put_performed 95, existed 0` AND
`current_method_available 95, stale_pick 0`, DO NOT RUN STEP 2.** Read the failures, fix, re-run
step 1 to 95, and only then write dossiers. **A partial step 1 followed by step 2 is not a
recoverable state on the same `as_of` date.**

## B4. ROLLBACK, STATED AS THE COO STATED IT -- code-and-rewrite, not an object restore

Continuation: revert `METHOD_VERSION` to `/1`; the readers then select the `/1` objects, which are
still in place. Dossier: no page reads the table (portal 0 files), and the rollback is the rewrite on
reverted code, **which lands on the next `as_of` date because today's object names already exist.**
**I sign that as stated and name its consequence: the dossier rollback is not same-day.** That
asymmetry is the whole reason limb 4 is a gate and not a discriminator.

## B5. TWO MORE STOP LIMBS

5. **A dossier write printing `unchanged ... wrote 0` on any name** -- STOP and read it as a row: the

6. **`stale_pick` non-zero at any point after step 1** -- STOP. That is `Z-S45` live on a served
