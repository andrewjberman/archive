  - `grade(name, type) -> (verdict, canonical_form)`: the verdict is one of `CONFORMANT`, `ALIAS`, `OUT-OF-PATTERN`, `NOT-GRADED`. A RAISE is `raise RaiseDefect(message)`, a class defined in the module.

    - `validate [--registry-dir DIR] [--systems-file FILE]`: exit 0 if valid, 1 if refused, printing each refusal with its field.

- A GENERATED file carries `GENERATED by lib/opal_naming.py from infra/logic/registry@<first 16 hex of registry_hash()>` in its own comment syntax. A JSON file carries it as a top-level `"_generated"` key, which is not an export.
- `.tools/naming-gate.py`, the commit limb:
  - `--diff FILE` grades a unified diff's ADDED lines. A string is NEW if it is absent from the file's pre-image at HEAD, and every string in a `--- /dev/null` file is NEW.
  - `--enforce`, env `NAMING_GATE_ENFORCE=1`, or a present `org/mcp/naming-gate.enforce` makes a REFUSE exit 1. Otherwise it is WARN and exits 0.
  - Output: one `NAMING <verdict> <file>:<line> <string> -> <canonical>` line per graded string (`<verdict>` is the grade, or `REFUSE`), then one `NAMING-GATE: <PASS|WARN|REFUSE> <n> graded` line.
  - An internal error prints `NAMING ERROR <reason>`, and exits 0 when not enforcing.
  - Every verdict line is appended to `org/mcp/naming-gate-verdicts.log`. That log is runtime state: never commit it.
- `.tools/naming-apply-gate.py DIR`, the safe-apply limb: the same output lines and the same enforce rules, over every resource-name attribute in DIR's `.tf` files.
