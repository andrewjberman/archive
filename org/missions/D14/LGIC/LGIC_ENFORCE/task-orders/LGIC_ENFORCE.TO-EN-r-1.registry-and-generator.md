`EN-r-1` -- the registry rows, the validator and the generator (PRD candidate E2; DEC-1, DEC-5).

**The registry (DEC-1).** Create five JSON files in `infra/logic/registry/`, seeded from `infra/logic/05_IDENTITY_SPINE.md`:
- `systems.json`, rows `key`, `class` (one of the schema's `system.classes`: `PRODUCT`, `PLATFORM_SUBSYSTEM`, `VENDOR`), `long`, `short` (only where sanctioned) and `owner_directive` (a D-code that resolves in `org/missions/DIRECTIVES.yaml`). A key the schema's `system.never_a_system` excludes is refused: a firm, a project code, a workstream code, a cadence or a generic noun. `opal` is never a row.
- `scopes.json`, rows key, class, long, short, tenancy, bucket and aliases.
- `tiers.json`, tier to home rule per tenancy.
- `exemptions.json`, per firm bucket, each exempt principal with its `reason` and `signoff_ref`.
- `remediations.json`, per remediation project, its owned surfaces and ranking row.

There is NO kinds file: kinds and cadences are owned by `NAMING_SCHEMA.json` (v1.4 at HEAD), which the code reads at run time and never copies. `bd` appears only as an alias or a refused token.

**The validator and the generator** go in `lib/opal_naming.py` (interfaces below; the builders `key`, `address`, `name` and `grade` are EN-b-1's, next in your slot's queue):
- `validate` refuses the two issuer fixtures `org/missions/D14/LGIC/LGIC_ENFORCE/deliverables/2.0.0_SA_COO~G/fixed_inputs/tests/r1/systems_missing_owner.json` and `org/missions/D14/LGIC/LGIC_ENFORCE/deliverables/2.0.0_SA_COO~G/fixed_inputs/tests/r1/systems_firm_key.json` (exit 1, naming the field).
- `generate --out DIR` reproduces each carrier in `org/missions/D14/LGIC/LGIC_ENFORCE/deliverables/CARRIER_CENSUS.md` (EN-c-1, merged) **byte-for-byte in its EXPORTED content**, into DIR, never over the carrier. Writing the carriers themselves is EN-v-1..6's.
- `registry_hash()` per the interfaces.

**The interfaces this round fixes.** The checker calls exactly these, so build to this shape:
- `lib/opal_naming.py`, standard library only, loaded BY PATH (`lib/` has no `__init__.py`; the checker uses `importlib.machinery.SourceFileLoader`, as `lib/tests/test_trading_calendar.py` does):
  - `key(source, scope, tier, table, partition) -> str`: exactly `{source}/{scope}/{tier}/{table}/{partition}`.
  - `address(source, scope, tier, table, partition, object=None) -> str`: `s3://{bucket}/{key}`, plus `/{object}` when given. The bucket comes from the tier home rule and the scope's tenancy, never from an argument.
  - `name(system, scope, function, kind, qualifier=None) -> str`: takes the LONG scope and emits the SHORT form (S4). `scope=None` is a shared resource (S5).
  - `grade(name, type) -> (verdict, canonical_form)`: the verdict is one of `CONFORMANT`, `ALIAS`, `OUT-OF-PATTERN`, `NOT-GRADED`. A RAISE is `raise RaiseDefect(message)`, a class defined in the module.
  - `lookup(scope) -> dict`: the `scopes.json` row for a long form, a short form or an alias, else `KeyError`.
  - `fence_patterns(firm_long) -> list[str]`: the IAM ARN globs matching principals that carry that firm's scope token.
  - `registry_hash() -> str`: sha256 over each `*.json` in `infra/logic/registry/` in name order, fed as `name + "\n" + bytes` with CRLF read as LF; hex.
  - The CLI, `python lib/opal_naming.py <sub>`:
    - `validate [--registry-dir DIR] [--systems-file FILE]`: exit 0 if valid, 1 if refused, printing each refusal with its field.
    - `generate --out DIR [--target PATH ...]`: writes each generated file at its repo-relative path under DIR. With no `--target`, it writes the 8 DEC-5 carrier files, the module's generated locals, and `infra/aws/terraform/modules/opal_name/tests/vectors.json`.
    - `vectors`: prints the vector JSON.
    - `census [--names FILE] [--live] [--repo]`: exits non-zero on the first RAISE, printing the string.
- A GENERATED file carries `GENERATED by lib/opal_naming.py from infra/logic/registry@<first 16 hex of registry_hash()>` in its own comment syntax. A JSON file carries it as a top-level `"_generated"` key, which is not an export.
- `.tools/naming-gate.py`, the commit limb:
  - `--diff FILE` grades a unified diff's ADDED lines. A string is NEW if it is absent from the file's pre-image at HEAD, and every string in a `--- /dev/null` file is NEW.
  - `--enforce`, env `NAMING_GATE_ENFORCE=1`, or a present `org/mcp/naming-gate.enforce` makes a REFUSE exit 1. Otherwise it is WARN and exits 0.
  - Output: one `NAMING <verdict> <file>:<line> <string> -> <canonical>` line per graded string (`<verdict>` is the grade, or `REFUSE`), then one `NAMING-GATE: <PASS|WARN|REFUSE> <n> graded` line.
  - An internal error prints `NAMING ERROR <reason>`, and exits 0 when not enforcing.
  - Every verdict line is appended to `org/mcp/naming-gate-verdicts.log`. That log is runtime state: never commit it.
- `.tools/naming-apply-gate.py DIR`, the safe-apply limb: the same output lines and the same enforce rules, over every resource-name attribute in DIR's `.tf` files.

**Read:** 05_IDENTITY_SPINE.md; NAMING_SCHEMA.json; DIRECTIVES.yaml; CARRIER_CENSUS.md; the eight DEC-5 carrier files (read-only).
