## THE DECISIONS -- CLOSED AT L4

- **DEC-1 The contract is ONE JSON schema at `org/standards/LGCTFM_CONTRACT.schema.json`, derived from ATOM_DECOMP's
  rectangle and extended with the DESIRED half.** The row's domain is IV.8's class list BY SUBTRACTION from
  `NAMING_SCHEMA.json`'s node-type vocabulary at the run's vintage, never a forward list; the fields per class are
  seeded from `lambda-source-map.json`'s and `EC2_MANIFEST.json`'s own field lists (Part VII bullet 3). Every cell is
  `{value, status, evidence}`; a resource the walk could not see is a row with status UNMEASURED, never a missing row.
  The Rule 24 record (MECE over the declared domain, same grain -- one resource per row, a plane is a resource, a fork
  is a row over resources -- one intent per axis, state coherence naming which cells a rename does NOT move and which a
  home move does NOT rename) and the word-boundary token census of every enum value are ALREADY LANDED as
  `infra/logic/11_LGCTFM_CONTRACT_SCHEMA_RECORD.md` @`a71a2406be` (the CRO's OPTION 1, Part V.1), absorbed here as prior
  art the way `04_`/`05_`/`06_` were by the sibling PRDs; T1 authors the JSON schema FROM it and cites it, and a schema
  enum the record does not name is a Rule 24 act of its own, not a T1 liberty. The record's section 1.1 is the
  partition of the 33 types and its sums.
- **DEC-2 The engine is `lib/opal_lgctfm.py`, standard library only, ASCII only, and the method is
  `infra/logic/10_LEGACY_TRANSFORM.md`.** The same contract `lib/opal_naming.py` keeps (stdlib, ASCII), so the gate,
  the runtime and a fresh worktree can import it with no dependency. The skill `.claude/skills/lgctfm/SKILL.md` is the
  one invocation: subject in, run directory out. The engine is a WALKER over existing instruments and a CALLER of
  existing builders; it implements no census of its own where one exists.
- **DEC-3 The walk reads BOTH trigger APIs, through `comp-trigger`, and carries the five scheduling atoms per leg x
  table.** A contract whose trigger denominator names only `list-rules` or only `list-schedules` is refused by the
  schema (IV.6). The walk order, fixed: the ledger's plane rows for the subject (the seed) -> the buckets and prefixes

  `name()` for a resource name, the bucket grammar for a bucket, `grade()` for the verdict; the run stamps

  `missing_registry_row` names the row Rule 30 requires (a `{system}` not in `systems.json`, a scope not in

- **DEC-5 A fork is two current resources whose DESIRED canonical form is ONE string.** Detected from the desired twin,
  never from name patterns. The FORK row names the members, the one job, and the canonical member: the conformant one
  where one is; where BOTH are non-conformant, the member the ledger's disposition names, and absent that a QUESTION
